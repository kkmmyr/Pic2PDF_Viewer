# 要件定義書

最終更新: 2026-05-08（要件方針の再定義）

## 1. 目的

**同人誌の閲覧と整理に特化した、個人 LAN ソロ用 Web アプリケーション。**

ZIP / WebP 画像で蓄積した同人誌コンテンツを PDF 化してブラウザ上で快適に閲覧し、作者・シリーズなど最低限のメタ情報で整理するためのツール。

### 1.1. 対象ユーザー・利用前提

- **単一ユーザー**: 開発者本人 1 人による LAN 内利用を前提とする。アカウント機能・認証は持たない。
- **取り込み元**: 主に ZIP / フォルダ単位の同人誌コンテンツ。**ファイル名・フォルダ名に規則性は無い前提**（作者ごとに命名がバラバラ）。
- **DLsite / Fanza の作品 ID は基本的に取れない前提** で設計する。Web 検索 + LLM による自動メタデータ取得は精度が出ないため採用しない。

### 1.2. 設計方針（核となる 3 原則）

1. **ミニマル化**: 使われない機能は削る。「あって安心」だけの機能は持たない。
2. **手動 + AI 提案**: メタデータ整理は手動を前提とし、AI は **自動実行ではなく "提案"** として支援する。提案はユーザー確認後に確定する。
3. **同人誌の閲覧体験を磨く**: 1 冊が短く冊数が多い同人誌の特性に合わせ、サークル横断・見開き表示・関連書籍ナビを継続的に強化する。

## 2. コア機能

### 2.1. PDF 閲覧 (Reader) — 最重要

**このアプリの核機能**。明日壊れて一番困るのは閲覧機能。

- **見開きモード**:
    - **Auto（自動）**: ページの縦横比を判定して縦長なら見開き / 横長なら 1 ページ表示。デフォルト。
    - **Spread（固定見開き）**: 常に 2 ページ表示。
    - **Single（固定 1 ページ）**: 常に 1 ページ表示。
    - ヘッダーボタンで Auto → Spread → Single → Auto の順に循環。
- **右綴じ（RTL）**: 漫画と同様、右が若いページ。
- **没入型モード**: PDF 閲覧中はグローバルヘッダー非表示、コントロールバーはマウスオーバー時のみ表示。
- **ページ送り操作**:
    - 左側クリック / 矢印キー（RTL/LTR を考慮した方向）で次ページ。
    - キーボード操作中心の運用を想定（ボタンより矢印キーが主）。
- **高速閲覧モード (Image-Based Viewing)**: PDF 生成時に抽出された WebP 画像があれば PDF レンダリングをスキップして直接表示。無ければ `react-pdf` フォールバック。
- **ナビゲーション**: URL パラメータ (`?path=...`, `?file=...`) で状態管理。ブラウザ「戻る」「進む」で履歴を辿れる。

#### 改善予定（優先度高）

- **見開き原稿（センターカラー等）の表示崩れ修正**: 見開きページと 1 ページ画像が混在すると画面が崩れる問題を解消する。
- **同サークル次の作品にリーダーから直接ジャンプ**: 関連書籍パネルを拡張し、リーダー内から同サークルの次作品へ素早く遷移できるようにする。

### 2.2. PDF 生成 (Generator)

ZIP / フォルダ単位で取り込んだ同人誌を PDF 化する機能。

- 指定した親ディレクトリ以下を再帰的に走査する。
- **フォルダ処理**: 各ディレクトリ内の WebP 画像を自然順ソートで PDF 化。出力名は `<フォルダ名>.pdf`。
- **ZIP ファイル処理** (主流): ディレクトリ内の `.zip` を検知し、中の WebP 画像を同様に PDF 化。出力名は `<ZIP ファイル名>.pdf`。
- 結合 PDF は `backend/data/main/pdfs_compressed` 配下に出力。
- **完了後の処理**: 成功したフォルダ / ZIP は `backend/data/main/complete` に移動。
- **一括圧縮** (`POST /api/batch_compress`): 既存 `images` 配下の画像から JPEG 品質指定で圧縮版 PDF を一括生成（`quality` 1〜95）。同名 PDF が既存ならスキップ。

### 2.3. メタデータ管理（作者・シリーズ）

書籍単位でメタデータを管理する。データはサーバー側 `backend/data/meta/{source}/meta.json` に保存。

- **管理する項目（手動運用するもの）**:
    - **作者名**（基本はサークル名、個人活動のみの場合は個人作家名）
    - **シリーズ**（`series_id` / `series_title` / `series_index`）
    - **お気に入り**（トグル）
    - **読書状態**（未読 / 読書中 / 読了）
    - **非表示フラグ**（ゴミ箱方式）
- **編集 UI**:
    - サムネイルカードクリックで直接 PDF へ遷移（詳細パネルなし）。
    - **複数書籍への一括設定**: 選択モードで複数選択 → 「作者を設定」「シリーズに登録」等のボタンから一括上書き。一括成功時は選択モードを自動解除（連続操作の意図が薄いため）。
- **検索・フィルター**:
    - **タイトル検索**: タイトル / 作者名に部分一致。
    - **作者フィルター**: ライブラリヘッダーのドロップダウンで完全一致。
    - **シリーズフィルター**: 同上。

### 2.4. シリーズ管理

- **手動を前提とする**。同人誌では命名規則が作者依存で揺れが大きく、ルールベース・LLM 補助とも実用精度に達しない判断（[§7. 撤去された機能](#7-撤去された機能)参照）。
- **データモデル**: `meta.json` 各エントリに `series_id` / `series_title` / `series_index` を任意フィールドとして保存。`series_index` は `float`（小数巻 `2.5`, `4.5` 等に対応）。
- **手動編集**:
    - 書籍カードから「シリーズに追加」/「新規シリーズ作成」/「シリーズから外す」が可能。
    - **一括登録**: 選択モードで複数選択 → 「シリーズに登録」から既存シリーズへ追加 / 新規作成。巻数は **選択順** に自動採番（既存シリーズへの追加時は `max(series_index) + 1` から続けて採番）。
    - **DnD 並べ替え**: シリーズドリルダウン中（`?series=...`）は `series_index` 順で表示し、ドラッグ&ドロップで並べ替え可能。ドロップ時に `1.0, 2.0, 3.0, ...` で振り直し。
- **AI 提案（既存シリーズへの紐付け候補）— 2026-05-09 実装**:
    - **入力**: ユーザーが選択した複数冊。
    - **出力**: 「これらは既に登録されている『○○シリーズ』に属するのではないか」という **既存シリーズへの所属候補** を提示。
    - **動作原則**: 自動実行しない。提案のみ。ユーザー確認後に紐付け確定。
    - **UI**: `BulkSeriesAssignDialog` の第 3 モード「AI が提案するシリーズに追加」。モード選択時に `POST /api/series/suggest` を自動呼び出しし、上位 5 件をラジオで表示。
    - **マッチング**: ルールベース（タイトル前方一致スコア + 作者集合一致ボーナス）。LLM 連携は POC 段階では未対応。
    - **新規シリーズ発見** ではなく **既存シリーズへの紐付け** に焦点を絞ることで、撤去した自動グループ化の精度問題（取りこぼし、誤登録名）を回避する。

### 2.5. ライブラリ表示

PDF 一覧画面のレイアウト・操作。

- **フォルダ階層表示**: サブディレクトリはフォルダアイコンで表示、クリックでドリルダウン、戻るボタンで親階層へ。
- **サムネイル表示**: PDF の 1 ページ目をサムネイルとして表示。
- **ソート種別**（ライブラリヘッダーで切替、選択は localStorage に永続化）:
    - 名前（昇順 / 降順）
    - 作成日時（昇順 / 降順）
    - **お気に入り優先**（お気に入りを先頭、同グループ内は名前昇順）
    - **よく見る順** (`view_desc`): 閲覧回数の降順。同数は名前昇順。
    - **最近見た順** (`recent_view`): 最終閲覧時刻の降順。未閲覧は末尾。
- **グループ化表示**: ライブラリヘッダーの「グループ化」セレクトで切替。
    - **なし**（デフォルト）: フラット表示
    - **シリーズで**: 同 `series_id` を最終巻のサムネイルで集約
    - **作者で**: 同作者集合を集約。代表サムネは現ソート順の先頭
    - **作者 → シリーズで**: 2 階層ドリルダウン
- 集約された仮想カードは紫枠で表示。クリックでドリルダウン（パンくずナビゲーション）。
- **閲覧記録**:
    - PDF を開いたタイミングで `view_count` と `last_viewed_at` を記録。
    - **連打抑制**: 同じ書籍を 5 分以内に再度開いてもカウントは増えない（最終閲覧時刻のみ更新）。
    - 読書状態の自動遷移（`unread → reading`、最終ページ到達で `reading → done`）。

### 2.6. 関連書籍パネル

リーダーで最終ページに到達した時、関連書籍をフローティングパネルで提示する。

- **集計軸**: 同シリーズ / 同作者 / 共通タグ（タグ撤去後はシリーズ・作者のみ）。
- **拡張予定**: リーダー内から **同サークル次の作品へ直接ジャンプ** できるよう導線を強化（[§2.1 改善予定](#21-pdf-閲覧-reader--最重要)参照）。

### 2.7. 書籍編集

- **PDF 結合**: 選択モードで 2 冊以上選び「PDF を結合」から順番通りに 1 つの PDF に結合。出力名はダイアログで指定（重複名は拒否）。サムネイルも自動生成。
- **サムネイル再生成**: 単発 / 一括（選択モード）。
- **ページ削除**: PDF 閲覧画面の「編集モード」で任意のページを選択して削除し、上書き保存。

### 2.8. 非表示（ゴミ箱方式）

- 個別書籍を「非表示」にして一覧・検索・フィルター・グループ化のすべてから隠す。
- **操作**: 書籍カードの目アイコン (`EyeOff`) で単冊、選択モードで一括。
- **確認・復元**: ヘッダーの「非表示を表示」トグル ON で **非表示書籍のみ** を表示し、目アイコン (`Eye`) で復元。
- **データ保持**: 書籍ファイル本体は削除せず、`meta.json` の `hidden` フラグのみ更新。

### 2.9. Hitomi 新着監視

外部サイトの新着監視を独立スクリプトとして提供（[Hitomi 新着監視設計書](../03_詳細設計/hitomi新着監視設計書.md)）。

## 3. 取り込みパイプライン

### 3.1. 主な取り込み元

- **ZIP（最頻）**: 所定フォルダに ZIP を置く → Generator で PDF 化。
- **WebP 画像フォルダ**: 既に展開済みの画像フォルダから PDF 化。

### 3.2. ファイル名・フォルダ名の前提

**規則性は無い前提で設計する**。作者ごとに命名がバラバラのため、ファイル名解析による作者名抽出は行わない。

### 3.3. DLsite / Fanza 連携

- **基本方針: 採用しない**。同人誌は作品 ID が取得できないケースが大半のため、Web 検索 + LLM による自動メタデータ取得は採用しない。
- **将来の余地**: 公開ページ範囲で「作品名検索 → キーワードタグ取得」が現実的に動く目処が立てば、補助機能として再検討する余地を残す（現時点では計画外）。

## 4. 撤去予定機能（実装中）

新方針への移行に伴い、以下の機能は撤去する。撤去後は本セクションを [§7. 撤去された機能](#7-撤去された機能) へ移動する。

| 機能 | 撤去理由 |
|---|---|
| **シリーズ自動グループ化**（ルールベース + Gemma 補助） | 同人誌の命名揺れに対し精度が実用に達しない。手動運用が前提と判断 |
| **サークル名 Auto-Fill**（Web 検索 + LLM） | 品質が悪く、結局手動修正が必要なため使われていない |
| **タグ手入力機能** | 利用用途がなく放置されている。将来 DLsite キーワード取得が実現した場合は別形態で復活検討 |
| **「次の巻へ」フローティングボタン** | 矢印キー操作中心で利用されていない |
| **未分類シリーズ候補レポート** | AI 提案（既存シリーズへの紐付け）に置換 |

撤去時は **`meta.json` の対応フィールド（`tags` 等）を完全削除するマイグレーション** を実施する。

**注**: レーティング（★1〜5）は本ファイル以前のバックログで実装候補として挙がっていたが、コード上に実装されたことはなく、利用習慣も無いため [機能追加候補.md](機能追加候補.md) の対象外テーブルへ移動した。

## 5. 保留領域（要件未確定）

以下は現時点で利用方針を保留し、要件定義書からは詳細仕様を切り出さない。

### 5.1. Kindle 連携（`Kindle` タブ + `kindle-pdf/` キャプチャツール群）

- **現状**: ライブラリの「Kindle」タブ、`kindle-pdf/main_auto.py`（漫画/雑誌キャプチャ）、`kindle-pdf/main_novel.py` + `batch_ocr.py`（小説キャプチャ + OCR）が存在。
- **方針**: 現時点では利用頻度が低く、将来は別ツールへの分離を検討するが、**現状は保留** とする。詳細仕様は別途維持する。

### 5.2. OCR（Searchable PDF 生成）

- **現状**: `yomitoku` + `ReportLab` による透明テキスト埋め込み PDF 生成。Kindle 小説取り込みの標準フローに統合。
- **方針**: Kindle 連携と同様に保留。同人誌（generated ソース）への適用可能性は将来検討。
