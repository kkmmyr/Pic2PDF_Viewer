# 要件定義書

## 1. 目的
WebP画像を管理・閲覧するためのWebアプリケーション。
大量の画像をPDFとしてまとめ、ブラウザ上で快適に閲覧することを目的とする。

## 2. 主な機能

### 2.1. PDF生成 (Generator)
*   指定した親ディレクトリ以下を再帰的に走査する。
*   **フォルダ処理**: 各ディレクトリ内のWebP画像を収集し、ファイル名の「自然順」でソートしてPDF化。出力名は `<フォルダ名>.pdf`。
*   **ZIPファイル処理**: ディレクトリ内の `.zip` ファイルを検知し、中のWebP画像を同様にソートしてPDF化。出力名は `<ZIPファイル名>.pdf`。
*   1つのPDFファイルに結合し、`backend/data/main/pdfs` ディレクトリ（またはそのサブディレクトリ）に出力する。
*   **完了後の処理**: PDF生成が成功したフォルダまたはZIPファイルは、`backend/data/main/complete` ディレクトリに移動される。
*   **圧縮版PDF生成** (オプション):
    *   PDF生成時に `generate_compressed: true` を指定することで、画質を下げた圧縮版PDFを `backend/data/main/pdfs_compressed` ディレクトリにも同時出力できる。
    *   圧縮品質は `quality` パラメータ (1〜95) で指定。
    *   **一括圧縮** (`POST /api/batch_compress`): 既存の全書籍の画像データから遡って圧縮版PDFを一括生成する機能も提供。


### 2.2. PDF閲覧 (Viewer)
*   `backend/pdfs` 配下のPDFファイルおよびディレクトリを一覧表示する。
*   **フォルダ階層表示**:
    *   サブディレクトリがある場合はフォルダアイコンで表示。
    *   クリックすることで階層を降り（ドリルダウン）、戻るボタンで親階層に戻ることができる。
*   **サムネイル表示**:
    *   PDFファイルは1ページ目をサムネイルとして表示する。
*   **リーダー機能**:
    *   **見開きモード**:
        *   **Auto（自動）**: ページを開く・ページ遷移のたびにページの縦横比を判定し、縦長なら見開き（2ページ）、横長なら1ページ表示に自動切り替えする。デフォルトはこのモード。
        *   **Spread（固定見開き）**: 常に2ページ表示。
        *   **Single（固定1ページ）**: 常に1ページ表示。
        *   ヘッダーのボタンをクリックするたびに Auto → Spread → Single → Auto の順で循環する。
    *   **右綴じ（RTL）**: 一般的な漫画と同様、右側が若いページ（例: 1ページ）、左側が次のページ（例: 2ページ）となる配置。
    *   **没入型モード (Immersive Mode)**:
        *   PDF閲覧中はグローバルヘッダーを非表示にし、コンテンツ領域を最大化する。
        *   リーダー上部のコントロールバーはマウスオーバー時のみ表示され、閲覧の邪魔にならないようにする。
    *   **ページ送り操作**:
        *   左側（次ページ側）クリック: 次の見開きへ進む。
        *   右側（現ページ側）クリック: 前の見開きへ戻る。
        *   **キーボード操作**:
            *   矢印キー（←/→）でページ送りが可能。
            *   RTL/LTRの設定に応じて、直感的な方向（例: RTLなら左キーで「次へ」）に移動する。
*   **ナビゲーション**:
    *   URLパラメータ (`?path=...`, `?file=...`) を使用して状態を管理。
    *   ブラウザの「戻る」「進む」ボタンで、フォルダ移動やPDFの開閉履歴を辿ることができる。
*   **編集機能**:
    *   **ページ削除**:
        *   PDF閲覧画面で「編集モード」に切り替えることで、任意のページを選択して削除できる。
        *   削除実行後、ファイルは上書き保存され、サムネイルも必要に応じて更新される。
*   **高速閲覧モード (Image-Based Viewing)**:
    *   PDF生成時に抽出されたWebP画像が存在する場合、PDFレンダリングの代わりに画像を直接読み込んで表示する。
    *   これにより、特に高解像度の書籍において、PDFのパース処理をスキップして高速にページを表示できる。
    *   画像が存在しない場合は、従来のPDFレンダリング（`react-pdf`）に自動的にフォールバックする。

### 2.3. Kindle連携 (Kindle Library)
*   **専用ライブラリタブ**:
    *   通常のPDF生成（Generator）とは別に、Kindleから取り込んだコンテンツ専用の「Kindle」タブをライブラリ画面に設ける。
    *   タブの切り替えにより、表示する書籍一覧をフィルタリングする。
*   **Kindleキャプチャツール連動 (`kindle-pdf`)**:
    *   **漫画/雑誌 (`main_auto.py`)**:
        *   黒帯検知による自動クロップ機能。
        *   フルスクリーン化およびページめくり自動化。
    *   **小説 (`main_novel.py` + `batch_ocr.py`)**:
        *   **キャプチャ (`main_novel.py`)**:
            *   **白背景検知**: X軸方向（左右）のコンテンツ領域を自動検出してクロップ。Y軸はフルスクリーン設定に従う。
            *   **高速撮影**: OCR処理を撮影時から切り離し、画像の保存に専念する。
        *   **バッチOCR (`batch_ocr.py`)**:
            *   バックグラウンドで画像を読み込み、`yomitoku` でOCR処理を実行。
            *   **Searchable PDF**: OCR結果のテキストと座標を利用し、透明テキスト埋め込みPDFを生成する。
            *   **読み順補正**: 縦書きの読み順（右→左）を考慮したテキスト配置。
    *   **共通機能**:
        *   **ページめくり方向指定**:
            *   撮影開始時に「左キー（右開き）」または「右キー（左開き）」を選択可能。

## 3. 実装済み追加機能

### 3.1. テキスト付きPDF (Searchable PDF)
- 画像ベースのPDF上に透明テキストレイヤーを埋め込み、テキスト検索やコピーを可能にする。
- `yomitoku` (OCR) + `ReportLab` (PDF生成) を連携させ、Kindle小説取り込みの標準フローとして統合済み。
- 詳細: [OCR設計書.md](../03_詳細設計/OCR設計書.md)

### 3.2. 書籍メタデータ管理（作者名・タグ）
- 書籍単位で作者名・タグ（ジャンル等の自由ラベル）を複数登録できる。データはサーバー側 `backend/data/meta/{source}/meta.json` に保存。
- **単冊編集**: サムネイルカードをクリックすると直接 PDF に遷移する（詳細パネルなし）。
- **複数書籍への一括設定**: 選択モードで複数書籍を選択し「作者を設定」/「タグを設定」ボタンから一括上書き。
- **タイトル検索**: ヘッダーの検索欄にテキストを入力すると、タイトル・作者名・タグのいずれかに部分一致する書籍を絞り込む。
- **作者フィルター / タグフィルター**: ライブラリヘッダーのドロップダウンで作者名やタグを選択し、完全一致する書籍のみ表示する。両方指定すると AND 条件。
- **注**: 単冊の作者名・タグ編集は選択モード（1冊のみ選択）から一括設定ダイアログを使って行う。

### 3.3. サークル名自動登録（Auto-Fill）
- ライブラリ画面の「サークル名自動登録」バーから、複数書籍の作者名（同人誌の場合はサークル名）を Web 検索 + LLM で一括推定して `meta.json` に保存できる。
- **モード選択**:
    - **未登録のみ**: 作者名エントリが存在しない書籍だけを処理。
    - **作者不明のみ**: 既に「作者不明」と登録されている書籍と未登録の書籍を再試行（デフォルト）。
    - **全件上書き**: 登録済みを含む全件を上書き。
- **検索戦略**: `generated` ソースは DLsite / Fanza に対する `site:` 検索を優先し、ヒットしない場合のみ汎用クエリにフォールバックする。`kindle` / `novel` は最初から汎用クエリ。
- **進捗表示**: 実行中はバー上に「件数 N / M」と現在処理中のタイトルを表示し、完了後にスキップ件数を含めたサマリーを出す。
- **既存値の保持**: 自動登録は `authors` のみを上書きし、閲覧回数 / 最終閲覧時刻などの他フィールドは保持する。
- **依存**: ローカル LLM（Gemma 4）と SearXNG を別途起動しておく必要がある。

### 3.4. 書籍編集機能
書籍カードに対して、ライブラリ画面・選択モードから以下の編集操作が可能。

- **PDF 結合**: 選択モードで 2 冊以上の PDF を選び「PDF を結合」ボタンから順番通りに 1 つの PDF に結合する。出力ファイル名はダイアログで指定（重複名は拒否）。サムネイルも自動生成される。
- **サムネイル再生成（単発）**: 各書籍カードの再生成アイコンから 1 冊分のサムネイルを作り直す。OCR や手動置き換えで PDF 内容を変えた場合に使う。
- **サムネイル一括再生成**: 選択モードで複数書籍を選び、ヘッダーから一括でサムネイルを作り直す。失敗した書籍はトースト通知で報告する。
- **ページ削除**: PDF 閲覧画面の「編集モード」で任意のページを選択して削除する（既出 2.2）。

### 3.5. 閲覧履歴・並び替え（ソート）
- ライブラリヘッダーのドロップダウンで以下のソート種別を選択できる（選択は localStorage に永続化）。
    - **名前（昇順 / 降順）**
    - **作成日時（昇順 / 降順）**
    - **お気に入り優先**: お気に入りを先頭にまとめ、同グループ内は名前昇順。
    - **よく見る順** (`view_desc`): 閲覧回数の降順。同数の場合は名前昇順。
    - **最近見た順** (`recent_view`): 最終閲覧時刻 (`last_viewed_at`) の降順。未閲覧は末尾。
- **閲覧記録**:
    - 書籍カードをクリックして PDF を開いたタイミングで、サーバー側の `meta.json` に閲覧回数 (`view_count`) と最終閲覧時刻 (`last_viewed_at`) を記録する。
    - **連打抑制**: 同じ書籍を 5 分以内に再度開いてもカウントは増えない（最終閲覧時刻のみ更新）。
- **お気に入り**: ソース別にカードのお気に入りトグルが利用でき、状態は localStorage に保存される。
