# サーバー連携 よく利用するコマンド

> status: living | last-verified: 2026-07-28

Git Bash (Windows) から実行するコマンドを用途別にまとめる。
前提: Tailscale が起動していること、SSH 鍵認証が設定済みであること。
コマンドはリポジトリルートから実行する。

本書はコピー用コマンドだけを管理する。成功判定、障害時の判断、バックアップ方針は
[運用ガイド](運用ガイド.md)を正本とする。

PowerShell から実行する場合、WSL の `bash` ではなく Git Bash を明示する:

```powershell
& 'C:\Program Files\Git\bin\bash.exe' scripts/deploy_to_linux.sh
```

---

## データ同期 (`sync_to_linux.sh`)

```bash
# 同人誌の新刊を追加した後（画像 + サムネイル）
bash scripts/sync_to_linux.sh doujin

# 漫画の新刊を追加した後
bash scripts/sync_to_linux.sh comic

# 小説の新刊を追加した後
bash scripts/sync_to_linux.sh novel

# 全カテゴリ一括（doujin / comic / novel、時間がかかる）
bash scripts/sync_to_linux.sh all
```

> **hitomi について**: hitomi はサーバー上で直接追加するため、`sync_to_linux.sh` の対象外。

> **⚠️ DB 同期について**: `meta2.db` はサーバー側が正とする。`sync_to_linux.sh` に DB 同期機能はない（2026-05-19 削除）。ジャンル・シリーズ・作者の設定はサーバー（`http://medaroserver:8090`）上で直接行うこと。

## アプリコードデプロイ (`deploy_to_linux.sh`)

```bash
# docs を変更した場合は、先に配信用 HTML を更新する
uvx --with mkdocs-material --with mkdocs-mermaid2-plugin mkdocs build --clean

# フロントビルド → workspace転送 → DBバックアップ → backend世代切替 → サービス再起動
bash scripts/deploy_to_linux.sh
```

処理内容:
1. `frontend/` を `npm run build`
2. ルート`pyproject.toml` / `uv.lock`、`backend/`、`common/llm/`、lock検証に必要な`kindle-pdf/pyproject.toml`を世代別staging pathへtar+ssh転送
3. `frontend/dist/` を転送
4. `deploy/` (nginx / systemd 設定) を転送
5. 実行中のNovel writerが0件であることを検査し、app processを一時停止して検証付きDB backupと復元試験を実行
6. workspace lockから新しいbackend世代専用venvを構築し、LanceDB version、backend import、世代外の固定Lance pathをsmoke検査。`shadow` / `lance_icu`ではactive ICU tableのno-match検索も実行
7. backward-compatible migrationを適用後、`backend` / `common/llm` symlinkを新世代へ切り替え、Linux側で`sudo systemctl restart pic2pdf-viewer`
8. service / HTTP probe不合格時はsourceとvenvを含む直前backend世代へrollbackして再起動

> `deploy_to_linux.sh` 自体は MkDocs を生成しない。`docs/` または `mkdocs.yml`
> を変更した場合は、必ず同じ作業ツリーで
> `uvx --with mkdocs-material --with mkdocs-mermaid2-plugin mkdocs build --clean`を先に実行する。

## Linux サービス管理（SSH 接続後）

```bash
# サービス状態確認
sudo systemctl status pic2pdf-viewer

# サービス再起動
sudo systemctl restart pic2pdf-viewer

# リアルタイムログ（Ctrl+C で終了）
sudo journalctl -u pic2pdf-viewer -f

# 最新 50 行のログ
sudo journalctl -u pic2pdf-viewer -n 50
```

## 動作確認

```bash
# 1. アプリと設計書サイトが HTTP 200
curl -fsS -o /dev/null -w "%{http_code}\n" http://medaroserver:8090/
curl -fsS -o /dev/null -w "%{http_code}\n" http://medaroserver:8090/site/index.html

# 2. Linux の実在APIが応答するか確認（SSH 不要、ブラウザでも可）
curl http://medaroserver:8090/api/pdfs?source=doujin | python3 -c "import sys,json; d=json.load(sys.stdin); print('books:', len(d['files']))"

# 3. 配信した設計書の固有語句をサーバー上で確認
ssh amashio@medaroserver \
  "grep -F '確認したい固有語句' '/opt/pic2pdf-viewer/frontend/dist/site/対象ページ.html' | head -n 1"

# 4. サービス状態と直近の error ログを確認
ssh amashio@medaroserver \
  "systemctl is-active pic2pdf-viewer && journalctl -u pic2pdf-viewer -p err -n 50 --no-pager"

# 必要に応じて meta2.db の特定書籍を確認
ssh amashio@medaroserver 'python3 -c "
import sqlite3
con = sqlite3.connect(\"/opt/pic2pdf-viewer/data/meta2.db\")
rows = con.execute(\"SELECT book_id, genre, series_title FROM books_meta WHERE book_id LIKE \\\"%キーワード%\\\"\").fetchall()
for r in rows: print(r)
"'
```

> `/api/health`は定義していないため404が正常。デプロイ確認には上記の実在APIを
> 使用する。`journalctl -p err`は過去のエラーも含むため、デプロイ時刻が明確な
> 場合は`--since 'YYYY-MM-DD HH:MM:SS'`を併用する。tarのfuture timestamp警告を
> 含む成功判定は[運用ガイド](運用ガイド.md)を参照する。

## よくある作業フロー

### 同人誌の新刊を追加した（doujin）

Samba 共有（`\\medaroserver\pic2pdf-input`）にファイルをコピーし、ブラウザの「PDF 生成」ページで「スキャン & 生成」を押すだけ。Windows バックエンドは不要。
詳細: [Linux_Sambaセットアップ.md](Linux_Sambaセットアップ.md)

### 漫画・小説の新刊を追加した（comic / novel）

```bash
bash scripts/sync_to_linux.sh comic   # または novel
```

### Windows で書籍にメタを付けた

メタ情報（ジャンル・シリーズ・作者）はサーバー上で設定すること。DB 同期機能は削除済み。

### コードを修正・機能追加した

```bash
uvx --with mkdocs-material --with mkdocs-mermaid2-plugin mkdocs build --clean   # docs を変更した場合
bash scripts/deploy_to_linux.sh
```

### 全部まとめて同期（週次など）

```bash
bash scripts/sync_to_linux.sh all      # 画像・サムネイルのみ（DB は除外）
bash scripts/deploy_to_linux.sh        # コード変更があれば
```
