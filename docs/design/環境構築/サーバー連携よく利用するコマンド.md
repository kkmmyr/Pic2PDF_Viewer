# サーバー連携 よく利用するコマンド

> status: living | last-verified: 2026-07-03

Git Bash (Windows) から実行するコマンドを用途別にまとめる。
前提: Tailscale が起動していること、SSH 鍵認証が設定済みであること。

---

## データ同期 (`sync_to_linux.sh`)

```bash
# 同人誌の新刊を追加した後（画像 + サムネイル）
bash sync_to_linux.sh doujin

# 漫画の新刊を追加した後
bash sync_to_linux.sh comic

# 小説の新刊を追加した後
bash sync_to_linux.sh novel

# 全カテゴリ一括（doujin / comic / novel、時間がかかる）
bash sync_to_linux.sh all
```

> **hitomi について**: hitomi はサーバー上で直接追加するため、`sync_to_linux.sh` の対象外。

> **⚠️ DB 同期について**: `meta.db` はサーバー側が正とする。`sync_to_linux.sh` に DB 同期機能はない（2026-05-19 削除）。ジャンル・シリーズ・作者の設定はサーバー（`http://100.107.238.88:8090`）上で直接行うこと。

---

## アプリコードデプロイ (`deploy_to_linux.sh`)

```bash
# フロントビルド → コード転送 → サービス再起動 を一括実行
bash deploy_to_linux.sh
```

処理内容:
1. `frontend/` を `npm run build`
2. `backend/`（.venv / data / complete 等を除外）を tar+ssh 転送
3. `frontend/dist/` を転送
4. `deploy/` (nginx / systemd 設定) を転送
5. Linux 側で `sudo systemctl restart pic2pdf-viewer`

## Linux サービス管理（SSH 接続後）

```bash
# サービス状態確認
sudo systemctl status pic2pdf-viewer

# サービス再起動
sudo systemctl restart pic2pdf-viewer

# リアルタイムログ（Ctrl+C で終了）
sudo journalctl -u pic2pdf-viewer -f

# 最新 50 行のログ
sudo journalctl -u pic2pdf-viewer -n 50
```

## よくある作業フロー

### 同人誌の新刊を追加した（doujin）

Samba 共有（`\\medaroserver\pic2pdf-input`）にファイルをコピーし、ブラウザの「PDF 生成」ページで「スキャン & 生成」を押すだけ。Windows バックエンドは不要。
詳細: [Linux_Sambaセットアップ.md](Linux_Sambaセットアップ.md)

### 漫画・小説の新刊を追加した（comic / novel）

```bash
bash sync_to_linux.sh comic   # または novel
```

### Windows で書籍にメタを付けた

メタ情報（ジャンル・シリーズ・作者）はサーバー上で設定すること。DB 同期機能は削除済み。

### コードを修正・機能追加した

```bash
bash deploy_to_linux.sh
```

### 全部まとめて同期（週次など）

```bash
bash sync_to_linux.sh all      # 画像・サムネイルのみ（DB は除外）
bash deploy_to_linux.sh        # コード変更があれば
```
