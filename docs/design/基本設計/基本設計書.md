# 基本設計書

> status: living | last-verified: 2026-08-02

## 1. アーキテクチャ設計

### 1.1. 技術スタック
*   **Frontend**: React (Vite), TypeScript, TailwindCSS (`darkMode: 'class'`)
    *   PDF描画: `react-pdf`
    *   ルーティング: `react-router-dom`
    *   アイコン: `lucide-react`
    *   HTTPクライアント: `axios` (共通 `apiClient` による管理)
    *   サーバー状態管理: `@tanstack/react-query`（Phase 65 で導入。ポーリングは `refetchInterval` で統一）
    *   **注**: MUI (`@mui/material`) は全廃し、TailwindCSSに統一済み。
*   **Web UI Viewer**:
    *   ブラウザベースのモダンなUI (React + TailwindCSS)。
    *   グローバルヘッダーの製品名はブランド表示とし、画面遷移には使用しない。同人誌ライブラリへは「同人誌」グループの「ライブラリ」リンクから遷移する。狭幅画面のナビゲーションは先頭項目から横スクロールできる配置とする。
    *   生成されたPDFの閲覧、サムネイル表示（Lazy Load）。
    *   **見開き自動判定**: ページの縦横比を取得し、Auto / Spread / Single の3モードで見開き表示を制御。
    *   ファイル／フォルダ名のリネーム。フォルダ作成・移動 UI/API は 2026-05-01 に撤去済み。
    *   お気に入り / 並び替え機能（LocalStorage永続化）。
    *   ダークモード対応（localStorage + flash防止インラインスクリプト）。
    *   PDF内テキスト検索（Searchable PDF対応、Ctrl+F）。
    *   **書籍メタデータ管理**: 作者名・シリーズ情報をサーバー側 SQLite (`meta2.db`) に保存。タイトル検索欄での横断検索・各種フィルター・複数書籍への一括設定（作者・シリーズ登録）に対応。既存作者の一括設定は未選択で開始し、作者を明示的に選んだ場合のみ適用する。**一括操作の成功時は選択モードを自動解除** して通常表示に戻す。
    *   **シリーズ管理**: 書籍をシリーズで集約・ドリルダウン表示。シリーズ内の巻順は **DnD で並べ替え** 可能（ドロップ即時保存・失敗時ロールバック）。シリーズ巻の閲覧中は **`↓` / `↑` キー** で同フォルダ内の次巻 / 前巻に 1 ページ目から遷移できる（`useReaderShortcuts` 経由）。
    *   **Novel OCR 実行**: Webブラウザから直接OCR処理を実行・監視する機能。
*   **Backend**: Python (FastAPI)
    *   **Architecture**: サービス層 (Services) によるビジネスロジックの分離。
    *   PDF変換: `img2pdf`, `Pillow`
    *   サムネイル生成: `Pillow` (生成時), `pymupdf` (既存PDF読み込み時)
    *   ソート: `natsort`

    *   サーバー: `uvicorn`
*   **Kindle キャプチャツール** (`kindle-pdf/`, Python Client)
    *   GUI自動化: `pyautogui`
    *   UI 識別: `uiautomation`（control の識別・矩形取得に限定）
    *   画像処理: `opencv-python` (cv2), `Pillow`
    *   依存管理: `uv`（`pyproject.toml` / `uv.lock`）
    *   通常運用: `scripts/run_capture_agent.bat`。`run_comic.bat` / `run_novel.bat` は診断・互換用
    *   OCR・PDF 生成は backend の job queue が担当（小説系のみ）

### 1.2. データフロー

#### 1. 取り込み（フォルダ監視 + 手動、非同期）

**自動（主経路、2026-07-04〜）**:
1.  **User** -> `DOUJIN_INPUT_DIR`（Samba 共有: `\\medaroserver\pic2pdf-input`）に ZIP / フォルダを置く
2.  **Server** (`DoujinWatcher`, lifespan 常駐) -> 定期スキャン（デフォルト 15 秒）でスナップショット取得。2 回連続一致（静穏検知）で取り込みジョブを自動起動
3.  以降は手動と同一経路（`scan_and_generate` -> images & Thumbnail 生成 -> 成功分を `complete/` へ移動）
4.  **Client** -> `GET /api/generate/watcher`（ポーリング）-> 監視状態（state / pending_items / active_job_id / retry_blocked）を表示

トップレベルの隠しディレクトリ（`.` 始まり）は監視対象外とする。
Kindle 自動撮影は `pic2pdf-input/.kindle-capture-inbox` を論理的に分離した
成果物受信箱として利用し、同人誌の自動生成へ混入させない。

**手動（「今すぐスキャン」、失敗残骸の再試行用）**:
1.  **Client** -> `POST /api/generate`（ボディなし）-> **Server**（実行中なら 409 + 実行中 job_id）
2.  **Server** -> ジョブ作成 (UUID) -> `asyncio.create_task` でバックグラウンド起動し、完了まで Task をサービス内集合で保持 -> Response `{job_id, status: "pending"}`
3.  **Client** -> `GET /api/generate/job/{job_id}` (ポーリング 1500ms間隔) -> **Server** -> ジョブ進捗
4.  完了時: `status: "completed"` + 生成ファイルリスト

自動・手動は共有ロックで直列化される（失敗残骸はスナップショット不変の間は自動再試行されず、手動スキャンでのみ再試行）。

#### 2. PDF一覧・閲覧
1.  **Client** -> `GET /api/pdfs?path=...&source=[doujin|comic|novel]` -> **Server**
2.  **Server** -> `source` パラメータに基づき、画像ディレクトリ (`data/doujin/images/`, `data/comic/images/`, `data/kindle_novel/images/`) のサブディレクトリを書籍として走査。
3.  **Server** -> Response (Files with Thumbnail URLs) -> **Client**
4.  **Client** -> `GET` Static Files -> **Server** -> 画像 / サムネイル -> **Client**

#### 3. Kindleキャプチャ（外部ツール `kindle-pdf/`）

*   **通常運用**: 購入書籍詳細から 1 冊分の capture job を作成し、Windows agent が起動済み Microsoft Store版 Kindle へ接続する。ASINで本人照合し、必要ならダウンロード、先頭移動、全画面撮影を行う。
*   **シリーズ補助運用**: `scripts/capture_kindle_series.py` は複数候補を巻順に解決し、前巻の撮影・転送・登録成功を確認してから次の 1 冊分の job を作る。capture job 自体の処理単位は常に 1 冊である。オプトインの復旧モードでは、撮影開始前に Kindle プロセスが消失した失敗だけを即時検知し、再起動後に同じ ASIN を一意に再照合できた場合に限って同じ 1 冊の新規 job を最大 1 回作る。それ以外の失敗では後続巻を開始しない。
*   **漫画 (`comic`)**: agent 通常経路では見開きモードを有効にし、Kindle の `ReadingArea` 内で白背景境界から安全な見開き幅を推定して撮影する。黒帯検出は非見開き互換経路に限定する。撮影した PNG は専用 Samba 受信箱へ送り、Linux backend が `data/comic/images/<書籍名>/` へ原子的に正式配置する。
*   **小説 (`novel`)**: 白背景境界を検出して PNG を送り、Linux backend が `data/kindle_novel/images/<書籍名>/` へ正式配置する。OCR は後続の backend job queue が担当する。
*   **登録前品質ゲート**: Windows agent は正式撮影前に2画面のカナリアを実行し、撮影後に連番・復号・寸法・hash・件数・終端証跡を検査して version 2 manifest を公開する。Linux backend は実ファイルから再計算できる項目と証跡の内部整合を独立検証し、高信頼の反復画面オーバーレイを含む不合格packageを正式画像領域へ配置しない。終端観測とカナリア差分の意味判定はWindows側で行い、Linux側で再実行する契約ではない。復号・hash計算等の読み取り専用処理だけを少数workerで並列化し、Kindle操作、package確定、DB更新は1冊ずつ直列実行する。
*   **互換経路**: `run_comic.bat` / `run_novel.bat` は診断・手動復旧用に残す。通常運用の本人照合・転送・登録経路には使わない。

#### 4. Novel OCR・DB 構築（バックエンド job queue）

管理画面（`/novel/manage`）から手動投入。バックエンドが非同期ジョブとして処理する。

1.  **OCR ジョブ**: `data/kindle_novel/images/<書籍名>/` の PNG を Surya OCR 2 で処理する。ページ単位の品質検査とチェックポイント保存後、run を `awaiting_qa` に置く。必須ページの画像照合・補正と run 承認が完了した場合だけ、SQLite `novel.db` の `pages.full_text` へ1冊分を確定する（Searchable PDF は生成しない）。`yomitoku` は限定補助・比較・後方互換用。
2.  **Full Build ジョブ**:
    - Step 1: OCR 済み `pages.full_text` をチャンク化し、`bge-m3` で埋め込みベクトルを再構築。
    - Step 2: Qwen で書籍サマリとキャラクター辞典を 1 回の呼び出しで生成。
3.  **Context 生成ジョブ** (`generate_contexts`): Full Build とは別に、Qwen で Contextual Retrieval 用コンテキスト文を生成し、コンテキスト込みの埋め込みを再構築する。
4.  **関係生成ジョブ** (`generate_relations`、任意): ページ上の人物共起とキャラクター辞典を用いて関係グラフを生成する。

**段階移行計画（未実装）**: Full BuildのStep 2だけを、Mac上のCodex CLIによる
GPT-5.6 Solの1冊1回主生成へ置き換える。決定的検査はローカル、高リスク主張は別の新規Solセッション、
公開は人手承認後の一括確定とする。OCR、embedding、検索QA、チャンク文脈、関係生成は変更しない。
詳細は[ADR-0018](ADR/0018_sol-primary-post-ocr-generation.md)と
[Sol主生成・選択的独立評価設計](../詳細設計/機能別/小説RAG_Sol生成・評価設計.md)を参照。

#### 5. Kindle 購入カタログ

1. **Windows 管理端末** -> Amazon エクスポートを認証済み Samba 共有内の専用隠しディレクトリ（Linux の `AMAZON_DATA_DIR`）へ同期
2. **User** -> `/kindle/catalog` から差分取り込みを開始
3. **Backend** -> 専用 `kindle_catalog.db` へ冪等 upsert
4. **Client** -> ページング一覧、所有状態、画像取込状態を表示
5. **User** -> Pic2PDFViewer の既存 `comic` / `novel` と ASIN の候補を確認して確定
6. **User** -> キャプチャジョブを作成
7. **Windows Agent** -> ジョブを claim、Kindle をキャプチャし専用受信箱へ送信
8. **Linux Backend** -> 完了成果物を検証し正式配置、`meta2.db` とジョブ状態を更新

カタログは Linux が正本であり、`kindle購入履歴` の画像・表紙キャッシュは読み込まない。DB 選定は [ADR-0016](ADR/0016_kindle-catalog-sqlite.md)、詳細は [Kindle 購入カタログ設計](../詳細設計/機能別/Kindle購入カタログ設計.md) を参照。

購入書籍の選択後に、起動済み Kindle アプリでの検索・本人照合、未ダウンロード待機、先頭移動、全ページ撮影、登録までを自動実行する。詳細は [Kindle 自動撮影取込 要件](../要件定義/Kindle自動撮影取込_要件.md)を参照。初期版は 1 冊ずつ処理し、Kindle の自動起動・ログイン・画面ロック解除は行わない。
