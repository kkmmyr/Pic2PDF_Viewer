# ADR-0023: Qwen＋dots OCRの人手QAをリスク対象へ限定する

- **Status**: Superseded by ADR-0024
- **Date**: 2026-08-23
- **決定者**: プロジェクトオーナー
- **Supersedes**: [ADR-0022](0022_review-assisted-qwen-dots-ocr.md)の全ページ人手照合条件
- **関連**: [OCR設計書](../../詳細設計/機能別/OCR設計書.md) / [小説OCR品質改善 実装計画](../../../log/計画/小説OCR品質改善_実装計画.md)

> 2026-08-23に、人手必須QAと本番engine切替は
> [ADR-0024](0024_codex-operated-offline-ocr-publication.md)のCodex管理隔離実行・reviewed package反映へ置き換えた。

## コンテキスト

ADR-0022は機械gate未達を理由に、複合版の全ページを人手で原画像照合する条件を採用した。
実書籍pilotのrun 184では57画面を完走したが、全件目視は個人利用でも負担が大きかった。
一方、候補切替、候補解析失敗、反復、画像のみ、分類未確定を含む高リスク画面とclean本文標本の
計19画面をプロジェクトオーナーが確認した結果、画面19の自然な意味誤認1件を除き、重大な欠落・
読順崩壊はなかった。その後、候補差分の大きい7画面を追加で原画像監査し、画面11の重複、13の誤認、
36の2文欠落も特定した。4画面はいずれも原文が確定でき、補正文として保存できた。画像のみ4画面、
表紙2画面、引用1画面も分類を確定できた。

## 決定

1. Qwen3.5-OCR-JP-2B主候補＋dots.mocr全ページ副候補の構成、固定revision、両raw保存、
   完全集合・画像SHA・provenance検査は維持する。
2. 人手必須QAは、clean以外の候補選択理由、候補解析失敗、選択候補の反復、候補の有意な文字量差、
   image-only、通常散文以外のlayout、分類未確定、内容risk flagのあるページへ限定する。
3. これらに加え、各冊子のcleanな通常本文から中央付近を1画面以上、位置に依存しない基準標本として確認する。
4. 残りの`qwen_clean`通常本文は、選択本文が非空・非反復で、両候補とprovenanceが完備し、
   未選択候補に有意な追加本文がなく、入力SHAが不変な場合だけ機械支援承認できる。
   ページQAメモへ人手確認か機械支援承認かを明記する。
5. 1ページでも重大な欠落・読順崩壊・UI混入を見つけた場合は縮小を中止し、当該runを全ページQAへ戻す。
6. 自動公開は行わない。リスク対象の人手承認、残ページの監査付き承認、公開前backup、原子的公開、
   旧版rollback確認を通過したrunだけを本番採用候補にする。

## 根拠

run 184では選択候補がdotsへ切り替わった全15画面、候補解析失敗、反復、画像のみ、分類未確定、
clean本文標本を含む19画面を人手確認した。Qwen欠落疑いの画面20・26・52、Qwen反復の画面21、
構造解析異常の画面47・57にも重大問題はなく、画像のみ画面は検索本文を持たない分類で妥当だった。
自然な意味誤認を完全には機械検出できないため自動公開には昇格しないが、異常信号と独立候補を使った
リスク抽出にclean標本を加えることで、個人利用で受容可能な確認量とrollback可能性を両立できる。

run 184では19画面をプロジェクトオーナー確認、追加7画面をCodex原画像監査、残るclean通常本文31画面を
機械支援監査として全57画面を承認した。画面11・13・19・36へ補正文を保存した後、隔離DBで公開し、
本文・FTS・履歴を検査して旧run 76へrollbackした。rollback後の本文、文字数、page分類、索引可否、FTSは
公開前と一致した。画像パスは旧Windows絶対パスを復元せず、SHA一致を確認した現在のMac入力パスへ
再基準化され、`ocr_done_at`も切替時刻へ更新される。この意味でのrollbackはcanonical本文・索引・分類の
復元であり、DB全フィールドまたはDBファイルのバイト一致を意味しない。

## 結果（Consequences）

- 人手確認量を全57画面からpilot実績19画面程度へ縮小できる。
- 機械支援承認と人手承認をQAメモで区別し、後から再監査できる。
- 機械signalに現れない自然な誤認を見逃す残存リスクを受容する。
- model、prompt、runtime、selectorを変更した場合は、本判断を引き継がず再pilotする。

## 再評価条件

- 本番運用で検索・要約の意味を変える誤認、段落欠落、読順崩壊を発見した。
- 候補間の同一誤認が増え、独立候補がrisk抽出に寄与しなくなった。
- 未調整holdoutの全機械gateへ合格し、さらに確認範囲を縮小できる根拠が得られた。
