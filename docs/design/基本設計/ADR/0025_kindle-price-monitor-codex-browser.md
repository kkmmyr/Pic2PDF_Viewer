# ADR-0025: Kindle価格監視をCodexブラウザ観測で実行する

- **Status**: Accepted
- **Date**: 2026-08-23
- **Related**: [Kindle価格監視設計](../../詳細設計/機能別/Kindle価格監視設計.md)、[Kindle購入カタログ設計](../../詳細設計/機能別/Kindle購入カタログ設計.md)

## Context

Kindle書籍の特定URLについて、現在価格と定価を定期確認して通知したい。
Amazonアソシエイトへの加入や、Amazonページをバックエンドから直接取得する方式は
採用しない。また、Kinseli/KiseppeのデータAPIは、個人利用を許可する公開説明を確認
できず、自動利用の根拠として採用しない。

## Decision

監視対象URLは画面から `kindle_catalog.db` に保存し、Codexのスケジュール実行が
各URLをブラウザで開いて、画面に表示された価格だけを観測する。価格の保存・比較・
Discord通知・失敗状態はPic2PDFViewer側のCLIとSQLiteが担当する。

ブラウザ観測とアプリ側の状態更新を分離するため、Codexは対象一覧をCLIから取得し、
観測結果をJSONでCLIへ渡す。アプリのAPIやDBに対する価格取得処理は実装しない。

## Alternatives considered

### Kinseli/KiseppeのAPIを利用する

不採用。データソースの利用許可が公開情報から確認できず、個人利用を理由に継続的な
自動取得を正当化できない。

### AmazonページをバックエンドからHTTP取得する

不採用。ユーザーが避けたいスクレイピングに該当し、Amazon側のブロックやHTML変更にも
弱い。

### Playwright等を常駐サーバーで実行する

現段階では不採用。技術的には安定させやすいが、今回の「Codexで開いて確認する」という
運用意図から外れ、ブラウザ自動取得の常駐基盤を別途保守する必要がある。

## Consequences

### Positive

- Amazonの画面で実際に表示されている値だけを判定できる。
- Kinseliの非公開・不明確なデータ利用条件に依存しない。
- 監視対象、履歴、通知状態をアプリ画面から管理できる。

### Negative

- Codexのブラウザセッション、Amazonのログイン要求、CAPTCHA、画面変更に依存する。
- ページを開けない回は価格が欠測になり、通知を保証できない。
- 定期的なブラウザ観測はAmazon側から自動アクセスと判断される可能性があり、利用規約・
  ブロック・アカウント制限のリスクは残る。
- 価格の基準となる「定価」がページに表示されない書籍は、比率判定できない。
