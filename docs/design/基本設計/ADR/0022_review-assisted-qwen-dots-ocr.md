# ADR-0022: Qwen3.5 OCRとdots.mocrを全ページレビュー前提で採用する

- **Status**: Superseded by ADR-0023
- **Date**: 2026-08-23
- **決定者**: プロジェクトオーナー
- **関連**: [OCR設計書](../../詳細設計/機能別/OCR設計書.md) / [小説OCR品質改善 実装計画](../../../log/計画/小説OCR品質改善_実装計画.md) / [ADR-0021](0021_sol-image-ocr-campaign.md)

## コンテキスト

完全自動公開を想定した加重CER 0.5%未満・ページ最大CER 2.0%未満の機械gateでは、
評価したローカルOCR候補を正式採用できなかった。一方、Qwen3.5-OCR-JP-2Bは正常ページで
低い誤り率を示し、独立dots候補を使うレビュー用複合版は、開封済みJSSODa縦書き79枚で
加重CER 0.4091%・ページ最大2.8835%だった。総合gateは下回ったがページ最大gateは未達であり、
未調整holdout合格とは扱えない。本アプリは個人利用で、
原画像、候補本文、ページ単位補正文、承認後の原子的公開、rollbackを既に保持できる。

## 検討した選択肢

| 選択肢 | 概要 | 採用しなかった理由 |
|---|---|---|
| 機械gate合格まで候補探索を続ける | 全自動品質だけを完了条件にする | 改善幅に対して探索費用が大きく、既存の人手QA基盤を活用できない |
| dots.mocr単体 | 固定79枚を完走済みの候補を使う | 加重CER 0.8990%・最大4.0155%で、Qwen複合候補より修正量が多い |
| Qwen単体 | 日本語特化モデルだけを使う | 79枚中4枚が8,000 tokenまで反復し、単体加重CER 104.9354%となった |
| **Qwen主候補＋全ページdots副候補＋全ページ画像照合** | 両候補を保存し、欠落疑いも比較して公開前に修正・承認する | （採用） |

## 決定

1. 固定revisionの`ebinan92/Qwen3.5-ocr-jp-2b`を主候補、固定revisionのdots.mocrを
   全ページで生成する独立副候補とした複合版を、**レビュー前提の正式採用候補**とする。
2. 反復、8,000 token到達によるHTML切断、plain text契約外の可視markup、隣接する狭い縦列bboxの
   左→右出力に加え、反復のないdots本文がQwenより30文字・2%以上長い場合をレビュー初期候補の切替信号とする。
   bbox判定は広い領域や離れたblockを比較しない。正解本文、ページID、特定誤字をselectorへ渡さず、
   選択にかかわらず両候補のraw出力と本文を保存する。モデルrevision・fingerprint・promptがページ間で混在したrunは拒否する。
3. この版で生成した全ページを必須QAとする。narrativeは例外なく原画像と照合して誤字・欠落・読順を
   `corrected_text`で修正し、non-narrativeは分類を確認する。全ページ承認までcanonical本文・FTSへ公開しない。
4. 修正後本文は運用品質として採用できるが、修正後CERをモデル単独性能として報告しない。
   未修正予測とverified ground truthによる機械gateは、自動公開またはレビュー縮小の条件として残す。
5. 公式固定prompt、greedy生成、元画像RGBを既定とする。画像の一律拡大、自由prompt、
   誤字辞書による無条件置換、候補間の推測合議は採用しない。
6. Apple Silicon 64GBでは両modelを同時常駐させず、Qwen全ページ、process終了、dots全ページ、
   process終了、selectorの順に実行する。各段階はscope固定checkpointから再開できるが、両候補の
   完全集合検査が終わるまではDBへpage結果を保存しない。timeout・子process失敗・選択本文の反復は
   run全体をfail closedにする。
7. modelが非空のraw応答を返して候補形式だけを解析できない場合は、rawと解析理由を候補checkpointへ
   隔離する。もう一方の候補が非空かつ反復なしの場合だけ全ページQAへ進め、両候補を安全に採用できない
   ページが1枚でもあればrun全体を失敗にする。

## 根拠

固定79枚ではQwen 72枚、dots 7枚を初期候補に選び、総編集距離223/54,504文字となった。dots単体の
距離490、Qwenの反復4枚を除く距離662より少なく、調査済み候補の中で最も少ない平均修正量を期待できる。
重大な生成反復は既存guardでdotsへ隔離できる。ページ最大gate超過の誤りは実在するため自動公開には不十分だが、原画像との
全件照合を公開条件にすれば、モデルの残存誤りを人手修正で閉じられる。個人利用ではこの確認費用を
受容でき、旧公開本文の保持とtransactional rollbackにより導入失敗も回復できる。

## 結果（Consequences）

### ポジティブ

- 無期限の候補探索を止め、再現可能なモデル版とレビュー手順を本番導入へ進められる。
- 誤認ページを修正した高品質本文を、原画像と監査証跡付きで公開できる。
- 将来機械gateへ合格した場合も、同じstaging・publication経路のままレビュー範囲を縮小できる。

### ネガティブ・受容したコスト

- 全ページのQAとnarrative全ページの画像照合が必要で、大量冊数の初回導入には時間がかかる。
- Qwenとdotsが同じ文字を誤る場合や、自然だが誤った文字列は自動検知できない。
- 二つのモデルを全ページで実行するため、推論時間と保存量が増える。
- 固定79枚のモデル生成時間はQwen 3,179.58秒、dots 1,016.64秒、合計4,196.22秒（約53.1秒/ページ）で、
  実書籍では画像条件と反復率により増減する。

### 影響範囲

- OCR workerへ複合engineを追加し、全ページを`required`にする版識別子を保存する。
- QA画面では原画像、Qwen候補、dots候補、補正文、候補切替理由を確認可能にする。
- 1冊pilotを全ページ修正・公開・rollbackまで実施してから複数冊へ拡大する。

## 将来の再評価条件

- 新版が未調整holdoutの全機械gateへ合格し、100画面の出力契約試験も通過した。
- 1冊pilotで列欠落・意味変更の見落とし、修正不能な読順崩壊、過大な確認時間が発生した。
- Qwenまたはdotsの重み、prompt、processor、runtimeを変更する。
- 独立候補が同じ固定79枚で修正量・異常率・処理時間を明確に改善する。
