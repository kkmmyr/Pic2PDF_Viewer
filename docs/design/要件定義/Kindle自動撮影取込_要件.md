# Kindle 自動撮影取込 要件

> status: living | last-verified: 2026-07-25

要件状態: **要件確定・未実装（2026-07-25）**

実装計画: [Kindle 自動撮影取込 実装計画](../../log/計画/Kindle自動撮影取込_実装計画.md)

## 1. 目的

Kindle 購入カタログで購入書籍を 1 冊選択した後、Windows 上の起動済み Kindle アプリで対象書籍を自動的に特定し、表紙または先頭から最終ページまで撮影して、Pic2PDFViewer の `comic` または `novel` へ登録する。

誤った書籍や巻を撮影すること、途中成果物を正式画像として公開することを、操作回数の少なさより優先して防止する。

## 2. 前提

- 個人 LAN 内の単一利用者による運用を対象とする。
- 初期版は 1 ジョブにつき 1 冊を処理する。
- Kindle アプリは起動済み、Amazon アカウントへログイン済みとする。
- Windows は画面ロックされていないことを前提とする。
- 撮影中は対象 Windows 端末のマウスとキーボードを操作しない。
- Kindle アプリが終了している場合、エージェントは自動起動せずジョブを失敗させる。
- 未ダウンロード書籍は、ダウンロード完了を待ってから撮影する。
- 読書途中の書籍も、撮影前に表紙または先頭位置へ戻す。
- 撮影後の Kindle 読書位置は最終ページになってよい。

## 3. 対象フロー

1. 購入書籍の詳細で、タイトル、ASIN、著者、シリーズ・巻、出力先種別、ページ送り方向を確認する。出力先種別はカタログ分類を初期値にするが、`comic` / `novel` を利用者が変更できる。
2. 確認後、1 冊分の capture job を作成する。
3. Windows エージェントがジョブを claim する。
4. エージェントが起動済み Kindle アプリへ接続する。
5. Kindle ライブラリで対象書籍を検索し、候補の本人性を照合する。
6. 未ダウンロードの場合はダウンロードを開始し、完了まで待機する。
7. 対象書籍を開き、表紙または先頭位置へ移動する。
8. 既存 capturer で最終ページまで撮影する。
9. 画像と manifest を Samba inbox へ `.partial` 名で転送し、完了後に `.ready` へ rename する。
10. Linux バックエンドが内容を検証し、正式画像領域へ原子的に配置する。
11. `meta2.db.books_meta` へ ASIN を設定し、ジョブを完了する。

## 4. 対象書籍の検索と照合

### 4.1 照合原則

- Kindle の購入済みライブラリから検索する。
- Kindle 側で ASIN を取得できる場合は、カタログの ASIN との完全一致を最優先とする。
- ASIN を取得できない場合は、正規化した完全タイトルに加え、著者またはシリーズ・巻の一致を必要とする。
- タイトルの部分一致だけでは撮影を開始しない。
- 候補が複数ある場合、必要な照合情報を取得できない場合、または巻違いを否定できない場合はエラー終了する。
- 照合失敗時は撮影、転送、正式配置、ASIN 更新を一切行わない。

### 4.2 実機成立性ゲート

本実装前に、対象 Kindle アプリの実機で次を確認する。

- Windows UI Automation などから検索欄、検索結果、ダウンロード状態、読書画面を識別できること
- ASIN、タイトル、著者、シリーズ・巻のうち、本人照合に必要な情報を取得できること
- 未ダウンロードから読書画面表示までの完了条件を判定できること
- 表紙または先頭位置への移動を再現できること

画面上の絶対座標だけで検索候補を選択する方式は、本人照合の正本にしない。十分な照合方法が成立しない場合は、自動撮影へ進まず計画を見直す。

## 5. Kindle アプリ操作

- エージェントは起動済み Kindle アプリへ接続し、別プロセスとして起動しない。
- 検索文字列の入力、検索結果の取得、対象候補の選択は Kindle 操作コントローラーへ集約する。
- ダウンロード中は進行中状態をジョブへ反映する。
- ダウンロード待機時間はエージェント設定で変更可能にし、期限超過時は失敗させる。
- アプリ更新、ログイン要求、確認ダイアログなどで予定した画面へ到達できない場合は失敗させる。
- 読書画面の `ReadingArea` が安定し、先頭位置へ移動できたことを確認してから
  capturer を起動する。漫画ではフッター文字列がUI Automationへ公開されない
  場合があるため、ページ移動と先頭境界は読書領域の画像差分を正本として判定する。

## 6. 撮影と登録

- `comic` は既存 `AutoKindleCapturer`、`novel` は既存 `NovelKindleCapturer` を利用する。
- カタログの `book_type` は出力先種別の初期値にとどめ、撮影方法と登録先を決める正本にはしない。開始確認で利用者が確定した `source` を capture job に保存する。
- 「全ページ」は、Kindle 上の表紙または先頭位置から、既存のページ変化判定が最終ページを検出するまでとする。
- `expected_screens` は任意の補助条件であり、Kindle の紙面ページ数とは同一視しない。
- 撮影結果が 0 枚の場合は失敗とする。
- Linux 側の manifest、ハッシュ、パス、件数、容量検証を維持する。
- 正式画像配置と `meta2.db` 更新は、全検証成功後だけ行う。
- 失敗時は正式画像領域と `meta2.db` に途中状態を残さない。

重複ページ、白紙、欠落を画像解析で検出する追加品質ゲートは、既存バックログ B-32 の範囲とし、本機能の初期版には含めない。

## 7. ジョブ状態と復旧

利用者に表示する処理工程は次のとおりとする。

| 状態 | 意味 |
|---|---|
| `queued` | Windows エージェントの取得待ち |
| `claimed` | エージェントがジョブを取得済み |
| `locating_book` | Kindle 内で書籍を検索・照合中 |
| `downloading` | 未ダウンロード書籍の取得待ち |
| `positioning` | 読書画面を表紙・先頭位置へ移動中 |
| `capturing` | ページ撮影中 |
| `awaiting_files` | 転送済み成果物の検証・登録待ち |
| `succeeded` | 正式配置と ASIN 設定が完了 |
| `failed` | 安全に処理を中止 |

- 同一 ASIN の未完了ジョブを重複作成しない。
- エージェントは処理中に heartbeat を更新する。
- heartbeat が規定時間更新されないジョブは、無期限に実行中表示へ残さず失敗として回収できること。
- 失敗ジョブは履歴として保持し、原因解消後は新しいジョブとして再実行する。
- 初期版では複数ジョブの並列実行を行わない。

## 8. エラー分類

少なくとも次の失敗理由を、内部コードと利用者向け日本語説明へ分離する。

- Kindle アプリ未起動
- Kindle ウィンドウまたは必要な UI 要素を検出できない
- 対象書籍が見つからない
- 候補が複数あり一意に決められない
- ASIN・タイトル・著者・巻情報による本人照合が不足
- ダウンロード失敗またはタイムアウト
- 表紙・先頭位置への移動失敗
- 撮影失敗
- 転送失敗
- Linux 側の検証または正式登録失敗
- heartbeat 期限切れ

エラー表示には、どの工程で停止したかと再実行前に確認すべき内容を含める。

## 9. UI

### 9.1 購入書籍

- 書籍詳細から「撮影して取り込む」を開始する。
- 開始前にタイトル、ASIN、著者、シリーズ・巻、`comic` / `novel`、ページ送り方向を表示し、`comic` / `novel` とページ送り方向を変更できる。
- Kindle アプリ起動済み、ログイン済み、画面ロックなし、処理中の端末操作禁止を確認事項として表示する。
- 確定操作は確認ダイアログを経由し、送信中は二重実行できない。

### 9.2 キャプチャ

- 現在工程、対象書籍、開始日時、経過時間、撮影済み画面数、失敗理由を表示する。
- 内部状態値をそのまま主表示せず、日本語ラベルと説明を表示する。
- 5 秒間隔の capture job ポーリングを維持する。
- 失敗後は原因を確認し、新しいジョブとして再実行できる。
- iPad は状態閲覧を主要用途とするが、端末種別による機能無効化は行わない。

## 10. スコープ外

- 初期版での複数書籍選択と連続処理
- 複数 Windows エージェントによる並列撮影
- Kindle アプリの自動起動
- Amazon アカウントへのログイン自動化
- Windows のロック解除
- 撮影中の同一端末の併用
- 既存画像の自動 ASIN 確定
- Amazon データ、Kindle Info、旧 DB の取込ロジック変更
- 旧アプリの画像、表紙、レビュー、感想の取り込み
- 追加の重複・白紙・欠落画像検出

## 11. 受入条件

### 11.1 正常系

- [ ] 購入書籍から 1 冊分のジョブを作成できる。
- [ ] 起動済み Kindle アプリの購入済みライブラリから対象書籍を一意に照合できる。
- [ ] 未ダウンロード書籍はダウンロード完了後に撮影を開始する。
- [ ] 読書途中の書籍を表紙または先頭位置へ戻せる。
- [ ] 表紙または先頭から最終ページまで撮影できる。
- [ ] 転送・検証成功後だけ正式画像領域と `meta2.db` が更新される。
- [ ] 登録完了後、購入書籍の画像状態が取込済みに変わる。

### 11.2 安全性

- [ ] Kindle 未起動時にアプリを起動せず、理由付きで失敗する。
- [ ] 候補なし、候補複数、本人照合不足のいずれでも撮影を開始しない。
- [ ] ダウンロード、先頭移動、撮影、転送、登録の各失敗で途中成果物を正式公開しない。
- [ ] 同一 ASIN の未完了ジョブを重複作成できない。
- [ ] エージェント異常終了後にジョブが無期限に実行中として残らない。

### 11.3 表示と運用

- [ ] 購入書籍詳細で開始前の対象と運用前提を確認でき、カタログ分類と実書籍が異なる場合に `comic` / `novel` を変更できる。
- [ ] キャプチャページで現在工程、経過、結果、失敗理由を確認できる。
- [ ] デスクトップで開始と監視、iPad 相当幅で状態閲覧ができる。
- [ ] ライト・ダークテーマ、loading、empty、error、disabled、success を確認できる。
- [ ] キーボード操作、フォーカス表示、accessible name を確認できる。
