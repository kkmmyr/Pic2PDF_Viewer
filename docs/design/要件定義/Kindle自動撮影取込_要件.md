# Kindle 自動撮影取込 要件

> status: living | last-verified: 2026-09-05

Windows上のKindleで購入済み書籍を撮影し、確認済みの画像だけをPic2PDFViewerへ取り込む。
ジョブ状態、manifest、品質検査、シリーズ実行の契約は
[Kindle自動撮影ジョブ契約](../詳細設計/機能別/Kindle自動撮影ジョブ契約.md)を正本とする。
画面操作、撮影矩形、ページ送りは[kindle-pdf詳細設計](../../../kindle-pdf/docs/detailed_design.md)を参照する。
登録前検証とmanifestの合否条件は自動撮影ジョブ契約が所有する。
整理前の要件と受入済み履歴は[再編前記録（凍結）](../../archive/要件/Kindle自動撮影取込_再編前_2026-09-05.md)を参照する。

## 1. 目的

利用者が購入カタログで確認した1冊を、Windows上で起動・ログイン済みのKindleから撮影し、
comic または novel の正式画像として登録する。誤った書籍・巻の撮影、途中成果物の公開、
既存の正式画像の破壊を、操作回数の少なさより優先して防止する。

## 2. 前提

- 個人LAN内の単一利用者が、Kindleを起動・ログイン済みかつ画面ロック解除済みのWindows端末で実行する。
- 撮影中は対象端末のマウスとキーボードを利用者が操作しない。
- 対象Kindleを前面化できない場合は停止し、他アプリへページ送りキーを送らない。
- 撮影後のKindle読書位置は最終ページになってよい。
- 通常の単冊撮影ではKindleの起動・ログイン・画面ロック解除を自動化しない。
- activeなcapture jobはsource・ASINにかかわらずシステム全体で最大1件とする。
- シリーズの限定復旧は、利用者が明示的に有効化し、撮影開始前のプロセス消失など契約上の全条件を満たす場合だけ許可する。

## 3. 利用フロー

1. 購入カタログでタイトル、ASIN、著者、シリーズ・巻、出力先種別、ページ送り方向を確認し、必要ならcomic / novelを明示選択する。
2. 確認操作で1冊のcapture jobを作成し、他のactive jobがあれば開始しない。
3. Windows agentが対象を照合し、必要時だけダウンロード、先頭位置への移動、撮影、転送を順に実行する。
4. Linuxが成果物とmanifestを検証し、成功時だけ正式画像とASIN紐付けを確定する。
5. 利用者は処理工程、結果、失敗理由、登録後の要確認候補を確認し、失敗時は原因を解消して新しいjobとして再実行する。

## 4. 誤登録を防ぐ条件

- ASINの完全一致を最優先にし、ASINが取得できない場合は正規化した完全タイトルと著者またはシリーズ・巻の一致を必要とする。
- 候補なし、候補複数、本人照合不足、ダウンロード・先頭移動・撮影・転送・検証の失敗時は、撮影開始または正式登録を行わない。
- source・ASINを問わずactive jobがある間は、同一書籍にも別書籍にも新しいjobを作成しない。
- 登録に成功したwarningは失敗と区別して表示し、候補ページをreaderで開く操作は既読更新を行わない。既読・未確認の変更は明示操作だけで行う。
- 失敗時は既存の正式画像、ASIN紐付け、DBの公開状態を維持する。

## 5. 受入条件

以下は現在の受入基準であり、個別の実機確認結果は再編前記録と技術知見に保存する。


### 5.1 正常系

- 購入書籍から 1 冊分のジョブを作成できる。
- 起動済み Kindle アプリの購入済みライブラリから対象書籍を一意に照合できる。
- 検索欄に全角入力や以前の検索語が残っていても、半角ASINへ全置換してから照合できる。
- 未ダウンロード書籍はダウンロード完了後に撮影を開始する。
- 読書途中の書籍を表紙または先頭位置へ戻せる。
- 表紙または先頭から最終ページまで撮影できる。
- 不自然に短い撮影結果を正式登録せず、既存の正式データを置換しない。
- `comic` は 2 ページ表示で外側余白を抑え、左右ページを欠落なく撮影できる。
- `novel` は 1 ページ表示で本文最下部を切らずに撮影できる。
- `novel` の保存画像に Kindle の上部書名と下部ページ・進捗表示が含まれない。
- 同名書籍を再撮影して置換した後、ブラウザーキャッシュ中の旧ページと新ページが混在せず、再読込だけで新しい画像列を表示できる。
- 転送・検証成功後だけ正式画像領域と `meta2.db` が更新される。
- 登録完了後、購入書籍の画像状態が取込済みに変わる。
- 連続3画面だけに現れる右下通知を登録拒否せず要確認warningへ残し、正常画面では発火しない。

### 5.2 安全性

- Kindle 未起動時にアプリを起動せず、理由付きで失敗する。
- 候補なし、候補複数、本人照合不足のいずれでも撮影を開始しない。
- ダウンロード、先頭移動、撮影、転送、登録の各失敗で途中成果物を正式公開しない。
- 全source・全ASINを通じて、未完了ジョブを同時に複数作成できない。
- エージェント異常終了後にジョブが無期限に実行中として残らない。

### 5.3 表示と運用

- 購入書籍詳細で開始前の対象と運用前提を確認でき、カタログ分類と実書籍が異なる場合に `comic` / `novel` を変更できる。
- キャプチャページで現在工程、経過、結果、失敗理由を確認できる。
- 内部error codeと日本語の案内を分け、停止した工程と再実行前に確認する内容を示す。
- 未完了jobがある場合は開始を無効化し、処理中jobへの導線を示す。確認ダイアログを開いた後に
  未完了jobを検出した場合も新規送信しない。詳細な表示分岐は[購入カタログ設計](../詳細設計/機能別/Kindle購入カタログ設計.md)を参照する。
- 登録成功後の品質warningを要確認候補として確認済み管理でき、対象ページを直接開ける。
- デスクトップで開始と監視、iPad 相当幅で状態閲覧ができる。
- ライト・ダークテーマ、loading、empty、error、disabled、success を確認できる。
- キーボード操作、フォーカス表示、accessible name を確認できる。

## 6. 対象外

ログイン・Windowsロック解除の自動化、撮影中の端末併用、既存画像のASIN自動確定は行わない。
旧アプリの画像・表紙・レビュー・感想の取り込みは含めない。
未校正warningを自動削除や登録拒否へ昇格しない。単一・2画面、右下以外の非反復通知や欠落ページの
自動検出は保証しない。検査範囲と判定条件は自動撮影ジョブ契約を参照する。
