# Kindle 自動撮影取込 要件

> status: living | last-verified: 2026-08-22

要件状態: **実装・Phase 5 実機受入完了（2026-07-26）**

完了記録: [Kindle 自動撮影取込 実装計画](../../archive/Kindle自動撮影取込_実装計画.md)

実機知見: [Kindle 自動撮影 実機知見](../../log/技術知見/Kindle自動撮影_実機知見.md)

## 1. 目的

Kindle 購入カタログで購入書籍を 1 冊選択した後、Windows 上の起動済み Kindle アプリで対象書籍を自動的に特定し、表紙または先頭から最終ページまで撮影して、Pic2PDFViewer の `comic` または `novel` へ登録する。

誤った書籍や巻を撮影すること、途中成果物を正式画像として公開することを、操作回数の少なさより優先して防止する。

## 2. 前提

- 個人 LAN 内の単一利用者による運用を対象とする。
- 初期版は 1 ジョブにつき 1 冊を処理する。
- 通常の撮影開始時は Kindle アプリが起動済みで、Amazon アカウントへログイン済みとする。
- Windows は画面ロックされていないことを前提とする。
- 撮影中は対象 Windows 端末のマウスとキーボードを操作しない。
- 各ページ送り直前にKindleウィンドウを前面化し、前面ウィンドウハンドルの一致を
  確認してからキーを送る。一致しない場合はキーを他アプリへ送らず失敗させる。
- 通常の単冊撮影開始時に Kindle アプリが終了している場合、エージェントは自動起動せずジョブを失敗させる。
- シリーズ直列実行中に撮影開始前の Kindle プロセス消失を確認した場合だけ、利用者が明示的に有効化した
  復旧モードは Kindle を再起動できる。失敗 job が撮影未開始、対象 ASIN が同一、別の未完了 job がない、
  再起動後のライブラリで ASIN を一意に再照合できた、という全条件を満たしてから同じ 1 冊の新規 job を
  最大 1 回だけ作る。条件を確認できない場合は後続巻を開始せず fail closed とする。
- 未ダウンロード書籍は、ダウンロード完了を待ってから撮影する。
- 読書途中の書籍も、撮影前に表紙または先頭位置へ戻す。
- 撮影後の Kindle 読書位置は最終ページになってよい。

## 3. 対象フロー

1. 購入書籍の詳細で、タイトル、ASIN、著者、シリーズ・巻、出力先種別、ページ送り方向を確認する。出力先種別はカタログ分類を初期値にするが、`comic` / `novel` を利用者が変更できる。
2. 確認後、1 冊分の capture job を作成する。
3. Windows エージェントがジョブを claim する。
4. エージェントが起動済み Kindle アプリへ接続する。
5. Kindle ライブラリで対象書籍を検索し、候補の本人性を照合する。
6. 未ダウンロードの場合はダウンロードを開始し、完了まで待機する。
7. 対象書籍を開き、`comic` は 2 ページへ切り替え、`novel` は 1 ページまたはリフロー型設定を確認したうえで、表紙または先頭位置へ移動する。
8. Kindle の読書領域を基準に上下 UI と漫画の外側余白を除外し、既存 capturer で最終ページまで撮影する。
9. 画像と manifest を Samba inbox へ `.partial` 名で転送し、完了後に `.ready` へ rename する。
10. Linux バックエンドが内容を検証し、正式画像領域へ原子的に配置する。
11. `meta2.db.books_meta` へ ASIN を設定し、ジョブを完了する。

## 4. 対象書籍の検索と照合

### 4.1 照合原則

- Kindle の購入済みライブラリから検索する。
- Kindle 側で ASIN を取得できる場合は、カタログの ASIN との完全一致を最優先とする。
- ASIN を取得できない場合は、正規化した完全タイトルに加え、著者またはシリーズ・巻の一致を必要とする。
- タイトルの部分一致だけでは撮影を開始しない。
- 候補が複数ある場合、必要な照合情報を取得できない場合、または巻違いを否定できない場合はエラー終了する。
- 照合失敗時は撮影、転送、正式配置、ASIN 更新を一切行わない。

### 4.2 実機成立性ゲート

本実装前に、対象 Kindle アプリの実機で次を確認する。

- Windows UI Automation などから検索欄、検索結果、ダウンロード状態、読書画面を識別できること
- ASIN、タイトル、著者、シリーズ・巻のうち、本人照合に必要な情報を取得できること
- 未ダウンロードから読書画面表示までの完了条件を判定できること
- 表紙または先頭位置への移動を再現できること

画面上の絶対座標だけで検索候補を選択する方式は、本人照合の正本にしない。十分な照合方法が成立しない場合は、自動撮影へ進まず計画を見直す。

## 5. Kindle アプリ操作

- エージェントは起動済み Kindle アプリへ接続し、別プロセスとして起動しない。プロセス起動は
  オプトインのシリーズ直列復旧経路だけが担当し、capture agent 自身の責務にはしない。
- 検索文字列の入力、検索結果の取得、対象候補の選択は Kindle 操作コントローラーへ集約する。
- 検索値の半角ASIN完全一致後、ASIN付き候補カードが遅れて描画される場合は
  reader timeout内で有界に再取得し、単発の0件だけで`book_not_found`にしない。
- UI Automation は検索欄・ASIN付き書籍カード・ダウンロード状態等の識別と矩形取得に
  使う。検索欄とページ番号入力欄はIMEや残存入力の影響を避けるため、
  `ValuePattern.SetValue`で半角値全体を置換し、同じ`ValuePattern`から完全一致を
  読み戻せた場合だけ続行する。クリックは取得したcontrolへの通常のマウス操作を
  維持する。
  ウィンドウの前面化は取得したネイティブウィンドウハンドルを使う。
  前面ウィンドウのハンドルがKindleと一致することを確認してからクリックし、
  Windowsの前面化制限等で一致しない場合は操作を行わず失敗させる。
  画面全体の固定絶対座標は本人照合や操作先決定に使わない。
- ダウンロード中は進行中状態をジョブへ反映する。
- ダウンロード待機時間はエージェント設定で変更可能にし、期限超過時は失敗させる。
- アプリ更新、ログイン要求、確認ダイアログなどで予定した画面へ到達できない場合は失敗させる。
- 読書画面の `ReadingArea` が安定し、「位置に移動」による直接遷移と
  source 別のフッター表示で先頭位置を確認してから capturer を起動する。
- 対象を開いた時点でフッターが表紙を示す場合は、同じ1ページへの直接遷移を
  Kindleが無効入力として拒否するため、直接遷移を省略する。小説の`ページ1/N・0%`
  であれば、利用者が確定した次ページ方向と逆へ1回だけ進めて表紙を確認する。
- 「位置に移動」は本人照合済みの右上メニューボタンを通常クリックして開く。
  Microsoft Store版ではポップアップが別のUI Automation rootへ公開され、項目controlを
  安定取得できないため、メニューボタン矩形に対する相対位置で先頭項目をクリックする。
  ただしクリック後に型付き`EditControl`のAutomationIdが`go-to-page-input`であることを
  確認できなければ直ちに停止し、別項目を操作した状態では処理を継続しない。
- 移動の確定は型付き`ButtonControl`のAutomationIdが`modal-confirm`であることを確認して
  control中心を通常クリックし、ページ番号入力
  ダイアログが閉じ、入力controlが消失したことを有界に待機する。入力エラー表示でも
  画面画像は変化するため、画像差分だけでは終了とみなさない。control消失を
  確認できない場合はフッターが先頭を示していても撮影を開始しない。
- 小説で直接遷移後が `ページ1/N・0%` の場合は表紙の次の画面であるため、
  利用者が確定した次ページ方向と逆の矢印キーを1回だけ送り、
  `Location 1・0%` を確認する。
- 小説の固定画像を含む先頭領域では、ロケーション `1` を指定しても
  Kindle が表紙を `Location 2〜4・0%` と表示する書籍がある。
  入力値 `1` を読み戻せた直接遷移に限り、`Location 1〜4・0%` を
  先頭近傍として許可する。`Location 5` 以降または進捗 `1%` 以上は許可しない。
- 直接遷移または結果確認に失敗した場合は撮影を開始しない。数十画面以上を
  逆方向へ送る処理や、画像差分による連続先頭探索は行わない。
  `left` の書籍は右キー、`right` の書籍は左キーで先頭境界まで戻る。
- 撮影前のページ設定は `source` を正本とし、`comic` は `aaOption-Split`
  （2 ページ）を選択する。`novel` は `aaOption-Single` が提供される書籍では
  選択し、リフロー型小説のようにページ数レイアウトが提供されない書籍では
  `フォント-item` の存在を確認して1ページ表示として扱う。
  ページ数 option を選択した場合は UI Automation の ToggleState が On であることを
  確認し、確認できない場合は撮影を開始しない。前のジョブのレイアウト設定を
  暗黙に引き継がない。
- 撮影中のページ送りは選択した矢印キーを使う。Microsoft Store版では前面ウィンドウが
  Kindleでも20画面前後でWebView側のキーボードフォーカスを失う実機例があるため、
  各キー送信前に取得済み`ReadingArea`の中心を通常クリックしてフォーカスを戻す。
  キー送信後もページが変化しない場合の有界再試行では、取得済み`ReadingArea`に
  相対する「次のページ」側の矢印領域を1回だけクリックする。固定絶対座標には依存せず、
  キーと相対クリックの両方で変化しない場合だけ終端または未完了と判定する。

## 6. 撮影と登録

- `comic` は既存 `AutoKindleCapturer`、`novel` は既存 `NovelKindleCapturer` を利用する。
- カタログの `book_type` は出力先種別の初期値にとどめ、撮影方法と登録先を決める正本にはしない。開始確認で利用者が確定した `source` を capture job に保存する。
- Microsoft Store 版では固定の上下除外幅を使わず、最大化後の UI Automation
  実矩形をウィンドウ相対座標へ変換して上下境界とする。`comic` は `ReadingArea`
  全体、`novel` は `TopChrome.bottom` から `Footer.top` までを保存し、本文を
  切らずに上部の書名と下部の現在ページ・進捗表示を除外する。
- `comic` の左右境界は黒帯の有無だけで決めず、先頭ページの非白色領域から
  1 ページ幅を推定し、2 ページ分の幅を読書領域中央へ確保する。先頭の表紙だけが
  単ページ表示でも、後続の見開きが切れない安全幅を使用する。
- 「全ページ」は、Kindle 上の表紙または先頭位置から、既存のページ変化判定が最終ページを検出するまでとする。
- ページ変化判定は全画面の平均差分だけに依存しない。白地に小さなタイトル、著作権表記、
  章扉など疎な文字同士の遷移を検出するため、一定輝度以上変化した画素の比率も併用する。
  微小な1画素ノイズは同一画面として許容する。
- `expected_screens` は任意の補助条件であり、Kindle の紙面ページ数とは同一視しない。
- `expected_screens`指定時はその件数、未指定時は小説50画面・漫画10画面を
  共有前の最低件数とする。未満は`capture_incomplete`として失敗させる。
- 正式撮影前に同じsource・方向・撮影矩形で先頭2画面の短時間カナリアを実行する。
  2画面が復号可能、同一寸法、視覚的に異なることを確認し、先頭へ再移動して
  開始位置を再検証できた場合だけ`capturing`へ進む。失敗時は正式画像を作らない。
- Linux 側の manifest、ハッシュ、パス、件数、容量検証を維持する。
- capture agent は version 2 manifest に、撮影画面数、撮影矩形、終了理由、
  無変化確認回数、最終画像参照を含む撮影完了証跡を記録する。
- version 2 manifestにはカナリアのpolicy version、合否、2画像のSHA-256・寸法・
  差分指標も含め、Linux側で形式、2つのSHA-256が異なること、正の差分指標、
  正式撮影の矩形・寸法との一致を検証する。カナリア画像自体はpackageへ含めないため、
  Linux側でSHA-256と差分指標を再計算する契約ではない。
- 正常な終了理由は、規定回数のページ送り後も画面が変化しない
  `visual_no_change_after_retries`、または期待画面数到達後に追加のページ送りで
  無変化を確認した `expected_screen_count_confirmed` に限定する。期待画面数へ
  到達しただけでは全ページ撮影済みとみなさない。
- Linux 側は agent の合否だけを信用せず、連番、画像復号、寸法一貫性、SHA-256、
  manifest件数を実ファイルから再計算し、撮影矩形と終了証跡はschema・件数・最終画像・
  規定確認回数の内部整合を検証する。不一致時は登録しない。終端観測フレームはpackageへ
  含めないため、最終ページ到達と無変化回数をLinux側で再観測する契約ではない。
- 完全重複、低容量、白紙・疎な画面は Phase 1 では警告候補として記録する。
  章扉、挿絵、奥付などの正当な画面を誤削除しないため、自動削除や登録拒否には
  使用せず、既存画像で閾値を校正してから段階的に厳格ゲートへ昇格する。
- 撮影領域の外周に、内容の異なる複数ページをまたいで同じ位置・同じ画素形状の
  構造化領域が反復する場合は、Windows 通知等の画面オーバーレイ候補として検査する。
  反復率と隣接タイル数が高信頼条件を満たす場合は `capture_incomplete` として登録前に拒否し、
  中信頼候補は `repeated_screen_overlay_candidate` warning として manifest へ残す。
  完全重複ページだけで構成された反復、無地の余白、単一ページだけの意匠では拒否しない。
- 等間隔標本では見逃す短時間通知については、全ページを3画面のrolling windowで調べる。
  内容の異なる連続3画面すべてで、右下隅の隣接2タイルが構造を保ったまま近似一致する場合だけ
  `transient_bottom_right_overlay_candidate` warningとして残す。登録、OCR、後続撮影は止めない。
  単一画面、2画面だけ、右下以外、無地または低エッジ領域はこの検出の対象外とする。
- 正式画像配置と `meta2.db` 更新は、全検証成功後だけ行う。
- 失敗時は正式画像領域と `meta2.db` に途中状態を残さない。

近似重複、端切れ、Kindle UI 混入、シリーズ内の画面数外れ値を検出する追加品質ゲートは、既存バックログ B-32 で段階導入する。シリーズ内画面数は、同じsourceの正常終了実績が3冊以上ある場合に、新しい撮影数が中央値の0.5倍未満または2倍超なら候補とし、登録や後続jobは止めずwarning証跡をsession stateへ保存する。画面オーバーレイの高信頼検出は実機汚染画像と正常な再撮影画像で校正済みのため blocking とする。連続3画面の右下通知は実陽性2種と正常727画面で校正済みだが、通知位置と継続時間を限定したwarningから開始し、それ以外のUI混入を検出済みとは扱わない。

## 7. ジョブ状態と復旧

利用者に表示する処理工程は次のとおりとする。

| 状態 | 意味 |
|---|---|
| `queued` | Windows エージェントの取得待ち |
| `claimed` | エージェントがジョブを取得済み |
| `locating_book` | Kindle 内で書籍を検索・照合中 |
| `downloading` | 未ダウンロード書籍の取得待ち |
| `positioning` | 読書画面を表紙・先頭位置へ移動中 |
| `capturing` | ページ撮影中 |
| `awaiting_files` | 転送済み成果物の検証・登録待ち |
| `succeeded` | 正式配置と ASIN 設定が完了 |
| `failed` | 安全に処理を中止 |

- source・ASINにかかわらず、未完了ジョブはシステム全体で最大1件とする。
  作成時の存在確認とINSERTは同一の即時transactionで行い、UI・複数runner間の
  競合でも複数のqueued jobを作成しない。
- エージェントは処理中に heartbeat を更新する。
- heartbeat が規定時間更新されないジョブは、無期限に実行中表示へ残さず失敗として回収できること。
- 失敗ジョブは履歴として保持し、原因解消後は新しいジョブとして再実行する。
- 初期版では複数ジョブの並列実行を行わない。
- シリーズ一括運用はエージェントの処理単位を変えず、1 冊の `succeeded` と正式登録を
  確認してから次の 1 冊を作成する直列オーケストレーターで支援する。
- 直列オーケストレーターは既定で dry-run とする。`--apply` による実行時は
  `--expected-total` を必須とし、対象冊数の一致、未完了ジョブがないことを
  満たした場合だけ最初のジョブを作成する。dry-run は期待冊数を省略して
  候補一覧を調査できるが、冊数未確認のまま実行へ移行できない。
- 各冊の失敗、監視タイムアウト、正式登録未確認、別の未完了ジョブ検出のいずれかで
  次冊の作成を停止する。全対象を先にキューへ投入しない。
- オプトインの Kindle 復旧は `kindle_not_running` / `kindle_app_exited` /
  `kindle_ui_unavailable` のうち、`started_at` がなく撮影枚数 0、かつ Kindle プロセスが実際に
  消失している失敗だけを対象とする。`download_failed`、書籍照合、位置決め、撮影、転送、登録の
  失敗は対象にしない。プロセスが残っている UI 不調を自動終了させない。
- 復旧後は同じ ASIN をライブラリ検索して一意に再照合し、別の未完了 job がないことを再確認する。
  自動復旧回数を使い切った場合、または再照合に失敗した場合は後続巻を作らず停止する。
- シリーズ直列実行はセッション全体でKindle復旧回数と連続`download_failed`を記録する。
  Kindle復旧は全冊を通じて1回までとする。現行runnerはエラー種別を問わず最初のfailed jobで
  停止し、後続jobを作成しない。連続`download_failed`の上限3冊はセッション状態に保持する
  安全上限だが、2冊目までを自動継続する制御は未実装である。一度停止したセッションは
  自動解除しない。
- 実行セッション状態はatomic置換JSONへ永続化し、対象manifestのdigestが一致する
  `running`状態だけを利用者の明示指定で再開できる。破損、digest不一致、trip済み、
  完了済みstateはfail closedで拒否する。

## 8. エラー分類

少なくとも次の失敗理由を、内部コードと利用者向け日本語説明へ分離する。

- Kindle アプリ未起動
- Kindle ウィンドウまたは必要な UI 要素を検出できない
- 対象書籍が見つからない
- 候補が複数あり一意に決められない
- ASIN・タイトル・著者・巻情報による本人照合が不足
- ダウンロード失敗またはタイムアウト
- ページレイアウトの選択または選択状態確認の失敗
- 表紙・先頭位置への移動失敗
- 撮影失敗
- 転送失敗
- Linux 側の検証または正式登録失敗
- heartbeat 期限切れ

エラー表示には、どの工程で停止したかと再実行前に確認すべき内容を含める。

## 9. UI

### 9.1 購入書籍

- 書籍詳細から「撮影して取り込む」を開始する。
- 開始前にタイトル、ASIN、著者、シリーズ・巻、`comic` / `novel`、ページ送り方向を表示し、`comic` / `novel` とページ送り方向を変更できる。
- Kindle アプリ起動済み、ログイン済み、画面ロックなし、処理中の端末操作禁止を確認事項として表示する。
- 確定操作は確認ダイアログを経由し、送信中は二重実行できない。
- source・ASINにかかわらずactive jobが1件でもある場合は開始操作を無効化し、同一ASINと
  他ASINで説明を分けて処理中jobへの導線を表示する。確認ダイアログ表示後にactive jobを
  検出した場合も、確定操作を無効化する。backendの同一transaction制約は最終防衛線として維持する。

### 9.2 キャプチャ

- 現在工程、対象書籍、開始日時、経過時間、撮影済み画面数、失敗理由を表示する。
- 内部状態値をそのまま主表示せず、日本語ラベルと説明を表示する。
- 5 秒間隔の capture job ポーリングを維持する。
- 失敗後は原因を確認し、新しいジョブとして再実行できる。
- 登録に成功したmanifestのwarningは失敗と分離した「要確認候補」として永続化し、
  書籍・warning code単位の件数と対象ページを表示する。章扉、表紙、挿絵、奥付等の
  正常画面を含み得ることを明示し、登録成功、OCR開始、画像削除を変更しない。
- 要確認候補は未確認を既定表示とし、明示操作で確認済み／未確認を切り替えられる。
  候補ページはcomic / novelそれぞれの既存リーダーで直接開ける。
- iPad は状態閲覧を主要用途とするが、端末種別による機能無効化は行わない。

## 10. スコープ外

- UI での複数書籍選択と一括ジョブ投入
- 複数 Windows エージェントによる並列撮影
- 利用者操作なしで最初の撮影を開始するための Kindle 自動起動
- ログイン要求、更新画面、プロセスが残った UI 不調に対する Kindle の強制終了・自動復旧
- Amazon アカウントへのログイン自動化
- Windows のロック解除
- 撮影中の同一端末の併用
- 既存画像の自動 ASIN 確定
- Amazon データ、Kindle Info、旧 DB の取込ロジック変更
- 旧アプリの画像、表紙、レビュー、感想の取り込み
- 完全重複・低容量・白紙・近似重複・端切れwarningを自動削除またはblockingへ昇格すること
- 単一画面、2画面だけ、または右下以外に現れる非反復Kindle / OS UI混入と、欠落ページの自動検出
