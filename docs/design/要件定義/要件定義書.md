# 要件定義書

> status: living | last-verified: 2026-09-05

## 1. 目的

**同人誌・漫画・小説を閲覧・整理する、個人LAN内の単一ユーザー向けWebアプリケーション。**

同人誌はZIP / WebP画像を取り込んで画像として閲覧し、漫画は画像とPDFに対応する。
Kindleの撮影画像も取り込み、小説は原画像とOCR本文を分けて保存し、全文検索・RAG質問応答・
人物辞典・書籍要約を利用できる。小説向けSearchable PDFは生成しない。
作者・シリーズなどのメタデータで、3つのsource（`doujin` / `comic` / `novel`）を整理する。

### 1.1. 対象ユーザー・利用前提

- **単一ユーザー**: 開発者本人1人がローカルPCまたは信頼済みLAN/Tailscale内で利用する。利用者アカウント機能は持たない。端末間agentの認証境界は[セキュリティ設計](../詳細設計/セキュリティ設計書.md)を参照する。
- **取り込み元**: ZIP / フォルダ単位の同人誌画像、漫画の画像・PDF、Kindleの撮影画像。一般の取込元は**ファイル名・フォルダ名に規則性がない前提**とし、Kindle自動撮影の成果物は専用manifestで検証する。
- **DLsite / Fanza の作品 ID は基本的に取れない前提** で設計する。Web 検索 + LLM による自動メタデータ取得は精度が出ないため採用しない。

### 1.2. 設計方針（核となる 3 原則）

1. **ミニマル化**: 使われない機能は削る。「あって安心」だけの機能は持たない。
2. **手動 + AI 提案**: メタデータ整理は手動を前提とし、AI は **自動実行ではなく "提案"** として支援する。提案はユーザー確認後に確定する。
3. **同人誌の閲覧体験を磨く**: 1 冊が短く冊数が多い同人誌の特性に合わせ、サークル横断・見開き表示・関連書籍ナビを継続的に強化する。

## 2. コア機能

### 2.1. PDF 閲覧 (Reader) — 最重要

**このアプリの核機能**。明日壊れて一番困るのは閲覧機能。

- **見開きモード**:
    - **Auto（自動）**: ページの縦横比を判定して縦長なら見開き / 横長なら 1 ページ表示。デフォルト。閾値 `width > height * 1.2` で横長判定（センターカラー等の見開き原稿を検出）し、ペアの片方でも横長を検出すれば 1 ページ表示に切り替わる。1 ページ表示時は見開き原稿が画面幅一杯で表示される。
    - **Spread（固定見開き）**: 常に 2 ページ表示。横長ページが含まれる場合は崩れることを許容（手動オーバーライドの責任）。
    - **Single（固定 1 ページ）**: 常に 1 ページ表示。
    - ヘッダーボタンで Auto → Spread → Single → Auto の順に循環。
- **右綴じ（RTL）**: 漫画と同様、右が若いページ。
- **没入型モード**: PDF 閲覧中はグローバルヘッダー非表示、コントロールバーはマウスオーバー時のみ表示。
- **ページ送り操作**:
    - 左側クリック / 矢印キー（RTL/LTR を考慮した方向）で次ページ。
    - キーボード操作中心の運用を想定（ボタンより矢印キーが主）。
- **高速閲覧モード (Image-Based Viewing)**: PDF 生成時に抽出された WebP 画像があれば PDF レンダリングをスキップして直接表示。無ければ `react-pdf` フォールバック。
- **ナビゲーション**: URL パラメータ (`?path=...`, `?file=...`) で状態管理。ブラウザ「戻る」「進む」で履歴を辿れる。

今後の改善候補は[バックログ](../../log/計画/バックログ.md)を参照する。

### 2.2. 取り込み (Generator) — フォルダ監視による自動取り込み

ZIP / フォルダ単位で置かれた同人誌を画像ディレクトリへ取り込む機能。**入力フォルダに置くだけで自動的に取り込まれる**（手動の「今すぐスキャン」も利用できる）。

- **フォルダ監視（自動取り込み）**:
    - バックエンド起動時に監視ループを開始し、`DOUJIN_INPUT_DIR`（Samba 共有）を定期スキャン（デフォルト 15 秒間隔。`DOUJIN_WATCH_INTERVAL_SEC` / `DOUJIN_WATCH_ENABLED` で調整・無効化可）。
    - **静穏検知**: 入力ディレクトリのスナップショット（ZIP はサイズ + mtime、フォルダはファイル数 + 合計サイズ + 最大 mtime）が 2 回連続で一致したら「コピー完了」とみなして取り込みを起動。コピー途中のファイルを掴まない。
    - **失敗残骸の再試行抑制**: 前回試行時とスナップショットが同一なら自動再実行しない。再試行は手動「今すぐスキャン」でのみ行う。
    - **Samba 切断耐性**: 入力フォルダに到達できない間は `input_missing` 状態で待機し続ける（クラッシュ・エラー蓄積しない）。
    - watchdog（ファイルシステムイベント）ではなくポーリング方式を採用。入力元が Samba 共有でありイベント通知が信頼できないため。
- **排他制御**: 手動実行と自動実行は共有ロックで直列化。実行中の手動リクエストは HTTP 409。
- 指定した親ディレクトリ以下を再帰的に走査する。
- **フォルダ処理**: 各ディレクトリ内の WebP 画像を自然順ソートで `data/doujin/images/<フォルダ名>/` に展開。書籍はこの画像ディレクトリを正として管理（image-only モード）。
- **ZIP ファイル処理** (主流): ディレクトリ内の `.zip` を検知し、中の WebP 画像を同様に展開。
- **完了後の処理**: 成功したフォルダ / ZIP は `data/doujin/complete/` に移動（この冪等性が監視ループの繰り返し実行を安全にしている）。

### 2.3. メタデータ管理（作者・シリーズ）

書籍単位でメタデータを管理する。データはサーバー側 `backend/data/meta2.db`（SQLite、WAL モード）の `books_meta` テーブルに保存。保存契約は[バックエンド詳細設計](../詳細設計/詳細設計書_バックエンド編.md)を参照する。

- **管理する項目（手動運用するもの）**:
    - **作者名**（基本はサークル名、個人活動のみの場合は個人作家名）
    - **シリーズ**（`series_id` / `series_title` / `series_index`）
    - **シリーズ／作者の代表ピン**（星トグル。`group_pins`へ保存）
    - **読書状態**（未読 / 読書中 / 読了）
    - **非表示フラグ**（ゴミ箱方式）
- **編集 UI**:
    - サムネイルカードクリックで直接 PDF へ遷移（詳細パネルなし）。
    - **複数書籍への一括設定**: 選択モードで複数選択 → 「作者を設定」「シリーズに登録」等のボタンから一括上書き。一括成功時は選択モードを自動解除（連続操作の意図が薄いため）。作者の既存候補は未選択状態（「作者を選択...」）で開始し、明示的に選択するまで適用できない。
- **検索・フィルター**:
    - **タイトル検索**: タイトル / 作者名に部分一致。
    - **作者フィルター**: ライブラリヘッダーのドロップダウンで完全一致。
    - **シリーズフィルター**: 同上。

### 2.4. シリーズ管理

- **手動を前提とする**。同人誌では命名規則が作者依存で揺れが大きく、ルールベース・LLM 補助とも実用精度に達しない判断（[§7. 撤去された機能](#7)参照）。
- **データモデル**: `meta2.db` の `books_meta` テーブルに `series_id` / `series_title` / `series_index` カラムとして保存。`series_index` は `float`（小数巻 `2.5`, `4.5` 等に対応）。
- **手動編集**:
    - 書籍カードから「シリーズに追加」/「新規シリーズ作成」/「シリーズから外す」が可能。
    - **一括登録**: 選択モードで複数選択 → 「シリーズに登録」から既存シリーズへ追加 / 新規作成。巻数は **選択順** に自動採番（既存シリーズへの追加時は `max(series_index) + 1` から続けて採番）。
    - **DnD 並べ替え**: シリーズドリルダウン中（`?series=...`）は `series_index` 順で表示し、ドラッグ&ドロップで並べ替え可能。ドロップ時に `1.0, 2.0, 3.0, ...` で振り直し。
- **AI 提案（既存シリーズへの紐付け候補）— 2026-05-09 実装**:
    - **入力**: ユーザーが選択した複数冊。
    - **出力**: 「これらは既に登録されている『○○シリーズ』に属するのではないか」という **既存シリーズへの所属候補** を提示。
    - **動作原則**: 自動実行しない。提案のみ。ユーザー確認後に紐付け確定。
    - **UI**: `BulkSeriesAssignDialog` の第 3 モード「AI が提案するシリーズに追加」。モード選択時に `POST /api/series/suggest` を自動呼び出しし、上位 5 件をラジオで表示。
    - **マッチング**: ルールベース（タイトル前方一致スコア + 作者集合一致ボーナス）。LLM 連携は POC 段階では未対応。
    - **新規シリーズ発見** ではなく **既存シリーズへの紐付け** に焦点を絞ることで、撤去した自動グループ化の精度問題（取りこぼし、誤登録名）を回避する。

### 2.5. ライブラリ表示

PDF 一覧画面のレイアウト・操作。

- **読み込み・空・失敗状態**: PDF 一覧の取得中は書籍カード型のスケルトンと「ライブラリを読み込み中…」を表示する。一覧取得に失敗した場合は「ライブラリ情報を取得できませんでした」と再試行操作を表示し、空ライブラリとして扱わない。取得完了後、登録書籍自体が 0 件なら「書籍がありません」、登録書籍はあるが検索・作者・シリーズ・読書状態・ジャンル・非表示条件で表示対象が 0 件なら「条件に一致する書籍がありません」と条件解除操作を表示する。メタ情報またはジャンル情報だけの取得失敗では警告を表示し、取得済みの書籍一覧は継続表示する。
- **画面表記**: 利用者向けのライブラリ画面では `Library` / `PDFs` 等の英語表記を使用せず、「ライブラリ」/「書籍」へ統一する。
- **フォルダ階層表示**: サブディレクトリはフォルダアイコンで表示、クリックでドリルダウン、戻るボタンで親階層へ。
- **サムネイル表示**: PDF の 1 ページ目をサムネイルとして表示。
- **書籍カードの情報階層**: 同人誌・漫画のライブラリと小説 DB の通常書籍カードは、表紙、タイトル、作者、ソース固有の補助情報、読書状態・操作の順で表示する。小説 DB 固有の短い要約と OCR / RAG 構築状態は残し、読書状態の位置だけを共通化する。
- **書籍カードの操作性**: 表紙、作者、管理操作はキーボードで到達・実行できるようにし、アイコンだけの操作には読み上げ可能な名前を付ける。主要なタップ領域は 44px 以上、keyboard focus は可視化し、意味を持つ文字・操作には薄いグレーを使用しない。
- **一覧応答性能**: `GET /api/pdfs` は同一 source / path の連続取得でディレクトリ全走査を繰り返さず、キャッシュ命中時の本番応答を 200ms 未満とする。書籍・サムネイルの追加、名前変更、削除、再生成は遅くとも 30 秒以内、既知の書き込み経路では即時に一覧へ反映する。API レスポンス形式は変更しない。
- **ソート種別**（ライブラリヘッダーで切替、選択は localStorage に永続化）:
    - 名前（昇順 / 降順）
    - 作成日時（昇順 / 降順）
    - **お気に入り優先**（お気に入りを先頭、同グループ内は名前昇順）
    - **よく見る順** (`view_desc`): 閲覧回数の降順。同数は名前昇順。
    - **最近見た順** (`recent_view`): 最終閲覧時刻の降順。未閲覧は末尾。
- **グループ化表示**: ライブラリヘッダーの「グループ化」セレクトで切替。
    - **なし**（デフォルト）: フラット表示
    - **シリーズで**: 同 `series_id` を最終巻のサムネイルで集約
    - **作者で**: 同作者集合を集約。代表サムネは現ソート順の先頭
    - **作者 → シリーズで**: 2 階層ドリルダウン
- 集約された仮想カードは紫枠で表示。クリックでドリルダウン（パンくずナビゲーション）。
- **閲覧記録**:
    - PDF を開いたタイミングで `view_count` と `last_viewed_at` を記録。
    - **連打抑制**: 同じ書籍を 5 分以内に再度開いてもカウントは増えない（最終閲覧時刻のみ更新）。
    - 読書状態の自動遷移（`unread → reading`、最終ページ到達で `reading → done`）。

### 2.6. 関連書籍パネル

リーダーで最終ページに到達した時、関連書籍をフローティングパネルで提示する。

- **集計軸**: 同シリーズ / 同作者のみ（タグ機能は撤去済み）。
- 改善候補と優先度は[バックログ](../../log/計画/バックログ.md)を参照する。

### 2.7. 書籍編集

- **PDF 結合**: 選択モードで 2 冊以上選び「PDF を結合」から順番通りに 1 つの PDF に結合。出力名はダイアログで指定（重複名は拒否）。サムネイルも自動生成。
- **サムネイル再生成**: 単発 / 一括（選択モード）。
- **ページ編集**: 同人誌・漫画Readerの編集モードで全ページサムネイルを表示し、削除対象の複数選択とDnD並び替えを行う。並び替えは`POST /api/pdfs/{filename}/reorder_pages`で即時保存する。`doujin`は画像ファイルを再配置し、`comic`は対象PDFを再構築する。削除・並び替えとも確認と失敗時表示を持つ。小説のPNGリーダーにはページ編集UIを設けない。

### 2.8. 非表示（ゴミ箱方式）

- 個別書籍を「非表示」にして一覧・検索・フィルター・グループ化のすべてから隠す。
- **操作**: 書籍カードの目アイコン (`EyeOff`) で単冊、選択モードで一括。
- **確認・復元**: ヘッダーの「非表示を表示」トグル ON で **非表示書籍のみ** を表示し、目アイコン (`Eye`) で復元。
- **データ保持**: 書籍ファイル本体は削除せず、`meta2.db` の `books_meta.hidden` カラムのみ更新。

### 2.9. Hitomi 新着監視

外部サイトの新着監視を独立スクリプトとして提供（[Hitomi 新着監視設計書](../詳細設計/機能別/hitomi新着監視設計書.md)）。

- 検出した作品は `meta2.db` に永続保存し、既読化後も自動削除しない。
- 画面は「新着」と「履歴」を切り替え、履歴から過去に検出した作品を再確認できる。
- 監視対象と監視ジョブ状態は、独立スクリプトから扱いやすい JSON のまま保持する。

### 2.10. Kindle 購入カタログ

- 購入、Kindle Unlimited 借用、返品、シリーズ、著者、ジャンルを Linux サーバーで一元管理する。
- 購入書籍一覧は検索・ページング・種別・所有状態・画像取込状態で絞り込める。
- Amazon エクスポートと Kindle Info を設定済みサーバーディレクトリから差分取り込みする。
- 既存 `kindle購入履歴` DB から初回移行できるが、感想、レビュー、評価、表紙パス、表紙キャッシュ、同アプリが保存した画像は移行しない。
- Pic2PDFViewer に既にある `comic` / `novel` 画像は候補表示し、ユーザーの確定操作後に ASIN で紐付ける。候補の自動確定はしない。
- Windows Kindle キャプチャは Linux が発行するジョブに従い、成果物だけを専用受信箱へ送る。
- 購入書籍の選択から Kindle 内の本人照合、未ダウンロード待機、先頭移動、全ページ撮影、登録までを 1 冊ずつ自動実行する。詳細条件は [Kindle 自動撮影取込 要件](Kindle自動撮影取込_要件.md)で管理する。
- Kindle アプリは起動済み・ログイン済み、Windows は画面ロックなし、処理中は端末を操作しないことを前提とする。アプリ起動・ログイン・ロック解除は自動化しない。
- `run_comic.bat` / `run_novel.bat` の手動起動は診断・互換経路として残すが、通常運用は購入カタログから作成した capture job と `run_capture_agent.bat` を使う。

詳細は [Kindle 購入カタログ設計](../詳細設計/機能別/Kindle購入カタログ設計.md) を参照。

### 2.11. Kindle 価格監視

- Amazon.co.jp の Kindle 書籍 URL を画面から監視対象として追加・削除・無効化できる。
- Codex の定期実行が対象 URL をブラウザで開き、画面表示から現在価格と定価/参考価格を読み取る。
- 定価比率の閾値（既定50%）および前回価格からの値下がりを判定し、条件成立時にDiscordへ通知する。
- 価格履歴と読み取り失敗理由を保存し、価格が取得できない場合は誤通知しない。
- Kinseli/Kiseppe API、AmazonアソシエイトAPI、Amazonページへのバックエンド直接取得は使用しない。
- Amazonのログイン、CAPTCHA、購入操作は自動化しない。

詳細は [Kindle価格監視設計](../詳細設計/機能別/Kindle価格監視設計.md) と
[ADR-0025](../基本設計/ADR/0025_kindle-price-monitor-codex-browser.md) を参照。

## 3. 取り込みパイプライン

### 3.1. 主な取り込み元

- **ZIP（最頻）**: 所定フォルダにZIPを置き、監視によって閲覧用画像へ取り込む。
- **WebP 画像フォルダ**: 展開済みの画像フォルダを閲覧用画像として取り込む。

### 3.2. ファイル名・フォルダ名の前提

**規則性は無い前提で設計する**。作者ごとに命名がバラバラのため、ファイル名解析による作者名抽出は行わない。

### 3.3. DLsite / Fanza 連携

- **基本方針: 採用しない**。同人誌は作品 ID が取得できないケースが大半のため、Web 検索 + LLM による自動メタデータ取得は採用しない。
- **将来の余地**: 公開ページ範囲で「作品名検索 → キーワードタグ取得」が現実的に動く目処が立てば、補助機能として再検討する余地を残す（現時点では計画外）。

## 5. 小説本文と生成物の提供範囲

### 5.1. OCR（novel.db 直接格納）

- 小説は原画像を閲覧し、承認済みOCR本文を検索・RAGに利用する。Searchable PDFは生成しない。
- サーバーOCRはQA完了後の1冊分だけを公開し、未承認・失敗時に既存本文を上書きしない。
- Codex管理のOCRはMacの隔離環境で原画像照合・補正を行い、検証済みpackageをLinuxへ渡す。
  通常の利用者QAは要求せず、一意に確定できない箇所は保留する。
- packageの取り込みと公開を分け、取り込みだけでは検索対象の本文を変更しない。
  Macから本番DBを直接更新せず、自動公開・DB丸ごと置換・手動SQL patchは行わない。

engineの選択、証跡、QA、公開・復旧条件は[OCR設計書](../詳細設計/機能別/OCR設計書.md)、
未完了の品質改善は[OCR実装計画](../../log/計画/小説OCR品質改善_実装計画.md)を参照する。
同人誌へのOCR適用は現行提供範囲に含めない。

### 5.2. OCR後のSol生成・評価

承認済み小説本文からあらすじ・短縮要約・人物辞典の候補を作成する隔離CLIを持つ。
書籍単位の明示的opt-in、外部送信範囲の制限、独立評価と承認を要求し、失敗時は旧公開版を保持する。
Qwenの対話QA・オフライン経路を維持するが、Sol失敗時の自動公開の代替にはしない。

隔離実行の契約とPhase 3の未実装境界は
[Sol生成・評価設計](../詳細設計/機能別/小説RAG_Sol生成・評価設計.md)、
導入の残作業は[Sol導入計画](../../log/計画/Sol生成・評価_導入計画.md)を参照する。
