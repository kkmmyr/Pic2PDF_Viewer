## 1. プロジェクト全体ディレクトリ構成

```
Pic2PDF_Viewer/
├── backend/                # FastAPI バックエンド（uv workspace member）
├── kindle-pdf/             # Kindle 自動化ツール（別 uv workspace member）

├── common/                 # 共有モジュール（llm / ocr / llama.cpp。llm は uv workspace member）

    ├── index.md            # mkdocs ランディングページ + 正本マップ
```

## 2. 運用・開発メモ

- **起動方法**: [起動方法.md](../../../起動方法.md) を参照
    - 開発モード: Backend `uv run uvicorn main:app --reload --port 8766` / Frontend `npm run dev` (Port 5176)
    - Windows ローカルリリース: NSSM の `Pic2PDFViewer` サービスが Backend (Port 8090) から dist を同一オリジン配信する。初回登録は `scripts/setup_service.bat`
    - Linux 本番: nginx (Port 8090) から systemd 管理の uvicorn (127.0.0.1:8091) へリバースプロキシする。`scripts/deploy_to_linux.sh` がビルド・転送・DB バックアップ・再起動を行う
    - ポート割当の詳細・他プロジェクトとの調整は `D:\61.tool\common\port\README.md` を参照
- **Backend 再起動**: `scripts/start.bat` を再実行するだけで Backend のみ再起動できる
    - Port 8766 が LISTENING 状態なら uvicorn プロセスツリーを終了。`backend/start_server.bat` 内の再起動ループが同タブ内で `uv sync` → uvicorn 再起動を自動実行する（新タブは開かない）
    - 未起動なら通常通り Backend + Frontend 両方を起動する
- **注意点**:
    - `react-pdf` のWorker設定は `new URL('pdfjs-dist/build/pdf.worker.min.mjs', import.meta.url)` で Vite バンドル経由で読み込む。CDN不要。
    - `<Document>` コンポーネントを使うファイルと同じモジュールで `workerSrc` を設定すること（`ReaderPanel.tsx`）。
    - `novel` ソースは `NovelReaderPage` で `kindle_novel/images/{book}/` の元 PNG を表示する。OCR 本文は `novel.db` に保持し、Searchable PDF は生成しない。
    - 静的マウントは `/thumbnails`（`data/doujin/thumbnails/`）/ `/images`（`data/doujin/images/`）/ `/comic/{pdfs,thumbnails,images}` / `/kindle_novel/{thumbnails,images}`。`/pdfs` と `/kindle_novel/pdfs` のマウントは廃止済み（`doujin` / `novel` は image-only モードで運用）。`pdfs_compressed/` は 2026-07-04 の batch_compress 撤去にともない出力経路も消滅（残存ディレクトリは手動削除可）。
- **環境設定**:
    - Frontend: `frontend/.env` に `VITE_DEFAULT_SOURCE_DIR` を設定することで生成画面のデフォルトパスを変更可能。
    - Backend: `python-dotenv` 導入済み。`.env` ファイルから設定を読み込む。

### 2.1 依存関係の健全性チェック

- Frontend は `npm run lint:deps`（Knip）で、未使用ファイル・未使用npm依存・
  未宣言importを検査する。公開exportは既存barrelの互換面が広いため
  ブロッキング対象から外し、検出結果を無差別に自動削除しない。
- ソースから直接importするパッケージは、推移依存に頼らず各workspace memberの
  manifestへ直接宣言する。
- patch/minor更新とmajor更新は分離し、major更新は専用ブランチで型チェック・
  テスト・実機確認を行う。

### 2.2 構造・契約の品質ゲート

規模、複雑度、OpenAPI契約、import方向、設計書整合性の検査を
pre-commitとGitHub Actionsから同じ入口で実行する。検査対象、blocking条件、
baseline更新、例外期限の正本は
[品質ガードレール](品質ガードレール.md)とする。

## 3. リリースビルド構成

開発時とは別ポートで動作する「ビルド済み配信」モード。修正時は通常通り dev サーバーで作業し、Windows ローカルでは `scripts/build_release.bat`、Linux 本番では `scripts/deploy_to_linux.sh` からビルドする。

### 3.1 ポート割り当て
| モード | Backend | Frontend | 起動方法 |
|---|---|---|---|
| 開発 | 8766 (uvicorn --reload) | 5176 (vite dev, strictPort) | `scripts/start.bat` |
| Windows ローカルリリース | 8090 (NSSM 管理の uvicorn) | Backend に統合（dist 配信） | `scripts/setup_service.bat`（初回）/ `scripts/restart_service.bat` |
| Linux 本番 | 8091 (uvicorn / localhost のみ) | nginx 8090 が dist と API を同一オリジン配信 | `scripts/deploy_to_linux.sh` / systemd |

### 3.2 動作原理
1. `npm run build` で `frontend/dist/` に静的アセットを出力。
2. `backend/main.py`は以下のSPA handlerを最後に常時登録し、
   OpenAPI schemaをgitignore対象の`FRONTEND_DIST_DIR`の有無から独立させる。
    - `/` → `dist/index.html`
    - `/{full_path:path}` → `dist/` 配下にファイルがあれば返す。なければ `index.html`（SPA fallback）
    - `/api`, `/pdfs`, `/thumbnails`, `/images`, `/kindle/...` などの既存マウントが優先されるよう、SPA 用 catch-all は **最後** に登録する。
    - `dist/index.html`がない開発環境では、handlerは`404`を返す。
      `/assets`のstatic mountだけは実directoryがあるときに登録する。
3. リリースモードでは同一オリジンで動くため、フロントエンドは `BASE_URL=''` （相対パス）で API を叩く。

Vite の `manualChunks` は PDF / TanStack Query / vis-network / lucide-react の大容量・独立性が高い依存だけを用途別チャンクへ分割する。`@dnd-kit` / React / Axios 等は CommonJS 変換ヘルパーを共有するため、単独チャンクや汎用 `chunk-vendor` へ強制せずViteの自動分割へ委ねる。強制分割すると、生成順によって `chunk-dnd → api_client → chunk-vendor` 等の循環初期化が発生し、起動時に `TypeError: t is not a function` となる。

### 3.3 フロント側の API URL 切り替え
`frontend/src/config/api.ts` で `import.meta.env.PROD` を判定:
- `true`（`vite build`）→ `BASE_URL = ''`（同一オリジンで相対パス）
- `false`（`vite dev`）→ `VITE_API_URL` または `http://localhost:8766`

### 3.4 起動スクリプト
| ファイル | 役割 |
|---|---|
| `scripts/start.bat` | 未起動なら Backend + Frontend 両方を Windows Terminal タブで起動。Port 8766 が LISTENING なら uvicorn を終了して Backend のみ再起動 |
| `backend/start_server.bat` | `uv sync` → uvicorn 起動のループ。uvicorn が停止するたびに自動で再起動（Ctrl+C → Y で停止） |
| `scripts/build_release.bat` | `cd frontend && npm run build` を実行（dist 再生成） |
| `scripts/setup_service.bat` | Windows ローカルリリース用の `Pic2PDFViewer` NSSM サービスを登録 |
| `scripts/restart_service.bat` | frontend build 後などに Windows サービスを再起動 |
| `scripts/open_viewer.bat` | `http://localhost:8090` をブラウザで開く |
| `scripts/deploy_to_linux.sh` | frontend build、世代別workspace / dist / deploy設定の転送、DB世代backup、新backend世代のlock同期とatomic切替、`pic2pdf-viewer` systemd service再起動・失敗時rollback |
| `deploy/activate-backend.sh` | writer / backup競合検査、復元試験、世代別backend / common / venvのsmoke・切替、HTTP不合格時の一体rollback |

### 3.5 Windows サービスの自動起動 / クラッシュ時自動再起動

Windows ローカルリリースは NSSM の `Pic2PDFViewer` サービスで管理する。
起動種別は自動（遅延開始）とし、クラッシュ時の再起動、ログ出力、
子プロセス停止を NSSM に委ねる。旧タスクスケジューラ経路は二重起動を
避けるため無効化する。

登録・解除・ログオンアカウントの設定は
[Windows サービス化セットアップ](../環境構築/Windowsサービス化セットアップ.md)
を参照。

### 3.6 文字エンコーディング上の注意
Windows の `.bat` は **ASCII コメントを原則**とする。日本語コメントを含むと UTF-8 として保存され、`chcp 65001` 後でも cmd.exe のパーサが行をまたいで誤動作する場合がある。

### 3.7 設計ドキュメントの HTML 配信（mkdocs-material、2026-05-11 追加 / 2026-05-11 出力先変更）

`docs/*.md` を `mkdocs build` で `frontend/public/site/` に HTML 化する。出力先を Vite の `publicDir` 配下に置くことで、Vite dev / Vite dist / FastAPI 直接マウントのすべてから配信される。詳細は [ADR-0008](../基本設計/ADR/0008_design-docs-html-build.md)。

**配信構成**:
- Vite (`frontend/public/site/`): dev (`:5176`) / build 後の `dist/site/` → リリース統合 (`:8090`) のいずれでも `/site/` から自動配信
- FastAPI (`backend/main.py`): ローカル作業ツリーの `frontend/public/site/` 存在時に `app.mount("/docs-html", StaticFiles(directory=..., html=True))` を登録（ローカル後方互換）
- SPA catch-all より前に登録（優先順位）
- 開発・リリース両モードで有効

**閲覧 URL**:
| モード | URL |
|---|---|
| 開発（mkdocs serve）| `http://localhost:8000` |
| 開発（Vite dev、ビルド済み）| `http://localhost:5176/site/index.html` |
| 開発（backend 直接、ビルド済み）| `http://localhost:8766/docs-html/` |
| リリース（Vite dist 経由）| `http://localhost:8090/site/index.html` |
| Windows ローカルリリース（後方互換）| `http://localhost:8090/docs-html/` |

フロントエンド画面のヘッダー右上「設計書」リンクから別タブで開ける（[`frontend/src/components/Layout.tsx`](../../../frontend/src/components/Layout.tsx)）。

**ビルドコマンド**:
- 初回: `uv tool install mkdocs --with mkdocs-material --with mkdocs-mermaid2-plugin` + `uv tool update-shell` → PowerShell 再起動
- 単発: `uv run mkdocs build --clean`
- 開発時プレビュー: `uv run mkdocs serve`

**git 管理**: `frontend/public/site/` は `.gitignore`。ソース `docs/*.md` のみコミットする。`npm run build` 時は `frontend/dist/site/` にもコピーされるため、`docs/` または `mkdocs.yml` を変更したデプロイでは `scripts/deploy_to_linux.sh` より先に `uv run mkdocs build --clean` を実行する。デプロイスクリプト自体は MkDocs を生成しない。
