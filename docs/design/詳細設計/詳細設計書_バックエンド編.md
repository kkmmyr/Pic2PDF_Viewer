## 2. データ配置 (Backend)
- `backend/data/`: データ格納ルート
    - `doujin/`: 同人誌データ（source='doujin'、旧 `main/`）
    - `comic/`: 漫画データ（source='comic'、旧 `kindle/`）
    - `kindle_novel/`: 小説キャプチャデータ（source='novel'）
    - `meta2.db`: 書籍メタデータ + ジャンルリスト + UI 設定 + Hitomi検出履歴（Phase 64 で JSON → SQLite 移行）
        - `books_meta` テーブル: キー `"{path}/{filename}"` / 値カラム `authors`, `hidden`, `genre`, `read_state`, `view_count`, `last_viewed_at`, `series_id`, `series_index`, `series_title`, `asin`
        - `genres` テーブル: ソース別の表示順ジャンルリスト
        - `ui_filters` テーブル: ソース別 UI フィルター設定（`read_state_filter`, `genre_filter`）
        - `group_pins` テーブル: シリーズ/作者カードの代表ピン（`pin_type` = `"series"` | `"author"`）
        - `hitomi_arrivals` テーブル: Hitomiで検出した作品と既読状態。既読化後も自動削除しない
        - 旧 `meta/` / `genres/` ディレクトリの JSON は移行後 `.bak` にリネームされ残置
    - `kindle_catalog.db`: Kindle購入カタログ、capture job、登録後画像QA監査
        - `capture_quality_audits`: 成功jobごとのimmutableなquality監査世代。warning 0件も保存し、
          再撮影・再監査では旧世代をsupersedeして監査履歴を残す
        - `capture_quality_warnings`: active監査世代のwarningをcode単位で集約し、元finding証跡と
          確認済み状態を保持する。capture job完了更新と同じtransactionで挿入する
    - `logs/`: バックエンドログ（`app.log` + `app.log.1`〜`app.log.5`、`RotatingFileHandler` で自動世代管理）。詳細は [ADR-0006](../基本設計/ADR/0006_backend-log-file-persistence.md)
    - `novel_db/sol_ocr_campaigns/`: manifest、分割割当、ページ成果物、比較report。書籍画像・本文をGitへ含めず、campaign IDごとに保持する。

## 4. ロギング (utils/logger.py)

設計判断の詳細は [ADR-0006](../基本設計/ADR/0006_backend-log-file-persistence.md)。

- **取得方法**: 各モジュールで `from utils.logger import get_logger; logger = get_logger(__name__)`
- **ハンドラ構成**:
  - **StreamHandler** (`sys.stdout`): 各モジュール logger に直接付与。`get_logger(__name__)` 初回呼び出し時にセット。開発時のターミナル可視性を確保
  - **RotatingFileHandler** (`backend/data/logs/app.log`): root logger に 1 度だけ付与。`logger.propagate=True`（デフォルト）経由で全モジュール logger のログがファイルに集約される。ファイルハンドルを 1 個に集約することで Windows でのローテーション競合を回避
- **ローテーション**: 10MB × 5 世代（最大合計 50MB）、UTF-8 エンコーディング
- **ログレベル**:
  - 自前モジュール logger: `INFO`（既定）
  - root logger: `WARNING`（サードパーティ DEBUG 混入防止、`get_logger` 呼び出し時に未設定なら自動セット）
- **フォーマット**: `%(asctime)s [%(levelname)s] %(name)s: %(message)s`（`asctime` は `%Y-%m-%d %H:%M:%S`）
- **セキュリティ監査ログ**: `Security:` 接頭辞で grep 可能。詳細は [セキュリティ設計書 §2-5](セキュリティ設計書.md)

## 5. クラス設計

### バックエンド (`backend/`)

#### APIレスポンススキーマ (`backend/routers/schemas/`)

- OpenAPIの`response_model`に使用するPydanticモデルは、責務ごとに
  `common.py`、`library.py`、`novel_db.py`、`ocr.py`、`kindle_catalog.py`へ分割する。
- `routers/schemas/__init__.py`が公開モデルを再exportし、ルーターはこの公開境界または
  互換facadeからimportする。モデル名とfield定義をOpenAPI契約の正本とする。
- 旧`routers/api_schemas.py`は既存importを壊さない互換facadeとして維持し、
  新しいモデルは機能別moduleへ追加する。
- 構造変更時は正規化した`openapi.json`を変更前後で比較し、model moduleの移動だけで
  schema名、required、nullable、defaultを変えない。

#### `GenerateJob` / `JobStore` (`backend/services/job_manager.py`)
- **役割**: 非同期PDF生成ジョブのライフサイクル管理。利用元は `routers/generate.py`（旧 `routers/pdfs.py` から分離）。
- **設計**:
    - `GenerateJob`: UUID・ステータス・進捗アイテム・ファイルリスト・エラーを保持。`threading.Lock` で状態更新をスレッドセーフに。
    - `JobStore`: 最大 `JOB_MAX_JOBS` 件のジョブをメモリ管理。FIFO方式で古いジョブを自動削除。
- **エンドポイント** (`backend/routers/generate.py`):
    - `POST /api/generate` → `services/generate_service.start_generate_job(trigger="manual")` 経由でバックグラウンド非同期実行 + `{job_id}` を即返却。実行中（生成ロック取得済み）は **409** + 実行中 job_id を detail に返す。成功時は `doujin_watcher.clear_last_attempted()` を呼び、失敗残骸への自動再試行ブロックを解除する（手動実行 = 再試行の意思表示）。
    - `GET /api/generate/job/{job_id}` → ジョブ進捗取得（クライアントが1500msでポーリング）。`trigger: "manual" | "auto"` を含む。
    - `GET /api/generate/watcher` → フォルダ監視の状態取得（下記 `DoujinWatcher` 参照）。
    - `GET /api/status`（変換状態一覧）と `POST /api/batch_compress`（一括圧縮）は 2026-07-04 に撤去（[要件定義書 §7](../要件定義/要件定義書.md#7)）。

#### `generate_service` (`backend/services/generate_service.py`)
- **役割**: PDF 生成ジョブの実行ロジック（2026-07-04 に `routers/generate.py` から分離）。手動 API（`POST /api/generate`）と `DoujinWatcher` の自動起動が**同一コードパス**（`start_generate_job()`）を通る。
- **排他制御**: モジュールレベルの `generate_lock`（`asyncio.Lock`）で手動・自動を直列化。`start_generate_job()` はロック取得済みなら `None` を返し、呼び出し側が 409 等でハンドリング。`locked()` チェックから `acquire()` まで await を挟まないため asyncio 単一スレッド下で競合しない。従来の「手動連打で並行実行される」バグもこれで解消。
- **Task寿命**: `asyncio.create_task()` で起動した Task はモジュール内集合に強参照を保持し、完了コールバックで集合から除去する。同期的なPDF生成処理は `asyncio.to_thread()` で既定スレッドプールへ委譲し、イベントループを塞がない。
- `get_active_job_id()`: 現在ロックを保持して実行中のジョブ ID を返す（`GET /api/generate/watcher` の `active_job_id` と 409 detail に使用）。
- genre 初期化（新規書籍のみ `genre: "オリジナル"`）もこの層に移動。

#### `DoujinWatcher` (`backend/services/doujin_watcher.py`)
- **役割**: `DOUJIN_INPUT_DIR`（Samba 共有）を定期スキャンし、「置くだけで取り込まれる」自動取り込みを実現（2026-07-04）。lifespan で `start()` / `stop()`。
- **方式**: watchdog（FS イベント）ではなく**ポーリング + 静穏検知**。Samba 共有はイベント通知が信頼できないため。間隔は `DOUJIN_WATCH_INTERVAL_SEC`（デフォルト 15 秒）、`DOUJIN_WATCH_ENABLED=false` で無効化。
- **静穏検知**: トップレベルの ZIP（サイズ + mtime）/ フォルダ（再帰ファイル数 + 合計サイズ + 最大 mtime）のスナップショットが **2 回連続で一致**したらコピー完了とみなし `start_generate_job(trigger="auto")` を起動。コピー途中のファイルを掴まない。
- **失敗残骸の再試行抑制**: 直前に自動起動したスナップショット（`_last_attempted`）と同一の間は自動再実行しない（`retry_blocked=true` として API に露出）。再試行は手動「今すぐスキャン」でのみ。
- **状態遷移**（`tick()` 1 回ごと、テストは `tick()` を直接呼ぶ）: `disabled` / `input_missing`（入力不達。Samba 切断時もクラッシュせず待機）/ `idle` / `waiting_stable`（コピー進行中）/ `running`。

#### ルーター共通依存 (`backend/routers/_deps.py`)
- **役割**: ルーターで共通利用する FastAPI 依存関数を集約。
- **関数**:
    - `validated_source(source: str = "doujin") -> str`: クエリパラメータ `source` を `VALID_SOURCES` で検証する `Depends` 用関数。無効値は 400。
    - `assert_valid_source(source: str) -> None`: リクエストボディ内 `source` フィールドを検証するヘルパー（`Depends` を経由しないボディ POST 用）。無効値は 400。
    - `validate_request_targets(path: str, names: list[str]) -> None`: `path` を `validate_safe_path`、各 name を `validate_safe_name` で検証する。多くのエンドポイントで重複していた 2 行検証を 1 行に圧縮（Phase 47）。
    - `log_and_raise_500(operation: str)`: エンドポイントデコレータ。想定外例外を`logger.exception(operation)`で記録し`HTTPException(500)`へ変換する。`HTTPException`は素通しする。
- **適用範囲**: source検証は`series.py`、`genres.py`、`routers/meta/`、`library.py`、`pdfs.py`等が必要な境界で利用する。`log_and_raise_500`は`pdfs.py`、`library.py`、`novel_build.py`、`routers/novel_db/`の非stream endpointへ適用する。SSE、`ocr.py`、`generate.py`、`thumbnails.py`には一律適用せず、response開始後の例外や固有のerror contractを各routerが処理する。適用数を固定値として設計契約にしない。

#### `FileManager` (`backend/services/file_manager.py`)
- **役割**: PDF・サムネイル・画像ディレクトリの3点セット操作を一元管理。`routers/library.py` の重複コードを集約。
- **主要メソッド**:
    - `rename_with_assets(path, old_name, new_name, is_folder, dirs)`: PDF+サムネイル+画像ディレクトリをリネーム。失敗時は自動ロールバック。PDF が存在しない場合（doujin image-only モード）はスキップ。存在チェックは「PDF または images ディレクトリのどちらか一方が存在すること」。
    - `delete_with_assets(item, path, dirs)`: PDF+サムネイル+画像ディレクトリをディスクから完全削除。`DELETE /api/pdfs` からのみ呼ばれる。PDF が存在しない場合はスキップ（images ディレクトリのみ削除）。存在チェックは「PDF または images ディレクトリのどちらか一方が存在すること」。

#### `PdfGenerator` (`backend/services/pdf_generator.py`)
- **役割**: ディレクトリやZIPファイルのスキャン、画像からのサムネイル生成・ファイル移動を一元管理。
- **設計**:
    - ZIP・ディレクトリのどちらも「`images_dir` にファイルを配置 → `_collect_images` → `_generate_outputs`」という共通フローで処理する。
    - `output_dir=None` を渡すと image-only モード（PDF 生成をスキップ）。`doujin` ソースはこのモードで呼び出す。
    - `process_zip` / `process_directory` は書籍単位の例外を `self.failed_items: list[(name, error)]` に集約する。`scan_and_generate` の戻り値 `GenerateResult` 経由でジョブ層に伝播し、`GET /api/generate/job/{id}` の `failed_items` でフロントに可視化する（**サイレント失敗防止**）。
- **戻り値型**:
    - `GenerateResult(generated: list[str], failed_items: list[tuple[str, str]])` — `scan_and_generate` の戻り値。`failed_items` は `(item_name, error_message)` の組。
- **主要メソッド・関数**:
    - `_collect_images(images_dir)`: ディレクトリ内の WebP を natsorted で収集するモジュールレベル関数。
    - `_check_zip_safety(webp_infos, zip_filename)`: zip bomb 対策のモジュールレベル関数。`process_zip()` が ZIP を開いた直後・解凍前に呼び、`ZIP_MAX_ENTRIES` / `ZIP_MAX_PER_FILE_BYTES` / `ZIP_MAX_TOTAL_UNCOMPRESSED_BYTES` を超える場合は `ValueError` を投げる。違反時は `logger.warning("Security: ZIP rejected ...")` で監査ログも残す（[セキュリティ設計書 §2-5](セキュリティ設計書.md)）。
    - `process_directory()`: WebP を `images_dir` にコピーして共通フローへ。失敗時は `failed_items` に `(folder_name, error)` を追加。
    - `process_zip()`: ZIP を `images_dir` に展開して共通フローへ。展開前に `_check_zip_safety()` で安全検査。失敗時は `failed_items` に `(item_name, error)` を追加。
    - `_generate_outputs(item_name, item_images_dir)`: サムネイル生成 + PDF 生成（`output_dir` が `None` の場合はスキップ）。
    - `run()`: 処理の実行と、完了ファイルの `complete/` への移動・空ディレクトリ削除の制御。
- **生成後のメタ初期化** (`backend/services/generate_service.py` `_run_generate_job`):
    - `scan_and_generate` で新規生成された各書籍について、メタにエントリが存在しない場合のみ `genre: "オリジナル"` を初期書き込みする（再生成時は既存エントリを保持）。

#### `PdfService` (`backend/services/pdf_service.py`)
- **役割**: 既存PDFの編集操作を一元管理。
- **主要メソッド**:
    - `delete_pages()`: 指定されたページの削除とPDFの再保存。
    - `reorder_pages()`: `Document.select(page_indices)` で PDF を再構築し、上書き保存する（B-3）。`page_indices` は `[0..N-1]` の完全なパーミュテーションであることを要求し、違反時は `ValueError`。
    - `get_page_count()`: PDFの総ページ数を取得。

#### `ImageService` (`backend/services/image_service.py`)
- **役割**: image-only モード（`doujin` ソース）の書籍ページ列を操作するヘルパー。`PdfService` の image-only 版に相当。
- **主要関数**:
    - `list_book_images(img_dir, book_name, path) -> list[str]`: `images/{path}/{book_name}/` 配下の WebP を natsort 順で絶対パスのリストとして返す。ディレクトリ不在時は空リスト。
    - `delete_book_image_pages(book_dir, page_indices) -> int`: `book_dir` 配下の WebP を natsort 順に並べ、`page_indices`（0 始まり）に該当する WebP ファイルを削除する。重複排除 + 降順ソートでインデックスずれを防ぐ。範囲外インデックスは `ValueError`。戻り値は削除後の総ページ数。
    - `reorder_book_image_pages(book_dir, page_indices) -> int`: `book_dir` 配下の WebP を `page_indices` の指す順序で `page_0001.webp` / `page_0002.webp` / ... と再採番する（B-3）。一時名 `__reorder_tmp_NNNN.webp` 経由の 2 段階リネームで、入力順と既存ファイル名の衝突を回避する。`page_indices` は `[0..N-1]` の完全なパーミュテーションであることを要求し、違反時は `ValueError`。戻り値は総ページ数（並び替え前後で不変）。
- **設計判断**: `routers/thumbnails.py` の private `_get_webps` ヘルパーをここに移して `list_book_images` として公開。`routers/thumbnails.py` も同関数を使うようにリファクタ。

#### `routers/library.py:list_book_images`
- `GET /api/books/{path}/images` は画像を natural sort したうえで、各画像 URL にファイルの更新時刻（nanosecond）を `v` クエリとして付与する。
- Kindle 再撮影や再生成で同じ `001.png` などを置換しても URL が変わるため、ブラウザーの HTTP キャッシュに残った旧画像と新画像が混在しない。画像内容が変わらなければ `v` も変わらず、通常閲覧のキャッシュは維持する。
- novel 書籍一覧の `thumbnail_url` も `001.png`（未生成時は書籍ディレクトリ）の更新時刻を `v` として返す。`NovelReaderPage` はこの値を書籍全ページの版として引き継ぐ。
- Kindle 更新時の再検証、撮影品質、同名置換後の障害切り分けは
  [Kindle 自動撮影 実機知見](../../log/技術知見/Kindle自動撮影_実機知見.md)を参照する。

#### ライブラリ一覧service / cache (`backend/services/library_listing.py`)

- `GET /api/pdfs`の画像directory走査、thumbnail URL生成、作成日時取得をrouterからserviceへ移す。
  routerはsource/path検証、`BackgroundTasks`へのthumbnail生成登録、response変換だけを担当する。
- process内cacheはsource/pathごとに最大128件のLRUとして保持し、有効期間は30秒とする。
  cache entryは解決済みimages / thumbnails directoryと両directoryの`st_mtime_ns`をsignatureに含める。
- 有効期間内でもdirectory identityまたはsignatureが変わればcache missとして再走査する。
  thumbnail生成、rename、delete、generate完了の既知の書き込み経路では対象source/pathを明示的に無効化する。
- cache missの同一key走査はlock内で直列化し、cache hitでは書籍directory配下を走査しない。
  呼び出し側へはcopyを返し、cache entryを変更させない。
- thumbnail未生成のentryは従来どおり`thumbnail=null`で返してbackground生成を1回だけ登録する。
  生成失敗時も30秒後に再走査・再登録でき、失敗したnull entryを無期限に固定しない。
- `PdfListResponse`のfield、URL、並び順、image-only判定は変更しない。

#### `routers/pdfs.py:delete_pages` のソース別分岐
- `doujin`: `ImageService.delete_book_image_pages` を呼び、削除後は `pdf_generator.generate_thumbnail`（PIL ベース）で先頭画像から表紙を再生成。
- `comic` / `novel`: 従来通り `PdfService.delete_pages` を呼び、`ThumbnailService.generate_thumbnail`（fitz ベース）で表紙を再生成。
- 404 判定: `doujin` は `images/{book_name}/` ディレクトリが存在しないとき、`comic`/`novel` は PDF が存在しないとき。

#### `routers/pdfs.py:reorder_pages` のソース別分岐（B-3）
- `doujin`: `ImageService.reorder_book_image_pages` を呼び、再採番後の先頭 WebP から表紙を再生成。
- `comic` / `novel`: `PdfService.reorder_pages` を呼び、再構築後の PDF 先頭ページから表紙を再生成。
- 404 判定は `delete_pages` と同じ規則。
- バリデーション: `page_indices` の長さが現在の総ページ数と一致し、`[0..N-1]` の完全なパーミュテーションになっていることを `_validate_permutation` ヘルパーで先にチェックして 400 を返す（service 層に到達する前に拒否してエラーメッセージを明確化）。

#### `ThumbnailService` (`backend/services/thumbnail_service.py`)
- **役割**: **PDF からの**サムネイル画像生成（fitz ベース）。
- **主要メソッド**:
    - `generate_thumbnail(pdf_path, thumbnail_path, scale=0.5)`: PDF 先頭ページをスケール指定でレンダリングし JPEG 出力。
- **画像（WebP / JPEG / PNG）からのサムネイル生成は別関数**:
    - `services/pdf_generator.py:generate_thumbnail(image_path, output_path) -> bool` を使う（PIL ベース）。
    - 現行 PyMuPDF ビルドが WebP を読めない (`FileDataError`) ため、`doujin` ソース（image-only モード）の経路では fitz を使ってはならない。
    - 役割分担: **PDF → ThumbnailService（fitz）** / **画像 → pdf_generator.generate_thumbnail（PIL）**。
- **呼び出しパス**:
    - `routers/pdfs.py:delete_pages` / `merge_pdfs`: PDF 操作後の再生成 → fitz
    - `routers/thumbnails.py:_regenerate_one`: PDF があれば fitz、PDF 不在 + WebP のみなら PIL（image-only モード対応）
    - `routers/library.py:_list_from_images`: BackgroundTasks で WebP/PNG/JPG → PIL（全ソース共通）
    - `services/pdf_generator.py:_generate_outputs`: PDF 生成と同時に PIL で 1 枚目から作成

#### `GenreStore` (`backend/services/genre_store.py`)
- **役割**: ジャンルリストの読み書き・ソース別ロック管理を一元化。`routers/genres.py` が使用するインフラ層。
- **保存先**: `backend/data/meta2.db` の `genres` テーブル（Phase 64 で `data/genres/{source}.json` から SQLite WAL に移行）。
- **主要関数**:
    - `load_genres(source)`: ソース別ロックを取得して `genres` テーブルから読み込んで返す。テーブル未登録時は `_derive_from_meta` で初期リストを生成してから保存して返す。
    - `save_genres(source, genres)`: ソース別ロックを取得して `genres` テーブルに書き込む。
    - `_derive_from_meta(source)`: 初回ロード時の migration 用関数。`meta` テーブルの `genre` カラムを収集して名前順にソートした初期 list を返す。並び順は UI からの `PATCH /api/genres/reorder` で更新されるため、ここでは単純なソートに留める。
- **ロック**: `utils.locks.SourceLockManager` のインスタンスを保持し、source 単位で `load_genres` / `save_genres` を直列化する（読み書き双方をロック下で行うことで、初期生成中の不整合を防ぐ）。

#### `GenreAPI` (`backend/routers/genres.py`)
- **役割**: ジャンルリストの CRUD と並べ替えエンドポイント。
- **エンドポイント**:
    - `GET /api/genres?source=` → 順序付きジャンルリストを返す。
    - `POST /api/genres` → `{source, name}` でジャンルを追加。重複時は 409。
    - `DELETE /api/genres/{name}?source=` → ジャンルをリストから削除（書籍の `genre` フィールドは変更しない）。
    - `PATCH /api/genres/reorder` → `{source, genres}` で順序を更新（集合が一致しない場合は 400）。

#### `MetaStore` (`backend/services/meta_store.py`)
- **役割**: SQLite `meta2.db` の `books_meta` 読み書き・ソース別ロック管理を一元化する facade。`routers/meta/` のインフラ層。
- **型定義**:
    - `MetaEntry(TypedDict)`: `authors: list[str]` / `view_count?: int` / `last_viewed_at?: float` / `series_id?: str` / `series_title?: str` / `series_index?: float` / `hidden?: bool` / `genre?: str` / `read_state?: ReadState` / `volume?: int | None` / `publisher?: str` / `asin?: str` / `isbn?: str` / `release_date?: str`（任意フィールド。`series_index` は doujin/comic の小数巻用 float。`volume` は novel 向け整数巻番号）
    - `ReadState = Literal['unread', 'reading', 'done']` / `VALID_READ_STATES` 定数で列挙を一元管理
    - `MetaDict = dict[str, MetaEntry]`
- **主要関数**:
    - `get_lock(source)`: ソース別 `threading.Lock` を返す（`utils.locks.SourceLockManager` への薄いプロキシ）。
    - `load_meta(source)` / `save_meta(source, data)`: SQLite 行と `MetaDict` の相互変換。`save_meta` は全体同期用。
    - `make_key(path, name)`: `"{path}/{name}"` または `"{name}"` のキーを生成。
    - `update_meta_locked(source, updater)`: ロック取得→同一 transaction でロード→updater適用→差分行だけ反映するユーティリティ。
- **接続寿命**: `services.meta_db.db_connection()` が `commit/rollback` に加えて `close()` を保証する。APIごとに短命接続を使い、pool は持たない。
- **ロック**: `utils.locks.SourceLockManager` のインスタンスを保持。`MetaStore` と `GenreStore` は別インスタンスを持つため、両者のロックは独立する。

#### シリーズ手動編集 API (`backend/routers/series.py`)
- **役割**: 書籍を既存または新規シリーズに手動で割り当てる API。自動グループ化は撤去済み（2026-05-09、Phase 6）。
- **書き込み**:
    - `series_id`（共通プレフィックス + 作者をハッシュ化した安定 ID、`stable_series_id` で生成）/ `series_title` / `series_index`（`float`、小数巻 `2.5` 等に対応）を `meta2.db` に書き戻す。
- **API**:
    - `POST /api/series/assign` → 書籍に既存または新規シリーズを設定。`index` は `float` または `float[]`（配列指定で `names[i]` に `index[i]` を割り当てる、複数選択からの一括登録用）。
    - `POST /api/series/unassign` → 書籍をシリーズから外す。
    - `POST /api/series/reorder` → 同シリーズに属する書籍の `series_index` を `names` の順序で `1.0, 2.0, ...` に振り直す（DnD 並べ替え用）。`series_id` 不一致の書籍が混在すれば 400（中途半端な書き込みなし）。
- **`services/series_detector.py` のヘルパー（純関数）**:
    - `authors_key(authors)`: 作者集合を順序非依存のキーにする。
    - `stable_series_id(prefix, authors_key)`: シリーズ名 + 作者集合から安定 ID を生成。

#### `SeriesSuggester` (`backend/services/series_suggester.py`)
- **役割**: 既存シリーズへの紐付け候補をルールベースで提案する純関数群（A-1）。`POST /api/series/suggest` から呼ばれる。書き込み副作用なし。撤去された自動グループ化（Phase 6）の代替で、**「新規シリーズの発見」ではなく「既存シリーズへの追加候補」** に絞ることで誤検出（取りこぼし・誤登録名）を回避する。
- **マッチング戦略**:
    - 既存シリーズの `series_title` から末尾の巻数表記（数字 / 漢数字 / `vol.N` / `(上中下)`）を除いた本体で比較。
    - 各選択書籍タイトルとの **共通プレフィックス長 / min(タイトル長, シリーズ本体長)** をスコア化。
    - 全選択書籍の平均スコアを採用（複数冊が同一シリーズに属することを評価）。
    - 全書籍で作者集合が一致した場合のみ `AUTHOR_MATCH_BONUS=0.2` 加点。最大 1.0 にクランプ。
    - 閾値 `SUGGEST_MIN_SCORE=0.4` 未満は除外、スコア降順で `SUGGEST_MAX_CANDIDATES=5` 件まで返す。
- **主要関数**:
    - `suggest_series(meta, path, names) -> list[SuggestedSeries]`: メイン関数。
    - `_strip_volume_suffix(title)`: シリーズ表示名末尾の巻数表記を除去（純関数）。
    - `_aggregate_existing_series(meta)`: meta から既存シリーズを集計（series_id 単位）。
- **方針**: 自動実行しない。フロントエンドのダイアログから明示的に呼ばれた時のみ動く。

#### メタデータAPI (`backend/routers/meta/`)
- **役割**: 書籍メタデータ（作者名）の HTTP ハンドラのみを担う。ロジックは `MetaStore` に委譲。
- **エンドポイント**:
    - `GET /api/meta?source=` → `books_meta` の対象 source 全体を返す。任意の書籍キーに対する値は `BookMetaEntryOut` で具象型化し、未設定の任意フィールドはレスポンスから除外する。
    - `GET /api/meta/export?source=` → `books_meta` の対象 source を JSON としてダウンロード（`Content-Disposition: attachment`）。可搬バックアップ用。
    - `PATCH /api/meta` → `names`（ファイル名リスト）と `authors` / `hidden` / `genre` / `read_state` を受け取り、指定されたフィールドのみ更新。他は保持される。`hidden=true` で非表示化、`hidden=false` で再表示（フィールド削除）、`genre` は文字列で上書き（空文字でフィールド削除）、未指定なら変更しない。
    - `POST /api/meta/view` → 閲覧記録（`view_count` / `last_viewed_at` 更新、連打抑制 5 分）。

#### 閲覧回数 / 最近見た順ソート（バックエンド側）
- **保存先**: `meta2.db.books_meta` の `view_count` と `last_viewed_at`。NULL は読み込み時に未設定として扱う。
- **連打抑制**: `view_count` は前回 `last_viewed_at` から `VIEW_COUNT_DEBOUNCE_SEC = 300`（5分）以上経過した場合のみ +1 する。`last_viewed_at` は呼び出し毎に常に現在時刻で更新する（「最近見た順」ソートに反映するため）。
- **メタデータマージ規則**: `PATCH /api/meta`（作者更新）と `POST /api/meta/view`（閲覧記録）は互いに干渉しない。authors 更新時は既存の `view_count` / `last_viewed_at` を保持し、閲覧記録時は既存の `authors` を保持する。`authors` を空配列で更新した場合、他のフィールドが残っていれば `authors: []` で残し、何も残らなければエントリ自体を削除する。

#### 読書状態 (`read_state`)
- **保存先**: `meta2.db.books_meta.read_state`。NULL の既存エントリは `view_count` から派生（フロント側で 0→unread / >0→reading として扱う、バックエンドは値を返すだけ）。
- **自動遷移**: `POST /api/meta/view` で `view_count` が +1 されるとき（連打抑制でカウント据え置きの場合は除く）、既存 `read_state` が `'done'` でなければ `'reading'` に書き換える。`done` を維持するのは「読了済みの再読」を区別したいため。
- **手動遷移**: `PATCH /api/meta` の `read_state` フィールドで `'unread'` / `'reading'` / `'done'` 設定 or 空文字で削除。空文字削除後は再び `view_count` 由来の派生で扱われる（unread に戻すなら view_count を 0 にしないと派生で `reading` になる点に注意）。
- **最終ページ到達**: フロントエンドの `ReaderPanel` で `isAtLastSpread && readState !== 'done'` のときに 1 度だけ `PATCH /api/meta` で `done` に書き換える（多重発火は `useRef` でガード、選択 PDF が変わったらリセット）。詳細は [ライブラリ・リーダーUI設計](機能別/ライブラリ・リーダーUI設計.md)。
- **バリデーション**: `routers/meta.update_meta` で `meta_store.VALID_READ_STATES` に含まれない値（空文字以外）が来たら 400。`merge_entry_fields` の `read_state` パラメータは `None`（変更しない）/ `''`（削除）/ `'unread'|'reading'|'done'`（設定）の 3 系統。
- **API**:
    - `POST /api/meta/view` — body: `{ path: string, name: string, source: string }`。レスポンス `{ view_count: number, last_viewed_at: number, incremented: boolean }`。`incremented` は連打抑制に該当した場合 `false`。
    - `GET /api/meta` のレスポンスにも `view_count` / `last_viewed_at` が含まれる。

UI 側のソート挙動（`view_desc` / `recent_view`）は [ライブラリ・リーダーUI設計](機能別/ライブラリ・リーダーUI設計.md)を参照。

### Kindleキャプチャ連携

LinuxとWindowsをまたぐjob状態、heartbeat、package、シリーズ停止・再開条件は
[Kindle 購入カタログ設計 §7](機能別/Kindle購入カタログ設計.md#kindle-capture-contract)を正本とする。
Windows側のcapturer、controller、画像QA、package生成、限定復旧は
[`kindle-pdf/docs/detailed_design.md`](../../../kindle-pdf/docs/detailed_design.md)を参照する。
本書はbackendが所有するjob repository、package再検証、正式配置と補償だけを扱う。

#### Kindle capture job 契約 (`backend/services/kindle_catalog/capture_jobs.py`)
- **責務分割**: `capture_jobs.py`は互換facade、
  `capture_job_repository.py`は状態transaction、`capture_package_validator.py`は
  version 2 manifest・パス・サイズ・hash・画像復号・寸法の再計算、撮影完了証跡の内部整合、
  旧warning / overlay policy v1組と短時間右下通知を含むv2組の互換検証、
  `capture_registration.py`は完了workflowを調停する。
  `capture_registration_repository.py`は完了対象jobの取得と所有・状態確認、
  条件付き`awaiting_files → succeeded`更新を担当する。
  `capture_publication.py`はstaging copy、既存target退避、正式publish、meta更新、
  package archiveと逆順補償を担当し、catalog DBを直接参照しない。
- **状態**: 新規自動経路は `queued → claimed → locating_book → downloading（必要時）→ positioning → capturing → awaiting_files → succeeded`。旧 `waiting_user` 経路も段階導入互換として維持する。
- **作成排他**: `capture_job_repository.create()` は `BEGIN IMMEDIATE` 内で
  全source・全ASINの未完了jobが0件であることを確認してからINSERTする。
  runner側の事前確認とは独立した最終防衛線とする。
- **claim**: `BEGIN IMMEDIATE` と条件付き更新で 1 件だけ取得し、カタログ DB から ASIN、正式・正規化タイトル、著者、シリーズ、巻を `identity` に合成する。
- **heartbeat**: claim、状態更新、専用 heartbeat API で `heartbeat_at` を更新する。次回 claim 時に設定期限を超えた active job を `agent_heartbeat_timeout` で `failed` へ回収する。
- **時刻**: `started_at` は `capturing` 開始時、`completed_at` は `failed` / `succeeded` 確定時だけ設定する。
- **エラー**: agent 所有権と許可状態遷移を transaction 内で検証し、異なる agent、terminal job、逆向き遷移を拒否する。
- **補償**: 正式画像配置、`meta2.db`更新、packageの`processed/`移動、
  capture job成功更新の順に実行する。途中で失敗した場合は画像とmetaを戻し、
  packageを`.ready`へ復元してjobを`awaiting_files`のまま維持する。
  ready検証、staging copy、既存target退避、target publish、meta更新、package archive、
  job更新直前を障害注入境界とし、条件付きjob更新が1行以外の場合も同じ補償を行う。
- **再撮影置換**: 正式画像が既にある場合は、metaの同一`book_id`が同じASINを
  保持するときだけ置換を許可する。旧画像は
  `PIC2PDF_DATA_DIR/.capture-replacement-backup/<時刻>_<job短縮ID>/`へ世代退避し、
  新画像・meta・package・job更新の失敗時は旧画像を同じ正式パスへ戻す。
  同名でもASINが異なる、または既存metaでASINを確認できない場合は置換しない。

#### novel_db 書籍名の安全境界 (`backend/routers/novel_db/_deps.py`, `backend/services/novel_db/library.py`)
- `/api/novel_db/books/{book_name...}` 系の書籍名は共通依存関数で
  `validate_safe_name(book_name)` を適用し、区切り文字・ドライブ名・特殊名を 400 で拒否する。
- 書籍詳細が画像ディレクトリを参照する際は service 境界でも
  `resolve_under_base(KINDLE_NOVEL_IMAGES_DIR, book_name)` を通し、解決先が
  `KINDLE_NOVEL_IMAGES_DIR` 外へ出る場合は参照しない。

#### novel_db lexical検索境界 (`backend/services/novel_db/search.py`, `page_fts.py`)

- `search.py:lexical_search`がFTS5、shadow dual-read、LanceDB ICUを切り替える唯一の選択境界で、
  APIレスポンス型と後段RRFは変更しない。shadowはFTS5順位だけを利用者へ返す。
- `page_fts.py`はSQLite `pages`を正本として世代別ICU indexを構築し、SQLiteのactive世代と
  source世代が一致する場合だけ検索する。不整合・stale・LanceDB例外時は`search.py`がFTS5へ縮退する。
- 構築・shadow開始・rollbackの運用契約は
  [小説RAG 検索QA設計 §1.2](機能別/小説RAG_検索QA設計.md#rag-search-rollback)を正本とする。

#### Novel OCR job実行経路
- 現行queueは`job_worker.py` → `job_executor.py` → `ocr_job_application.execute_ocr_job()` → worker protocolの順で実行する。
- `extractor.py:run_ocr_subprocess`は互換的なbuilder経路に残るが、queue jobの正本入口ではない。
- `kindle-pdf/searchable_pdf.py`と`batch_ocr.py`は削除済みで、Searchable PDFは生成しない。
- 詳細なrun、QA、公開契約は[OCR設計書](機能別/OCR設計書.md)を正本とする。

### OCRエンジン

#### Surya OCR 2（主系）
- **役割**: `backend/services/novel_db/ocr_worker.py` から OpenAI 互換
  `llama-server` を呼び出し、縦書き小説をページ単位で OCR する。
- **実行形態**: `SURYA_INFERENCE_URL` の既存サーバーへ接続するか、
  `SURYA_LLAMA_SERVER_PATH` / `SURYA_MODEL_PATH` /
  `SURYA_MMPROJ_PATH` を使って worker がローカルサーバーを起動する。
- **品質制御**: 複数画像候補、ページ品質ゲート、yomitoku 独立照合、
  QA ステージングを経て、1 冊分が合格したときだけ公開テーブルへ確定する。

#### `YomitokuEngine` (`D:\61.tool\common\ocr\ocr_engine.py`、補助系)
- **役割**: `yomitoku` ライブラリを用いた独立再読、比較、
  後方互換 OCR。通常運用の主エンジンではない。
- **主要メソッド**:
    - `extract_text()`: 画像からテキストを抽出。段落判定または単語判定に分岐。
    - `_process_words()`: 単語情報の処理。thickness統一・aspect比判定・フリガナ除去・正規化。
    - `filter_ruby_text()`: ヒストグラム谷（valley）自動検出によるフリガナ除去。
    - `normalize_text()`: 3点リーダー・特殊記号の正規化。
- 詳細設計: [機能別/OCR設計書.md](機能別/OCR設計書.md)

#### GPT-5.6 Sol画像OCR（版管理付きcampaign）

- **役割**: 既存Surya主系を置換せず、固定manifestの原画像から独立したOCR候補を作り、
  legacyとの差と運用品質を全冊で評価する移行経路。
- **実行形態**: ChatGPTログイン済みCodex desktopで最大3 worker。認証cacheとDBをworkerへ渡さず、
  冊子単位artifactを検証して`ocr_runs` / `ocr_page_results`へ直列importする。
- **版管理**: canonical `pages`を合成legacy runへsnapshotし、`ocr_publications`の追記履歴で
  active runを管理する。昇格とrollbackは本文・FTS・書籍時刻を含む単一transactionとする。
- **品質境界**: 全ページ完全性、画像SHA、schema、反復・空本文、画像照合QAを満たす冊子だけを昇格する。
  legacy差分率はCERとみなさず、verified ground truthがある標本だけで精度を比較する。
- **再pilot契約**: 初回単一転記v1は監査専用とし、再開は独立候補A/Bと第三session checkerを束ねる
  v2 artifactに限定する。右→左のoverlap列帯転記と左→右coverage照合で列欠落をfail closedにし、
  manifest全標本が揃う前の部分import、campaign/promptを跨ぐrun再利用、legacyを見た候補選択を禁止する。
