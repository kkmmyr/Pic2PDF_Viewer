# Mac OCR 補助確認設計

> status: living | last-verified: 2026-09-05

Mac 専用 OCR アプリを、本番の Windows OCR パイプラインとは独立した
**第二 OCR・目視確認・比較評価手段**として検証するための方針を定める。

本書は将来評価の設計であり、現時点で特定アプリの採用や
`novel.db` への自動取り込みを決定するものではない。
本番 OCR の品質ゲート、QA、正式公開条件は
[OCR設計書](OCR設計書.md)を正本とする。

---

## 1. 目的と位置づけ

Mac OCR の目的は、次の補助確認を Windows 主系とは異なる実装で行うことである。

- 縦書き本文の列欠落、読み順の乱れ、ルビ混入、重複、幻覚の発見
- Windows の Surya OCR 2 / yomitoku と異なる誤り傾向の把握
- キャプチャ直後または公開前 QA でのページ単位スポット確認
- 将来、再現可能な第二 OCR として組み込めるかの評価

Mac OCR の結果だけで、`ocr_page_results`、`pages`、`pages_fts`、
LanceDB、`books.ocr_done_at` を更新してはならない。
正式公開には既存の run QA と承認フローを必須とする。

---

## 2. 計画との分担

候補製品、評価順序、購入・インストール判断は
[小説OCR品質改善 実装計画 §5](../../../log/計画/小説OCR品質改善_実装計画.md#mac-ocr-evaluation)を正本とする。
本書は、候補に共通する入力保護、比較方法、DB・公開境界、セキュリティ、runtime manifestの契約を持つ。
## 3. 評価コーパス

既存の OCR QA で画像照合済みの書籍から、20〜30画面を固定して使用する。
著作物の原画像・正解本文はリポジトリへコミットしない。

最低限、次のページ種別を含める。

1. 表紙・口絵・画像のみ
2. 前付け、目次、奥付
3. 通常の縦書き本文
4. ルビ、傍点、小書き仮名、固有名詞を含む本文
5. 複数列、短い独立列、会話中心のページ
6. 挿絵と本文が混在するページ
7. 疎ページ、章扉、広告、試し読み境界
8. 過去に列欠落、反復、人物名誤読が発生した難ページ

同じ入力画像の SHA-256 とキャプチャ画面番号を記録し、
アプリ間・再実行間で同一入力を比較する。

---

## 4. 評価手順

1. 原本 PNG を読み取り専用の入力として扱い、加工・上書きしない。
2. 各アプリで日本語を明示し、設定可能なら CJK 縦書きを指定する。
3. 1画面ごとの生 OCR テキストを、アプリ名・版・設定・実行日時とともに保存する。
4. OCR設計書の公開済み採用本文、固定正解、原画像の3者と照合する。
5. 読み順、欠落、重複、ルビ、固有名詞、句読点についてページ単位で記録する。
6. 同一設定で再実行し、出力の安定性を確認する。
7. 結果は評価レポートとして `docs/log/技術知見/` に要約し、
   生画像・全文 OCR 出力は Git 管理しない。

評価中の出力を本番 DB へ直接投入しない。
補正文として利用する場合も、既存の Codex 補正と同じく
原画像照合と run QA を経て採用する。

---

## 5. 評価指標

| 観点 | 確認内容 |
|---|---|
| 完走性 | 対象画面を欠番・クラッシュなしで処理できるか |
| 文字精度 | 固定正解がある画面の CER、固有名詞・助詞・小書き仮名の誤り |
| 完全性 | 列・段落・末尾の欠落、画像のみページへの本文幻覚 |
| 構造 | 縦書きの列順、複数列、目次、挿絵混在ページの読み順 |
| 反復 | 行・列・段落の重複生成 |
| ルビ | 本文への読み混入、親文字欠落 |
| 再現性 | 同一入力・同一設定で出力が安定するか |
| 運用性 | ページ対応、設定記録、バッチ処理、CLI、失敗箇所の追跡 |
| 機密性 | 完全ローカル処理か、外部送信の有無を明確にできるか |

主系を上回る平均精度だけを採用条件にしない。
主系と異なる欠落を安定して検出できるなら、第二 OCR として価値がある。

---

## 6. セキュリティとデータ取扱い

- OCR対象には著作物や成人向けコンテンツが含まれ得るため、
  **端末内処理を既定**とする。
- クラウド OCR、オンライン AI、外部アップロードは、
  送信先・保持期間・利用規約を確認し、ユーザーが明示的に許可した評価でのみ使用する。
- 生画像、全文 OCR、正解本文は Git、Issue、外部ログへ保存しない。
- アプリの診断送信・クラッシュレポート・同期機能も評価開始前に確認する。
- 一時出力は本番データディレクトリおよび `novel.db` から分離し、
  評価完了後に保持要否を判断する。

---

## 7. 非目標

- Mac を本番 OCR agent として直ちに採用すること
- Windows CUDA / Surya OCR 2 を置き換えること
- アプリの検索可能 PDF を小説 RAG の正本にすること
- OCR結果を無承認で公開・索引化すること
- 公称スペックだけで採用製品を決めること

---

## 8. 比較の成立条件

Mac単独のYomiToku/MPS実測が未取得のため、WindowsとMacの差をCUDA/MPS差へ帰属しない。
比較時は入力SHA-256、両環境のruntime manifest、同一条件での2回実行を必須とする。
run 185 / 186 / 190とWindows CPU/CUDA比較の記録は
[追加実測履歴（凍結）](../../../archive/検証/Mac_OCR補助確認_追加実測履歴_2026-09-05.md)を参照する。

Windows側の保存済み比較基準はrun 190を参照する。新たなMac比較では同一入力・設定・来歴の成立を再確認する。

次のMac YomiToku評価packageは、出力本文に加えて次を必須manifestとする。

- macOS・機種・SoC、Python、YomiToku、PyTorchのversion
- `mps` / `cpu`、device availability、推論精度と前処理設定
- OCR wrapper・model・pipelineのSHA-256とdirty状態
- 入力画面番号・画像SHA-256・処理成否
- 初期化、画面単位OCR、全体終了、QA、補正、package生成の各時刻
- 同一process条件での2回実行と正規化本文SHA-256

実測の詳細とWindows基準値は
[OCR品質改善 技術知見 §20](../../../log/技術知見/OCR品質改善_技術知見.md#ocr-yomitoku-cross-platform-20260829)
を参照する。
