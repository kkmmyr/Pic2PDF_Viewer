## 1. レイヤ構成

依存方向は原則として次の一方向とする。

```text
router / page
  └─ component
      └─ hook / feature
          └─ api client / query / utility / type
```

- `pages/`: URL単位の画面構成とページ固有のquery stateを担当する。
- `components/`: 表示と利用者操作を担当し、HTTP通信を直接実装しない。
- `hooks/`: 画面状態、派生計算、mutation調停を担当する。
- `features/`: 機能単位のAPI、Query Options、SSE、型変換、複数UIが共有する
  React非依存の状態計算を担当する。
- `config/api_client.ts`: 通常APIの共通Axios client。
- `types/api.d.ts`: OpenAPIから生成する型。直接編集しない。
- `utils/`: Reactへ依存しない純関数。

`@/`エイリアスを使用し、深い相対importを増やさない。barrel exportは公開境界に限定し、
循環importを作る再exportは行わない。

## 2. 状態の所有者

状態は寿命と共有範囲で配置を決める。

| 状態 | 所有者 | 例 |
|---|---|---|
| URLで再現・共有すべき状態 | React Router search params / path | source、選択書籍、検索、page、scope |
| サーバーが正本の状態 | TanStack Query | 書籍一覧、meta、OCR run、capture job |
| 画面をまたいで保持するUI状態 | Zustand | ライブラリの選択モード、現在path |
| 同一画面ツリーの高頻度状態 | Context selector | Reader、LibraryPanelの表示状態 |
| 一時入力・開閉・進行中表示 | component / custom hook | dialog入力、drag中page、SSE本文 |

同じ値をURL、Zustand、local stateへ二重保存しない。サーバー由来データを
`useState + useEffect`へコピーせず、Query cacheを参照する。

### Zustand

`stores/libraryStore.ts`はライブラリのUI状態だけを保持する。PDF一覧やmetaは保持しない。
サーバー更新後はQuery keyをinvalidateし、storeのversion値で再取得を模倣しない。

### Context selector

`LibraryPanelContext`と`ReaderContext`は、近接したcomponent群へ画面状態を渡す。
Readerは`use-context-selector`のフィールド単位selectorを使い、複数値を新しいobjectへ
まとめて返さない。購読していない状態の更新でページ描画を再renderさせないためである。

## 3. サーバー状態とAPI

### TanStack Query

- 一覧・詳細・検索・履歴は`useQuery`または`useInfiniteQuery`で取得する。
- Query keyは機能別Factoryを正本とし、文字列配列を利用側へ直書きしない。
- mutation成功後は影響するkeyだけをinvalidateまたは楽観更新する。
- 取得失敗を空配列へ変換しない。画面はerrorとemptyを区別する。
- 書籍やscopeの切替時はQuery functionへ渡される`AbortSignal`をHTTP clientへ引き渡す。

### HTTP client

通常APIは`config/api_client.ts`を使用する。長時間のPDF生成は
`config/generate_api_client.ts`、POST bodyを必要とするSSEは
`features/novel_db/sse.ts`などの専用境界を使用する。componentから直接`fetch`しない。

LibraryのAmazon CSV取込とmeta exportは`features/library/api.ts`をHTTP境界とし、
`useAmazonImport` / `useMetaExport`のTanStack mutationが実行状態と副作用順序を所有する。
`AmazonImportButton` / `ToolsMenu`は表示・event配線だけを行い、`apiClient`をimportしない。
Amazon取込レスポンスはOpenAPI生成`AmazonImportResponse`を正本とし、response interceptorが返す
本文をAxios responseの`.data`として二重unwrapしない。meta exportだけはOpenAPI上の本文型が
`unknown`のdownload responseであるため、API境界が`responseType='blob'`を指定して`Blob`へ狭める。

OCRのstatus / run / stopとQA / ground truthは`features/ocr/api.ts`をHTTP境界とする。
`useOcrStatus`はポーリングと表示用状態だけを所有し、`apiClient`を直接importしない。
runの単冊指定`target_dir`はOpenAPI契約どおりquery parameterで送り、request bodyに入れない。
status / run / stopの応答はOpenAPI生成`StatusResponse` / `OcrRunResponse` / `OcrStopResponse`を
`features/ocr/types.ts`から参照する。

Kindle capture品質warningは`features/kindle/api.ts`をHTTP境界とし、capture画面のQuery / Mutationが
未確認・確認済み・全件の取得と明示的な既読更新を所有する。候補ページはnovelでは既存の
`/novel/reader/:bookName?page=N`（`book_id`末尾の`.pdf`を除去）、comicでは
`/comic?file=:bookId&page=N`へ遷移する。
comic readerの初期pageは画像件数確定後に一度だけ適用し、通常の書籍選択・解除では検索parameterを
除去して別書籍へ引き継がない。ページを開く操作だけでは候補を確認済みにしない。

### OpenAPI型

`types/api.d.ts`は`npm run generate:types`で生成する。画面用の閉じたunionや、
生成schemaより厳しいUI契約が必要な場合だけ`types/`にadapter型を置き、生成型と
重複するinterfaceを理由なく増やさない。

## 4. コンポーネントとフック

### Page

Pageはルート引数、URL query、主要query hook、画面レイアウトを組み合わせる。
複雑な派生計算や副作用手順をPageへ直接置かず、hookまたはfeatureへ移す。

### Component

- `components/ui/`: 機能を知らない共通UI primitive。
- `components/library/`、`reader/`、`novel_db/`等: 機能固有の表示。
- Dialogは共通`Dialog` / `ConfirmDialog` shellを使用する。
- エラーは`sonner`または画面内`Alert`で表示し、`alert()` / `confirm()`を使わない。
- アイコンだけのbuttonには操作名を示す`aria-label`を付ける。

### Hook

- hookは1つの状態機械、派生計算、または副作用境界を担当する。
- 画面全体の調停hookはleaf hookの呼び出しと結果の組み立てに限定する。
- OCR QAは`useOCRQaController`がrun/page選択、Query、mutation、入力状態を所有し、
  `OCRQaPanel`は表示とイベント配線だけを担当する。
- OCR実行パネルは`useOcrStatus`が2秒ポーリングとrun / stop操作を所有し、
  すべてのHTTP呼出しを`features/ocr/api.ts`に委譲する。
- Kindleは`features/kindle/`がOpenAPI型alias、API関数、query key、用途別Query/Mutation、
  catalog/capture/import/link各screenを所有する。`pages/Kindle*.tsx`はfeature shellの
  compositionだけを行う。旧`hooks/useKindleCatalog.ts`と`types/kindleCatalog.ts`は
  workspace内参照が0件であることをKnipとimport検索で確認したため撤去済み。
- Libraryは`useLibraryPanel`を公開facadeとし、rename・thumbnail・一覧invalidateは
  `useLibraryBookActions`、dialog/selection/filter/displayは既存domain hookが所有する。
- Libraryの手動toolは`useAmazonImport` / `useMetaExport`がmutation中の二重送信防止を所有する。
  前者は`novel` / `comic`を独立実行して成功分を集約し、後者は取得したBlobを従来命名規則でdownloadする。
- Novel DBのSSEは`sse-transport.ts`がHTTP/stream frame、`qa-sse.ts`、`chat-sse.ts`、
  `discussion-sse.ts`がdomain event変換を所有する。旧`sse.ts`はproduction/test参照0を
  確認して撤去済みで、新規importは用途別moduleを直接参照する。
- 同じ副作用を複数componentへ実装しない。
- 純粋なページ計算、sort、正規化は`utils/`または機能別の純関数へ置く。

ファイルごとの非自明な役割は
[ファイルマップ §2](詳細設計書_フロントエンド_ファイルマップ.md#2)を参照する。

## 5. 共通UI規約

### セマンティックトークン

Tailwindの色名を用途ごとに混在させず、次を使用する。

- `primary-*`: 主CTA、navigation、主要選択。
- `accent-*`: grouping、active mode、補助的な選択。
- `success-*`: 成功。
- `red-*`: 破壊的操作・error。
- `amber-*`: warning、お気に入り、選択中カード。

z-indexはTailwind v4の`frontend/src/index.css`にある`@theme`の`--z-*`と
`@layer utilities`の
`z-card-badge`、`z-floating-action`、`z-overlay-bar`、`z-header`、`z-global-navigation`、`z-toast`、
`z-dialog`、`z-dialog-nested`を使う。任意値の`z-[...]`を追加しない。

### Button

`components/ui/button.tsx`の`variant × size`を使う。

- `primary`: 実行・確定。
- `secondary`: 中立・取消・mode off。
- `danger`: 削除など回復困難な操作。
- `ghost`: toolbarのアイコン操作。

Dialog footerは`DialogPrimaryButton` / `DialogCancelButton`を使い、通常Buttonとの
padding差を利用側で再実装しない。

### AlertとDialog

- API取得失敗、validation、emptyを同じ表示にしない。
- DialogはEsc、閉じるbutton、必要に応じて外側clickの扱いを明示する。
- 破壊的操作は`ConfirmDialog danger`を経由する。
- mutation中は確定buttonをdisabledにし、二重送信を防ぐ。

### light / dark

`useDarkMode`とReact mount前のinline scriptで`html.dark`を同期し、初期flashを防ぐ。
native form controlも含めるため`html.dark`へ`color-scheme: dark`を設定する。

## 6. Routingと画面構成

`router.tsx`はdata routerを使用し、各routeに`errorElement`を設定する。
`RouteErrorPage`はloader/lazy routeの失敗、`ErrorBoundary`は描画中例外を担当し、
両者を統合しない。

主要画面:

- `/doujin`、`/comic`、`/novel`: ライブラリと画像/PDF reader。
- `/novel/db`、`/novel/detail`: 小説DB検索・QA・書誌管理。
- `/novel/manage`: OCR / build job管理。
- `/kindle/catalog`、`/kindle/links`、`/kindle/capture`、`/kindle/imports`:
  Kindle通常運用。

sourceはURL pathから`doujin | comic | novel`へ導出し、別storeへ複製しない。

### グローバルナビゲーション

`GlobalNavigation` がルートと表示名の対応を一元管理し、`Layout` はreader表示時の非表示判定と
ページ本体の構成だけを担当する。

- PC（`lg`以上）は同人誌・小説をカテゴリ別ドロップダウン、漫画・購入書籍を直接リンクとして表示する。同人誌にはライブラリ・取り込み・新着、小説には書籍DB・読書会・関係グラフ・管理を配置する。
- Kindleの画像紐付け・キャプチャ・取込管理は既存のKindle内サブナビゲーションを正本とし、グローバルナビゲーションからは購入書籍へ遷移する。
- モバイル（`lg`未満）はブランド、カテゴリ名と画面名、ハンバーガーボタンを1行に表示する。ドロワーはカテゴリ別に全グローバル導線、設計書リンク、ライト／ダークモード切替を表示し、リンク選択、背景選択、`Escape`で閉じる。テーマ切替後もドロワーは開いたままとし、連続操作と表示確認を妨げない。
- 現在地はURL pathから導出し、PCではヘッダー下の補助行、モバイルではヘッダー内にカテゴリ名と画面名を併記する。現在のリンクには`aria-current="page"`を付与する。
- メニューとドロワーの開閉ボタンは`aria-expanded` / `aria-controls`を持ち、主要操作の高さ・幅は44px以上、キーボードフォーカスはringで明示する。
- グローバルナビゲーションは横スクロールを使用しない。reader表示中は従来どおりグローバルヘッダー全体を非表示にする。

## 7. エラー・loading・empty

画面は最低限、次を区別する。

1. 初回loading
2. 再取得中（既存表示を維持）
3. empty
4. error + 再試行
5. mutation中のdisabled
6. 部分成功または失敗項目あり

ルート例外、React描画例外、APIエラー、SSE error eventを同じ経路で処理しない。
利用者が再試行できるか、入力を修正すべきか、管理者確認が必要かを表示する。

## 8. アクセシビリティ

個人LANの単一利用者向けだが、標準HTMLのkeyboard操作を壊さないことを最低基準とする。

- 入力中はglobal shortcutを抑制する。
- Dialogの閉じるbutton、アイコンbuttonへaccessible nameを付ける。
- `Alert`は必要な場面で`role="alert"`を持つ。
- 色だけで状態を区別せず、textまたはiconを併用する。
- iPad相当幅では閲覧を優先するが、端末種別による機能禁止は行わない。

フォーカストラップ、landmark、`eslint-plugin-jsx-a11y`の全面導入は、利用要件が
拡大した時点でバックログとして要件を確定する。

## 9. 変更時の確認

- ファイル追加・移動後にファイルマップを再生成する。
- API型変更時にOpenAPIと`api.d.ts`を再生成する。
- URL state変更時はreload、共有URL、戻る・進むを確認する。
- server state変更時はloading、empty、error、retry、disabledを確認する。
- reader変更時はLTR/RTL、single/spread、先頭/末尾、keyboard/touchを確認する。
- desktop、iPad相当幅、light/darkを確認する。
