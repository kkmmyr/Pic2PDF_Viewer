# セキュリティ設計書

> status: living | last-verified: 2026-08-02

本アプリケーションのセキュリティ設計の根拠・防御範囲・制限をまとめる。

---

## 1. 信頼モデル

本アプリケーションは**ローカルホスト専用のシングルユーザーツール**。

- **想定環境**: `localhost:8766` (API・dev) / `localhost:5176` (UI・dev) / `localhost:8090` (リリース統合) をローカル PC で使用する
- **想定攻撃者**: 外部ネットワークからの不正アクセス、または悪意あるウェブページからの CSRF
- **想定外**: マルチユーザー認証、データの暗号化保存、監査ログ

> 認証・認可機能は実装していない。LAN 外に公開することを想定していないため、必要になった場合は別途設計が必要。

## 2. バックエンド セキュリティ

### 2-1. CORS

**ファイル**: `backend/main.py` / `backend/config/__init__.py`

```python
# デフォルト許可オリジン
_default_origins = "http://localhost:5176,http://127.0.0.1:5176"
CORS_ORIGINS = os.environ.get("ALLOWED_ORIGINS", _default_origins).split(",")
```

- `localhost` / `127.0.0.1` のみ許可（ポート 5176 = フロント開発サーバー）
- 環境変数 `ALLOWED_ORIGINS` で上書き可能（LAN 内共有等の拡張時）
- `allow_methods=["*"]` は CORS ヘッダーの制御用であり、実際の認可ではない

### 2-2. パストラバーサル防止

**ファイル**: `backend/utils/path_utils.py`

ファイル I/O を行うエンドポイントではユーザー入力パスを検証し、
データディレクトリ外へのアクセスを防ぐ。既存経路の例外は下記に明示する。

| 関数 | 防御対象 | 拒否する入力例 | 拒否しない入力例（誤検出回避） |
|---|---|---|---|
| `validate_safe_path(path)` | ディレクトリトラバーサル | `..`, `../etc/passwd`, `foo/../bar`, `/etc/passwd`, `\\server\share`, `C:/Windows`, `C:\\Windows` | `わたし...変えられちゃいました.pdf` 等、`..` を成分として含まないファイル名 |
| `validate_safe_name(name)` | パスセパレータを含む名前 / 特殊成分名 | `..`, `.`, `folder/file.pdf`, `..\\foo` | `..secret`, `My....pdf` 等、名前自体が `..` / `.` ではない文字列 |
| `resolve_under_base(base, path)` | データルート外への解決（symlink を含む） | drive 絶対パス、root 外を指す symlink | `base` 自身とその実在・未作成の子孫 |

**検証ルール (`validate_safe_path`)**:
- パスを `/` または `\\` で分割し、**いずれかの成分が `".."` と完全一致** → `HTTP 400`
- `"/"` で始まる → `HTTP 400`（Unix 絶対パス）
- `"\\"` で始まる → `HTTP 400`（Windows UNC パス）
- Windows drive を持つ（`C:/...` / `C:\\...` / `C:relative`）→ `HTTP 400`
- 正規化: バックスラッシュをスラッシュに統一して返す

ファイル I/O の直前には `resolve_under_base(base, path)` を使う。入力を検証してから
`Path.resolve()` し、解決結果が `base.resolve()` 配下であることを `Path.is_relative_to()`
で確認する。これにより文字列上は相対パスでも、データルート内の symlink を経由して
外へ出るケースを拒否する。

> **設計判断**: `".."` を部分文字列で検出する単純実装はファイル名中の三点リーダ的な `...`（連続 3 ドット）を誤検出するため採用しない。OS が `..` を特別扱いするのは「パス成分として `..` 単独」のときだけであり、`foo..bar` や `わたし...` は OS にとってただの名前で安全。

**検証ルール (`validate_safe_name`)**:
- 名前が `"."` または `".."` と完全一致 → `HTTP 400`（カレント／親ディレクトリ参照を防止）
- `"/"` または `"\\"` を含む → `HTTP 400`（パスセパレータ混入を防止）

**適用箇所**: `routers/library.py` / `routers/meta/` パッケージ（`core.py` / `novel.py` / `admin.py`） / `routers/pdfs.py` / `routers/thumbnails.py` の全パラメータ受け取り箇所。読書会履歴の `book_name` は単一ディレクトリ名として `validate_safe_name()` し、`DISCUSSIONS_DIR` 配下へ `resolve_under_base()` する。`routers/genres.py` の `DELETE /genres/{name}` も `validate_safe_name(name)` を呼ぶ。

`routers/novel_db/` の書籍名パスは共通依存関数で `validate_safe_name()` を適用する。
書籍詳細で画像ディレクトリを組み立てる際は、さらに service 境界で
`resolve_under_base(KINDLE_NOVEL_IMAGES_DIR, book_name)` を通し、symlink 解決後も
基準ディレクトリ配下にある場合だけ参照する。

### 2-3. ファイル種別チェック

**ファイル**: `backend/utils/file_utils.py`

`config.py` で許可する拡張子を一元管理し、直書きチェックを禁止。

```python
is_pdf_file(name)   # .pdf
is_webp_file(name)  # config.SUPPORTED_WEBP_FORMAT
is_zip_file(name)   # config.SUPPORTED_ZIP_FORMAT
is_image_file(name) # config.SUPPORTED_IMAGE_FORMATS
```

任意ファイルを処理対象に混入させる攻撃に対する防御。

### 2-4. meta2.db 更新のアトミック性

**ファイル**: `backend/services/meta_store.py`

`update_meta_locked(source, updater)` は source 別ロックと SQLite transaction の updater
パターンで実装する。接続は close を保証する context manager で短命に扱い、変更・追加・
削除された行だけを同一 transaction で反映する。

Hitomi検出履歴も同じ `meta2.db` の `hitomi_arrivals` テーブルへ保存する。監視スクリプトの
追加処理と FastAPI の既読更新は短命接続・WAL・transaction を使用し、JSON 全体の
read-modify-write で発生し得たプロセス間の上書き競合を避ける。`gallery_id` を主キーにした
`INSERT ... ON CONFLICT DO NOTHING` により、監視の再実行と旧JSON移行を冪等にする。
旧JSONのmtime・サイズは `hitomi_legacy_imports` に記録し、変更時だけ再取り込みする。

### 2-5. ZIP 解凍上限（zip bomb 対策）

**ファイル**: `backend/config/__init__.py` / `backend/services/pdf_generator.py`

`doujin` ソースの ZIP 入力に対する DoS 対策。`process_zip()` は ZIP を開いた直後・解凍前に `_check_zip_safety(webp_infos, zip_filename)` を呼び、以下の上限を超える場合は ValueError を投げてジョブの `failed_items` に集約する。

| 定数 | 値 | 意味 |
|---|---|---|
| `ZIP_MAX_ENTRIES` | 5000 | ZIP 内 WebP エントリ数の上限 |
| `ZIP_MAX_PER_FILE_BYTES` | 50 MB | 1 エントリあたりの解凍後サイズ上限 |
| `ZIP_MAX_TOTAL_UNCOMPRESSED_BYTES` | 2 GB | 全エントリの解凍後サイズ合計上限 |

値は **個人ツールの想定範囲（〜1000 ページ × 〜500KB WebP ≒ 500MB / 1 冊）に余裕を持たせた**もの。超過は事実上不正な ZIP（zip bomb）か、想定外の大規模入力なので一律拒否する。

拒否時は `logger.warning("Security: ZIP rejected (<filename>) — <reason>", ...)` で**監査用ログ**を残す。一般的な I/O 失敗（`logger.error("Failed to generate PDF for ZIP %s ...", ...)`）と異なる接頭辞 `Security:` で出力するため、ログ走査時に区別できる。ログは [`backend/data/logs/app.log`](../../../backend/data/logs/) にファイル永続化されるため（[ADR-0006](../基本設計/ADR/0006_backend-log-file-persistence.md)）、ターミナルを閉じても監査痕跡が残る。

ZipSlip 対策は `os.path.basename(image_name)` で抽出パスを書籍ディレクトリ直下に正規化することで担保（`zf.extract()` は使わない）。

### 2-6. 監査ログとパス情報の取り扱い

**ファイル**: `backend/services/pdf_generator.py` /
`backend/services/novel_db/extractor.py`

ZIP の拒否・完了・失敗ログにはファイル名を使用し、ZIP 内エントリも
`os.path.basename(...)` で正規化する。OCR の進捗 API は書籍名・工程・ページ番号を
返し、OCR Python や一時 manifest の絶対パスをレスポンスへ含めない。

一方、障害解析用の `app.log` には出力先などローカル絶対パスが記録される場合がある。
このログは管理者用データとして扱い、画面共有・外部送付時はユーザー名、
ドライブ構成、書籍名を確認してマスクする。Discord 等へ `app.log` 全文を
自動転送しない。

### 2-7. Kindle キャプチャ受信箱

- Windows エージェント API は `X-Capture-Agent-Token` を定数時間比較し、トークン未設定時は 503 で無効化する。
- Windows OCR agentも同じ共有トークン契約を使い、`OCR_AGENT_ENABLED`が明示された場合だけ有効化する。画像取得はclaim済みjobのmanifest内ページに限定し、任意パスを受け取らない。ページ結果は書籍名・画面番号・画像SHA-256・agent所有権を照合してからLinux側DBへ保存し、WindowsからSQLiteを直接共有しない。
- Windows が書き込む Kindle 成果物は `KINDLE_CAPTURE_INBOX_DIR` で指定した
  論理専用受信箱だけに置く。既存環境では書き込み可能な
  `pic2pdf-input` 共有内の隠しディレクトリを再利用するが、
  `DoujinWatcher` の対象から除外する。`comic/images` /
  `kindle_novel/images` の正式領域は共有しない。
- Linux は `<job UUID>.ready` だけを処理し、manifest の job ID・ASIN・source と DB ジョブを照合する。
- 画像名は単一ファイル名と許可拡張子に限定し、symlink、パス区切り、未知ファイル、件数・単体容量・合計容量超過、SHA-256 不一致を拒否する。
- 検証済み画像は正式領域と同じファイルシステムの staging へコピーし、atomic rename 後に `meta2.db` と job 状態を更新する。既存同名書籍は上書きしない。
- agent 完了後の package は `processed/` へ移し、障害調査用に保持する。

### 2-8. SolによるOCR後処理の外部送信境界（計画）

[ADR-0018](../基本設計/ADR/0018_sol-primary-post-ocr-generation.md)の段階導入では、
ユーザーが書籍単位で明示的に許可した場合だけ、OCR承認済み本文をMac上のCodex CLIから
GPT-5.6 Solへ送信する。既定は無効とし、固定パイロット合格までは公開DBへ自動確定しない。

- 送信対象は`index_eligible=1`のOCR本文、書名、ページ番号、正規名台帳、状態契約に限定する。
- 原画像、PDF、ASIN、ローカル絶対パス、DB接続情報、Tailscale情報、既存認証情報を送信しない。
- ChatGPT側のモデル改善利用オフを運用前提とするが、アプリが設定状態を検証できるとはみなさない。
- Sol runnerはChatGPTログイン済みMacで動かし、Linuxサーバーへ`~/.codex/auth.json`をコピーしない。
  認証キャッシュはパスワード相当として扱い、Git、ジョブ成果物、ログ、バックアップへ含めない。
- `codex login status`がChatGPT認証であることを実行前に確認する。APIキー認証時は従量課金経路となるため、
  サブスクリプション前提ジョブを開始せず、APIへ自動切替しない。
- Codexはread-only sandbox、新規ephemeral session、外部検索・MCP不要の隔離プロファイルで実行する。
- LinuxとMacの入力パッケージ転送はTailscale内のSSH/SCP等の保護された経路を使い、import時に
  書名、ページ集合、OCR本文SHA-256をサーバー側で再照合する。
- 入力OCRのMac側stagingは成功・不採用後の既定7日で削除し、ハッシュ、候補、検査、使用量、承認記録を残す。
- ZDR、保存期間、データ所在地、SLAの保証が必要になった場合はサブスクリプション経路を流用せず、
  管理されたAPI組織またはEnterprise設定を別途設計する。

## 3. フロントエンド セキュリティ

### 3-1. ファイル名バリデーション

**ファイル**: `frontend/src/utils/validation.ts`

```typescript
export const FORBIDDEN_FILENAME_CHARS = /[/\\:*?"<>|]/;
```

Windows / macOS / Linux 共通の禁止文字を除外。各ダイアログで個別に正規表現を再定義しない（`validateFilename(value, kind)` を共有）。

### 3-2. XSS 防止

- React の JSX は文字列をデフォルトでエスケープするため、通常の文字列表示での XSS は発生しない
- `dangerouslySetInnerHTML` は原則禁止。唯一の例外は検索 snippet で、バックエンドが
  `html.escape()` 後に `<mark>` / `</mark>` だけを復元した値を `SearchHitItem` が描画する
- PDF ファイル名・メタデータを未サニタイズのまま `innerHTML` に渡す箇所はない

### 3-3. ダイアログの標準化

`confirm()` / `alert()` は使用禁止（`coding_conventions.md` 参照）。
共通コンポーネント `components/ui/confirm-dialog.tsx` を使用することで、ユーザー操作の一貫性とフィッシング的な悪用を防ぐ。

## 4. 依存関係のセキュリティ

### 自動ゲート

- **シークレット検査**: pre-commit は公式 `gitleaks` フックを固定バージョンで実行し、commit 対象の秘密情報を検出する。GitHub Actions でも `gitleaks/gitleaks-action` を実行し、ローカルフックを迂回した push / PR を検査する。
- **フロントエンド依存監査**: frontend CI の `npm ci` 後に `npm audit` を実行し、既知脆弱性があれば job を失敗させる。
- **Python依存監査**: backend CI の `uv sync` 後に `backend/tools/dependency_audit.py` を実行する。内部では `uv audit --locked` を呼び、`security/uv-audit-allowlist.toml` の期限・理由付き例外だけを許容する。期限切れ例外は監査実行前に失敗させる。

例外は「修正版へ即時更新できない互換性上の理由」がある場合のみ登録し、パッケージ・脆弱性ID・期限・理由を必須とする。期限更新だけで延命せず、期限到来時に実機互換性を再評価する。

### 監査手順

```bash
# /audit コマンドで一括実行
cd frontend && npm audit
cd backend && uv run python -m tools.dependency_audit
```

### 判断基準

| 重大度 | 対応 |
|---|---|
| critical / high | 速やかに対処（`npm audit fix` または手動更新） |
| moderate | dev dependency 由来かを確認し、本番影響なければ放置可 |
| low | 原則放置（次回更新時にまとめて対応） |

## 5. 将来の拡張時の注意

- **LAN 公開**: `ALLOWED_ORIGINS` に加え、認証機能（Basic 認証 or トークン）の追加を検討
- **ファイルアップロード機能追加**: Content-Type 検証とファイルサイズ上限の実装が必要
- **外部 API 連携拡張**: API キーを環境変数で管理し、ソースコードにハードコードしない
