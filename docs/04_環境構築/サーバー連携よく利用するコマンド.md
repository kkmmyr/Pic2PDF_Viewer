# サーバー連携 よく利用するコマンド

Git Bash (Windows) から実行するコマンドを用途別にまとめる。
前提: Tailscale が起動していること、SSH 鍵認証が設定済みであること。

---

## データ同期 (`sync_to_linux.sh`)

```bash
# Windows でメタ情報（ジャンル・作者・シリーズ）を編集した後
bash sync_to_linux.sh db

# 同人誌の新刊を追加した後（画像 + サムネイル + DB）
bash sync_to_linux.sh doujin

# 漫画の新刊を追加した後
bash sync_to_linux.sh comic

# 小説の新刊を追加した後
bash sync_to_linux.sh novel

# 全カテゴリ一括（時間がかかる）
bash sync_to_linux.sh all
```

> **⚠️ 注意**: Windows でジャンル・シリーズ・作者を設定したら、必ず `db` を実行すること。  
> 実行しないと Linux の meta.db が古いままになり、フィルターから書籍が除外される。

---

## アプリコードデプロイ (`deploy_to_linux.sh`)

```bash
# フロントビルド → コード転送 → サービス再起動 を一括実行
bash deploy_to_linux.sh
```

処理内容:
1. `frontend/` を `npm run build`
2. `backend/`（.venv / data / complete 等を除外）を tar+ssh 転送
3. `frontend/dist/` を転送
4. `deploy/` (nginx / systemd 設定) を転送
5. Linux 側で `sudo systemctl restart pic2pdf-viewer`

---

## Linux サービス管理（SSH 接続後）

```bash
# サービス状態確認
sudo systemctl status pic2pdf-viewer

# サービス再起動
sudo systemctl restart pic2pdf-viewer

# リアルタイムログ（Ctrl+C で終了）
sudo journalctl -u pic2pdf-viewer -f

# 最新 50 行のログ
sudo journalctl -u pic2pdf-viewer -n 50
```

---

## Windows サービス管理

```bat
rem リビルド後のサービス再起動（PowerShell または cmd）
restart_service.bat

rem サービス状態確認
sc query Pic2PDFViewer
```

## 動作確認

```bash
# Linux API が応答するか確認（SSH 不要、ブラウザでも可）
curl http://100.107.238.88:8090/api/pdfs?source=doujin | python3 -c "import sys,json; d=json.load(sys.stdin); print('books:', len(d['files']))"

# meta.db の特定書籍を確認
ssh amashio@medaroserver 'python3 -c "
import sqlite3
con = sqlite3.connect(\"/opt/pic2pdf-viewer/data/meta.db\")
rows = con.execute(\"SELECT book_id, genre, series_title FROM books_meta WHERE book_id LIKE \\\"%キーワード%\\\"\").fetchall()
for r in rows: print(r)
"'
```

## よくある作業フロー

### 新刊を追加した

```bash
bash sync_to_linux.sh doujin   # または comic / novel
```

### Windows で書籍にメタを付けた

```bash
bash sync_to_linux.sh db
```

### コードを修正・機能追加した

```bash
bash deploy_to_linux.sh
```

### 全部まとめて同期（週次など）

```bash
bash sync_to_linux.sh all
bash deploy_to_linux.sh        # コード変更があれば
```
