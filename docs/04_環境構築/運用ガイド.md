# 運用ガイド

本アプリケーションの日常運用・定期メンテナンス・トラブル対処をまとめたリファレンス。

---

## 1. アプリケーション起動・停止

### 起動

```bash
# バックエンド（ポート 8000）
cd backend
uv run uvicorn main:app --reload

# フロントエンド（ポート 5173）
cd frontend
npm run dev
```

`--reload` は開発時のみ有効（ファイル変更を自動反映）。本番相当で動かす場合は外す。

### 停止

各ターミナルで `Ctrl+C`。

## 2. バックアップ

### 対象ディレクトリ

| パス | 内容 | 復元困難度 |
|---|---|---|
| `backend/data/generated/` | 生成済み PDF | 高（再生成に時間がかかる） |
| `backend/data/kindle/` | Kindle キャプチャ画像 | 高（再キャプチャが必要） |
| `backend/data/novel/` | 小説 PDF | 高（手動配置ファイル） |
| `backend/data/*/meta.json` | 書誌メタデータ | 高（手動入力データを含む） |

> `backend/data/` 全体は `.gitignore` 対象。**git には保存されない。**

### 推奨バックアップ方法（robocopy）

```powershell
# OneDrive への同期コピー（差分のみ）
robocopy "D:\61.tool\Pic2PDF_Viewer\backend\data" `
    "C:\Users\<user>\OneDrive\Backup\Pic2PDF_data" `
    /MIR /FFT /Z /NP /LOG:"C:\temp\robocopy_pic2pdf.log"
```

- `/MIR`: ミラーリング（削除ファイルも同期）
- `/FFT`: FAT ファイルシステムタイムスタンプ許容（OneDrive 対策）
- `/Z`: 再起動可能モード（大容量ファイル向け）

### タスクスケジューラへの登録（週次自動実行）

1. タスクスケジューラを開く（`taskschd.msc`）
2. 「基本タスクの作成」→ 週次 → 上記コマンドを PowerShell で実行
3. 「最上位の特権で実行する」にチェック

## 3. 定期メンテナンス

### セキュリティ監査（月 1 回程度）

```bash
# まとめて実行（/audit コマンドでも可）
cd frontend && npm audit
cd ../backend && uv audit
```

- `npm audit fix` で解決可能な脆弱性は即適用
- `uv audit` は experimental（警告は無視してよい）

### 依存パッケージ更新

```bash
# フロントエンド（パッチ・マイナー更新）
cd frontend && npm update

# バックエンド
cd backend && uv lock --upgrade
```

更新後は必ずテストを実行: `/test`

## 4. SearXNG レート制限への対処

サークル名自動登録を大量実行（目安: 20 件以上）すると、SearXNG の上流検索エンジンが
レート制限・CAPTCHA ブロックを受け、全件「作者不明」が返るようになる。

### 症状確認

```bash
curl "http://localhost:8080/search?q=test&format=json" | jq .unresponsive_engines
```

`"一時停止"` や `"CAPTCHA"` のエントリがあれば制限中。

### 対処

| 対処 | 詳細 |
|---|---|
| **待機（推奨）** | 数時間〜1 日で自動解除。解除後に「作者不明」エントリは自動再試行される（`overwrite=false` 設定） |
| **待機時間延長** | `backend/routers/meta.py` の `time.sleep(5.0)` を 10〜30 秒に延長 |
| **分割実行** | 一度に全件実行せず、20〜30 件ずつ日を分けて実行 |

> 将来の改善案: 汎用検索エンジンの代わりに DLsite を直接クエリする方式への移行（精度・安定性が向上する見込み）。

## 5. よくあるトラブルシューティング

### バックエンドが起動しない

| 症状 | 原因 | 対処 |
|---|---|---|
| `Address already in use` | 旧プロセスが残っている | `netstat -ano \| findstr :8000` でPID確認後 `taskkill /PID <pid> /F` |
| `ModuleNotFoundError` | venv 未構築または壊れている | `cd backend && uv sync --group dev` |
| `VIRTUAL_ENV` 警告 | 別の Python 環境が有効 | 無視してよい（uv が `.venv/` を優先使用） |

### フロントエンドが起動しない

| 症状 | 原因 | 対処 |
|---|---|---|
| `EADDRINUSE` (port 5173) | 旧プロセスが残っている | タスクマネージャーで node.exe を終了 |
| `Cannot find module` | `node_modules` が壊れている | `cd frontend && rm -rf node_modules && npm install` |

### PDF 生成が完了しない

1. ブラウザの「生成中」表示を確認（バックグラウンドジョブは完了まで続く）
2. バックエンドのターミナルログでエラーを確認
3. `backend/data/<source>/` に画像ファイルが存在するか確認

### Discord 通知が届かない（Remote Control 連携）

詳細は [`RemoteControl_Discord通知設定.md`](RemoteControl_Discord通知設定.md) を参照。
`echo $DISCORD_WEBHOOK_URL` で Webhook URL が設定されているか確認する。
