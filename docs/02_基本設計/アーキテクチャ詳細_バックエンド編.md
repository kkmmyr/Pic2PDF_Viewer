## データディレクトリ構造 (backend/data/)

```
data/
├── main/
│   ├── images/          ← 元WebP画像（書籍一覧の走査元・/images で配信）
│   ├── thumbnails/      ← サムネイル（/thumbnails で配信）
│   ├── pdfs_compressed/ ← `POST /api/batch_compress` の出力先（任意機能、配信なし）
│   └── complete/        ← 処理済みZIP/フォルダ
├── kindle/
│   ├── pdfs/ / thumbnails/ / images/
├── kindle_novel/
│   ├── pdfs/ / thumbnails/ / images/
└── meta/                ← 書籍メタデータ（作者名・タグ・シリーズ等）
    ├── generated/meta.json
    ├── kindle/meta.json
    └── novel/meta.json
```

**注意:**
- `generated` ソースは **image-only モード**で運用する。書籍一覧は `images/` 配下のサブディレクトリを走査して構築するため、`pdfs_compressed/` 内の PDF は閲覧経路では使用しない（バッチ圧縮 API の出力先として残存）。
- `/pdfs` 静的マウントは廃止済み（main.py 参照）。`/thumbnails` / `/images` / `/kindle/...` / `/kindle_novel/...` のみマウントされる。
- `kindle` / `novel` ソースはキャプチャツールが生成した PDF を直接配信する経路（`/kindle/pdfs` / `/kindle_novel/pdfs`）を使用する。

`source` パラメータ: `generated`(default) / `kindle` / `novel`
