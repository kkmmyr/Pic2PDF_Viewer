### 1.2 データ配置 (Backend)
- `backend/data/`: データ格納ルート
    - `main/`: メイン（生成済）データ格納用
    - `kindle/`: Kindleキャプチャ (漫画)
    - `kindle_novel/`: Kindleキャプチャ (小説)
    - `meta/`: 書籍メタデータ（ソース別 `meta.json`）
        - キー形式: `"{path}/{filename}"` または `"{filename}"`（path が空の場合）
        - 値形式: `{"authors": ["作者A", "作者B"]}`

### 1.3 構成設定 (config.py)
- **パス定数**: `PDF_DIR`, `PDF_COMPRESSED_DIR`, `THUMBNAIL_DIR`, `IMAGES_DIR`, `COMPLETE_DIR`
- **Kindle**: `KINDLE_PDF_DIR`, `KINDLE_THUMBNAIL_DIR`, `KINDLE_IMAGES_DIR`
- **Kindle Novel**: `KINDLE_NOVEL_PDF_DIR`, `KINDLE_NOVEL_THUMBNAIL_DIR`, `KINDLE_NOVEL_IMAGES_DIR`
- **OCR起動設定**: `BATCH_OCR_LAUNCHER` — `kindle-pdf/start_batch_ocr.bat` へのパス。`.bat` ファイル経由で正しいPython環境とPATHを設定してOCRを起動する。
- **フロントエンド配信**: `FRONTEND_DIST_DIR` — `frontend/dist/` の絶対パス。リリースモード起動時に存在すれば `main.py` が SPA を同一オリジンで配信する。
- **サポートフォーマット**: `SUPPORTED_IMAGE_FORMATS`, `SUPPORTED_WEBP_FORMAT`, `SUPPORTED_ZIP_FORMAT`
- **数値定数**: `THUMBNAIL_HEIGHT`, `JOB_MAX_JOBS`, `OCR_LOG_MAXLEN`

## 2. クラス設計

### バックエンド (`backend/`)

#### `OCRService` (`backend/services/ocr_service.py`)
- **役割**: OCRバックグラウンドプロセスの管理、ログ収集、ステータス管理。
- **主要メソッド**:
    - `start_ocr()`: `batch_ocr.py` をサブプロセスとして起動。UTF-8エンコーディングを強制。
    - `stop_ocr()`: 実行中のプロセスを停止 (Terminate/Kill)。
    - `get_status()`: 現在の状態と直近のログを返却。

#### `GenerateJob` / `JobStore` (`backend/services/job_manager.py`)
- **役割**: 非同期PDF生成ジョブのライフサイクル管理。`routers/pdfs.py` から分離。
- **設計**:
    - `GenerateJob`: UUID・ステータス・進捗アイテム・ファイルリスト・エラーを保持。`threading.Lock` で状態更新をスレッドセーフに。
    - `JobStore`: 最大 `JOB_MAX_JOBS` 件のジョブをメモリ管理。FIFO方式で古いジョブを自動削除。
    - `JobStore.get_active_current_item()`: 最新の RUNNING ジョブの `current_item` を返す。`/api/status` エンドポイントで「処理中アイテム」を判定するために使用（旧 `GenerateState` は廃止）。
- **エンドポイント**:
    - `POST /api/generate` → バックグラウンドスレッド起動 + `{job_id}` を即返却。
    - `GET /api/generate/job/{job_id}` → ジョブ進捗取得（クライアントが1500msでポーリング）。

#### `FileManager` (`backend/services/file_manager.py`)
- **役割**: PDF・サムネイル・画像ディレクトリの3点セット操作を一元管理。`routers/library.py` の重複コードを集約。
- **主要メソッド**:
    - `move_with_assets(item, src_path, dst_path, dirs)`: PDF+サムネイル+画像ディレクトリを移動。失敗時は自動ロールバック。
    - `rename_with_assets(request, dirs)`: PDF+サムネイル+画像ディレクトリをリネーム。失敗時は自動ロールバック。

#### `PdfGenerator` (`backend/services/pdf_generator.py`)
- **役割**: ディレクトリやZIPファイルのスキャン、画像からのPDF生成、ファイル移動を一元管理。
- **設計**:
    - ZIP・ディレクトリのどちらも「`images_dir` にファイルを配置 → `_collect_images` → `_generate_outputs`」という共通フローで処理する。bytes/ファイルパスの二重実装を排除。
- **主要メソッド・関数**:
    - `_collect_images(images_dir)`: ディレクトリ内の WebP を natsorted で収集するモジュールレベル関数。
    - `process_directory()`: WebP を `images_dir` にコピーして共通フローへ。
    - `process_zip()`: ZIP を `images_dir` に展開して共通フローへ。
    - `_generate_outputs(item_name, item_images_dir)`: サムネイル・PDF・圧縮PDFの共通生成処理。
    - `run()`: 処理の実行と、完了ファイルの移動・空ディレクトリ削除の制御。

#### `PdfService` (`backend/services/pdf_service.py`)
- **役割**: 既存PDFの編集操作を一元管理。
- **主要メソッド**:
    - `delete_pages()`: 指定されたページの削除とPDFの再保存。
    - `get_page_count()`: PDFの総ページ数を取得。

#### `ThumbnailService` (`backend/services/thumbnail_service.py`)
- **役割**: PDFからのサムネイル画像生成。
- **主要メソッド**:
    - `generate_thumbnail()`: 最初のページを座標指定またはスケール指定で画像出力。

#### `MetaStore` (`backend/services/meta_store.py`)
- **役割**: meta.json の読み書き・ソース別ロック管理を一元化。`routers/meta.py` と `auto_fill_service.py` が共用するインフラ層。
- **型定義**:
    - `MetaEntry(TypedDict)`: `authors: list[str]` / `tags?: list[str]` / `view_count?: int` / `last_viewed_at?: float` / `series_id?: str` / `series_title?: str` / `series_index?: float` / `hidden?: bool`（任意フィールド、`series_index` は小数巻に対応するため float）
    - `MetaDict = dict[str, MetaEntry]`
- **主要関数**:
    - `get_lock(source)`: ソース別 `threading.Lock` を返す（遅延初期化）。
    - `load_meta(source)` / `save_meta(source, data)`: JSON の読み書き。
    - `make_key(path, name)`: `"{path}/{name}"` または `"{name}"` のキーを生成。
    - `update_meta_locked(source, updater)`: ロック取得→ロード→updater適用→保存を一括で行うユーティリティ。

#### `SeriesResolver` (`backend/services/series_resolver.py`)
- **役割**: 書籍を「同じ作者 + タイトル類似」のグループとしてシリーズ化する。`auto_fill_service.py` と同じ非同期ジョブパターンで動く。
- **マッチングルール（Phase 1: ルールベース）**:
    - **同作者**: 両書籍が `authors` の集合として完全一致する（順序は問わない、空は対象外）。
    - **共通プレフィックス**: タイトル（拡張子なしのファイル名）の先頭から共通文字列が `SERIES_MIN_PREFIX_LEN`（5）文字以上ある。
    - **残部分が巻数パターン**: プレフィックス除去後のサフィックスが以下のいずれかにマッチする:
        - 整数: `\s*[第]?\s*\d+\s*[巻]?\s*$`（例: ` 3`, ` 第3巻`, `03`）
        - **小数（fractional）**: `\s*\d+\.\d+\s*$`（例: ` 2.5`, ` 4.5`）
        - `\s*[vV][oO][lL]\.?\s*\d+(?:\.\d+)?\s*$`（例: `vol.4`, `Vol 04`, `vol.3.5`）
        - `\s*[(（][上中下前後]+[)）]\s*$`（例: `(上)`, `（下）`）
        - 漢数字: `\s*第?[一二三四五六七八九十百]+巻?\s*$`
    - **「巻数なし＝1 巻」ルール**: ペアの片方の残部分が空文字、もう片方が**整数の巻数（2 以上）**にマッチした場合、空側は **1.0 巻** として扱う。  
      例: 「寝取らせアーカイブ.pdf」+「寝取らせアーカイブ2.pdf」→ 前者は 1 巻、後者は 2 巻。  
      これは「シリーズの 1 巻目だけタイトルに巻数を付けない」慣習に対応する。
    - **巻数の数値化**: `series_index` は `float` 型で保存（`2.5` などの小数巻に対応）。整数は `2` でも `2.0` でも比較・ソートに支障なし。
- **状態モデル**:
    - `SeriesResolveState` dataclass: `status / total / done / created / current / error`
    - `status`: `idle | running | done | error`
- **書き込み**:
    - 同シリーズと判定されたエントリに `series_id`（共通プレフィックス + 作者をハッシュ化した安定 ID）/ `series_title`（共通プレフィックス）/ `series_index`（数値化した巻数）を書き戻す。
    - 既存の `series_id` は処理開始時に一旦クリアしてから再計算（再ラベル）。
- **API**:
    - `POST /api/series/resolve?source=&use_gemma=` → ジョブ起動（既に走っていれば 409）。
    - `GET /api/series/resolve/status?source=` → 進捗を返す。
    - `POST /api/series/assign` → 書籍に既存または新規シリーズを設定（手動編集）。`index` は `float` または `float[]`（配列指定で `names[i]` に `index[i]` を割り当てる、複数選択からの一括登録用）。
    - `POST /api/series/unassign` → 書籍をシリーズから外す。
    - `POST /api/series/reorder` → 同シリーズに属する書籍の `series_index` を `names` の順序で `1.0, 2.0, ...` に振り直す（DnD 並べ替え用）。`series_id` 不一致の書籍が混在すれば 400（中途半端な書き込みなし）。
- **Gemma 補助 (Phase 2)**:
    - `use_gemma=true` を指定すると、ルールベース判定後に「同作者でシリーズ未割当の書籍」を 1 件ずつ Gemma に問い合わせて、既存シリーズに追加判定する。
    - プロンプトは「次のタイトルは同シリーズか？YES/NO で答えよ」。Gemma の応答が `YES` で始まればシリーズメンバーとして追加（`series_index` は既存最大 +1）。
    - Gemma 呼び出しは `D:\61.tool\Gemma 4\ollama_client.call_ollama` を流用。Web 検索は不要。
    - 失敗（タイムアウト・モジュール不在）時は黙ってスキップしジョブ全体は成功扱い。

#### `AuthorResolver` (`backend/services/author_resolver.py`)
- **役割**: タイトルからサークル名/著者名を推定する。`auto_fill_service.py` から `resolve_author()` を呼ぶ。
- **解決フロー（`generated` ソース）**:
    1. **DLsite 直接検索**: `dlsite.com/maniax` の検索ページを HTTP フェッチ → Gemma で抽出
    2. **FANZA 直接検索**: `dmm.co.jp/dc/doujin` の検索ページを HTTP フェッチ → Gemma で抽出
    3. **SearXNG site: フィルタ**: `site:dmm.co.jp OR site:dlsite.com` で SearXNG 経由検索（フォールバック）
    4. **SearXNG 汎用クエリ**: `{title} サークル 同人誌` で SearXNG 汎用検索（最終フォールバック）
- **解決フロー（`kindle` / `novel` ソース）**: SearXNG 汎用クエリのみ
- **直接検索の実装**:
    - `web_extract.fetch_url_content(url)` で対象サイトの検索結果ページを直接 HTTP フェッチ
    - 取得したページテキストを `call_ollama` (Gemma) に渡してサークル名を抽出
    - SearXNG を経由しないためレート制限を回避できる
    - フェッチ失敗（タイムアウト・bot 検出）時は空文字を返し次ステップへフォールバック
- **サニタイズ** (`_sanitize_author`): URL / ブランド名 (`dlsite`, `dmm`, `fanza`) / 80 字超の長文 → `"作者不明"` に変換
- **主要関数**:
    - `resolve_author(title, source)`: 上記フローでサークル名を返す
    - `resolve_author_debug(title, source)`: 各ステップの中間結果も返すデバッグ用

#### `AutoFillService` (`backend/services/auto_fill_service.py`)
- **役割**: サークル名自動登録ジョブの状態管理・スレッド起動。`routers/meta.py` から抽出。
- **設計**:
    - `AutoFillState` dataclass: `status / total / done / skipped / current / results / error` を保持。
    - `mode` パラメータ（`missing_only` / `unknown_only` / `overwrite_all`）で処理対象を制御。
        - `missing_only`: 作者名エントリが未登録の書籍のみ処理。
        - `unknown_only`: 「作者不明」または未登録の書籍を処理（デフォルト）。
        - `overwrite_all`: 全件を上書き処理。
    - `state.total` は対象件数（スキップ分を除く）で設定する。
    - リクエスト間に `AUTOFILL_REQUEST_DELAY_SEC`（5.0秒）の sleep を挿入（直接クエリにも適用）。
    - **既存値の保持**: 各書籍のメタデータを更新する際、既存の `view_count` / `last_viewed_at` 等の他フィールドは保持し、`authors` のみを上書きする（`{**existing, "authors": [a]}` パターン）。`PATCH /api/meta` と同じ挙動。
- **主要関数**:
    - `get_auto_fill_state(source)` / `reset_auto_fill_state(source)`: ソース別状態管理。
    - `run_auto_fill(source, mode)`: バックグラウンドで実行するジョブ本体。
    - `start_auto_fill_job(source, mode)`: バックグラウンドスレッドを起動。

#### メタデータAPI (`backend/routers/meta.py`)
- **役割**: 書籍メタデータ（作者名）の HTTP ハンドラのみを担う。ロジックは `MetaStore` / `AutoFillService` に委譲。
- **エンドポイント**:
    - `GET /api/meta?source=` → meta.json 全体を返す。
    - `PATCH /api/meta` → `names`（ファイル名リスト）と `authors` / `tags` / `hidden` を受け取り、指定されたフィールドのみ更新。他は保持される。`hidden=true` で非表示化、`hidden=false` で再表示（フィールド削除）、未指定なら変更しない。
    - `POST /api/meta/view` → 閲覧記録（`view_count` / `last_viewed_at` 更新、連打抑制 5 分）。
    - `POST /api/meta/auto-fill` → 自動登録ジョブを起動。
    - `GET /api/meta/auto-fill/status` → ジョブ進捗を返す。
    - `GET /api/meta/auto-fill/test` → 1件分をデバッグ実行して中間結果を返す。

#### `useLibraryGrouping`
- **役割**: 書籍リストをシリーズ単位 / 作者単位で集約して仮想ディレクトリ的なカードを生成する。
- **モード** (`GroupMode = 'none' | 'series' | 'author' | 'author-then-series'`):
    - `none`: 集約しない。入力 `pdfs` をそのまま返す。
    - `series`: 同 `series_id` の書籍を集約。代表サムネイルは **最終巻**（`series_index` 最大）。displayTitle は `series_title`。
    - `author`: 同じ作者集合の書籍を集約。代表サムネイルは **入力順の 1 番目**（呼び出し側がソート済みなら「ソート 1 位」）。displayTitle は `{作者名} コレクション`。
    - `author-then-series`: 2 階層モード。`useLibraryGrouping` 自体は **`'series' | 'author' | 'none'` のいずれかに変換された値** を受け取る（モードの解釈は `LibraryPanel` 側で実施）:
        - 階層 1（authorFilter なし）: `author` として集約
        - 階層 2（authorFilter 適用中）: `series` として集約
        - 階層 3（seriesFilter 適用中）: `none` でフラット表示
- **戻り値**: `items` / `badgeByRepresentativeName` (count, kind, groupId, displayTitle) / `membersByRepresentativeName`。
- **共通**:
    - 集約対象だがメンバーが 1 冊だけのグループは集約しない（単独本扱い）。
    - 元の `pdfs` 順序を可能な限り保つ（代表書籍の元位置に集約カードを表示）。
    - シリーズ・作者ともに `kind` プロパティで PdfGrid 側の装飾（紫枠・バッジ・タイトル差し替え）を切り替える。

**LibraryPanel 側のパンくず計算**:
- ドリルダウン中（`authorFilter` または `seriesFilter` がセット）はパンくずを構築:
    1. 「ライブラリ」（全フィルタークリア）
    2. authorFilter があれば「作者: {名前}」
    3. seriesFilter があれば「シリーズ: {タイトル}」

- パンくず表示中は通常の作者・シリーズフィルター select は隠れる（重複防止）。

#### 閲覧回数 / 最近見た順ソート
- **保存先**: `meta.json` の各エントリに `view_count: int`（任意、デフォルト 0）と `last_viewed_at: float`（任意、UNIX 時刻）を追加。既存エントリには無いため読み込み時に 0 として扱う。
- **記録タイミング**: ライブラリのカードクリックで PDF を開いたタイミング（`LibraryPanel` 内で `onPdfClick` をラップ）で `POST /api/meta/view` を呼ぶ。
- **連打抑制**: `view_count` は前回 `last_viewed_at` から `VIEW_COUNT_DEBOUNCE_SEC = 300`（5分）以上経過した場合のみ +1 する。`last_viewed_at` は呼び出し毎に常に現在時刻で更新する（「最近見た順」ソートに反映するため）。
- **メタデータマージ規則**: `PATCH /api/meta`（作者更新）と `POST /api/meta/view`（閲覧記録）は互いに干渉しない。authors 更新時は既存の `view_count` / `last_viewed_at` を保持し、閲覧記録時は既存の `authors` を保持する。`authors` を空配列で更新した場合、他のフィールドが残っていれば `authors: []` で残し、何も残らなければエントリ自体を削除する。フロントエンドの `useBookMeta` ローカル状態も同じマージ規則で更新する。
- **API**:
    - `POST /api/meta/view` — body: `{ path: string, name: string, source: string }`。レスポンス `{ view_count: number, last_viewed_at: number, incremented: boolean }`。`incremented` は連打抑制に該当した場合 `false`。
    - `GET /api/meta` のレスポンスにも `view_count` / `last_viewed_at` が含まれる。
- **ソート挙動**:
    - `'view_desc'` — 閲覧回数の降順、同数の場合は名前昇順（`localeCompare('ja')`）。
    - `'recent_view'` — 最終閲覧時刻 (`last_viewed_at`) の降順。未閲覧（`undefined`）は末尾、同時刻は名前昇順。
- **UI**: ソートドロップダウン（`HeaderSortSelect`）に「よく見る順」「最近見た順」を追加。カード上には数字を表示しない（ソートのみ）。

- **設計**:
    - `useAutoFillAuthors` フックを内部で使い、ジョブの起動・進捗ポーリングを管理。
    - props は `source: LibrarySource` と `onComplete: () => void` のみ。
    - エラー時は内蔵のトーストで通知（ヘッダー側のトーストとは別系統）。

#### 選択モードの視覚スタイル（PdfGrid / FolderGrid）
- **選択中カード**: `border-amber-400` の枠 + `bg-amber-50 dark:bg-amber-900/20` の薄い琥珀色背景で表示。
- **PdfGrid のカード本体パネル**（サムネイル下部の書名・作者・日付エリア）も同じ条件で背景色を切り替える。サムネイル領域は画像で覆われるため枠と本体パネルの両方を着色することで選択状態を明確化する。
- **チェックアイコン**: 選択時は `text-amber-500` の `CheckSquare`、未選択時は `text-gray-400` の `Square`。
- **採用理由**: 従来の `border-blue-500` はダークモード（`bg-gray-800` 背景）で視認性が低く、UI 内の他の青系要素（作者タグ等）とも紛らわしかったため、アクセント色として琥珀（amber）に変更。両モードで高コントラスト。

## 4. リリースビルド構成

開発時とは別ポートで動作する「ビルド済み配信」モード。修正時は通常通り dev サーバーで作業し、確定したものを `build_release.bat` でビルドする。

### 4.1 ポート割り当て
| モード | Backend | Frontend | 起動方法 |
|---|---|---|---|
| 開発 | 8766 (uvicorn --reload) | 5176 (vite dev, strictPort) | `start.bat` |
| リリース | 8090 (uvicorn 単独) | Backend に統合（dist 配信） | `start_release.bat` |

### 4.2 動作原理
1. `npm run build` で `frontend/dist/` に静的アセットを出力。
2. リリース起動時、`backend/main.py` が `FRONTEND_DIST_DIR` の存在をチェックし、存在すれば以下のルートを最後に登録する:
    - `/` → `dist/index.html`
    - `/{full_path:path}` → `dist/` 配下にファイルがあれば返す。なければ `index.html`（SPA fallback）
    - `/api`, `/pdfs`, `/thumbnails`, `/images`, `/kindle/...` などの既存マウントが優先されるよう、SPA 用 catch-all は **最後** に登録する。
3. リリースモードでは同一オリジンで動くため、フロントエンドは `BASE_URL=''` （相対パス）で API を叩く。

### 4.3 フロント側の API URL 切り替え
`frontend/src/config/api.ts` で `import.meta.env.PROD` を判定:
- `true`（`vite build`）→ `BASE_URL = ''`（同一オリジンで相対パス）
- `false`（`vite dev`）→ `VITE_API_URL` または `http://localhost:8766`

### 4.4 起動スクリプト
| ファイル | 役割 |
|---|---|
| `build_release.bat` | `cd frontend && npm run build` を実行（dist 再生成） |
| `start_release.bat` | uvicorn を Port 8090 で起動し、ブラウザで `http://localhost:8090` を開く |

### 4.5 Windows ログイン時の自動起動 / クラッシュ時自動再起動

**タスクスケジューラ** に `Pic2PDF_Viewer` タスクとして登録（`Register-ScheduledTask`）：
- トリガー: `AtLogOn`（対象ユーザーのログオン時）
- アクション: `powershell -Command Start-Process cmd -ArgumentList '/c start_release.bat' -WindowStyle Minimized` で最小化起動
- 設定: `RestartCount=3` / `RestartInterval=1分` / `ExecutionTimeLimit=0`（無制限）
- 二重防御: `start_release.bat` 内にも `:loop` で uvicorn 再起動ループを実装。終了コード 0 のときだけ抜ける

登録・解除コマンドは [起動方法.md](../../起動方法.md) を参照。

### 4.6 文字エンコーディング上の注意
`start_release.bat` は **ASCII のみ** で記述する。日本語コメントを含むと UTF-8 として保存され、`chcp 65001` 後でも cmd.exe のパーサが行をまたいで誤動作する場合がある（実際にハマったので残しておく）。
