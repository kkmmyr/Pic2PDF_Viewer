### 1.2 データ配置 (Backend)
- `backend/data/`: データ格納ルート
    - `main/`: メイン（生成済）データ格納用
    - `kindle/`: Kindleキャプチャ (漫画)
    - `kindle_novel/`: Kindleキャプチャ (小説)
    - `meta/`: 書籍メタデータ（ソース別 `meta.json`）
        - キー形式: `"{path}/{filename}"` または `"{filename}"`（path が空の場合）
        - 値形式: `{"authors": ["作者A", "作者B"]}`

### 1.3 構成設定 (config.py)
- **パス定数**: `PDF_DIR`, `PDF_COMPRESSED_DIR`, `THUMBNAIL_DIR`, `IMAGES_DIR`, `COMPLETE_DIR`
- **Kindle**: `KINDLE_PDF_DIR`, `KINDLE_THUMBNAIL_DIR`, `KINDLE_IMAGES_DIR`
- **Kindle Novel**: `KINDLE_NOVEL_PDF_DIR`, `KINDLE_NOVEL_THUMBNAIL_DIR`, `KINDLE_NOVEL_IMAGES_DIR`
- **OCR起動設定**: `BATCH_OCR_LAUNCHER` — `kindle-pdf/start_batch_ocr.bat` へのパス。`.bat` ファイル経由で正しいPython環境とPATHを設定してOCRを起動する。
- **サポートフォーマット**: `SUPPORTED_IMAGE_FORMATS`, `SUPPORTED_WEBP_FORMAT`, `SUPPORTED_ZIP_FORMAT`
- **数値定数**: `THUMBNAIL_HEIGHT`, `JOB_MAX_JOBS`, `OCR_LOG_MAXLEN`

## 2. クラス設計

### バックエンド (`backend/`)

#### `OCRService` (`backend/services/ocr_service.py`)
- **役割**: OCRバックグラウンドプロセスの管理、ログ収集、ステータス管理。
- **主要メソッド**:
    - `start_ocr()`: `batch_ocr.py` をサブプロセスとして起動。UTF-8エンコーディングを強制。
    - `stop_ocr()`: 実行中のプロセスを停止 (Terminate/Kill)。
    - `get_status()`: 現在の状態と直近のログを返却。

#### `GenerateJob` / `JobStore` / `GenerateState` (`backend/services/job_manager.py`)
- **役割**: 非同期PDF生成ジョブのライフサイクル管理。`routers/pdfs.py` から分離。
- **設計**:
    - `GenerateJob`: UUID・ステータス・進捗アイテム・ファイルリスト・エラーを保持。`threading.Lock` で状態更新をスレッドセーフに。
    - `JobStore`: 最大 `JOB_MAX_JOBS` 件のジョブをメモリ管理。FIFO方式で古いジョブを自動削除。
    - `GenerateState`: `/api/status` エンドポイント向けの現在処理アイテム管理（シングルトン）。
- **エンドポイント**:
    - `POST /api/generate` → バックグラウンドスレッド起動 + `{job_id}` を即返却。
    - `GET /api/generate/job/{job_id}` → ジョブ進捗取得（クライアントが1500msでポーリング）。

#### `FileManager` (`backend/services/file_manager.py`)
- **役割**: PDF・サムネイル・画像ディレクトリの3点セット操作を一元管理。`routers/library.py` の重複コードを集約。
- **主要メソッド**:
    - `move_with_assets(item, src_path, dst_path, dirs)`: PDF+サムネイル+画像ディレクトリを移動。失敗時は自動ロールバック。
    - `rename_with_assets(request, dirs)`: PDF+サムネイル+画像ディレクトリをリネーム。失敗時は自動ロールバック。

#### `PdfGenerator` (`backend/services/pdf_generator.py`)
- **役割**: ディレクトリやZIPファイルのスキャン、画像からのPDF生成、ファイル移動を一元管理。
- **設計**:
    - ZIP・ディレクトリのどちらも「`images_dir` にファイルを配置 → `_collect_images` → `_generate_outputs`」という共通フローで処理する。bytes/ファイルパスの二重実装を排除。
- **主要メソッド・関数**:
    - `_collect_images(images_dir)`: ディレクトリ内の WebP を natsorted で収集するモジュールレベル関数。
    - `process_directory()`: WebP を `images_dir` にコピーして共通フローへ。
    - `process_zip()`: ZIP を `images_dir` に展開して共通フローへ。
    - `_generate_outputs(item_name, item_images_dir)`: サムネイル・PDF・圧縮PDFの共通生成処理。
    - `run()`: 処理の実行と、完了ファイルの移動・空ディレクトリ削除の制御。

#### `PdfService` (`backend/services/pdf_service.py`)
- **役割**: 既存PDFの編集操作を一元管理。
- **主要メソッド**:
    - `delete_pages()`: 指定されたページの削除とPDFの再保存。
    - `get_page_count()`: PDFの総ページ数を取得。

#### `ThumbnailService` (`backend/services/thumbnail_service.py`)
- **役割**: PDFからのサムネイル画像生成。
- **主要メソッド**:
    - `generate_thumbnail()`: 最初のページを座標指定またはスケール指定で画像出力。

#### `MetaStore` (`backend/services/meta_store.py`)
- **役割**: meta.json の読み書き・ソース別ロック管理を一元化。`routers/meta.py` と `auto_fill_service.py` が共用するインフラ層。
- **主要関数**:
    - `get_lock(source)`: ソース別 `threading.Lock` を返す（遅延初期化）。
    - `load_meta(source)` / `save_meta(source, data)`: JSON の読み書き。
    - `make_key(path, name)`: `"{path}/{name}"` または `"{name}"` のキーを生成。

#### `AutoFillService` (`backend/services/auto_fill_service.py`)
- **役割**: サークル名自動登録ジョブの状態管理・スレッド起動。`routers/meta.py` から抽出。
- **設計**:
    - `AutoFillState` dataclass: `status / total / done / skipped / current / results / error` を保持。
    - `overwrite=False` 時は `_has_real_author()` で確定済み書籍をスキップ、「作者不明」は再試行。
    - `overwrite=True` 時は全件処理。
    - SearXNG 上限対策として件数間に 5.0 秒 sleep を挿入。
- **主要関数**:
    - `get_auto_fill_state(source)` / `reset_auto_fill_state(source)`: ソース別状態管理。
    - `run_auto_fill(source, overwrite)`: バックグラウンドで実行するジョブ本体。
    - `start_auto_fill_job(source, overwrite)`: バックグラウンドスレッドを起動。

#### メタデータAPI (`backend/routers/meta.py`)
- **役割**: 書籍メタデータ（作者名）の HTTP ハンドラのみを担う。ロジックは `MetaStore` / `AutoFillService` に委譲。
- **エンドポイント**:
    - `GET /api/meta?source=` → meta.json 全体を返す。
    - `PATCH /api/meta` → `names`（ファイル名リスト）と `authors` を受け取り、複数冊を一括上書き。
    - `POST /api/meta/auto-fill` → 自動登録ジョブを起動。
    - `GET /api/meta/auto-fill/status` → ジョブ進捗を返す。
    - `GET /api/meta/auto-fill/test` → 1件分をデバッグ実行して中間結果を返す。

### Kindleキャプチャツール (`kindle-pdf/`)

#### `KindleCapturer` (`kindle-pdf/capturer.py`)
- **役割**: 基本的なKindleウィンドウ操作、スクリーンショット撮影、PDF作成。
- **主要メソッド**:
    - `find_window()`: Kindleウィンドウのハンドル取得。
    - `get_book_title()`: タイトル入力ダイアログ（`BookInfoDialog`）の表示。
    - `capture_loop()`: ページめくりと撮影のループ。

#### `AutoKindleCapturer` (`capturer.py`)
- **継承**: `KindleCapturer`
- **役割**: 漫画/雑誌用の自動クロップ（黒帯検出）。フルスクリーンモードを使用。

#### `NovelKindleCapturer` (`novel_capturer.py`)
- **継承**: `AutoKindleCapturer`
- **役割**: 小説用の自動クロップ（X軸白背景検出）と画像保存。
- **特徴**: OCR/PDF生成機能は削除（`batch_ocr.py`へ委譲）。撮影速度を優先。

#### `BookInfoDialog` (`capturer.py`)
- **役割**: 書籍情報入力ダイアログ。
- **入力**: タイトル、ページめくり方向（左キー/右キー）。

#### `SearchablePdfGenerator` (`kindle-pdf/searchable_pdf.py`)
- **役割**: 画像とOCR結果から「透明テキスト付きPDF」を生成する。
- **使用ライブラリ**: `ReportLab`
- **主要メソッド**:
    - `add_page(image_path, ocr_results)`: 画像を描画し、その上に検索用テキスト（透明）を配置する。
    - `_draw_vertical_text`: **1文字ずつ個別の `TextObject` で縦に配置**（旧: `-90°` 回転+`textOut(全文)` 方式は廃止）。
    - `_draw_horizontal_text`: 横書き（ルビ等）の配置。
- 詳細設計: [OCR設計書.md](OCR設計書.md)

#### `BatchOCR` (`kindle-pdf/batch_ocr.py`)
- **役割**: `kindle_novel/images` 配下の未処理フォルダを走査し、自動的にSearchable PDF化する。
- **フロー**: フォルダ検知 → OCR (`yomitoku`) → PDF生成 (`SearchablePdfGenerator`)

### OCRエンジン (`D:\61.tool\common\ocr\`)

#### `YomitokuEngine` (`ocr_engine.py`)
- **役割**: `yomitoku` ライブラリを用いたOCR処理。
- **主要メソッド**:
    - `extract_text()`: 画像からテキストを抽出。段落判定または単語判定に分岐。
    - `_process_words()`: 単語情報の処理。thickness統一・aspect比判定・フリガナ除去・正規化。
    - `filter_ruby_text()`: ヒストグラム谷（valley）自動検出によるフリガナ除去。
    - `normalize_text()`: 3点リーダー・特殊記号の正規化。
- 詳細設計: [OCR設計書.md](OCR設計書.md)

### フロントエンドContext (`frontend/src/contexts/`)

#### `LibraryContext` (`frontend/src/contexts/LibraryContext.tsx`)
- **役割**: ViewerPage が LibraryPanel に渡していた 21 個の props を Context に集約し、Props Drilling を解消する。
- **設計**:
    - `LibraryProvider`: `useUrlState` + PDF フェッチ + `useLibraryManagement` を内包し、`LibraryContext.Provider` で子にデータを提供。
    - `useLibraryContext()`: Provider 外で呼ばれると `throw Error` するカスタムフック。
    - `ViewerPage` は `LibraryProvider` でラップするだけの薄い構造になる。
    - `LibraryPanel` は props を受け取らず `useLibraryContext()` で必要な値・ハンドラを取得する。
- **提供する値 (LibraryContextValue)**:
    - 状態: `pdfs`, `directories`, `selectedPdf`, `currentPath`, `currentSource`, `isSelectionMode`, `selectedItems`, `isMoveDialogOpen`, `isCreateFolderOpen`, `renameTarget`
    - ナビゲーション: `onPdfClick`, `onFolderClick`, `onUpClick`, `onSourceChange`, `onClosePdf`, `onPdfUpdated`
    - ダイアログ操作: フォルダ作成・移動・リネームの開閉・実行ハンドラ群
    - `onRefresh`: PDF 一覧の再取得

### フロントエンドフック (`frontend/src/hooks/`)

#### `useDarkMode`
- **役割**: ダークモード状態の管理と永続化。
- **設計**:
    - `index.html` インラインスクリプトと連携し、React マウント前に `<html class="dark">` を適用してフラッシュを防止。
    - `useState` 初期化フェーズで即座に `classList` を操作（`useEffect` 待ちのラグを排除）。
    - `localStorage` キー `darkMode` に `true/false` 文字列で永続化。
    - システムカラースキーム (`prefers-color-scheme: dark`) をフォールバックとして使用。

#### `useFavorites`
- **役割**: お気に入りPDFの管理（ソース別）。
- **設計**:
    - `localStorage` キー `favorites_{source}` に `string[]` (JSON) で永続化。
    - `source` が切り替わった際に `useEffect` で該当ソースのデータを再ロード。
    - `toggle(name)` はimmutableなSet更新 + 即時永続化。

#### `useSortedPdfs`
- **役割**: PDF一覧の並び替えロジック（`useMemo` でメモ化）。
- **ソート順**: `name_asc` / `name_desc` / `date_asc` / `date_desc` / `favorites_first`
    - `favorites_first`: お気に入りを先頭に、同グループ内は名前昇順。
    - 日付ソートは `created_at` (Unix timestamp) を使用。

#### `useBookMeta`
- **役割**: 書籍メタデータ（作者名）の取得・更新・全作者名集計。
- **設計**:
    - `source` が変わると `GET /api/meta` を再取得。
    - `updateAuthors(path, names, authors)` で1冊または複数冊を一括更新し、ローカル状態も即時反映（再フェッチ不要）。
    - `allAuthors`: このソースに登録されている全作者名の重複排除・日本語ソート済みリスト。
- **主要戻り値**:
    - `getAuthors(path, name)`: キーを構築して作者名リストを返す。
    - `updateAuthors(path, names, authors)`: PATCH API を呼び出し、ローカル状態を更新。
    - `allAuthors`: フィルタードロップダウンの選択肢として使用。

#### `useBookImages`
- **役割**: 書籍の画像URL一覧を取得し、画像モード/PDFモードを判定する。
- **設計**:
    - `selectedPdf` が変わると `GET /api/books/{bookPath}/images` を呼び出して画像URLを取得。
    - 画像が取得できた場合は `isImageMode=true`（画像モード）、失敗した場合は `isImageMode=false`（PDFモード）。
    - **`novel` ソースは画像取得をスキップして PDFモードを強制する**。`kindle_novel/images/` に PNG ファイルが存在するが、このソースの目的は Searchable PDF のテキスト検索にあるため、PDF モードで表示する必要がある。

#### `useReaderNavigation`
- **役割**: リーダーのページナビゲーション（前/次ページ、ページジャンプ、リセット）を管理。
- **依存**: `numPages`, `isSpread`, `direction`, `isActive`
- **主要戻り値**: `pageNumber`, `setPageNumber`, `handleNext`, `handlePrev`, `resetPage`

#### `useUrlState`
- **役割**: ViewerPage の URLパラメータ (`?path=`, `?file=`, `?source=`) 同期を一元管理。
- **設計**:
    - `useSearchParams` ラッパー。`currentPath` / `selectedPdf` / `currentSource` を導出して返す。
    - ナビゲーション操作を関数として提供し、ViewerPage での状態二重管理を排除。
    - `source` を URL に含めることでリロード・直接アクセス時にも正しいソースが復元される。
    - `VALID_SOURCES` で無効なソース値を `'generated'` にフォールバック。
- **主要メソッド**:
    - `navigateIntoFolder(dirName, basePath, source)`: フォルダ内に移動（`?path=` を更新）。
    - `navigateUp(currentPath, source)`: 親階層へ戻る。
    - `selectPdf(pdfName, currentPath, source)`: PDF を選択（`?file=` を追加）。
    - `clearPdf(currentPath, source)`: PDF選択を解除してライブラリに戻る。
    - `setSource(source)`: ソース切り替え時に `?source=` だけ変更し、`path` / `file` をリセット。

### フロントエンドコンポーネント

#### `LazyThumbnail` (`frontend/src/components/reader/LazyThumbnail.tsx`)
- **役割**: サムネイル画像の遅延読み込み。
- **設計**: `IntersectionObserver` で viewport から200px前に入った時点で `src` をセット。エラー時は `FileText` アイコンにフォールバック。

#### `PdfSearchBar` (`frontend/src/components/reader/PdfSearchBar.tsx`)
- **役割**: PDF内テキスト検索UI。`ReaderHeader` 直下に固定表示。
- **設計**: 300msデバウンスで親へ検索テキストを通知。Enter/Shift+Enterで次/前へ移動。マッチ数 "X / Y" 表示。

#### `PageRenderer` (`frontend/src/components/reader/PageRenderer.tsx`)
- **役割**: 単一ページのレンダリング（PDFモード・画像モード両対応）。
- **設計**:
    - `onPageSize?: (width, height) => void` コールバックを持ち、ページサイズが確定した時点で親に通知する（自動見開き判定用）。
    - PDFモード: `<Page onRenderSuccess={(page) => onPageSize?.(page.width, page.height)}>` で通知。
    - 画像モード: `<img onLoad={(e) => onPageSize?.(img.naturalWidth, img.naturalHeight)}>` で通知。
    - `ReaderPanel` は右ページ（`side === 'right'`）またはシングルページ（`side === 'single'`）にのみ `onPageSize` を渡し、見開き時の二重発火を防ぐ。

#### `ReaderHeader` (`frontend/src/components/reader/ReaderHeader.tsx`)
- **役割**: リーダー上部コントロールバー。マウスオーバー時のみ表示（没入型モード）。
- **設計**:
    - **見開きモードボタン**: `spreadMode: SpreadMode` (`'auto' | 'spread' | 'single'`) を `onCycleSpreadMode` で循環（Auto → Spread → Single → Auto）。
    - `SPREAD_MODE_CONFIG` 定数でモードごとのラベル・アイコン・次モードを管理。
    - Auto モードは indigo 色で強調表示。他は gray。
    - ページ番号表示はクリックで直接入力（数値入力 → Enter/blur で `onPageJump` 呼び出し）。

#### `CreateFolderDialog` (`frontend/src/components/viewer/CreateFolderDialog.tsx`)
- **役割**: フォルダ作成ダイアログ（Tailwind実装）。
- **設計**: 空文字・禁止文字 (`/ \ : * ? " < > |`) のバリデーション。Enter でサブミット、Esc で閉じる、外クリックで閉じる。

#### `RenameDialog` (`frontend/src/components/viewer/RenameDialog.tsx`)
- **役割**: PDF/フォルダ共用のリネームダイアログ（Tailwind実装）。
- **設計**:
    - PDF の場合は拡張子 `.pdf` を入力欄から省き、確定時に自動付加。フォルダの場合はそのまま扱う。
    - バリデーション・Enter/Esc/外クリック動作は `CreateFolderDialog` と同様。
    - `isFolder` prop で PDF/フォルダを切り替える。

#### `ReaderPanel` (`frontend/src/components/viewer/ReaderPanel.tsx`)
- **役割**: PDFリーダーUI。ページ表示・見開き制御・検索・ページ削除を統合管理。
- **Worker設定**:
    - `pdfjs.GlobalWorkerOptions.workerSrc` を `new URL('pdfjs-dist/build/pdf.worker.min.mjs', import.meta.url).toString()` で設定。
    - `<Document>` コンポーネントと同一ファイルで設定する必要がある（react-pdf の要件）。Vite がビルド時にワーカーファイルを自動バンドルする。
    - `react-pdf/dist/Page/TextLayer.css` をインポートしてテキストレイヤーのスタイルを適用（ハイライト表示に必要）。
- **見開き制御**:
    - `spreadMode: SpreadMode` — `'auto' | 'spread' | 'single'` の3状態。
    - `autoIsSpread: boolean` — Auto モード時のみ使用。`handlePageSize` で更新。
    - 実効 `isSpread` = `spreadMode === 'auto' ? autoIsSpread : spreadMode === 'spread'`
    - `cycleSpreadMode()`: Auto → Spread → Single → Auto の順で循環。
    - `handlePageSize(width, height)`: `spreadMode === 'auto'` 時のみ動作。`width <= height`（縦長）なら見開き（`true`）、横長なら1ページ（`false`）に設定。
    - PDF切り替え時に `autoIsSpread` を `true` にリセット。
- **テキスト検索**:
    - `pdfRef` に `PDFDocumentProxy` を保持し、全ページのテキストを走査してマッチ数を算出・ハイライト表示。
    - `searchAllPages(text, pdf)` は `pdfRef.current` ではなく引数の `pdf` を直接受け取り、ロード直後の null 参照問題を回避。
    - `onDocumentLoadSuccess`: PDF ロード完了時点で `searchText` が入力済みの場合は即座に `searchAllPages` を呼び出す。
    - 検索バー (`PdfSearchBar`) は `isSearchOpen === true` の間は常に表示（`showHeader` とは独立）。
    - `ReaderHeader` は `showHeader || isSearchOpen` で検索中は常に表示。
- **ページ削除**: 編集モードで選択したページを `DELETE /api/pdfs/pages` で削除。完了後 `pdfVersion` をインクリメントしてPDFを再ロード。

#### `BulkAuthorDialog` (`frontend/src/components/viewer/BulkAuthorDialog.tsx`)
- **役割**: 選択モードで複数書籍を選択したときに作者名を一括設定するダイアログ（Tailwind実装）。
- **設計**:
    - タグ形式の入力（Enter/カンマで確定、Backspace で削除）。
    - 「一括適用」で選択中の全書籍の作者名を上書き（既存の作者名は破棄）。
    - `targetCount` prop で対象冊数をヘッダーに表示。
    - 選択モード中にヘッダーの「作者を設定」ボタンから開く。

## 3. 運用・開発メモ

- **起動方法**: [起動方法.md](../起動方法.md) を参照
    - Backend: `python -m uvicorn main:app --reload` (Port 8000)
    - Frontend: `npm run dev` (Port 5173)
- **注意点**:
    - `react-pdf` のWorker設定は `new URL('pdfjs-dist/build/pdf.worker.min.mjs', import.meta.url)` で Vite バンドル経由で読み込む。CDN不要。
    - `<Document>` コンポーネントを使うファイルと同じモジュールで `workerSrc` を設定すること（`ReaderPanel.tsx`）。
    - `novel` ソースは Searchable PDF なので PDF モードで表示する（`useBookImages` が画像取得をスキップ）。
    - `data/pdfs` / `data/thumbnails` は静的ファイルとして `/pdfs` / `/thumbnails` パスでマウントされている。
- **環境設定**:
    - Frontend: `frontend/.env` に `VITE_DEFAULT_SOURCE_DIR` を設定することで生成画面のデフォルトパスを変更可能。
    - Backend: `python-dotenv` 導入済み。`.env` ファイルから設定を読み込む。
