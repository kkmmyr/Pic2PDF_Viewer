## 2. 運用・開発メモ

- **起動方法**: [起動方法.md](../../起動方法.md) を参照
    - 開発モード: Backend `uv run uvicorn main:app --reload --port 8766` / Frontend `npm run dev` (Port 5176)
    - リリースモード: `start_release.bat` で Backend (Port 8090) が dist を同一オリジン配信
    - ポート割当の詳細・他プロジェクトとの調整は `D:\61.tool\common\port\README.md` を参照
- **Backend 再起動**: `start.bat` を再実行するだけで Backend のみ再起動できる
    - Port 8766 が LISTENING 状態なら uvicorn プロセスツリーを終了。`backend/start_server.bat` 内の再起動ループが同タブ内で `uv sync` → uvicorn 再起動を自動実行する（新タブは開かない）
    - 未起動なら通常通り Backend + Frontend 両方を起動する
- **注意点**:
    - `react-pdf` のWorker設定は `new URL('pdfjs-dist/build/pdf.worker.min.mjs', import.meta.url)` で Vite バンドル経由で読み込む。CDN不要。
    - `<Document>` コンポーネントを使うファイルと同じモジュールで `workerSrc` を設定すること（`ReaderPanel.tsx`）。
    - `novel` ソースは Searchable PDF なので PDF モードで表示する（`useBookImages` が画像取得をスキップ）。
    - 静的マウントは `/thumbnails`（`data/main/thumbnails/`）/ `/images`（`data/main/images/`）/ `/kindle/{pdfs,thumbnails,images}` / `/kindle_novel/{pdfs,thumbnails,images}`。`/pdfs` マウントは廃止済み（`generated` ソースは image-only モードで運用）。`pdfs_compressed/` は `POST /api/batch_compress` の出力先としてのみ残存し、配信経路はない。
- **環境設定**:
    - Frontend: `frontend/.env` に `VITE_DEFAULT_SOURCE_DIR` を設定することで生成画面のデフォルトパスを変更可能。
    - Backend: `python-dotenv` 導入済み。`.env` ファイルから設定を読み込む。

## 3. リリースビルド構成

開発時とは別ポートで動作する「ビルド済み配信」モード。修正時は通常通り dev サーバーで作業し、確定したものを `build_release.bat` でビルドする。

### 3.1 ポート割り当て
| モード | Backend | Frontend | 起動方法 |
|---|---|---|---|
| 開発 | 8766 (uvicorn --reload) | 5176 (vite dev, strictPort) | `start.bat` |
| リリース | 8090 (uvicorn 単独) | Backend に統合（dist 配信） | `start_release.bat` |

### 3.2 動作原理
1. `npm run build` で `frontend/dist/` に静的アセットを出力。
2. リリース起動時、`backend/main.py` が `FRONTEND_DIST_DIR` の存在をチェックし、存在すれば以下のルートを最後に登録する:
    - `/` → `dist/index.html`
    - `/{full_path:path}` → `dist/` 配下にファイルがあれば返す。なければ `index.html`（SPA fallback）
    - `/api`, `/pdfs`, `/thumbnails`, `/images`, `/kindle/...` などの既存マウントが優先されるよう、SPA 用 catch-all は **最後** に登録する。
3. リリースモードでは同一オリジンで動くため、フロントエンドは `BASE_URL=''` （相対パス）で API を叩く。

### 3.3 フロント側の API URL 切り替え
`frontend/src/config/api.ts` で `import.meta.env.PROD` を判定:
- `true`（`vite build`）→ `BASE_URL = ''`（同一オリジンで相対パス）
- `false`（`vite dev`）→ `VITE_API_URL` または `http://localhost:8766`

### 3.4 起動スクリプト
| ファイル | 役割 |
|---|---|
| `start.bat` | 未起動なら Backend + Frontend 両方を Windows Terminal タブで起動。Port 8766 が LISTENING なら uvicorn を終了して Backend のみ再起動 |
| `backend/start_server.bat` | `uv sync` → uvicorn 起動のループ。uvicorn が停止するたびに自動で再起動（Ctrl+C → Y で停止） |
| `build_release.bat` | `cd frontend && npm run build` を実行（dist 再生成） |
| `start_release.bat` | uvicorn を Port 8090 で起動し、ブラウザで `http://localhost:8090` を開く |

### 3.5 Windows ログイン時の自動起動 / クラッシュ時自動再起動

**タスクスケジューラ** に `Pic2PDF_Viewer` タスクとして登録（`Register-ScheduledTask`）：
- トリガー: `AtLogOn`（対象ユーザーのログオン時）
- アクション: `powershell -Command Start-Process cmd -ArgumentList '/c start_release.bat' -WindowStyle Minimized` で最小化起動
- 設定: `RestartCount=3` / `RestartInterval=1分` / `ExecutionTimeLimit=0`（無制限）
- 二重防御: `start_release.bat` 内にも `:loop` で uvicorn 再起動ループを実装。終了コード 0 のときだけ抜ける

登録・解除コマンドは [起動方法.md](../../起動方法.md) を参照。

### 3.6 文字エンコーディング上の注意
`start_release.bat` は **ASCII のみ** で記述する。日本語コメントを含むと UTF-8 として保存され、`chcp 65001` 後でも cmd.exe のパーサが行をまたいで誤動作する場合がある（実際にハマったので残しておく）。

### 3.7 設計ドキュメントの HTML 配信（mkdocs-material、2026-05-11 追加 / 2026-05-11 出力先変更）

`docs/*.md` を `mkdocs build` で `frontend/public/site/` に HTML 化する。出力先を Vite の `publicDir` 配下に置くことで、Vite dev / Vite dist / FastAPI 直接マウントのすべてから配信される。詳細は [ADR-0008](../02_基本設計/ADR/0008_design-docs-html-build.md)。

**配信構成**:
- Vite (`frontend/public/site/`): dev (`:5176`) / build 後の `dist/site/` → リリース統合 (`:8090`) のいずれでも `/site/` から自動配信
- FastAPI (`backend/main.py`): `frontend/public/site/` 存在時に `app.mount("/docs-html", StaticFiles(directory=..., html=True))` を登録（後方互換のため `/docs-html` も維持）
- SPA catch-all より前に登録（優先順位）
- 開発・リリース両モードで有効

**閲覧 URL**:
| モード | URL |
|---|---|
| 開発（mkdocs serve）| `http://localhost:8000` |
| 開発（Vite dev、ビルド済み）| `http://localhost:5176/site/index.html` |
| 開発（backend 直接、ビルド済み）| `http://localhost:8766/docs-html/` |
| リリース（Vite dist 経由）| `http://localhost:8090/site/index.html` |
| リリース（後方互換）| `http://localhost:8090/docs-html/` |

フロントエンド画面のヘッダー右上「設計書」リンクから別タブで開ける（[`frontend/src/components/Layout.tsx`](../../frontend/src/components/Layout.tsx)）。

**ビルドコマンド**: 詳細手順は `.claude/CLAUDE.md` の「設計ドキュメントの HTML 配信」セクション。
- 初回: `uv tool install mkdocs --with mkdocs-material --with mkdocs-mermaid2-plugin` + `uv tool update-shell` → PowerShell 再起動
- 単発: `mkdocs build`
- 開発時プレビュー: `mkdocs serve`

**git 管理**: `frontend/public/site/` は `.gitignore`。ソース `docs/*.md` のみコミットする。`npm run build` 時は `frontend/dist/site/` にもコピーされ、dist サイズが site 分（数 MB〜）肥大化する点に留意。リリースビルド時に `mkdocs build` を `build_release.bat` 等に追加することは将来検討（現在は手動）。
