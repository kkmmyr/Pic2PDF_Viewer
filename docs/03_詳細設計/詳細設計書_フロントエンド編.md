### 2.2 Hooks

`frontend/src/hooks/` 配下のカスタムフック。各フックのファイル詳細マップは [§1.2 ファイル詳細マップ](#12-ファイル詳細マップタスク起点) を参照（本節は設計理由・契約・利用元の説明）。

#### `useDarkMode`
- **役割**: ダークモード状態の管理と永続化。
- **設計**:
    - `index.html` インラインスクリプトと連携し、React マウント前に `<html class="dark">` を適用してフラッシュを防止。
    - `useState` 初期化フェーズで即座に `classList` を操作（`useEffect` 待ちのラグを排除）。
    - `localStorage` キー `darkMode` に `true/false` 文字列で永続化。
    - システムカラースキーム (`prefers-color-scheme: dark`) をフォールバックとして使用。
    - **`index.css` で `html.dark` に `color-scheme: dark` を当てる**ことで `<select>` のネイティブドロップダウンメニュー（option）等もダーク表示にする（Tailwind の `dark:` 修飾子は子要素のスタイルしか効かないため、ネイティブ UI 部分はこの設定で対応）。

#### `useSortedPdfs`
- **役割**: PDF一覧の並び替えロジック（`useMemo` でメモ化）。
- **ソート順**: `name_asc` / `name_desc` / `date_asc` / `date_desc` / `favorites_first`
    - `favorites_first`: お気に入りを先頭に、同グループ内は名前昇順。
    - 日付ソートは `created_at` (Unix timestamp) を使用。

#### `useBookMeta`
- **役割**: 書籍メタデータ（作者名・シリーズ・閲覧履歴・非表示・ジャンル・読書状態）の取得・更新・集計。
- **設計**:
    - `source` が変わると `GET /api/meta` を再取得。
    - `updateMeta` / `updateAuthors` / `updateTags` / `setHidden` / `updateGenre` でローカル状態も即時反映（再フェッチ不要）。
    - `allAuthors` / `allTags` / `allGenres` / `allSeries`: このソースに登録されている全項目の重複排除・日本語ソート済みリスト（フィルター select の選択肢に使用）。
    - `allSeriesWithStats`: `allSeries` に `maxIndex`（シリーズ内最大巻数）と `count`（冊数）を加えた拡張版。`ExistingSeriesOption[]` として一括登録ダイアログの選択肢に使用。
- **シリーズ関連 API**:
    - `assignSeries(path, names, { title, index, id? })`: 既存または新規シリーズに割り当て。`index` は `number | number[]`（配列で複数書籍に個別の巻数を当てられる）。`id` 省略時はバックエンドで `title + 作者集合` のハッシュから生成。
    - `unassignSeries(path, names)`: シリーズから外す。
    - `reorderSeries(path, names, seriesId)`: `names` の順序で `series_index` を `1, 2, 3, ...` に振り直す（DnD ドロップ時に呼ぶ）。**楽観的更新 + 失敗時ロールバック**: ローカル `meta` を即時に書き換えてから API を投げ、失敗時はスナップショットから元の `series_index` を復元する（ドロップ後にカードが元位置に戻ってチラつくのを防ぐ）。
- **その他主要戻り値**:
    - `getSeries(path, name)`: 1 冊のシリーズ情報 `{id, title, index}` を返す（未割当なら null）。`↓` / `↑` ショートカットによる次巻 / 前巻ジャンプの探索元として使用。
    - `getReadState(path, name)`: 読書状態 `'unread' | 'reading' | 'done'` を返す。`meta[key].read_state` があればそれを優先、なければ `view_count` から導出（0 → unread / >0 → reading）。後方互換のため、フィールドが無くても適切に動く。
    - `recordView(path, name)`: 閲覧記録（`view_count` / `last_viewed_at` を加算）。失敗時は黙ってスキップ。成功時は `read_state` も `'reading'` に自動遷移する（既存値が `'done'` の場合は維持）。
    - `setReadState(path, names, state)`: 読書状態を手動で書き換え（PATCH 経由）。`state` は `'unread' | 'reading' | 'done' | ''`（空文字で削除＝派生に戻す）。Reader の最終ページ到達時に `'done'` を立てる用途で使用。

#### `useSeriesSuggestion`（A-1）
- **役割**: 選択された複数冊に対して、既存シリーズへの紐付け候補を取得する（書き込みなし）。`BulkSeriesAssignDialog` の「AI が提案するシリーズに追加」モードから利用。
- **設計**:
    - `useSeriesSuggestion(source, path)` → `{ candidates, loading, error, fetchSuggestions(names), reset() }`。
    - `fetchSuggestions(names)` は `POST /api/series/suggest` を呼び出し、上位候補を `candidates` にセット。`names` が空ならクリアして即 return。
    - エラー時は `candidates=[]` + `error=メッセージ` をセット。トーストは呼び出し元で扱う想定。
    - 失敗握りつぶしはせず、ダイアログ内の error 表示で利用者にフィードバック。

#### `useGenres`
- **役割**: ジャンルリスト（表示順）の取得・追加・削除・並べ替えを管理。
- **設計**:
    - `source` が変わると `GET /api/genres` を再取得。
    - `addGenre(name)` / `removeGenre(name)` / `reorderGenres(newOrder)` でローカル状態も即時反映。
    - `reorderGenres` は楽観的更新 + 失敗時フェッチで復元。
    - `LibraryPanel` が `allGenres`（useBookMeta 由来）の代わりにこのフックを使用する。

#### `useDialogSubmit`
- **役割**: ダイアログ共通の `saving` / `error` 状態と非同期送信ハンドラを抽出（Phase 38）。
- **設計**:
    - `useDialogSubmit(onClose, fallbackErrorMsg?)` → `{ saving, error, setError, handleSubmit }`。
    - `handleSubmit(action)` で `setSaving(true)` → `await action()` → 成功時 `onClose()`、例外時 `setError(e.message)`。
    - 利用元: `BulkAuthorDialog` / `BulkGenreDialog` / `BulkSeriesAssignDialog` / `RenameDialog` / `MergeDialog` の保存パスを共通化（Phase 51 で Rename/Merge を追加）。

#### `useAutoFocusInput`
- **役割**: ダイアログを開いたときに input を自動フォーカスする共通フック（Phase 51）。
- **設計**:
    - `useAutoFocusInput(ref, shouldFocus, { delay?, select? })`。`shouldFocus` が `true` になったタイミングで `setTimeout(delay)` 後に `focus()`、`select: true` 指定時は `select()` も呼ぶ。
    - 旧来は各 Dialog で `useEffect + setTimeout(0/50)` を再実装し、`select()` 有無も不統一だった。
    - 利用元: `RenameDialog`（delay=50, select=true）/ `MergeDialog`（delay=0）。

#### `useTagsInput`
- **役割**: chip 形式の複数値入力 UI で必要な state とイベントハンドラを共通化する（Phase 52 で抽出）。命名は歴史的経緯（タグ機能撤去後も汎用 chip UI として残置）。
- **設計**:
    - `useTagsInput(initialTags?: string[])` → `{ tags, input, inputRef, setInput, addTag, removeTag, handleKeyDown, handleBlur, getFinalTags, reset }`。
    - `handleKeyDown`: Enter / `,` で項目確定、Backspace + 空入力で末尾を削除。
    - `getFinalTags()`: 送信直前に input にあるテキストも含めて重複排除した配列を返す。
    - `reset(next)`: open 時の状態リセットに使う。
    - 利用元: `BulkAuthorDialog`（作者名を chip 形式で複数入力）。

#### `useScrollMemory`
- **役割**: URL キー（`${path}:${source}`）単位でスクロール位置を記憶・復元する（Phase 50）。
- **設計**:
    - `containerRef` と `scrollKey` を受け取り、フォルダ移動時のスクロール位置を保持する。
    - `scrollKey` が変わると保存済み位置に `scrollTop` を復元、次の `scrollKey` 変更時に現在位置を記録。
    - 利用元: `LibraryPanel`（フォルダを行き来した際に前回のスクロール位置に戻る）。

#### `useLibrarySelectionShortcut`
- **役割**: `s` キーによる選択モードトグルのキーボードリスナーを集約する（Phase 50）。
- **設計**:
    - `isEnabled` フラグが `false` のとき（PDF 閲覧中など）はリスナーを外す。
    - 入力中（`<input>` / `<textarea>`）は抑制。
    - 利用元: `LibraryPanel`。

#### `useSeriesEditDialog`
- **役割**: `SeriesEditDialog` の開閉状態と `onAssign` / `onUnassign` ハンドラを集約する（Phase 50）。
- **戻り値**: `seriesEditTarget` / `openSeriesEdit` / `closeSeriesEdit` / `handleSeriesAssign` / `handleSeriesUnassign`
- **設計**:
    - `seriesEditTarget` は `{ name, current, allSeries }` を保持する。
    - `handleSeriesAssign` は API 呼び出し（`PATCH /api/series/assign`）と meta リフレッシュを担う。
    - `handleSeriesUnassign` は API 呼び出し（`DELETE /api/series/unassign/{...}`）と meta リフレッシュを担う。
    - 利用元: `LibraryPanel`（旧来は 20 行分の state + ハンドラがインラインで記述されていた）。

#### `useMetaDerived`
- **役割**: `meta` から派生する集計を `useMemo` でメモ化する純関数フック。
- **戻り値**: `allAuthors` / `allTags` / `allGenres` / `allSeries` / `allSeriesWithStats`（旧: `useBookMeta` が直接保持していたもの）。
- **使い分け**: `useBookMeta` 内部からも呼び出され、外部公開 API を維持しつつ集計責務を分離する。

#### `usePinnedBookSets`
- **役割**: `pinnedBooks`（トップ階層の `favorites_first` ソート用に作者・シリーズ両ピンを混在）と `contextualFavorites`（ドリルダウン中の星表示および `favorites_first` ソート用に文脈別に絞り込んだ Set）を派生計算する。
- **設計**: `meta` / `currentPath` / `seriesPins` / `authorPins` / `authorFilter` / `seriesFilter` から `useMemo` で 2 種類の Set を計算。`LibraryPanel` から派生計算ロジックを抽出。

#### `useSeriesAuthorFilter`
- **役割**: SeriesEditDialog / BulkSeriesAssignDialog に渡すシリーズ選択肢を、対象書籍の作者単位でフィルターする。
- **戻り値**:
    - `isMixedAuthors`: 選択書籍に複数の異なる作者セットが混在しているか（一括「シリーズに登録」ボタンの非活性判定に使用）。
    - `seriesEditFilteredSeries`: `SeriesEditDialog` 用。`seriesEditTarget` の作者に属するシリーズのみ。
    - `bulkSeriesFiltered`: `BulkSeriesAssignDialog` 用。選択書籍の共通作者に属するシリーズのみ。
    - `validSeriesIdsByAuthorKey(authorKey)`: 任意の作者キーから対応シリーズ ID を引くヘルパー。

#### `useLibraryFilter`
- **役割**: PDF一覧のフィルタリングロジック（`useMemo` でメモ化）。
- **設計**:
    - `searchText`（タイトル / 作者 部分一致）/ `authorFilter`（完全一致）/ `genreFilter`（genre フィールド完全一致）/ `seriesFilter`（series_id 完全一致）/ `currentPath` / `showHidden`（ゴミ箱モード）/ `readStateFilter`（読書状態フィルター）の変化でフィルタを再計算。
    - **ジャンルフィルター**: `genre` フィールドの完全一致。未設定書籍は空文字として扱われるため `genreFilter` が空でない場合は除外される。
    - **ゴミ箱方式**: `showHidden=false` のときは `hidden=true` を全件除外、`showHidden=true` のときは `hidden=true` の書籍**のみ** を表示する。
    - **読書状態フィルター**: `readStateFilter` が `'unread' | 'reading' | 'done'` のとき、その状態の書籍のみを表示する。状態は `useBookMetaCore.getReadState(path, name)` で派生取得（`meta[key].read_state` があればそれを優先、なければ `view_count` から導出: 0 → unread / >0 → reading）。`readStateFilter=''` でフィルター無効。後方互換のため、旧 localStorage キー `library_show_unread_only=true` は初回ロード時に `'unread'` へ移行される。
    - `LibraryPanel` から切り出すことでコンポーネントの責務を分離。

#### `useLibraryGrouping`
- **役割**: 書籍リストをシリーズ単位 / 作者単位で集約して仮想ディレクトリ的なカードを生成する。
- **モード** (`GroupMode = 'none' | 'series' | 'author' | 'author-then-series'`):
    - `none`: 集約しない。入力 `pdfs` をそのまま返す。
    - `series`: 同 `series_id` の書籍を集約。代表サムネイルは **最終巻**（`series_index` 最大）。displayTitle は `series_title`。
    - `author`: 同じ作者集合の書籍を集約。代表サムネイルは **入力順の 1 番目**（呼び出し側がソート済みなら「ソート 1 位」）。displayTitle は `{作者名} コレクション`。
    - `author-then-series`: 2 階層モード。`useLibraryGrouping` 自体は **`'series' | 'author' | 'none'` のいずれかに変換された値** を受け取る（モードの解釈は `LibraryPanel` 側で実施）:
        - 階層 1（authorFilter なし）: `author` として集約
        - 階層 2（authorFilter 適用中）: `series` として集約
        - 階層 3（seriesFilter 適用中）: `none` でフラット表示
- **戻り値**: `items` / `badgeByRepresentativeName` (count, kind, groupId, displayTitle, readCount) / `membersByRepresentativeName`。
    - `readCount`: シリーズメンバーのうち `view_count > 0` の冊数。作者集約では常に `0`（未使用）。
    - バッジ表示: シリーズ集約は `readCount/count巻`（例: `3/8巻`）、作者集約は `count冊`（変更なし）。
- **共通**:
    - 集約対象だがメンバーが 1 冊だけのグループは集約しない（単独本扱い）。
    - 元の `pdfs` 順序を可能な限り保つ（代表書籍の元位置に集約カードを表示）。
    - シリーズ・作者ともに `kind` プロパティで PdfGrid 側の装飾（紫枠・バッジ・タイトル差し替え）を切り替える。

#### `useLibraryPins`
- **役割**: シリーズ/作者集約カードの「代表サムネイル固定（ピン）」を管理する。旧 `useFavorites` を置き換え。
- **ストレージ**: ソース別に `pins_series_${source}` / `pins_author_${source}` を localStorage に保存。
- **データ構造**: `PinsMap = Record<groupId, book_name>`。1グループにつき1冊のみ。
  - シリーズ: `groupId = series_id`
  - 作者: `groupId = ソートした作者名を '\n' で結合した文字列`
- **戻り値**: `{ seriesPins, authorPins, toggleSeriesPin, toggleAuthorPin }`
- **ピンの反映**:
  - `useLibraryGrouping` がシリーズ代表選択時に `seriesPins[series_id]` を参照し、ピン済みならその巻を代表にする（なければ従来通り最終巻）。
  - 作者集約でも `authorPins[author_key]` を参照し、ピン済みなら先頭の代わりに使う。
- **クリック時のコンテキスト判定（LibraryPanel の `handleTogglePin`）**:
  - `seriesFilter` あり → シリーズピンを操作（どの巻をシリーズカバーにするか）
  - `authorFilter` あり（`seriesFilter` なし） → 作者ピンを操作（どのカードを作者代表にするか）
  - どちらもなし → `onToggleFavorite` を渡さないため星自体が表示されない
  - `effectiveGroupMode` は判定に使用しない（`seriesFilter` / `authorFilter` の有無のみで決定）
- **星の表示ルール（PdfCard）**:
  - トップ階層（`authorFilter` も `seriesFilter` もなし）: すべてのカードで星なし
  - 作者ドリルダウン中（`authorFilter` あり）: 作者集約カード以外（シリーズ集約・個別本）に星あり
  - シリーズドリルダウン中（`seriesFilter` あり）: 個別本に星あり
  - 判定: `!isSelectionMode && onToggleFavorite && badge?.kind !== 'author'`
- **`contextualFavorites`（PdfGrid の `favorites` 表示用 + ドリルダウン中の `favorites_first` ソート用）**:
  - `pinnedBooks`（シリーズ＋作者ピン混在）の代わりに文脈別のSetを `favorites` に渡す
  - `seriesFilter` 中 → シリーズピン済みの本のみ（星が塗られるのは1冊のみ）
  - `authorFilter` 中 → 作者ピン済みの本のみ（星が塗られるのは1冊のみ）
  - トップ階層 → 空Set（星は表示しないため不要）
- **`useSortedPdfs` への favorites 引数（`favorites_first` ソート用）**:
  - フィルタなし（トップ階層）→ `pinnedBooks`（シリーズ＋作者ピン混在）
  - `seriesFilter` または `authorFilter` あり → `contextualFavorites`（その文脈のピンのみ）
  - 理由: シリーズドリルダウン中に作者ピンの本が先頭に来る・作者ドリルダウン中にシリーズピンの本が先頭に来るのを防ぎ、星の表示と並び順の意味を一致させる。

**検索中の集約抑制（LibraryPanel）**:
- `searchText` が非空のとき、`useLibraryDisplay` へ渡す `groupMode` を強制的に `'none'` にする。
- これにより、グループ集約モード中でも検索テキストがヒットした個別書籍が代表カードではなく直接表示される。
- `authorFilter` / `seriesFilter` によるドリルダウンや breadcrumbs には影響しない（それらは `useLibraryDisplay` 内部で独立して計算）。

**LibraryPanel 側のパンくず計算**:
- ドリルダウン中（`authorFilter` または `seriesFilter` がセット）はパンくずを構築:
    1. 「ライブラリ」（全フィルタークリア）
    2. authorFilter があれば「作者: {名前}」
    3. seriesFilter があれば「シリーズ: {タイトル}」
- 各要素は `ChevronRight` で区切り、最後の要素以外はクリックで該当階層へ戻る。
- パンくず表示中は通常の作者・シリーズフィルター select は隠れる（重複防止）。

#### `usePdfSearch`
- **役割**: PDF内テキスト検索ロジック。`ReaderPanel` から切り出し。
- **設計**:
    - `searchAllPages(text, pdf)` で全ページのテキストを走査してマッチ数・先頭マッチページを算出。
    - `customTextRenderer` で一致箇所を `<mark>` タグでハイライト表示。

#### `useToast`
- **役割**: トースト通知の状態管理。`alert()` の代替。
- **設計**:
    - `showToast(message, type)` で通知を追加。4秒後に自動消去。`type`: `'success'` / `'error'` / `'info'`。
    - `dismissToast(id)` で手動消去。
    - `ToastContainer` コンポーネントと組み合わせて右下に固定表示。

#### `useSpreadMode`
- **役割**: リーダーの見開きモード（Auto / Spread / Single）と Auto 時のページサイズ判定を一元管理。`ReaderPanel` から切り出し。
- **戻り値**: `spreadMode`, `isSpread`, `cycleSpreadMode`, `handlePageSize`, `resetAutoSpread`
- **挙動**:
    - `spreadMode === 'auto'` 時のみ `handlePageSize(width, height)` で `autoIsSpread` を更新。
    - 横長判定は `width > height * 1.2` の閾値方式（センターカラー等の見開き原稿を検出）。閾値超え → 即 `false` 確定（1 ページ表示）。縦長・正方形に近いページは何もしない（初期値 `true` を維持）。
    - 左右両ページから通知される設計のため「片方でも横長を検出すれば 1 ページ表示」となる。ペア切替時の再判定は呼び出し側 (`ReaderPanel`) が `pageNumber` 変化時に `resetAutoSpread()` を呼ぶ。
    - `spreadMode === 'spread' / 'single'` の場合は `handlePageSize` は no-op。

#### `useEditMode`
- **役割**: リーダーの編集モード（ページ選択 + 削除 + 並び替え）を一元管理。`ReaderPanel` から切り出し。
- **UX**: `e` キーまたはヘッダーの編集ボタンで `isEditMode` を ON にすると `<PageGridOverlay>`（全画面オーバーレイ）が開き、全ページのサムネイルグリッドからページをマーク → 「削除実行」で一括コミット。マーク方式（オーバーレイ内では何度でも変更可、確定は確認ダイアログ経由）。並び替えは各カードのドラッグハンドルから DnD 操作し、ドロップ時に即時 API 呼び出し（B-3）。リーダー画面本体のページ上で直接クリック選択する旧 UX は廃止。
- **設計**:
    - 削除確認は OS ネイティブ `confirm()` を使わず、フック側で「削除待ち件数」(`pendingDeleteCount`) を保持し、呼び出し側 (`ReaderPanel`) が `<ConfirmDialog>` を表示する。
    - `requestDeletePages()` で確認ダイアログを開く → `confirmDeletePages()` で API 削除実行、`cancelDeletePages()` でキャンセル。
    - 選択 state (`selectedPages`) は `<PageGridOverlay>` 内のクリック / Shift+クリックで操作。`togglePageSelection(pNum, e)` は単発トグル、Shift キー押下時は `selectRange(from, to)` で範囲一括追加（範囲選択用に `lastClickedPage` を保持）。
    - **並び替え** (`applyReorder(newOrder: number[])`、B-3): `newOrder[i]` は「新しい位置 `i+1` に配置する元ページの 1 始まりページ番号」。フックは `POST /api/pdfs/{filename}/reorder_pages` を呼んで成功時に `bumpPdfVersion()` + `onPdfUpdated()` を実行。同時に `selectedPages` を新しい配置に追従させる（旧ページ番号 P が選択されていたら、新位置 `newOrder.indexOf(P) + 1` に置き換える）。失敗時はエラーメッセージをトーストで通知し state は変えない。
- **戻り値**: `isEditMode`, `selectedPages`, `toggleEditMode`, `togglePageSelection`, `selectRange`, `resetEditMode`, `requestDeletePages`, `confirmDeletePages`, `cancelDeletePages`, `pendingDeleteCount`, `applyReorder`

#### `useFullscreen`
- **役割**: Document Fullscreen API のラッパー。リーダー画面のフルスクリーン切り替え。
- **設計**:
    - `document.fullscreenElement` の有無で `isFullscreen` を判定。
    - `fullscreenchange` イベントを購読してブラウザ UI / Esc キー経由の解除も追従する。
    - `toggleFullscreen()` は失敗時（ユーザー拒否・iframe 等）は黙ってスキップ。
- **戻り値**: `isFullscreen`, `toggleFullscreen`

#### `useReaderShortcuts`
- **役割**: リーダー画面のキーボードショートカットを 1 か所に集約する。
- **キー割り当て**:
    - `f` — フルスクリーン切替
    - `e` — 編集モード切替
    - `?` — ショートカット一覧モーダル表示
    - `Ctrl+F` / `Cmd+F` — 検索バーを開く
    - `↓` — 次の巻へ（シリーズ未所属または次巻なしの場合は無効）
    - `↑` — 前の巻へ（シリーズ未所属または前巻なしの場合は無効）
- **設計**:
    - 入力中（`<input>` / `<textarea>` / `contentEditable`）の場合はキー割り当てを抑制する。
    - `isActive` フラグで PDF リーダーがアクティブな間だけ動かす。
    - `←` / `→` のページ送りは `useReaderNavigation` が管理。`↓` / `↑` のシリーズ巻間移動は本フックが管理。
    - `onNavigateNextVolume` / `onNavigatePrevVolume` が `null` のとき（次巻/前巻なし）は何もしない。
- **引数**: `{ isActive, onToggleFullscreen, onToggleEditMode, onOpenHelp, onToggleSearch, onNavigateNextVolume, onNavigatePrevVolume }`

#### `useReaderInput`
- **役割**: `useReaderShortcuts` のブリッジ層（Phase 58）。`hasNextVolume / hasPrevVolume` の有無と `onSelectPdf` の存在チェックを内包し、条件を満たさない場合はハンドラーを `null` にして無効化する。
- **引数**: `{ toggleFullscreen, toggleEditMode, openHelp, openSearch, hasNextVolume, hasPrevVolume, onSelectPdf, onNavigateNextVolume, onNavigatePrevVolume }`
- **設計**: `onSelectPdf` が未提供の場合は両ナビゲーションを `null`。`hasNextVolume=false` なら次巻 `null`、`hasPrevVolume=false` なら前巻 `null`。

#### `useReaderState`
- **役割**: `ReaderPanel` が使う全 hook の集約コンテナ（Phase 58）。15 以上の hook 呼び出しを 1 フックに束ね、JSX 側に必要な ~45 プロパティを一括返却する。
- **設計**: `useReaderInput` を内部で呼ぶ。副作用（imageMode 同期・selectedPdf リセット・pageNumber リセット）も本フックに集約。依存 hook への引数と返却値の組み立てロジックをすべて担うことで、`ReaderPanel.tsx` 本体を純 JSX オーケストレーター（168行）に保つ。

#### `useBookImages`
- **役割**: 書籍の画像URL一覧を取得し、画像モード/PDFモードを判定する。
- **設計**:
    - `selectedPdf` が変わると `GET /api/books/{bookPath}/images` を呼び出して画像URLを取得。
    - 画像が取得できた場合は `isImageMode=true`（画像モード）、失敗した場合は `isImageMode=false`（PDFモード）。
    - **`novel` ソースは画像取得をスキップして PDFモードを強制する**。`kindle_novel/images/` に PNG ファイルが存在するが、このソースの目的は Searchable PDF のテキスト検索にあるため、PDF モードで表示する必要がある。
    - **再フェッチトリガー**: `selectedPdf` / `currentPath` / `source` のいずれかが変わったとき、または `version`（オプション）が変わったときに再フェッチする。`version` は `usePdfDocumentState.pdfVersion` を渡す想定で、ページ削除（`useEditMode.confirmDeletePages`）後に `bumpPdfVersion()` が呼ばれて画像リストが更新される。`generated` ソースの image-only モードでもページ削除後に表示が即時追従する。
    - **flicker 防止のための effect 分割**: 状態リセット用 effect（deps: `selectedPdf` / `currentPath` / `source`）と画像取得用 effect（deps: 同 + `version`）を分離する。`version` のみ変化したときは古い `imageUrls` を保持したまま新しいリクエストを発行し、到着次第差し替える。これをやらないと version 変化のたびに `imageUrls=null` を経由して `isImageMode=false` に倒れ、`generated` ソースで存在しない PDF を `<Document>` が取りに行って削除直後にエラーが出る。

#### `useReaderNavigation`
- **役割**: リーダーのページナビゲーション（前/次ページ、ページジャンプ、リセット）を管理。
- **依存**: `numPages`, `isSpread`, `direction`, `isActive`
- **主要戻り値**: `pageNumber`, `setPageNumber`, `handleNext`, `handlePrev`, `resetPage`

#### `useUrlState`
- **役割**: ViewerPage の URLパラメータ (`?path=`, `?file=`) 同期を一元管理。
- **URL に同期する LibraryPanel 側のフィルター**（`useUrlState` 直下ではなく `LibraryPanel` で `useSearchParams` を直接利用）:
    - `?author=` — 作者フィルター
    - `?series=` — シリーズフィルター（series_id）
    - これらにより、シリーズ / 作者カードでドリルダウンした後にブラウザの戻るボタンで元の一覧に戻れる。
    - `searchText` は入力ごとに履歴汚染を避けるため URL 同期しない。
    - フォルダ移動・PDF 選択時には `useUrlState` の navigate メソッドが `setSearchParams({ path, ... })` 形式で**全パラメータを置き換え**るため、これらフィルターは自動的に消える。
- **設計**:
    - `useSearchParams` ラッパー。`currentPath` / `selectedPdf` を導出して返す。
    - ナビゲーション操作を関数として提供し、ViewerPage での状態二重管理を排除。
    - ソース（doujin/comic/novel）は URL パスから判定（`useCurrentSource` 参照）。
- **主要メソッド**:
    - `navigateIntoFolder(dirName, basePath)`: フォルダ内に移動（`?path=` を更新）。
    - `navigateUp(currentPath)`: 親階層へ戻る。
    - `selectPdf(pdfName, currentPath)`: PDF を選択（`?file=` を追加）。
    - `clearPdf(currentPath)`: PDF選択を解除してライブラリに戻る。

#### `useCurrentSource`
- **役割**: `useLocation().pathname` から現在の `LibrarySource`（`'doujin'` / `'comic'` / `'novel'`）を導出。
- **設計**: `/comic` 始まり → `'comic'`、`/novel` 始まり → `'novel'`、それ以外（`/doujin`）→ `'doujin'`。URL クエリ管理なし。`LibraryContext` と各コンポーネントで利用。

### 2.3 Utilities

`frontend/src/utils/` 配下の純関数。複数 hooks / コンポーネントから共通利用する小さなロジック。

#### `cmpJa` (`frontend/src/utils/sort.ts`)
- **役割**: 日本語ロケール文字列比較の共通関数（Phase 53）。
- **設計**: `cmpJa(a, b) = a.localeCompare(b, 'ja')`。`Array.prototype.sort` の比較関数として直接渡せる。
- **利用元**: `useSortedPdfs`（PDF 名昇順・降順・タイブレーク）、`useMetaDerived`（作者/ジャンル/シリーズタイトルの昇順ソート）。旧来は `localeCompare('ja')` がこれら 2 ファイル計 11 箇所に直書きされていた。

#### `authorsKey` (`frontend/src/utils/authors.ts`)
- **役割**: 作者集合をグループ化キー（文字列）に変換する共通関数（Phase 54-4）。
- **設計**: `authorsKey(authors) = [...(authors ?? [])].sort().join('\n')`。元配列を破壊せず、`null` / `undefined` も空文字に正規化する。区切り文字は作者名に通常含まれない `'\n'`。
- **利用元**: `LibraryPanel` / `useLibraryGrouping` / `usePinnedBookSets` / `useSeriesAuthorFilter` の 9 箇所で `[...authors].sort().join('\n')` が散在していたのを集約。

#### `formatTimestampJa` / `formatDateJa` / `formatDateTimeJa` (`frontend/src/utils/date.ts`)
- **役割**: 日付フォーマットを集約（Phase 54-6）。
- **設計**:
    - `formatTimestampJa(unixSec)`: Unix 秒（10 桁）を `YYYY/MM/DD` 風の OS ロケール表記に。`null` / `undefined` / `0` / 不正値は空文字。
    - `formatDateJa(iso)`: ISO 文字列を `2026/05/06` 形式（`ja-JP` の年月日）に。パース失敗時は元の ISO をそのまま返す。
    - `formatDateTimeJa(iso)`: ISO 文字列を `2026/05/06 12:34:56` 形式（`ja-JP` の日時）に。`null` / `undefined` は em-dash `'—'` を返し、パース失敗は元の ISO をそのまま返す。
- **利用元**: `PdfCard` / `HitomiArrivalCard` / `HitomiPage` の `new Date(...).toLocaleDateString()` 等を集約。

#### `errorMessage` (`frontend/src/utils/error.ts`)
- **役割**: `unknown` 値からエラーメッセージを抽出（Phase 54-5）。
- **設計**: `errorMessage(e, fallback) = e instanceof Error ? e.message : fallback`。
- **利用元**: 11 ファイルに散在していた `e instanceof Error ? e.message : "..."` 三項演算をすべて置換。`useDialogSubmit` / `useAsyncToast` の内部実装でも使用。

### 2.4 共通 UI プリミティブ

`frontend/src/components/ui/` 配下。アプリ全体で再利用するボタン / アラート / ダイアログ等の素材コンポーネント。デザイントークンも本セクションに含める。

#### デザイントークン（`tailwind.config.js`）

UI 全体の色を Tailwind の色名（`indigo-600` 等）にハードコードせず、**用途別のセマンティックトークン**経由で参照する。

- `primary-*`: 主 CTA（= indigo パレット）。ボタン・主要アクション・選択中の境界線に使う。
- `accent-*`: グループ化・トグル ON 状態（= purple パレット）。シリーズ集約カード（バッジ・枠・タイトル色）・グループモードバッジ・パンくず最終項目・Reader ヘッダーのモードトグル（見開き Auto / 検索 / 編集モード）・ドラッグハンドル hover など「アクティブ／集約系」の装飾全般。**例外**: form 要素の `accent-color` プロパティ用 `accent-purple-600` / `accent-primary-600` は Tailwind 組み込み色をそのまま使う（`accent-accent-600` という冗長な名前を避けるため）。
- 意味的役割を担う独自色（token 化対象外）:
    - `amber-*`: お気に入り星マーク / 選択中カードのハイライト
- `success-*`: 成功・hitomi 系（= emerald パレット）。
- z-index: `z-card-badge` / `z-floating-action` / `z-overlay-bar` / `z-header` / `z-toast` / `z-dialog` / `z-dialog-nested` を `tailwind.config.js` で定義済み。新規 floating UI を追加する際はこの階層を使うこと（`z-[40]` のような任意値は使わない）。

トークンは Tailwind のカラーパレット形式（50-950 のシェード）。各画面が独自に `bg-blue-600`・`bg-indigo-600` を混ぜていた状態を解消する目的で導入。**既存の `bg-indigo-*` 直書きは段階的に `bg-primary-*` に置換**していく方針（Phase B 以降）。

#### `Button` (`frontend/src/components/ui/Button.tsx`)
- **役割**: アプリ全体で再利用するボタンコンポーネント。`size × variant` の 2 軸で見た目を切り替える。
- **Props**: 標準の `ButtonHTMLAttributes<HTMLButtonElement>` をすべて受け取る + `variant` / `size` / `className`（追加クラスは末尾結合）。
- **`variant`**:
    - `primary`（既定）: `bg-primary-600` ベース。主 CTA。
    - `secondary`: `bg-gray-100 dark:bg-gray-800` ベース。サブアクション・トグル OFF 状態。
    - `danger`: `bg-red-600` ベース。削除など破壊的操作。
    - `ghost`: 背景なし、ホバー時のみ淡色。アイコンボタン用途。
- **`size`**:

#### `PageGridOverlay` (`frontend/src/components/reader/PageGridOverlay.tsx`)
- **役割**: 編集モード時に開く全画面オーバーレイ。全ページサムネイルをグリッド表示し、削除対象ページのマーク（複数選択）と一括削除、および DnD によるページ並び替え（B-3）を行う。
- **構造**: `fixed inset-0 z-dialog` の暗背景レイヤー上に、ヘッダー（ページ数 / 選択件数 / `×` 閉じる）+ サムネイルグリッド + フッター（「削除実行」ボタン）の 3 段構成。グリッドは `<DndContext>` + `<SortableContext>`（@dnd-kit/sortable）でラップする。
- **サムネイル取得**:
    - 既存 `GET /api/thumbnails/page?name=...&page=N&path=...&source=...&width=180` を流用（バックエンド改修なし）。
    - `generated`: `images/{book}/` 配下の WebP を直接返却 → 即時表示。
    - `kindle` / `novel`: fitz でレンダリング → JPEG。ブラウザの HTTP キャッシュ（`Cache-Control: max-age=3600`）が効くため 2 回目以降は瞬時。
    - 並列度 4 で `<img>` を一斉に発行（ブラウザのコネクション上限内で自然に直列化される）。生成中はスケルトン枠 + ページ番号のみを表示。
    - 削除実行後のキャッシュ無効化: URL に `&v={pdfVersion}` を付与してバージョン違いで別キャッシュ扱い（`pdfVersion` は `confirmDeletePages` / `applyReorder` の中で `bumpPdfVersion` 経由で 1 増える）。
- **選択 UX**:
    - クリックで個別トグル（`useEditMode.togglePageSelection`）。
    - **Shift+クリックで範囲選択**（直近クリック位置から現在位置までを一括追加）。`lastClickedPage` をオーバーレイ内 state で保持。
    - 選択済みページは `ring-4 ring-red-500` + 右上 `<CheckSquare>` で表示（既存 `PageRenderer` の選択 UI と整合）。
- **並び替え UX (B-3)**:
    - 各カードの**左上に GripVertical アイコンのドラッグハンドル**を追加。`<DragOverlay>` は使わず、ハンドル領域でだけドラッグを反応させる（カード本体のクリック = 選択トグルを温存）。
    - **単独 drag**: 起点カードが未選択の場合、そのカード 1 枚だけが移動する（`arrayMove` 相当）。選択状態には触れない。
    - **グループ drag**: 起点カードが選択済みの場合、選択中の全カードを **元の相対順を保ったまま** 移動先付近にまとめて挿入する（非連続な選択も 1 つの塊として動く）。アルゴリズムは `moveMultipleByIndex(arr, movedIndices, activeIndex, targetIndex)` を `frontend/src/utils/sort.ts` に追加して使用。
    - **ドロップ位置の semantic（AT 方式）**: active アイテム（ユーザーが実際にドラッグしたカード）が結果配列の `targetIndex` に着地するようグループ全体を配置する（`arrayMove` と同じ「ドロップ先の位置に active が来る」挙動で @dnd-kit のドラッグ中プレビューと一致）。グループの先頭は `targetIndex - activeOffsetInMoved` を `[0, remaining.length]` でクランプした位置に挿入される。
    - **コミット契機**: ドロップ即時に `useEditMode.applyReorder(newOrder)` を呼んで API へ送る。**確認ダイアログなし**（並び替えは取り消し可能で破壊性が低いため）。
    - **楽観的 visual update**: API 完了前にローカル `localOrder` state を newOrder に切り替えて視覚的に並び替え後の表示を見せる。API 失敗時はトーストで通知して localOrder を元に戻す。
    - **localOrder のリセット**: `numPages` または `pdfVersion` が変わったら identity（`[1, 2, ..., N]`）にリセットして、次の drag 操作のための状態を整える。
    - **選択の追従**: `applyReorder` は API 成功時に `selectedPages` を変換する（旧ページ番号 P が選択されていたら、新位置 `newOrder.indexOf(P) + 1` に置き換える）。これによりマークがページに紐づいて一緒に移動する。
- **削除実行**: フッターの「削除実行」ボタン（選択 0 件時は disabled）→ `requestDeletePages()` → `<ConfirmDialog>` → `confirmDeletePages()`。完了後、`useEditMode` 側で `selectedPages` がリセットされ、PDF 再ロード（`pdfVersion` 増加）でオーバーレイ内のサムネイルもバージョン付き URL で再取得される。
- **閉じる導線**: ヘッダーの `×` ボタン / Esc キー / ヘッダー外のオーバーレイ背景クリックは無効（誤操作防止）。`useEditMode.toggleEditMode()` を呼んで `isEditMode` を OFF にする。
- **キーボードショートカット**: 既存 `e` キーは引き続き編集モードトグル（オーバーレイ open/close と同期）。

    - `spreadMode: SpreadMode` — `'auto' | 'spread' | 'single'` の3状態。

    - `cycleSpreadMode()`: Auto → Spread → Single → Auto の順で循環。
    - `handlePageSize(width, height)`: `spreadMode === 'auto'` 時のみ動作。`width > height * 1.2`（横長 = センターカラー等の見開き原稿）なら 1 ページに確定、それ以外は何もしない（初期値の見開きを維持）。

    - `onDocumentLoadSuccess`: PDF ロード完了時点で `searchText` が入力済みの場合は即座に `searchAllPages` を呼び出す。
    - 検索バー (`PdfSearchBar`) は `isSearchOpen === true` の間は常に表示（`showHeader` とは独立）。
    - `ReaderHeader` は `showHeader || isSearchOpen` で検索中は常に表示。

    - **前巻探索**: `usePrevSeriesVolume(meta, getSeries, currentPath, selectedPdf)`。`series_index` が現在より小さい中で最大のエントリを選ぶ。

    - `onSelectPdf` は `ViewerPage` から `LibraryContext.onPdfClick` を渡す。

#### 一括操作後の選択モード自動解除（`useLibraryManagement` / `LibraryPanel`）
- **役割**: 作者・シリーズ・非表示・結合・サムネイル再生成の各バルク操作が **成功** したら、選択モードを抜けてチェックボックスを消し通常表示に戻す。

    - `LibraryPanel` の `handleBulkApplyAuthors` / `handleBulkAssignSeries` / `handleBulkToggleHidden` / `handleBulkDelete` / `handleMergePdfs` / `handleRegenThumbnailBulk` の **成功パス末尾** で `onClearSelection()` を呼ぶ。
    - `handleBulkDelete`: 非表示書籍専用の完全削除。`window.confirm` で確認後 `DELETE /api/pdfs` を呼び出す。失敗時は throw 経路でスキップされるため選択は残りリトライ可能。

#### 集約カードの一括選択（E-3）
- **挙動**: 選択モード中に集約カード（シリーズ / 作者グループの代表カード）をチェックすると、そのグループの全メンバーが一括で選択 / 解除される。

- **実装**:
    - `useLibraryManagement.bulkSelectItems(names: string[], select: boolean)`: 1 回の `setSelectedItems` 呼び出しで原子的に複数アイテムを add / remove。
    - `LibraryContext` に `onBulkSelect: (names: string[], select: boolean) => void` として公開。
    - `LibraryPanel` で `handleToggleSelect` ラッパーを作成。`grouped.membersByRepresentativeName.get(name)` が存在する場合は全メンバー名を `onBulkSelect` に渡す。存在しない（単独本）場合は通常の `onToggleSelect` を呼ぶ。
    - `PdfGrid` の `onToggleSelect` prop を `handleToggleSelect` に差し替え。
- **表示**: グループ全員が `selectedItems` に入るため、代表カード自体（`membersByRepresentativeName` に含まれる）も `isSelected=true` になり amber 枠で選択状態を示す。

### 3.1 LibraryHeader の 3 段構成

> 2026-04-29 再編。
- **役割**: ライブラリ画面のヘッダー。**責務分離**のため 3 段に再編。

### 3.2 スクロール位置保持

`ViewerPage` + `LibraryPanel` の協調。

ライブラリ ↔ PDF / シリーズ詳細 / 作者ドリルダウンといった画面遷移を行った後、戻る操作で**前回のスクロール位置に復帰する**ための仕組み。

- **問題**: SPA で URL が変わると React 再レンダリングでスクロールが 0 に戻る。条件分岐レンダー（`{selectedPdf ? <Reader/> : <Library/>}`）では `LibraryPanel` がアンマウントされるため DOM のスクロールも消える。
- **実装**:
    1. **`ViewerPage`**: `LibraryPanel` を常時マウントし、PDF 表示中は `display:none`、それ以外は `display:contents` で切り替える。これで DOM ノードと一緒にスクロール位置を維持できる。`ReaderPanel` は従来どおり条件付きマウント。
    2. **`LibraryPanel`**: `useRef<Map<string, number>>` でスクロール位置を **URL キー** ごとに保存する。URL キーは `${currentPath}|${currentSource}|${authorFilter}|${seriesFilter}|${selectedPdf ?? ''}` の組合せ。
        - **保存タイミング**: `document` の `click` イベント（**capture phase**）で `window.scrollY` を「現在の URL キー」に紐づけて保存する。capture phase なので React のクリックハンドラ（= `setSearchParams` を呼ぶ前）に確実に走る。
        - **復元タイミング**: URL キー変化を監視する `useEffect` で `requestAnimationFrame` 内に `window.scrollTo(0, targetY)`。レイアウト確定後に走らせるため `display:contents` 復帰や displayPdfs 変更の reflow を待てる。
        - **初回マウント**: `isFirstRenderRef` で初回だけ復元をスキップ（直接アクセス時のスクロールを尊重）。
- **スクロール対象**: ライブラリの実際のスクロールコンテナは `<html>`（= `window`）。Layout の `main.flex-1` が高さ固定でないため、コンテンツ全体がページレベルでスクロールする構造になっている。`window.scrollY` / `window.scrollTo` で扱える。
- **既知の制限**: クリック以外で URL を変える操作（ブラウザバック / 直接 URL 入力）は capture phase でカバーされない。ただしブラウザバックは標準のスクロール復元が働くため実害は少ない。

### 3.3 UI スタイル規約（ボタン色 / 読書状態バッジ / 選択モード）

#### ボタン色規約（全画面共通）

全画面で以下の 3 色規約を統一して使用する。

- **Primary** (`bg-indigo-600 text-white hover:bg-indigo-700`): 「実行する」操作。
    - Library: 一括アクション群（作者設定 / シリーズ登録 / 非表示 / 結合 / サムネイル再生成）
    - Dialog: `DialogPrimaryButton`（全ダイアログの確定ボタン）
    - OCR: Start OCR ボタン
- **Secondary** (`bg-gray-100 dark:bg-gray-800 text-gray-700 dark:text-gray-300 hover:bg-gray-200 dark:hover:bg-gray-700`): 中立・補助・取消。選択モード起動 / ツール開閉 / キャンセル / `DialogCancelButton`。
- **Danger** (`bg-red-600 text-white hover:bg-red-700`): 破壊的・回復不能な操作。OCR Stop ボタン / `ConfirmDialog` の `danger=true` 確認ボタン / Reader のページ削除ボタン。
- **Active tint (トグル ON)**: 現在 ON のトグルは indigo tint（`bg-indigo-100 dark:bg-indigo-900/40 text-indigo-700 dark:text-indigo-300`）または `bg-gray-700 text-white` で表示。
    - Reader: Search / Edit モード ON 時は indigo tint
    - Library: 非表示モード ON 時は `bg-gray-700 text-white`（Secondary active）
- **ナビゲーション**: `bg-indigo-600` を使用。
- **方針**: 旧設計の多色（blue / purple / emerald / amber など）を上記 3 色に集約。色ではなくアイコン + 文字で操作を区別する。`<select>` はネイティブスタイルを維持。

#### 読書状態バッジ（PdfCard）
- **条件**: `isGroup=false` かつ `readState !== undefined` のカードに表示
- **状態と表示**:
    - `'unread'` → "NEW" バッジ（`bg-sky-500 text-white`）
    - `'reading'` → "📖" バッジ（`BookOpen` アイコン、`bg-accent-500 text-white`）
    - `'done'` → "✓" バッジ（`Check` アイコン、`bg-emerald-500 text-white`）
- **配置**: カード下部の日付・アクション行（`flex items-center gap-1`）内、お気に入り星アイコンの隣に inline 表示
- **スタイル共通**: `text-xs font-semibold px-1.5 py-0.5 rounded-full leading-none`
- **派生**: `readState` は `useBookMetaCore.getReadState(path, name)` で算出。`meta[key].read_state` があればそれを優先、なければ `view_count` から導出（0 → unread / >0 → reading）。
- **渡し方**: `LibraryPanel` → `PdfGrid`（`getReadState` prop）→ `buildCardProps` → `PdfCard`（`readState` prop）→ `PdfCardActionButtons`
- **サムネイル領域に置かない理由**: シリーズ DnD 時のドラッグハンドルや集約バッジと重なるため
- **読書状態の遷移**:
    - **自動 (unread → reading)**: `recordView` 成功時、ローカル merge で「既存 read_state が無いか 'unread' なら 'reading' に書き換える」（`done` は維持）。バックエンド側の自動遷移と整合。
    - **自動 (reading → done)**: `ReaderPanel` で `isAtLastSpread && readState !== 'done'` を満たすとき `setReadState(path, [name], 'done')` を 1 度だけ呼ぶ（`useRef` で多重発火ガード、`selectedPdf` 切替でリセット）。
    - **手動**: `setReadState(path, names, state)` を `useBookMetaWrite` から提供（PATCH 経由）。空文字で削除すると派生に戻る。

#### 選択モードの視覚スタイル（PdfGrid）
- **選択中カード**: `border-amber-400` の枠 + `bg-amber-50 dark:bg-amber-900/20` の薄い琥珀色背景で表示。
- **PdfGrid のカード本体パネル**（サムネイル下部の書名・作者・日付エリア）も同じ条件で背景色を切り替える。サムネイル領域は画像で覆われるため枠と本体パネルの両方を着色することで選択状態を明確化する。
- **チェックアイコン**: 選択時は `text-amber-500` の `CheckSquare`、未選択時は `text-gray-400` の `Square`。

#### 関連書籍ページ（ReaderPanel）

最終ページの「次の仮想ページ」として「同シリーズ / 同作者」の関連書籍を提示する専用ページ。要件 A-2 / A-5。

- **遷移条件**: `isAtLastSpread` のときに次へ送り操作（クリック / 矢印キー / エッジホバー）を行うと専用ページに切り替わる。関連書籍が 0 件の場合は遷移せず最終ページに留まる。
- **戻り操作**: 関連書籍ページで前へ送ると最終ページに戻る（`pageNumber` は変えない）。
- **本切替時**: `selectedPdf` が変わったら自動的にフラグをリセット（最終ページではなく本の冒頭から始まる既存挙動を維持）。
- **データソース**: `useRelatedBooks` が返す `meta` 由来の同シリーズ / 同作者リスト。
- **セクション**:
    1. **同シリーズ**: `series_id` 一致 ＆ 自分を除く ＆ 同フォルダ。`series_index` 昇順、最大 8 件。
    2. **同作者**: 作者集合に少なくとも 1 人共通。同フォルダ ＆ 自分・同シリーズメンバーを除外。最大 5 件。
- **同フォルダ判定**: `useNextSeriesVolume` と同じ key prefix 比較ロジックを `useRelatedBooks` 内のヘルパで共有。
- **レイアウト**: 画面中央に書籍カードのレスポンシブグリッド（`grid-cols-2 md:grid-cols-3 xl:grid-cols-4`）。見開きモードに依らず単独中央表示。
- **カード構成**: 1 ページ目のサムネイル（`/api/thumbnails/page?page=1` をオンデマンド生成）+ タイトル。同シリーズカードは左上に `#{series_index}` バッジ。
- **ヘッダ表示**: 関連書籍ページ中はページ番号インジケータ（`{pageNumber} / {numPages}`）と PageSlider を非表示にする。
- **`read_state='done'` の発火**: 既存の最終ページ到達トリガーを維持（関連書籍ページに遷移する前に 1 度発火する）。
- **書籍切替**: カードクリックで `recordView` → `onSelectPdf(name)`。新書籍は冒頭ページから開く（既存の `handleSelectRelated` 経路）。
- **実装ポイント**: `useReaderNavigation` に `onNextAtEnd` / `onPrevIntercept` の任意コールバックを追加し、ReaderPanel 側で `isOnRelatedPage` ステートを操作する。`handlePrev` の先頭で intercept が true を返したら通常のページ戻し処理をスキップする。

### 3.4 SeriesEditDialog のシリーズ選択肢を作者単位でフィルター

**概要**  
現在 `SeriesEditDialog` に渡す `allSeries` は、ソース内の全シリーズ（作者問わず）を一覧表示している。  
同一作者に属するシリーズのみを表示するよう絞り込むことで、誤った作者へのシリーズ割り当てを防ぎ、選択肢を大幅に減らせる。

**実現可能性**  
- `meta` オブジェクトは全書籍の `authors` と `series_id` を持っており、クライアント側で「作者 → シリーズ一覧」を導出できる。
- `series_id` は `hash(seriesTitle + authors)` で生成されるため、同名シリーズでも作者が違えば別 ID になり、作者単位フィルターとアーキテクチャが整合している。

**実装方針**  
1. `LibraryPanel.tsx` で `seriesEditTarget`（編集対象書籍）の `authors` を取得する。
2. `meta` をスキャンして、`seriesEditTarget` の `authors` と一致する書籍が持つ `series_id` のみを抽出し、フィルター済みのシリーズリストを `SeriesEditDialog` に渡す。
3. `BulkSeriesAssignDialog`（複数書籍一括）も同様にフィルターを適用する。選択書籍の authors をすべて集約し、その作者のシリーズのみを表示する。
4. 選択書籍に**複数の異なる作者が混在する場合は、一括アクションバーの「シリーズに登録」ボタンを非活性化**する（ダイアログを開かせない）。複数作者をまたぐシリーズ登録は運用上想定しない。

**実装箇所（一括アクションバー）**  
- `LibraryHeader.tsx` または `useLibraryBulkActions.ts` 内の「シリーズに登録」ボタン制御部で、`selectedItems` の authors を集約し、ユニークな作者セットが 2 種類以上あれば `disabled` にする。

**エッジケース**  
- 対象書籍の `authors` が空の場合は全シリーズを表示（フォールバック）。
- 書籍に複数の作者がある場合は、いずれかの著者が一致するシリーズを表示。
- **採用理由**: 従来の `border-blue-500` はダークモード（`bg-gray-800` 背景）で視認性が低く、UI 内の他の青系要素とも紛らわしかったため、アクセント色として琥珀（amber）に変更。両モードで高コントラスト。

### アクセシビリティ（a11y）の現状と将来課題

**現状**: 個人 LAN シングルユーザーツールという [信頼モデル](セキュリティ設計書.md) のもと、a11y は最低限のみ対応:

- ✅ Dialog 共通シェル（[Dialog.tsx](../../frontend/src/components/ui/Dialog.tsx)）の閉じるボタンに `aria-label="閉じる"` あり
- ✅ Esc キー / 外クリックでダイアログ閉じる
- ✅ Tab キー操作は React + 標準 HTML 要素のデフォルト挙動を維持
- ✅ `: any` 禁止 / Hooks 規約遵守などのコード品質
- 🟡 **アイコンのみのボタンは `title=` 属性のみで運用**（80 箇所程度、ReaderHeader / LibraryBulkActionBar / PdfCardActionButtons 等）。`aria-label` 併用ではないためスクリーンリーダーで読み上げが弱い
- 🟡 **ランドマーク `role`（main / navigation / complementary 等）は未指定**。`Alert` のみ `role="alert"` 設定あり
- 🟡 **`eslint-plugin-jsx-a11y` 未導入**

**判断**: スクリーンリーダー利用を前提としていないため未対応で受容。将来 LAN 外公開や視覚障害者ユーザー想定が出たら、以下の順で対応:

1. `eslint-plugin-jsx-a11y` 導入で機械的検出
2. アイコンのみボタンに `aria-label` 付与（特に LibraryBulkActionBar / ReaderHeader / PdfCardActionButtons）
3. ランドマーク role 設定（Layout / LibraryPanel / ReaderPanel）
4. フォーカストラップ（Dialog 内 Tab 巡回の閉じ込め）の追加検討

新規候補は §3 への追記または `docs/06_リファクタリング/リファクタリング計画書.md` に登録する。
