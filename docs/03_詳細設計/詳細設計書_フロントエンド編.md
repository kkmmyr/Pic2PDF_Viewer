## 2. クラス設計

### 2.1 Context

`frontend/src/contexts/` 配下。Provider と useXxxContext のセット。

#### `LibraryContext` (`frontend/src/contexts/LibraryContext.tsx`)
- **役割**: ViewerPage が LibraryPanel に渡していた 21 個の props を Context に集約し、Props Drilling を解消する。
- **設計**:
    - `LibraryProvider`: `useUrlState` + PDF フェッチ + `useLibraryManagement` を内包し、`LibraryContext.Provider` で子にデータを提供。
    - `useLibraryContext()`: Provider 外で呼ばれると `throw Error` するカスタムフック。
    - `ViewerPage` は `LibraryProvider` でラップするだけの薄い構造になる。
    - `LibraryPanel` は props を受け取らず `useLibraryContext()` で必要な値・ハンドラを取得する。
- **提供する値 (LibraryContextValue)**:
    - 状態: `pdfs`, `selectedPdf`, `currentPath`, `currentSource`, `isSelectionMode`, `selectedItems`, `renameTarget`
    - ナビゲーション: `onPdfClick`, `onFolderClick`, `onUpClick`, `onSourceChange`, `onClosePdf`, `onPdfUpdated`
    - ダイアログ操作: リネームの開閉・実行ハンドラ群
    - `onRefresh`: PDF 一覧の再取得

### 2.2 Hooks

`frontend/src/hooks/` 配下のカスタムフック。アーキテクチャ詳細_フロントエンド編 の hooks 表にもファイルマップが載っている（こちらは設計理由・契約・利用元の説明）。

#### `useDarkMode`
- **役割**: ダークモード状態の管理と永続化。
- **設計**:
    - `index.html` インラインスクリプトと連携し、React マウント前に `<html class="dark">` を適用してフラッシュを防止。
    - `useState` 初期化フェーズで即座に `classList` を操作（`useEffect` 待ちのラグを排除）。
    - `localStorage` キー `darkMode` に `true/false` 文字列で永続化。
    - システムカラースキーム (`prefers-color-scheme: dark`) をフォールバックとして使用。
    - **`index.css` で `html.dark` に `color-scheme: dark` を当てる**ことで `<select>` のネイティブドロップダウンメニュー（option）等もダーク表示にする（Tailwind の `dark:` 修飾子は子要素のスタイルしか効かないため、ネイティブ UI 部分はこの設定で対応）。

#### `useSortedPdfs`
- **役割**: PDF一覧の並び替えロジック（`useMemo` でメモ化）。
- **ソート順**: `name_asc` / `name_desc` / `date_asc` / `date_desc` / `favorites_first`
    - `favorites_first`: お気に入りを先頭に、同グループ内は名前昇順。
    - 日付ソートは `created_at` (Unix timestamp) を使用。

#### `useBookMeta`
- **役割**: 書籍メタデータ（作者名・タグ・シリーズ・閲覧履歴・非表示）の取得・更新・集計。
- **設計**:
    - `source` が変わると `GET /api/meta` を再取得。
    - `updateMeta` / `updateAuthors` / `updateTags` / `setHidden` / `updateGenre` でローカル状態も即時反映（再フェッチ不要）。
    - `allAuthors` / `allTags` / `allGenres` / `allSeries`: このソースに登録されている全項目の重複排除・日本語ソート済みリスト（フィルター select の選択肢に使用）。
    - `allSeriesWithStats`: `allSeries` に `maxIndex`（シリーズ内最大巻数）と `count`（冊数）を加えた拡張版。`ExistingSeriesOption[]` として一括登録ダイアログの選択肢に使用。
- **シリーズ関連 API**:
    - `assignSeries(path, names, { title, index, id? })`: 既存または新規シリーズに割り当て。`index` は `number | number[]`（配列で複数書籍に個別の巻数を当てられる）。`id` 省略時はバックエンドで `title + 作者集合` のハッシュから生成。
    - `unassignSeries(path, names)`: シリーズから外す。
    - `reorderSeries(path, names, seriesId)`: `names` の順序で `series_index` を `1, 2, 3, ...` に振り直す（DnD ドロップ時に呼ぶ）。**楽観的更新 + 失敗時ロールバック**: ローカル `meta` を即時に書き換えてから API を投げ、失敗時はスナップショットから元の `series_index` を復元する（ドロップ後にカードが元位置に戻ってチラつくのを防ぐ）。
- **その他主要戻り値**:
    - `getSeries(path, name)`: 1 冊のシリーズ情報 `{id, title, index}` を返す（未割当なら null）。`↓` / `↑` ショートカットによる次巻 / 前巻ジャンプの探索元として使用。
    - `getReadState(path, name)`: 読書状態 `'unread' | 'reading' | 'done'` を返す。`meta[key].read_state` があればそれを優先、なければ `view_count` から導出（0 → unread / >0 → reading）。後方互換のため、フィールドが無くても適切に動く。
    - `recordView(path, name)`: 閲覧記録（`view_count` / `last_viewed_at` を加算）。失敗時は黙ってスキップ。成功時は `read_state` も `'reading'` に自動遷移する（既存値が `'done'` の場合は維持）。
    - `setReadState(path, names, state)`: 読書状態を手動で書き換え（PATCH 経由）。`state` は `'unread' | 'reading' | 'done' | ''`（空文字で削除＝派生に戻す）。Reader の最終ページ到達時に `'done'` を立てる用途で使用。

#### `useLibraryFilter`
- **役割**: PDF一覧のフィルタリングロジック（`useMemo` でメモ化）。
- **設計**:
    - `searchText`（タイトル / 作者 / タグ部分一致）/ `authorFilter`（完全一致）/ `tagFilter`（完全一致）/ `genreFilter`（genre フィールド完全一致）/ `seriesFilter`（series_id 完全一致）/ `currentPath` / `showHidden`（ゴミ箱モード）/ `readStateFilter`（読書状態フィルター）の変化でフィルタを再計算。
    - **ジャンルフィルター**: `genre` フィールドの完全一致。未設定書籍は空文字として扱われるため `genreFilter` が空でない場合は除外される。
    - **ゴミ箱方式**: `showHidden=false` のときは `hidden=true` を全件除外、`showHidden=true` のときは `hidden=true` の書籍**のみ** を表示する。
    - **読書状態フィルター**: `readStateFilter` が `'unread' | 'reading' | 'done'` のとき、その状態の書籍のみを表示する。状態は `useBookMetaCore.getReadState(path, name)` で派生取得（`meta[key].read_state` があればそれを優先、なければ `view_count` から導出: 0 → unread / >0 → reading）。`readStateFilter=''` でフィルター無効。後方互換のため、旧 localStorage キー `library_show_unread_only=true` は初回ロード時に `'unread'` へ移行される。
    - `LibraryPanel` から切り出すことでコンポーネントの責務を分離。

#### `useLibraryGrouping`
- **役割**: 書籍リストをシリーズ単位 / 作者単位で集約して仮想ディレクトリ的なカードを生成する。
- **モード** (`GroupMode = 'none' | 'series' | 'author' | 'author-then-series'`):
    - `none`: 集約しない。入力 `pdfs` をそのまま返す。
    - `series`: 同 `series_id` の書籍を集約。代表サムネイルは **最終巻**（`series_index` 最大）。displayTitle は `series_title`。
    - `author`: 同じ作者集合の書籍を集約。代表サムネイルは **入力順の 1 番目**（呼び出し側がソート済みなら「ソート 1 位」）。displayTitle は `{作者名} コレクション`。
    - `author-then-series`: 2 階層モード。`useLibraryGrouping` 自体は **`'series' | 'author' | 'none'` のいずれかに変換された値** を受け取る（モードの解釈は `LibraryPanel` 側で実施）:
        - 階層 1（authorFilter なし）: `author` として集約
        - 階層 2（authorFilter 適用中）: `series` として集約
        - 階層 3（seriesFilter 適用中）: `none` でフラット表示
- **戻り値**: `items` / `badgeByRepresentativeName` (count, kind, groupId, displayTitle, readCount) / `membersByRepresentativeName`。
    - `readCount`: シリーズメンバーのうち `view_count > 0` の冊数。作者集約では常に `0`（未使用）。
    - バッジ表示: シリーズ集約は `readCount/count巻`（例: `3/8巻`）、作者集約は `count冊`（変更なし）。
- **共通**:
    - 集約対象だがメンバーが 1 冊だけのグループは集約しない（単独本扱い）。
    - 元の `pdfs` 順序を可能な限り保つ（代表書籍の元位置に集約カードを表示）。
    - シリーズ・作者ともに `kind` プロパティで PdfGrid 側の装飾（紫枠・バッジ・タイトル差し替え）を切り替える。

#### `useLibraryPins`
- **役割**: シリーズ/作者集約カードの「代表サムネイル固定（ピン）」を管理する。旧 `useFavorites` を置き換え。
- **ストレージ**: ソース別に `pins_series_${source}` / `pins_author_${source}` を localStorage に保存。
- **データ構造**: `PinsMap = Record<groupId, book_name>`。1グループにつき1冊のみ。
  - シリーズ: `groupId = series_id`
  - 作者: `groupId = ソートした作者名を '\n' で結合した文字列`
- **戻り値**: `{ seriesPins, authorPins, toggleSeriesPin, toggleAuthorPin }`
- **ピンの反映**:
  - `useLibraryGrouping` がシリーズ代表選択時に `seriesPins[series_id]` を参照し、ピン済みならその巻を代表にする（なければ従来通り最終巻）。
  - 作者集約でも `authorPins[author_key]` を参照し、ピン済みなら先頭の代わりに使う。
- **クリック時のコンテキスト判定（LibraryPanel の `handleTogglePin`）**:
  - `seriesFilter` あり → シリーズピンを操作（どの巻をシリーズカバーにするか）
  - `authorFilter` あり（`seriesFilter` なし） → 作者ピンを操作（どのカードを作者代表にするか）
  - どちらもなし → `onToggleFavorite` を渡さないため星自体が表示されない
  - `effectiveGroupMode` は判定に使用しない（`seriesFilter` / `authorFilter` の有無のみで決定）
- **星の表示ルール（PdfCard）**:
  - トップ階層（`authorFilter` も `seriesFilter` もなし）: すべてのカードで星なし
  - 作者ドリルダウン中（`authorFilter` あり）: 作者集約カード以外（シリーズ集約・個別本）に星あり
  - シリーズドリルダウン中（`seriesFilter` あり）: 個別本に星あり
  - 判定: `!isSelectionMode && onToggleFavorite && badge?.kind !== 'author'`
- **`contextualFavorites`（PdfGrid の `favorites` 表示用 + ドリルダウン中の `favorites_first` ソート用）**:
  - `pinnedBooks`（シリーズ＋作者ピン混在）の代わりに文脈別のSetを `favorites` に渡す
  - `seriesFilter` 中 → シリーズピン済みの本のみ（星が塗られるのは1冊のみ）
  - `authorFilter` 中 → 作者ピン済みの本のみ（星が塗られるのは1冊のみ）
  - トップ階層 → 空Set（星は表示しないため不要）
- **`useSortedPdfs` への favorites 引数（`favorites_first` ソート用）**:
  - フィルタなし（トップ階層）→ `pinnedBooks`（シリーズ＋作者ピン混在）
  - `seriesFilter` または `authorFilter` あり → `contextualFavorites`（その文脈のピンのみ）
  - 理由: シリーズドリルダウン中に作者ピンの本が先頭に来る・作者ドリルダウン中にシリーズピンの本が先頭に来るのを防ぎ、星の表示と並び順の意味を一致させる。

**検索中の集約抑制（LibraryPanel）**:
- `searchText` が非空のとき、`useLibraryDisplay` へ渡す `groupMode` を強制的に `'none'` にする。
- これにより、グループ集約モード中でも検索テキストがヒットした個別書籍が代表カードではなく直接表示される。
- `authorFilter` / `seriesFilter` によるドリルダウンや breadcrumbs には影響しない（それらは `useLibraryDisplay` 内部で独立して計算）。

**LibraryPanel 側のパンくず計算**:
- ドリルダウン中（`authorFilter` または `seriesFilter` がセット）はパンくずを構築:
    1. 「ライブラリ」（全フィルタークリア）
    2. authorFilter があれば「作者: {名前}」
    3. seriesFilter があれば「シリーズ: {タイトル}」
- 各要素は `ChevronRight` で区切り、最後の要素以外はクリックで該当階層へ戻る。
- パンくず表示中は通常の作者・シリーズフィルター select は隠れる（重複防止）。

#### `useUrlState`
- **役割**: ViewerPage の URLパラメータ (`?path=`, `?file=`, `?source=`) 同期を一元管理。
- **URL に同期する LibraryPanel 側のフィルター**（`useUrlState` 直下ではなく `LibraryPanel` で `useSearchParams` を直接利用）:
    - `?author=` — 作者フィルター
    - `?series=` — シリーズフィルター（series_id）
    - `?tag=` — タグフィルター
    - これらにより、シリーズ / 作者カードでドリルダウンした後にブラウザの戻るボタンで元の一覧に戻れる。
    - `searchText` は入力ごとに履歴汚染を避けるため URL 同期しない。
    - フォルダ移動・ソース切替・PDF 選択時には `useUrlState` の navigate メソッドが `setSearchParams({ path, source, ... })` 形式で**全パラメータを置き換え**るため、これらフィルターは自動的に消える。
- **設計**:
    - `useSearchParams` ラッパー。`currentPath` / `selectedPdf` / `currentSource` を導出して返す。
    - ナビゲーション操作を関数として提供し、ViewerPage での状態二重管理を排除。
    - `source` を URL に含めることでリロード・直接アクセス時にも正しいソースが復元される。
    - `VALID_SOURCES` で無効なソース値を `'generated'` にフォールバック。
- **主要メソッド**:
    - `navigateIntoFolder(dirName, basePath, source)`: フォルダ内に移動（`?path=` を更新）。
    - `navigateUp(currentPath, source)`: 親階層へ戻る。
    - `selectPdf(pdfName, currentPath, source)`: PDF を選択（`?file=` を追加）。
    - `clearPdf(currentPath, source)`: PDF選択を解除してライブラリに戻る。
    - `setSource(source)`: ソース切り替え時に `?source=` だけ変更し、`path` / `file` をリセット。

### 2.3 Utilities

`frontend/src/utils/` 配下の純関数。複数 hooks / コンポーネントから共通利用する小さなロジック。

#### `cmpJa` (`frontend/src/utils/sort.ts`)
- **役割**: 日本語ロケール文字列比較の共通関数（Phase 53）。
- **設計**: `cmpJa(a, b) = a.localeCompare(b, 'ja')`。`Array.prototype.sort` の比較関数として直接渡せる。
- **利用元**: `useSortedPdfs`（PDF 名昇順・降順・タイブレーク）、`useMetaDerived`（作者/タグ/ジャンル/シリーズタイトルの昇順ソート）。旧来は `localeCompare('ja')` がこれら 2 ファイル計 11 箇所に直書きされていた。

#### `authorsKey` (`frontend/src/utils/authors.ts`)
- **役割**: 作者集合をグループ化キー（文字列）に変換する共通関数（Phase 54-4）。
- **設計**: `authorsKey(authors) = [...(authors ?? [])].sort().join('\n')`。元配列を破壊せず、`null` / `undefined` も空文字に正規化する。区切り文字は作者名に通常含まれない `'\n'`。
- **利用元**: `LibraryPanel` / `useLibraryGrouping` / `usePinnedBookSets` / `useSeriesAuthorFilter` の 9 箇所で `[...authors].sort().join('\n')` が散在していたのを集約。

#### `formatTimestampJa` / `formatDateJa` / `formatDateTimeJa` (`frontend/src/utils/date.ts`)
- **役割**: 日付フォーマットを集約（Phase 54-6）。
- **設計**:
    - `formatTimestampJa(unixSec)`: Unix 秒（10 桁）を `YYYY/MM/DD` 風の OS ロケール表記に。`null` / `undefined` / `0` / 不正値は空文字。
    - `formatDateJa(iso)`: ISO 文字列を `2026/05/06` 形式（`ja-JP` の年月日）に。パース失敗時は元の ISO をそのまま返す。
    - `formatDateTimeJa(iso)`: ISO 文字列を `2026/05/06 12:34:56` 形式（`ja-JP` の日時）に。`null` / `undefined` は em-dash `'—'` を返し、パース失敗は元の ISO をそのまま返す。
- **利用元**: `PdfCard` / `HitomiArrivalCard` / `HitomiPage` の `new Date(...).toLocaleDateString()` 等を集約。

#### `errorMessage` (`frontend/src/utils/error.ts`)
- **役割**: `unknown` 値からエラーメッセージを抽出（Phase 54-5）。
- **設計**: `errorMessage(e, fallback) = e instanceof Error ? e.message : fallback`。
- **利用元**: 11 ファイルに散在していた `e instanceof Error ? e.message : "..."` 三項演算をすべて置換。`useDialogSubmit` / `useAsyncToast` の内部実装でも使用。

### 2.4 共通 UI プリミティブ

`frontend/src/components/ui/` 配下。アプリ全体で再利用するボタン / アラート / ダイアログ等の素材コンポーネント。デザイントークンも本セクションに含める。

#### デザイントークン（`tailwind.config.js`）

UI 全体の色を Tailwind の色名（`indigo-600` 等）にハードコードせず、**用途別のセマンティックトークン**経由で参照する。

- `primary-*`: 主 CTA（= indigo パレット）。ボタン・主要アクション・選択中の境界線に使う。
- `accent-*`: グループ化・トグル ON 状態（= purple パレット）。シリーズ集約カード（バッジ・枠・タイトル色）・グループモードバッジ・パンくず最終項目・Reader ヘッダーのモードトグル（見開き Auto / 検索 / 編集モード）・ドラッグハンドル hover など「アクティブ／集約系」の装飾全般。**例外**: form 要素の `accent-color` プロパティ用 `accent-purple-600` / `accent-primary-600` は Tailwind 組み込み色をそのまま使う（`accent-accent-600` という冗長な名前を避けるため）。
- 意味的役割を担う独自色（token 化対象外）:
    - `amber-*`: お気に入り星マーク / 選択中カードのハイライト
    - `emerald-*`: PdfCard のタグ chip（hitomi 系の `success-*` とは別用途）
- `success-*`: 成功・hitomi 系（= emerald パレット）。
- z-index: `z-card-badge` / `z-floating-action` / `z-overlay-bar` / `z-header` / `z-toast` / `z-dialog` / `z-dialog-nested` を `tailwind.config.js` で定義済み。新規 floating UI を追加する際はこの階層を使うこと（`z-[40]` のような任意値は使わない）。

トークンは Tailwind のカラーパレット形式（50-950 のシェード）。各画面が独自に `bg-blue-600`・`bg-indigo-600` を混ぜていた状態を解消する目的で導入。**既存の `bg-indigo-*` 直書きは段階的に `bg-primary-*` に置換**していく方針（Phase B 以降）。

#### `Button` (`frontend/src/components/ui/Button.tsx`)
- **役割**: アプリ全体で再利用するボタンコンポーネント。`size × variant` の 2 軸で見た目を切り替える。
- **Props**: 標準の `ButtonHTMLAttributes<HTMLButtonElement>` をすべて受け取る + `variant` / `size` / `className`（追加クラスは末尾結合）。
- **`variant`**:
    - `primary`（既定）: `bg-primary-600` ベース。主 CTA。
    - `secondary`: `bg-gray-100 dark:bg-gray-800` ベース。サブアクション・トグル OFF 状態。

- **`size`**:
    - `sm`: `px-2.5 py-1 text-xs` — フィルターバー内の細かいトグル。

- **役割**: PDFリーダーUI。ページ表示・見開き制御・検索・ページ削除の **統合（合成）** を担う。各種ロジックはカスタムフックに委譲。
- **Worker設定**:
    - `pdfjs.GlobalWorkerOptions.workerSrc` を `new URL('pdfjs-dist/build/pdf.worker.min.mjs', import.meta.url).toString()` で設定。
    - `<Document>` コンポーネントと同一ファイルで設定する必要がある（react-pdf の要件）。Vite がビルド時にワーカーファイルを自動バンドルする。

- **委譲先フック**:
    - `useSpreadMode()` — `spreadMode` / `isSpread` / `cycleSpreadMode` / `handlePageSize` / `resetAutoSpread` を提供。
    - `useEditMode({...})` — `isEditMode` / `selectedPages` / `toggleEditMode` / `togglePageSelection` / `requestDeletePages` / `confirmDeletePages` / `cancelDeletePages` / `pendingDeleteCount` を提供。
    - `useReaderNavigation()` — ページナビゲーション。

    - `spreadMode: SpreadMode` — `'auto' | 'spread' | 'single'` の3状態。

    - `cycleSpreadMode()`: Auto → Spread → Single → Auto の順で循環。
    - `handlePageSize(width, height)`: `spreadMode === 'auto'` 時のみ動作。`width <= height`（縦長）なら見開き、横長なら1ページに設定。
    - PDF切り替え時は `resetAutoSpread()` で `autoIsSpread` を `true` にリセット。
- **テキスト検索**:
    - `pdfRef` に `PDFDocumentProxy` を保持し、全ページのテキストを走査してマッチ数を算出・ハイライト表示。
    - `searchAllPages(text, pdf)` は `pdfRef.current` ではなく引数の `pdf` を直接受け取り、ロード直後の null 参照問題を回避。
    - `onDocumentLoadSuccess`: PDF ロード完了時点で `searchText` が入力済みの場合は即座に `searchAllPages` を呼び出す。
    - 検索バー (`PdfSearchBar`) は `isSearchOpen === true` の間は常に表示（`showHeader` とは独立）。
    - `ReaderHeader` は `showHeader || isSearchOpen` で検索中は常に表示。
- **ページ削除**: `useEditMode` の `requestDeletePages()` で確認状態を作り、`<ConfirmDialog>` で削除確認。`confirmDeletePages()` で実際の削除 API 呼び出し → 完了後 `pdfVersion` をインクリメントして PDF を再ロード。

    - `'view_desc'` — 閲覧回数の降順、同数の場合は名前昇順（`localeCompare('ja')`）。
    - `'recent_view'` — 最終閲覧時刻 (`last_viewed_at`) の降順。未閲覧（`undefined`）は末尾、同時刻は名前昇順。

### 3.2 スクロール位置保持

`ViewerPage` + `LibraryPanel` の協調。

ライブラリ ↔ PDF / シリーズ詳細 / 作者ドリルダウンといった画面遷移を行った後、戻る操作で**前回のスクロール位置に復帰する**ための仕組み。

- **問題**: SPA で URL が変わると React 再レンダリングでスクロールが 0 に戻る。条件分岐レンダー（`{selectedPdf ? <Reader/> : <Library/>}`）では `LibraryPanel` がアンマウントされるため DOM のスクロールも消える。
- **実装**:
    1. **`ViewerPage`**: `LibraryPanel` を常時マウントし、PDF 表示中は `display:none`、それ以外は `display:contents` で切り替える。これで DOM ノードと一緒にスクロール位置を維持できる。`ReaderPanel` は従来どおり条件付きマウント。
    2. **`LibraryPanel`**: `useRef<Map<string, number>>` でスクロール位置を **URL キー** ごとに保存する。URL キーは `${currentPath}|${currentSource}|${authorFilter}|${seriesFilter}|${selectedPdf ?? ''}` の組合せ。
        - **保存タイミング**: `document` の `click` イベント（**capture phase**）で `window.scrollY` を「現在の URL キー」に紐づけて保存する。capture phase なので React のクリックハンドラ（= `setSearchParams` を呼ぶ前）に確実に走る。
        - **復元タイミング**: URL キー変化を監視する `useEffect` で `requestAnimationFrame` 内に `window.scrollTo(0, targetY)`。レイアウト確定後に走らせるため `display:contents` 復帰や displayPdfs 変更の reflow を待てる。
        - **初回マウント**: `isFirstRenderRef` で初回だけ復元をスキップ（直接アクセス時のスクロールを尊重）。
- **スクロール対象**: ライブラリの実際のスクロールコンテナは `<html>`（= `window`）。Layout の `main.flex-1` が高さ固定でないため、コンテンツ全体がページレベルでスクロールする構造になっている。`window.scrollY` / `window.scrollTo` で扱える。
- **既知の制限**: クリック以外で URL を変える操作（ブラウザバック / 直接 URL 入力）は capture phase でカバーされない。ただしブラウザバックは標準のスクロール復元が働くため実害は少ない。

### 3.3 UI スタイル規約（ボタン色 / 読書状態バッジ / 選択モード）

#### ボタン色規約（全画面共通）

全画面で以下の 3 色規約を統一して使用する。

- **Primary** (`bg-indigo-600 text-white hover:bg-indigo-700`): 「実行する」操作。
    - Library: 一括アクション群（作者設定 / タグ設定 / シリーズ登録 / 非表示 / 結合 / サムネイル再生成）
    - Dialog: `DialogPrimaryButton`（全ダイアログの確定ボタン）
    - OCR: Start OCR ボタン
- **Secondary** (`bg-gray-100 dark:bg-gray-800 text-gray-700 dark:text-gray-300 hover:bg-gray-200 dark:hover:bg-gray-700`): 中立・補助・取消。選択モード起動 / ツール開閉 / キャンセル / `DialogCancelButton`。
- **Danger** (`bg-red-600 text-white hover:bg-red-700`): 破壊的・回復不能な操作。OCR Stop ボタン / `ConfirmDialog` の `danger=true` 確認ボタン / Reader のページ削除ボタン。
- **Active tint (トグル ON)**: 現在 ON のトグルは indigo tint（`bg-indigo-100 dark:bg-indigo-900/40 text-indigo-700 dark:text-indigo-300`）または `bg-gray-700 text-white` で表示。
    - Reader: Search / Edit モード ON 時は indigo tint
    - Library: 非表示モード ON 時は `bg-gray-700 text-white`（Secondary active）
- **ナビゲーション**: `bg-indigo-600` を使用。
- **方針**: 旧設計の多色（blue / purple / emerald / amber など）を上記 3 色に集約。色ではなくアイコン + 文字で操作を区別する。`<select>` はネイティブスタイルを維持。

#### 読書状態バッジ（PdfCard）
- **条件**: `isGroup=false` かつ `readState !== undefined` のカードに表示
- **状態と表示**:
    - `'unread'` → "NEW" バッジ（`bg-sky-500 text-white`）
    - `'reading'` → "📖" バッジ（`BookOpen` アイコン、`bg-accent-500 text-white`）
    - `'done'` → "✓" バッジ（`Check` アイコン、`bg-emerald-500 text-white`）
- **配置**: カード下部の日付・アクション行（`flex items-center gap-1`）内、お気に入り星アイコンの隣に inline 表示
- **スタイル共通**: `text-xs font-semibold px-1.5 py-0.5 rounded-full leading-none`
- **派生**: `readState` は `useBookMetaCore.getReadState(path, name)` で算出。`meta[key].read_state` があればそれを優先、なければ `view_count` から導出（0 → unread / >0 → reading）。
- **渡し方**: `LibraryPanel` → `PdfGrid`（`getReadState` prop）→ `buildCardProps` → `PdfCard`（`readState` prop）→ `PdfCardActionButtons`
- **サムネイル領域に置かない理由**: シリーズ DnD 時のドラッグハンドルや集約バッジと重なるため
- **読書状態の遷移**:
    - **自動 (unread → reading)**: `recordView` 成功時、ローカル merge で「既存 read_state が無いか 'unread' なら 'reading' に書き換える」（`done` は維持）。バックエンド側の自動遷移と整合。
    - **自動 (reading → done)**: `ReaderPanel` で `isAtLastSpread && readState !== 'done'` を満たすとき `setReadState(path, [name], 'done')` を 1 度だけ呼ぶ（`useRef` で多重発火ガード、`selectedPdf` 切替でリセット）。
    - **手動**: `setReadState(path, names, state)` を `useBookMetaWrite` から提供（PATCH 経由）。空文字で削除すると派生に戻る。

#### 選択モードの視覚スタイル（PdfGrid）
- **選択中カード**: `border-amber-400` の枠 + `bg-amber-50 dark:bg-amber-900/20` の薄い琥珀色背景で表示。
- **PdfGrid のカード本体パネル**（サムネイル下部の書名・作者・日付エリア）も同じ条件で背景色を切り替える。サムネイル領域は画像で覆われるため枠と本体パネルの両方を着色することで選択状態を明確化する。
- **チェックアイコン**: 選択時は `text-amber-500` の `CheckSquare`、未選択時は `text-gray-400` の `Square`。

#### 関連書籍パネル（ReaderPanel）

最終ページ到達時に「同シリーズ / 同作者 / 共通タグ」の関連書籍を提示するフローティングパネル。要件 A-5。

- **表示条件**: `isAtLastSpread` のときのみ表示。表示中の書籍を読み終えた直後に「次に読むもの」を提示する用途。
- **データソース**: `meta` のみを参照。`pdfs` 一覧は `ReaderPanel` に渡っていないため、関連書籍の表示は **書籍名 + クリックで `onSelectPdf(name)`** に割り切る（サムネイルは読み込まない）。
- **セクション**:
    1. **同シリーズ**: `series_id` 一致 ＆ 自分を除く ＆ 同フォルダ。`series_index` 昇順、各セクション最大 8 件（シリーズは「全巻」見せたい）。
    2. **同作者**: 作者集合一致（順序無視・全員一致）または重複（少なくとも 1 人共通）。同フォルダ ＆ 自分・同シリーズメンバーを除外。最大 5 件。
    3. **共通タグ**: タグの交差が 1 個以上ある書籍。同フォルダ ＆ 自分・同シリーズメンバー・同作者ヒットを除外。最大 5 件。
- **同フォルダ判定**: `useNextSeriesVolume` と同じ key prefix 比較ロジックを共通ヘルパに抽出して再利用。
- **配置**: `position: fixed` の右下フローティングカード（`right-6 bottom-20`）。`z-overlay-bar`。
- **空表示**: 3 セクションいずれも 0 件ならパネル自体を表示しない（無駄な空枠を出さない）。
- **アクセシビリティ**: 各セクションヘッダに `<h3>`、書籍リンクは `<button>`（マウス・キーボード両対応）。

### 3.4 SeriesEditDialog のシリーズ選択肢を作者単位でフィルター

**概要**  
現在 `SeriesEditDialog` に渡す `allSeries` は、ソース内の全シリーズ（作者問わず）を一覧表示している。  
同一作者に属するシリーズのみを表示するよう絞り込むことで、誤った作者へのシリーズ割り当てを防ぎ、選択肢を大幅に減らせる。

**実現可能性**  
- `meta` オブジェクトは全書籍の `authors` と `series_id` を持っており、クライアント側で「作者 → シリーズ一覧」を導出できる。
- `series_id` は `hash(seriesTitle + authors)` で生成されるため、同名シリーズでも作者が違えば別 ID になり、作者単位フィルターとアーキテクチャが整合している。

**実装方針**  
1. `LibraryPanel.tsx` で `seriesEditTarget`（編集対象書籍）の `authors` を取得する。
2. `meta` をスキャンして、`seriesEditTarget` の `authors` と一致する書籍が持つ `series_id` のみを抽出し、フィルター済みのシリーズリストを `SeriesEditDialog` に渡す。
3. `BulkSeriesAssignDialog`（複数書籍一括）も同様にフィルターを適用する。選択書籍の authors をすべて集約し、その作者のシリーズのみを表示する。
4. 選択書籍に**複数の異なる作者が混在する場合は、一括アクションバーの「シリーズに登録」ボタンを非活性化**する（ダイアログを開かせない）。複数作者をまたぐシリーズ登録は運用上想定しない。

**実装箇所（一括アクションバー）**  
- `LibraryHeader.tsx` または `useLibraryBulkActions.ts` 内の「シリーズに登録」ボタン制御部で、`selectedItems` の authors を集約し、ユニークな作者セットが 2 種類以上あれば `disabled` にする。

**エッジケース**  
- 対象書籍の `authors` が空の場合は全シリーズを表示（フォールバック）。
- 書籍に複数の作者がある場合は、いずれかの著者が一致するシリーズを表示。
- **採用理由**: 従来の `border-blue-500` はダークモード（`bg-gray-800` 背景）で視認性が低く、UI 内の他の青系要素（作者タグ等）とも紛らわしかったため、アクセント色として琥珀（amber）に変更。両モードで高コントラスト。

### アクセシビリティ（a11y）の現状と将来課題

**現状**: 個人 LAN シングルユーザーツールという [信頼モデル](セキュリティ設計書.md) のもと、a11y は最低限のみ対応:

- ✅ Dialog 共通シェル（[Dialog.tsx](../../frontend/src/components/ui/Dialog.tsx)）の閉じるボタンに `aria-label="閉じる"` あり
- ✅ Esc キー / 外クリックでダイアログ閉じる
- ✅ Tab キー操作は React + 標準 HTML 要素のデフォルト挙動を維持
- ✅ `: any` 禁止 / Hooks 規約遵守などのコード品質
- 🟡 **アイコンのみのボタンは `title=` 属性のみで運用**（80 箇所程度、ReaderHeader / LibraryBulkActionBar / PdfCardActionButtons 等）。`aria-label` 併用ではないためスクリーンリーダーで読み上げが弱い
- 🟡 **ランドマーク `role`（main / navigation / complementary 等）は未指定**。`Alert` のみ `role="alert"` 設定あり
- 🟡 **`eslint-plugin-jsx-a11y` 未導入**

**判断**: スクリーンリーダー利用を前提としていないため未対応で受容。将来 LAN 外公開や視覚障害者ユーザー想定が出たら、以下の順で対応:

1. `eslint-plugin-jsx-a11y` 導入で機械的検出
2. アイコンのみボタンに `aria-label` 付与（特に LibraryBulkActionBar / ReaderHeader / PdfCardActionButtons）
3. ランドマーク role 設定（Layout / LibraryPanel / ReaderPanel）
4. フォーカストラップ（Dialog 内 Tab 巡回の閉じ込め）の追加検討

新規候補は §3 への追記または `docs/06_リファクタリング/リファクタリング計画書.md` に登録する。
