## §3. 外部 OCR / AI モデル

### §3.1 yomitoku（Deep Learning OCR）

| 項目 | 内容 |
|---|---|
| 配置 | プロジェクト外（[D:\61.tool\common\ocr](D:\61.tool\common\ocr) 等） |
| ライセンス | **要確認**（リポジトリ・PyPI 配布元の `LICENSE` を参照） |
| 学習モデル | 学習済みモデルは別途配布される場合があり、モデル自体のライセンスがコードと異なることが多い |
| 商用利用 | **要確認** |

**列挙する論点**:
- yomitoku は OSS だが、内部で利用する事前学習モデル（layout / text recognition）が個別ライセンスを持つ可能性がある
- 学習モデルが「研究用途のみ」「商用利用には別契約」等の場合、Pic2PDF_Viewer での利用範囲（個人利用）とのマッチングを確認要
- バージョンアップで依存モデル・ライセンスが変わる可能性

### §3.2 Gemma 4（Google 製大規模言語モデル）

| 項目 | 内容 |
|---|---|
| 配置 | プロジェクト外（[D:\61.tool\Gemma 4](D:\61.tool\Gemma 4)） |
| ライセンス | **Gemma Terms of Use**（Apache-2.0 ベースだが追加制限あり） |
| 利用範囲 | Google の利用規約により **「特定の禁止用途」が定義されている**（ヘイト・違法行為支援等） |

**列挙する論点**:
- Gemma の利用規約には「Prohibited Use Policy」がある。Pic2PDF_Viewer の用途（書籍メタデータ抽出 / シリーズ判定の補助）は通常用途で問題ない見込みだが、規約の最新版を確認すること
- モデル出力に対する責任は利用者側に帰属する旨が規約に記載されている
- バージョン更新時に規約も改定される場合あり

### §3.3 ローカル動作の前提

- yomitoku / Gemma 4 ともに**ローカル GPU/CPU で動作**しており、外部 API へのデータ送信は発生しない（プライバシー観点では有利）

## §4. 外部サービス連携の論点（事実の列挙のみ）

### §4.1 hitomi.la 新着監視

| 論点 | 状況 |
|---|---|
| アクセス対象 | hitomi.la（同人誌系画像投稿サイト） |
| 取得内容 | 特定作者の新着ギャラリーのメタデータ（タイトル・ID・ページ数等）。**画像本体の自動ダウンロードは行わない**（[hitomi新着監視設計書.md](hitomi新着監視設計書.md) §1） |
| 頻度 | 1 日数回（デフォルト 0:00 / 12:00 / 18:00）+ 手動 `/api/hitomi/run-now` |
| 実装 | NOZOMI URL から ID リスト取得、レート制限・robots.txt の遵守状況は要確認 |

**列挙する論点**:
- hitomi.la の利用規約・robots.txt に**自動アクセスに関する記述**があるか
- 著作権侵害コンテンツを含む可能性のあるサイトへの自動アクセスが**法的リスク**を生むかどうか
- 個人利用・閲覧目的に限定した運用であれば日本の私的複製の枠内に入るかどうか
- 監視結果を**外部に共有しない**運用が前提（state.json はローカル）

### §4.2 Kindle キャプチャ連携（外部ツール）

| 論点 | 状況 |
|---|---|
| 対象 | Amazon Kindle for PC のスクリーンショット連携（外部スクリプト） |
| Pic2PDF_Viewer の関与 | キャプチャされた画像を `kindle` ソースとして閲覧する後段の役割のみ |
| キャプチャ自体 | 別ツール（[D:\61.tool\common\new_project_format\.claude](D:\61.tool\common\new_project_format\.claude) 配下等？）で実施 |

**列挙する論点**:
- **Amazon Kindle 利用規約**: スクリーンショット取得・自動操作・コンテンツの保存は規約上禁止される行為に該当する可能性がある
- **DRM 回避禁止条項**: 著作権法上、技術的保護手段の回避は私的複製の例外から外れる
- **私的複製の範囲**: 日本の著作権法 30 条では「個人または家庭内で使用する目的での複製」は認められるが、DRM 回避を伴う場合は適用外
- Pic2PDF_Viewer 自体は**閲覧 UI** であり、キャプチャ取得は外部ツールの責任範囲。設計上分離されている

## §6. 機微データの扱い

### §6.1 ローカル保存データの種類

- 書籍画像・PDF（個人購入物・スクショ）
- メタデータ（作者名・タグ・閲覧履歴）
- hitomi 監視対象作者リスト
- ログ（バックエンド出力）

### §6.2 観点（列挙のみ）

- これらは個人の趣味嗜好を反映する情報であり、**第三者への意図しない公開を避ける**運用が望ましい
- バックアップ先（OneDrive 等の同期サービス）へ平文で同期される場合、**サービス側の規約と照合**が必要
- ログにタイトル・作者名等が記録される場合、ログのローテーション・削除ポリシーの整理が望ましい
- リポジトリへの誤コミット防止: `data/` 配下を `.gitignore` で除外しているか確認要

## §7. 推奨アクション（参考、判断は user）

最終判断は user に委ねるが、整理材料として以下を列挙:

1. **PyMuPDF の AGPL** について、現状の利用形態（LAN 個人利用）で問題が生じないことを記録（or 商用配布を想定するなら代替検討）
2. **yomitoku ライセンス** の確認（特に同梱学習モデル）
3. **hitomi.la / Kindle / DLsite / FANZA** に関する自動アクセスの規約確認、必要に応じて運用ガイドに「自己責任」明記
4. **プロジェクトの LICENSE 未指定** 問題: 配布予定がなければ現状維持で可、配布予定があれば LGPL/AGPL 派生条項に合わせる
5. **`.gitignore` の `data/` 除外** が漏れていないか確認
