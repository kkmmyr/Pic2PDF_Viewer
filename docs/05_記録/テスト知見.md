# テスト知見

## React 19 + @testing-library/react + Vitest — 偽陽性 unhandledRejection

### 症状

`renderHook` でエラーシナリオをテストしようとすると、フック内の try/catch が正しくエラーを
捕捉しているにもかかわらず、Vitest が `Unhandled Rejection: Error: <message>` を報告してテストが失敗する。

```
Error: not found
 ❯ new Error src/test/useBookDetail.test.ts:39:...
```

エラーは `waitFor` のタイムアウト（1000 ms）より先に ~80 ms で発生するため、タイムアウトではない。

### 根本原因

`@testing-library/react v16` の `renderHook` 内部で、`actCompat(() => { root.render(element) })` が
**await なし**で呼ばれる（フローティング thenable）。

React 19 の `act()` は非同期作業を自律的にフラッシュし、エラーがあれば返却した thenable を
reject する。しかし誰も await していないため、この thenable の rejection が
`process.on('unhandledRejection', ...)` に届き、Vitest のハンドラが拾って失敗にする。

Vitest には `processListeners('unhandledRejection').length > 1` ならスキップする guard があるが、
フック依存の追加リスナーが存在しない場合はスキップされない。

### 解決策：「初回成功 → refetch でエラー」パターン

**NG（浮遊 thenable がある初回レンダーでエラーを起こす）**:

```ts
it('fetch 失敗で error がセットされる', async () => {
    mockedFetch.mockRejectedValue(new Error('not found'));
    const { result } = renderHook(() => useBookDetail('book.pdf'));  // floating thenable が reject
    await waitFor(() => expect(result.current.isLoading).toBe(false));
    expect(result.current.error).toBeTruthy();
});
```

**OK（初回は成功させ、refetch でエラーを起こす）**:

```ts
it('fetch 失敗で error がセットされる', async () => {
    mockedFetch.mockResolvedValueOnce({ summary: '初回' });
    const { result } = renderHook(() => useBookDetail('book.pdf'));
    await waitFor(() => expect(result.current.isLoading).toBe(false));  // 初回成功を待つ

    mockedFetch.mockRejectedValueOnce(new Error('not found'));
    await act(async () => { await result.current.refetch(); });  // properly awaited

    expect(result.current.error).toBeTruthy();
    expect(result.current.detail).toBeNull();
});
```

`await act(async () => { ... })` が properly await されているため:
- `act()` の返却 thenable は処理済み → 浮遊 rejection なし
- `refetch()` 内の `await fetchX()` はフック自身の try/catch が捕捉 → rejection なし

### 影響したフック・テスト

| テストファイル | 修正したテストケース |
|---|---|
| `useBookDetail.test.ts` | fetch 失敗で error がセットされ detail は null のまま |
| `useBookCharacters.test.ts` | fetch 失敗で error がセットされ characters は空 |
| `useCharacterDetail.test.ts` | fetch 失敗で error がセットされる |

### 注意点

- `useBookCharacters` の catch ブロックは `setCharacters([])` を呼ばない。
  初回モックを `mockResolvedValueOnce([])` とすれば `characters` は `[]` のまま維持される。
- `useCharacterDetail` の catch ブロックは `setDetail(null)` を呼ぶため、
  初回成功後に refetch でエラーになっても `detail` は `null` になる。

### 環境

- React: ^19.2.6
- @testing-library/react: ^16.3.2
- Vitest: v4.1.5
- Node.js: Windows 11 Home 10.0.26200
