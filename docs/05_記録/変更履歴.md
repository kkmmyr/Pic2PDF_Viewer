## 2026-05-04: fix(author_resolver) — `_sanitize_author` の AttributeError と「該当なし」誤抽出

### 背景

`GET /api/meta/auto-fill/test?title=同人音声&source=generated` の動作確認中に 3 件の不具合を発見。

1. **P1 クラッシュ**: `_extract_circle_from_page` が Gemma の JSON 応答から `parsed.get("result", "")` を取り出す際、Gemma が稀に数値型を返すと `_sanitize_author(value: str)` の `value.strip()` で `AttributeError: 'int' object has no attribute 'strip'` が発生し、`/auto-fill/test` が 500 で落ちる。
2. **誤抽出（文言）**: DLsite で 0 件ヒットだった検索結果ページ（タイトル「このすばらしい世界に祝福を」等の非同人作品）から、Gemma が「条件に一致する作品は見つかりませんでした」というページ文言を抽出し、それが author としてそのまま採用されてしまう。
3. **誤抽出（数値 sentinel）**: Gemma が「該当なし」の sentinel として `"-1"` や `"0"` を返すケースが観測され、これも `_INVALID_PATTERNS` も長さ制限も通過してしまい author に採用される。

### 内容

- `backend/services/author_resolver.py`
    - `_sanitize_author(value)` の冒頭で `value` を `str()` 経由で正規化してから `strip()` する（`None` は空文字扱い）。シグネチャの型注釈は `str` のままでも実行時は防御。
    - `_INVALID_PATTERNS` に `"見つかりません"` を追加。これにより「条件に一致する作品は見つかりませんでした」「該当する作品が見つかりません」「検索結果が見つかりません」など DLsite/FANZA の 0 件レスポンス文言が一律 `"作者不明"` に丸められる。
    - 純数値文字列（`-1` / `0` / `3.14` 等）も `"作者不明"` に丸める。サークル名として出現しない値域。
- `backend/tests/test_author_resolver.py`
    - `TestSanitizeAuthor` に「整数入力」「None 入力」「該当なし文言」「純数値文字列」4 ケースを追加。
- 設計書: `docs/03_詳細設計/詳細設計書_バックエンド編.md` のサニタイズ節を更新。

### 確認

- `GET /api/meta/auto-fill/test?title=同人音声&source=generated` → 500 が返らず `used_step` が返ること。
- `title=このすばらしい世界に祝福を` → `final` が `"作者不明"` または空（「見つかりませんでした」「-1」が author として残らない）。

## 2026-05-04: fix(viewer) — ライブラリ ↔ ドリルダウン / PDF 戻り時のスクロール位置保持

### 背景
- 戻るボタンで一覧画面に戻ると常にスクロールが先頭に戻ってしまう問題があった。
- 原因 1: `ViewerPage.tsx` が `{selectedPdf ? <Reader/> : <Library/>}` の条件分岐で `LibraryPanel` をアンマウントしていたため DOM のスクロールが消失。
- 原因 2: シリーズ / 作者カードのドリルダウン → 戻る、では URL クエリ (`?series=` `?author=`) は変わるがコンポーネントは残るものの、復元するための保存機構が無かった。

### 内容
- **`pages/ViewerPage.tsx`**: `LibraryPanel` を常時マウントし、PDF 表示中は `display:none`、それ以外は `display:contents` で切り替えるラッパーに変更。`ReaderPanel` は従来どおり条件付きマウント。
- **`components/viewer/LibraryPanel.tsx`**: URL キー (`path|source|author|series|selectedPdf`) を Key として `useRef<Map<string, number>>` にスクロール位置を保存・復元する仕組みを追加。
    - 保存: `document` の `click` capture phase で `window.scrollY` を**現在の**URL キーに保存（React のクリックハンドラが `setSearchParams` を呼ぶ前に走る）。
    - 復元: URL キー変化を `useEffect` で監視し `requestAnimationFrame` で `window.scrollTo(0, targetY)`。レイアウト確定後に実行。
    - 初回マウントは復元スキップ。
- **設計書**: `docs/03_詳細設計/詳細設計書_フロントエンド編.md` に「スクロール位置保持」節を追加。`ViewerPage` の役割注記を更新。

### 補足
- ライブラリの実際のスクロールコンテナは `<html>`（= `window`）。当初は `LibraryPanel` 内の `flex-1 overflow-auto` を疑ったが、デバッグログで `<html>` がスクロール対象であることを確認した。
- ブラウザバック / 直接 URL 入力経由の遷移は capture phase に乗らないが、ブラウザ標準のスクロール復元で実用上は問題ない。

## 2026-05-04: change — hitomi 新着「新着情報を取得」のスキップを 1 日 / 0 時リセット式に変更

### 背景

`POST /api/hitomi/run-now` は UI 連打や watchlist 編集ごとの全件再フェッチで
hitomi.la に過剰アクセスしないため、直近 N 日以内にチェック済みの作者をスキップする
ガード（デフォルト 3 日）を備えていた。これを「1 日 1 回」かつ「0:00 を境にリセット」
する仕様に変更する。日付が変われば即座に再フェッチでき、同一日内の重複アクセスは
抑制できる、より直感的なポリシー。

### 内容

- `backend/tools/hitomi_monitor.py`:
  - `main()` の引数を `min_age_hours: float | None` から `threshold: datetime | None`
    に変更。閾値の計算責務を呼び出し側へ移譲（`should_skip_artist` は変更なし）
- `backend/routers/hitomi.py`:
  - `POST /api/hitomi/run-now` のクエリパラメータを
    `skip_recent_days: float = 3.0` から `force: bool = False` に変更
  - `force=False`（既定）の場合、ローカルタイムの当日 0:00 を閾値として算出し
    `hitomi_monitor.main(threshold=...)` に渡す
- `frontend/src/pages/HitomiPage.tsx`:
  - スキップ件数のトーストメッセージを「直近 3 日以内に取得済み」→「本日既に取得済み」へ更新
- `docs/03_詳細設計/hitomi新着監視設計書.md` §6.7 を仕様変更に合わせて更新

### 影響

- API 後方互換: `skip_recent_days` パラメータは廃止（フロントは未使用なので影響なし）
- Task Scheduler 経由（CLI 直接実行）は引き続き `threshold=None` でスキップ無し

## 2026-04-29: fix(reader) — ページスライダーの矢印キー方向逆転を修正

## 2026-04-29: fix(hitomi) — NOZOMI URL の作者名エンコードを修正（`_` → `%20`）

### 概要

`artist not found on hitomi.la` で失敗。原因は **NOZOMI URL 仕様の誤認**。

検索ページの URL（`hitomi.la/search.html?artist:aka_shio`）では `_` が空白の代わりに
使われるため誤認したが、これは検索クエリ層の慣習で、NOZOMI ファイル名の物理仕様とは
別物だった。

### 変更内容

**変更:**
- `backend/services/hitomi/nozomi.py`:
  - `_build_nozomi_url(artist_normalized, language)` を **`build_nozomi_url(artist_key, language)`** へ改名・公開化
  - 内部 key の `_` を空白に戻してから `urllib.parse.quote(safe="")` で URL encode する処理に変更
  - 例: `aka_shio` → URL に埋め込む際は `aka%20shio`
- `docs/03_詳細設計/hitomi新着監視設計書.md`:
  - §4.1 `normalized` フィールドの説明を「内部識別子」と明確化


`color-scheme` プロパティは Chromium / Firefox 共にネイティブフォーム要素のテーマを切り替える。これでドロップダウン展開時のメニューもダーク UI になる。

  - `kindle_novel/images/` に PNG ファイルが存在するため従来は画像モードで開かれており、`<Document>` がレンダリングされず `onDocumentLoadSuccess` が呼ばれなかった。

#### 2. pdfjs Worker が正常に起動しない問題
- `components/viewer/ReaderPanel.tsx`: `workerSrc` を `new URL('pdfjs-dist/build/pdf.worker.min.mjs', import.meta.url).toString()` に変更。
  - `<Document>` コンポーネントと同一ファイル内で設定しなければならない（react-pdf の要件）。
  - Vite がビルド時にワーカーファイルを自動バンドルするため CDN 不要。
- `pages/ViewerPage.tsx`: 重複していた `workerSrc` 設定を削除。

#### 3. TextLayer スタイルが適用されない問題
- `components/viewer/ReaderPanel.tsx`: `import 'react-pdf/dist/Page/TextLayer.css'` を追加。ハイライト表示に必須。

#### 4. 検索バーを開いても表示されない問題
- `components/viewer/ReaderPanel.tsx`:
  - 検索バー表示条件を `isSearchOpen && showHeader` → `isSearchOpen` のみに変更。
  - `ReaderHeader` の `showHeader` を `showHeader || isSearchOpen` に変更（検索中はヘッダーを常に表示）。

#### 5. `pdfRef.current` が null になる タイミング問題
- `components/viewer/ReaderPanel.tsx`:
  - `searchAllPages(text, pdf)` の引数を `pdfRef.current` ではなく `PDFDocumentProxy` を直接受け取る形に変更。
  - `onDocumentLoadSuccess`: PDF ロード完了時点で `searchText` が入力済みなら即座に `searchAllPages` を呼び出す。

#### 6. ソース切り替え後に PDF URL が 404 になる問題
- `hooks/useUrlState.ts`: `currentSource` を URL `?source=` パラメータから取得・管理するよう変更。
  - 全ナビゲーション関数 (`navigateIntoFolder`, `navigateUp`, `selectPdf`, `clearPdf`) のシグネチャに `source: LibrarySource` を追加。
  - `resetAll()` を `setSource(source)` に置き換え（`?source=` のみ変更し他はリセット）。
- `pages/ViewerPage.tsx`: `currentSource` の `useState` を削除。`useUrlState()` から取得するよう変更。

### コードリファクタリング
- `backend/services/pdf_service.py`: `typing.List` → `list[int]`、`temp_path` の `finally` ブロッククリーンアップ。
