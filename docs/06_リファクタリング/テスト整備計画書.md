# テスト整備計画書（バックエンド編）

バックエンド (`backend/`) のテストカバレッジ不足を整理し、追加すべきテストケース候補を実装着手用に列挙する。
フロントエンドは対象外（別途整備予定）。

実行コマンド: `cd backend && uv run pytest tests/ -v`

> **進捗 (2026-05-06)**: 全 8 Phase 完了。バックエンドテスト件数 235 件 → **564 件**、テストファイル数 14 → **28** に増加。
> 詳細は §7「実施結果」を参照。

## 3. テストケース候補（実装着手用）

優先度の表記:
- **🔴 高**: 主要 API・破壊的操作・ロジックが独立して回帰しやすい
- **🟡 中**: 補助ロジック・例外時挙動
- **🟢 低**: 自明なヘルパー・ラッパー（最低限のスモークテストで十分）

各セクションは **既存テストの追加分** と **新規テストファイル** に分けている。

### 3.1 routers/library.py 🔴 高

**新規テストファイル**: `backend/tests/test_router_library.py`

`generated` ソースは `images/` 走査、`kindle` / `novel` は `pdfs/` 走査と分岐する点を意識。

#### `GET /api/pdfs`
- [ ] generated: `images/{book}/*.webp` がある書籍が一覧に含まれる
- [ ] generated: WebP が空のサブディレクトリは除外される
- [ ] generated: 既存サムネイルがある場合 `thumbnail` URL が返る、無い場合は `null`（BackgroundTasks 経由で生成）
- [ ] kindle: PDF ファイルのみ列挙され、サブディレクトリは除外される
- [ ] kindle: `path` クエリで階層下を取得できる
- [ ] 不正な `source` で 400
- [ ] `..` を含む `path` で 400（path traversal）
- [ ] 存在しない `path` で空配列を返す
- [ ] `path` がファイル（ディレクトリでない）の場合 400

#### `GET /api/books/{path}/images`
- [ ] generated: WebP 一覧の URL が natsort 順で返る
- [ ] 存在しないパスで 404
- [ ] ディレクトリでないパスで 400

#### `PATCH /api/rename`
- [ ] PDF ファイルのリネームで PDF / サムネイル / images の3点セットが更新される
- [ ] フォルダのリネームで配下も含めて更新される
- [ ] meta.json のキーが旧→新に付け替わる（authors / tags / series 引き継ぎ）
- [ ] フォルダリネーム時に meta.json のキー prefix が一括で書き換わる
- [ ] 存在しない `old_name` で 404
- [ ] `new_name` が既存で 400
- [ ] 不正文字を含む name で 400
- [ ] `source` 不正で 400

#### `DELETE /api/pdfs`
- [ ] 複数 names を一度に削除でき、`deleted_count` が一致する
- [ ] meta.json から該当キーが削除される
- [ ] 存在しない name はエラーリストに入るが他の削除は続行する
- [ ] 全件失敗のとき 500
- [ ] image-only モード（PDF 不在）でも images / thumb は削除される

## 8. 改善提案（テスト作成中に発見）

優先度は実害ベース:
- 🔴 高 — 実機で再現する可能性のあるバグ
- 🟡 中 — 防御層が弱くセキュリティ・運用上の懸念がある

### 8.1 ✅ 修正済み — image-only モードのサムネイル再生成が WebP 入力で失敗

**該当箇所**: `services/thumbnail_service.py:24`（fitz は WebP を読めない）/
`routers/thumbnails.py:_regenerate_one` の image-only フォールバック /
`routers/library.py:_list_from_images` の BackgroundTasks フォールバック

**症状**: `services/pdf_generator.py:generate_thumbnail` (PIL ベース) と
`services/thumbnail_service.py:ThumbnailService.generate_thumbnail` (fitz ベース) で
サムネイル生成関数が 2 系統に分裂しており、WebP 入力経路で誤って後者（fitz）が
呼ばれていた。`fitz.open(<webp>)` は `FileDataError` を投げるため、
generated ソースでサムネイルが消えると自動回復しない。

**影響**: 通常運用では `pdf_generator.scan_and_generate` がサムネイルを作るので
影響なし。ただし以下のエッジケースで自動生成が動かない:
- サムネイル「再生成」エンドポイント（`POST /api/thumbnails/regenerate`）
- サムネイルファイルが消えた状態で `/api/pdfs` を叩いたときの BackgroundTasks 補完

**対応**（2026-05-06 実施）:
1. `services/pdf_generator.generate_thumbnail` の戻り値を `None` → `bool` に変更し、
   親ディレクトリ自動作成も追加
2. `routers/thumbnails.py:_regenerate_one` の WebP フォールバックを `pdf_generator.generate_thumbnail` に差し替え
3. `routers/library.py:_list_from_images` の BackgroundTasks も同様に差し替え

**回帰テスト**:
- `test_router_thumbnails.py::test_regenerate_from_webp_when_pdf_missing` をモック解除し、実 WebP で JPEG が生成されることを確認
- `test_router_library.py::test_background_task_creates_thumbnail_from_webp` を新規追加（BackgroundTasks の本番経路を検証）

### 8.2 ✅ 修正済み — 複数 router で `?source=invalid` バリデーション欠落

**該当箇所**:
- `routers/library.py`: `list_pdfs` / `list_book_images` (クエリ) / `rename_item` / `delete_pdfs` (body)
- `routers/pdfs.py`: `delete_pages` (クエリ) / `merge_pdfs` (body)

`get_dirs_by_source` の fall-through により generated として扱われていた。

### 8.3 ✅ 修正済み — `services/genre_store.py` の `_GENRE_ORDER` ハードコード削除

### 9.1 計測ツール

`pytest-cov` を導入（[backend/pyproject.toml](../../backend/pyproject.toml) `[dependency-groups.dev]`）。設定は `[tool.coverage.*]` で集中管理。

```bash
cd backend && uv run pytest --cov                       # ターミナル表示
cd backend && uv run pytest --cov --cov-report=html     # HTML レポート (htmlcov/)
```

`htmlcov/` と `.coverage` は `.gitignore` 対象。

### 9.2 ベースライン（2026-05-07 時点 / 575 tests passing）

カバレッジが低いモジュール（外部 HTTP / 外部プロセスに強く依存するため意図的に低い）:

### 9.3 運用方針

- カバレッジ閾値は **強制しない**（個人ツール、CI 未導入のため）。プルダウンを検知したら手動で調査
- 新規ロジック追加時は本表の数値が極端に下がらないことを目安にする
- 外部 HTTP モジュールは「テスト追加コスト > 利得」と判断し、カバレッジ低を許容
