## Phase 4 — エラーハンドリング統一（低リスク）

### 課題

ルーター間でエラー処理が統一されておらず、`except Exception` でスタックトレースが消える。

| ファイル | 問題 |
|---|---|
| `routers/pdfs.py:69-72` | `except Exception as e: str(e)` のみ、ログなし |
| `routers/library.py:113-117` | 全例外を 500 に集約 |
| `routers/ocr.py` | エラーハンドリングほぼなし |

### 対処

**4-1. FastAPI の exception_handler を使ったミドルウェア統一**

`backend/main.py` に追加:
```python
@app.exception_handler(FileOperationError)
async def file_op_handler(request, exc):
    logger.error("FileOperationError: %s", exc, exc_info=True)
    return JSONResponse(status_code=500, content={"detail": str(exc)})
```

既存の `exceptions.py` に例外クラスを追加し、各ルーターで `raise FileOperationError(...)` に統一する。

**4-2. logger の活用**

`except Exception` → `logger.exception(...)` に置き換え（スタックトレース保存）。

**変更対象:** `backend/main.py`, `backend/routers/*.py`, `backend/exceptions.py`

## Phase 5 — ViewerPage の Props Drilling 解消（中リスク）

### 課題

`ViewerPage.tsx` → `LibraryPanel` に **21個の props** が渡されており保守困難。

```
ViewerPage
└── LibraryPanel (21 props)
    └── LibraryHeader (15 props)
```

### 対処方針

**Context API でライブラリ状態を一元管理する。**

```
frontend/src/contexts/LibraryContext.tsx (新規)
  - currentPath / currentSource / selectedItems / isSelectionMode
  - ダイアログ開閉状態 (isMoveDialogOpen etc.)
  - ハンドラ関数群
```

`ViewerPage` → `LibraryProvider` で包むだけにし、`LibraryPanel` は Context から必要な値を取得する。

**変更対象:** `frontend/src/pages/ViewerPage.tsx`, `frontend/src/components/viewer/LibraryPanel.tsx`  
**新規作成:** `frontend/src/contexts/LibraryContext.tsx`

> **注意:** 影響範囲が広いため、Phase 4 完了後に着手すること。

## Phase 6 — pdf_generator.py のリファクタリング（中リスク）

### 課題

`services/pdf_generator.py`（241行）で ZIP / ディレクトリ処理のスキャンロジックが重複し、単一クラスに6つの責務が混在している。

```python
# 95-119行 と 136-156行 で同じ walk ロジックが重複
for root, _, files in os.walk(...):
    for f in sorted(files):
        if f.lower().endswith(SUPPORTED_IMAGE_FORMATS):
```

### 対処

**6-1. 画像収集ロジックを共通関数に抽出**

```python
# services/pdf_generator.py 内
def _collect_images(source_dir: str) -> list[str]:
    """ディレクトリから対応画像ファイルを収集する（ZIP展開後・ディレクトリ共用）"""
```

**6-2. ZIP処理と Directory処理のフロー統一**

ZIP の場合は一時ディレクトリに展開 → `_collect_images` → PDF生成 → クリーンアップ  
Directory の場合も同じフローを通るよう統一する。

**変更対象:** `backend/services/pdf_generator.py`

### 10-1. ファイル拡張子フィルタリングの関数化

**問題**: `.lower().endswith('.webp')` などの判定が複数ファイルに散在
**対象**: `routers/pdfs.py:104,121,185` / `services/pdf_generator.py:31,86,199` / `routers/library.py:81`

**改善案**: `backend/utils/file_utils.py` にユーティリティ関数を追加
```python
def is_webp_file(name: str) -> bool: ...
def is_zip_file(name: str) -> bool: ...
def is_pdf_file(name: str) -> bool: ...
```

---

### 10-2. meta.json ロック→ロード→保存パターン統一

**問題**: 同じ lock/load/save シーケンスが `auto_fill_service.py` と `routers/meta.py` で重複
**対象**: `auto_fill_service.py:81-84` / `routers/meta.py:66-76`

**改善案**: `meta_store.py` に `update_meta_locked()` を追加
```python
def update_meta_locked(source: str, updater: Callable[[MetaDict], None]) -> None:
    with get_lock(source):
        meta = load_meta(source)
        updater(meta)
        save_meta(source, meta)
```

---

### 10-3. MetaDict 型定義追加

**問題**: `meta: dict` が非常に一般的で型チェックが効かない
**対象**: `auto_fill_service.py` / `meta_store.py`

**改善案**: TypedDict を使用
```python
class MetaEntry(TypedDict):
    authors: list[str]

MetaDict = dict[str, MetaEntry]
```
