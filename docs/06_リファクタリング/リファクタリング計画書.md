## このファイルの範囲

**書くもの:**
- **リファクタリング** — 外部挙動を変えずに内部構造を改善する（ファイル分割・hook 抽出・重複統合等）
- **技術メンテナンス** — 依存ライブラリ更新・インフラ/DB ツール導入・性能改善（例: React 19 化・TanStack Query 導入・LanceDB 移行）

**書かないもの:** ユーザーから見た新機能・新体験の追加 → [バックログ.md](../01_要件定義/バックログ.md) へ

| 判定 | 行き先 |
|---|---|
| ユーザー向けの振る舞いが新しく増える / 変わる | `バックログ.md`（A/B/C 階層） |
| 外部挙動を変えない内部構造改善 | 本ファイル **§ 未着手候補 — リファクタリング** |
| 依存・インフラ・性能特性が変わる（外部振る舞いは同等） | 本ファイル **§ 未着手候補 — 技術メンテナンス** |

迷ったら: ユーザーが画面で気づく差分があれば機能（バックログ）、なければ本ファイル。

## 対象外（現状維持）

リスク・工数に対してメリットが小さい、または現行設計で十分な項目。

| 項目 | 理由 |
|---|---|
| Phase 76: `axios` → `fetch` 移行 | grill-me（2026-05-15）で確認。`apiClient` インターフェースを維持する限り fetch に変えても「内部で fetch を呼ぶ axios 相当のラッパー」になるだけで実質的利得なし。動機も「モダン化」のみで弱い。axios に脆弱性が出た時点で再検討 |
| Pydantic ↔ TS 型自動生成（openapi-typescript 等） | 工数大。手書き同期で運用継続 |
| `pdf_generator.execute_moves` と `file_manager` のロールバック共通化 | 対象（処理ファイル種・タイミング）が異なり、共通化メリット小 |
| `GEMMA_TOOL_DIR` の Windows パス依存デフォルト値 | Phase 8 で `.env` で上書き可能。Linux/Mac 開発予定なし |
| SearXNG → DLsite 直接検索 | 既知の問題として記録済み（Phase 12 時点で対象外維持） |
| `useLibraryManagement` のリネーム | 影響範囲が広い割に効果小 |
| `types/index.ts` の `BookMetaEntry` 拡張 | サークル名のみ管理の現行設計で十分 |
| API バージョニング | 現状シングルクライアント構成のため不要 |
