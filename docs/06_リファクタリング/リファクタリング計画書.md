## 概要

| 項目 | 値 |
|---|---|
| 完了 Phase 数 | 54 + Phase 55〜61 全体 |
| 未着手 Phase 数 | 追加候補のみ（下記各節を参照） |

| 次の動き | 追加候補 P3 項目のうち優先度が上がったものから着手 |

優先度の判断基準:
- **P1**: 既に分離した責務が再膨張、または毎レンダー走る派生計算、緊急バグ修正など実害がある
- **P2**: 重複ロジック・読みづらさが顕在化しているが緊急性は中
- **P3**: 構造改善ではあるが現状で困っていない

#### Phase 57 — `novel_db.py` ルーター 6 分割 + API パス REST 化（P1）

**問題**: 644 行・25 関数に 7 責務が混在。Pydantic モデル 11 個インライン。後方互換レイヤーあり。  
**改善案**:
- `backend/routers/novel_db/` パッケージ化し 6 サブルーター作成（`lib.py` / `character.py` / `rebuild.py` / `search.py` / `qa.py` / `chat.py`）
- API パスをリソース名詞基準に再設計（REST 化）例: `POST /api/novel-db/books/{id}/rebuild`、`GET /api/novel-db/sessions/{id}/messages`
- Pydantic スキーマを `backend/routers/novel_db/schemas.py` に一元化
- 再構築ロックチェックを `FastAPI Depends`（`require_not_locked`）に抽出
- フロントエンドの API URL を `apiClient.ts` で一括置換（パス変更に追随）

**変更対象**: `backend/routers/novel_db.py`、`frontend/src/services/apiClient.ts` およびその呼び出し元  
**新規作成**: `backend/routers/novel_db/` パッケージ（`__init__.py` / `schemas.py` / `_deps.py` / 6 サブルーター）  
**完了条件**: 既存 pytest 全通過・新サブルーター各 1 件以上テスト追加・API 仕様書更新・dev server で全機能動作確認

### Phase 62 — ベクトル DB を sqlite-vec → LanceDB に移行（P2）

**問題**: sqlite-vec の `vec0` 仮想テーブルは線形スキャン（O(n)）のため、チャンク数増加（書籍追加・B-17 漫画キャプション追加）に比例して検索レイテンシが増大する。ANN インデックスを後から追加できない設計制約がある。

**改善案**:
- `chunks_vec` と `book_summaries_vec` を `data/novel.lancedb/` ディレクトリ内の LanceDB テーブルに置き換え
- デフォルトはフラット検索（完全一致相当）、チャンク数 50,000 超で IVF_PQ インデックスを自動ビルド
- FTS5 は SQLite に残す（ハイブリッド RRF 構成は変更なし）
- B-17 の `pages_caption_vec` は本実装時に直接 LanceDB で作成する（今回スコープ外）

**実装サブステップ**:
1. `uv add lancedb` — 依存追加
2. `backend/config/__init__.py` — `NOVEL_DB_LANCE_PATH` 追加（デフォルト `data/novel.lancedb`）
3. `backend/services/novel_db/lance_store.py` 新規作成
   - `get_db()` — LanceDB 接続（ディレクトリ自動作成）
   - `get_chunks_table()` / `get_summaries_table()` — テーブル取得（初回作成）
   - スキーマ: chunks = `(chunk_id: int, book_name: str, page_no: int, text: str, char_count: int, page_count: int, embedding: vector[1024])`
   - スキーマ: summaries = `(book_id: int, book_name: str, embedding: vector[1024])`
   - `maybe_create_index()` — `len(table) > 50_000` で IVF_PQ 自動ビルド
4. `backend/scripts/migrate_to_lancedb.py` 新規作成
   - SQLite `chunks_vec` → LanceDB `chunks` のバルクコピー（BLOB を `struct.unpack` で float32 リストに変換）
   - SQLite `book_summaries_vec` → LanceDB `book_summaries` のバルクコピー
   - 実行: `uv run python scripts/migrate_to_lancedb.py`
5. `backend/services/novel_db/search.py` 修正
   - `vec_search()`: sqlite-vec JOIN クエリ → LanceDB `.search().where().limit().to_list()`（`conn` 引数を削除）
   - `search_book_summaries()`: 同様に LanceDB 化
   - `hybrid_search()`: `vec_search(conn, ...)` → `vec_search(...)` 呼び出し変更
6. `backend/services/novel_db/builder.py` 修正
   - `rebuild_from_pages()`: `INSERT INTO chunks_vec` → `get_chunks_table().add([...])` に置き換え
   - 旧チャンク削除: `chunks_vec DELETE` → `table.delete(f"chunk_id IN ({ids})")` に変更
   - `serialize_f32` インポート削除
7. `backend/services/novel_db/full_builder.py` 確認
   - `book_summaries_vec` の upsert → LanceDB summaries テーブルの upsert に変更
8. `backend/services/novel_db/schema.py` 修正
   - `chunks_vec` / `book_summaries_vec` の DDL 削除
9. `backend/services/novel_db/embedder.py` 修正
   - `serialize_f32()` 削除

**ロールバック**: `data/novel.lancedb/` を削除 → `migrate_to_lancedb.py` 再実行で復元

**変更対象**: `backend/config/__init__.py` / `backend/services/novel_db/lance_store.py`（新規）/ `search.py` / `builder.py` / `full_builder.py` / `schema.py` / `embedder.py` / `backend/scripts/migrate_to_lancedb.py`（新規）  
**完了条件**: pytest 全通過（既存テスト）+ `hybrid_search` / `search_book_summaries` の結果が sqlite-vec 時代と同等 + 移行スクリプト実行確認 + 設計書更新

## 対象外（現状維持）

リスク・工数に対してメリットが小さい、または現行設計で十分な項目。

| 項目 | 理由 |
|---|---|
| Pydantic ↔ TS 型自動生成（openapi-typescript 等） | 工数大。手書き同期で運用継続 |
| `pdf_generator.execute_moves` と `file_manager` のロールバック共通化 | 対象（処理ファイル種・タイミング）が異なり、共通化メリット小 |
| `GEMMA_TOOL_DIR` の Windows パス依存デフォルト値 | Phase 8 で `.env` で上書き可能。Linux/Mac 開発予定なし |
| SearXNG → DLsite 直接検索 | 既知の問題として記録済み（Phase 12 時点で対象外維持） |
| `useLibraryManagement` のリネーム | 影響範囲が広い割に効果小 |
| `types/index.ts` の `BookMetaEntry` 拡張 | サークル名のみ管理の現行設計で十分 |
| API バージョニング | 現状シングルクライアント構成のため不要 |
