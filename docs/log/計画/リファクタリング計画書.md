## 4. 実施規則

各Phaseは次を満たしてから完了とする。

1. 変更前に既存挙動を固定するテストまたは比較手順を用意する。
2. 公開import、API、DB、保存ファイル、エラーコードの不変条件を明記する。
3. 設計書、変更履歴、ソース、テストの順で変更する。
4. 対象テストの後に全体テストと静的検査を行う。
5. 完了実績を本書から削除し、リファクタリング履歴へ移す。
6. 例外や保留は理由と再評価条件を記録し、無期限のignoreを作らない。

## 5. 技術メンテナンス候補

### TM-2. OCR ground truth APIの全件CER再計算を増分化する — P2

`GET /api/ocr/ground-truth`と単件更新応答は、登録済み全本文のLevenshtein距離をPythonの
二次元DPで都度再計算する。2026-08-01のB-35コーパス追加後、登録・更新は完了していても
全件応答が60秒を超える事例を確認した。

- API契約、CER正規化規則、DB正本を変更せず、ページ単位の編集距離と文字数を更新時に再計算する。
- 一覧・更新応答は保存済み集計を合算し、本文または候補変更時だけ対象ページを無効化する。
- 現行の全件再計算結果と同値であることを固定コーパスで比較し、失敗時は古い集計を返さない。
- 60秒タイムアウトを登録失敗と誤認しない監査手順を維持する。

着手条件はB-35の品質判定を妨げない独立ブランチを確保できること。完了条件は現行コーパスで
一覧・更新応答が10秒以内、全指標が従来実装と完全一致することとする。
