## 4. 実施規則

各Phaseは次を満たしてから完了とする。

1. 変更前に既存挙動を固定するテストまたは比較手順を用意する。
2. 公開import、API、DB、保存ファイル、エラーコードの不変条件を明記する。
3. 設計書、変更履歴、ソース、テストの順で変更する。
4. 対象テストの後に全体テストと静的検査を行う。
5. 完了実績を本書から削除し、リファクタリング履歴へ移す。
6. 例外や保留は理由と再評価条件を記録し、無期限のignoreを作らない。
