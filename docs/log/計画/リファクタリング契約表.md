## 3. 経路別の不変条件

### 3.1 Kindle UI 操作

- ASIN 一致または設計済み書誌照合が成立するまで対象 control を操作しない。
- source 別 page layout、先頭条件、最大 1 回の表紙補正、page key を変更しない。
- 固定画面座標、暗黙の Kindle process kill/restart、連続ページ送りによる先頭探索を導入しない。
- UIA/COM/readback を確認できなければ `positioning_failed` 等で fail closed にする。

### 3.2 capture file 公開

- agent は画像、hash、manifest、quality/canary 証跡を完成後にだけ `.ready` へ原子的公開する。
- backend は version 2 manifest と全画像を独立再検証する。
- DB、meta、正式画像、`processed/` の一部だけが成功した状態を残さない。
- 既存 target は同じ ASIN を meta で確認できる場合だけ置換する。

### 3.3 catalog DB 更新

- create/claim/state 更新は transaction と条件付き update で所有 agent・許可遷移を守る。
- digest による冪等性、import run の processed/skipped/updated 集計を維持する。
- Novel DB (`novel.db`) と Kindle catalog (`kindle_catalog.db`) の migration 系列を混在させない。

### 3.4 OCR subprocess

- worker の JSONL protocol は `page` / `progress` / `fatal` と既存 payload を維持する。
- unknown event、非 0 exit、quality failure を成功扱いしない。
- staging/QA を経ずに公開 tables へ本文を書かない。

### 3.5 OCR QA / publication

- required/rejected/unknown page または空の narrative text があれば approve しない。
- `ocr_quality_policy.json`、page/layout type、selected engine、quality flag の意味を変更しない。
- books/pages/FTS と run state は同一 transaction の成功時だけ確定する。

### 3.6 RAG LLM / DB / SSE

- token/segment/turn と terminal `done` / `error` の順序を維持する。
- prompt、model role、既定 options、history schema を構造変更へ混在させない。
- LLM または history 完了保存の失敗を正常完了として返さない。

### 3.7 frontend API / query / local state

- URL、query key、invalidate 範囲、SSE event 変換、toast/error 表示を維持する。
- page 間共有 cache/state を component local state へ縮退させない。
- mutation 失敗時に、成功を前提とした選択解除や cache 更新を残さない。

| C-06 | OCR QA/publication | publication transaction 中の DB 障害注入と rollback assertion が不足 | R3 | books/pages/FTS/run state が全て旧状態であることを確認 |
