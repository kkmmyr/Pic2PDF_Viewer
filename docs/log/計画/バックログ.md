## B. 中優先

<a id="b-26"></a>
### B-26. 書籍類似度推薦（novel）

**価値**: 書籍詳細から次に読む類似本を探し、読書会の比較トークにも使う。

**候補契約**: bge-m3全文、サマリ、タグ／著者の3軸を調整可能な重みで合成し、最大5件を表示する。
`book_similarities`へ事前計算し、管理画面から手動更新する。B-19のサマリembedding KNNは既存の簡易版。

**完了条件**: 評価集合で重み・閾値を決め、schema、API、UI、再計算運用を設計して実装する。
初期検討は[凍結要件メモ](../../archive/要件/書籍類似度推薦_初期要件メモ.md)を参照。

<a id="b-28"></a>
### B-28. 読書会ロングフォーム Phase 1 — 主観受入待ち

機械checkは実装済み。現行契約は[検索QA設計 §8](../../design/詳細設計/機能別/小説RAG_検索QA設計.md)を正本とする。

**残作業**: 層1合格台本1件を利用者が確認し、「笑える／へえ」が3箇所以上か、キャラがぶれないかを判定する。
合格なら本項目を削除し、不合格なら具体的な評価項目だけを別候補として起票する。

### B-2. メタデータ一括インポート

JSONまたはCSVを検証し、既存メタへ`upsert / overwrite / skip`の明示policyで取り込む。
schema差分、dry-run、rollback、衝突結果の提示が必要。

### B-4. キーボードショートカットのカスタマイズ

action-key mapをlocalStorageへ保存し、設定画面から編集する。衝突、予約キー、初期化、reader既存操作との互換を設計する。

### B-17. 漫画画像キャプション検索 — 保留

### B-18. リーダー統合「ここまでのあらすじ」

任意ページまでの本文から800〜1,500字のrecapを生成し、bookと`up_to_page`単位でcacheする。
ネタバレ境界、再生成、OCR更新時の無効化を着手前に確定する。

### B-25. meta.dbクラウド同期

ライブDBを同期フォルダへ置かず、SQLite Online Backupで作った検証済み世代だけを外部ストレージへ複製する。
復元は明示操作とし、衝突policy、暗号化、世代保持、復元試験を設計する。

<a id="b-37"></a>
### B-37. page-level LanceDB ICUへの段階移行 — 実利用観測待ち

世代別再構築、SQLiteとの件数・ID・hash検査、`fts5 / shadow / lance_icu`切替、stale検知、FTS5 fallback、
障害注入、復元試験、固定20問と封印12問の評価は完了した。既定は`fts5`で、shadowも利用者へFTS5順位を返す。

**残作業**:

1. `2026-08-23T08:56:00`以後の実利用queryを20件以上・10種類以上・3日以上観測し、
   unavailable / fallback / malformed 0件、ICU p95 200ms以下を機械判定する。
2. 合格後に利用者の別承認を得て`lance_icu`を既定へ切り替える。
3. 切替後に障害注入とFTS5 rollbackを再確認する。自動昇格しない。

正本は[検索QA設計 §10](../../design/詳細設計/機能別/小説RAG_検索QA設計.md#rag-search-evaluation)と
[ADR-0020](../../design/基本設計/ADR/0020_page-level-lancedb-icu-shadow.md)。dense model、reranker、embedding置換は含めない。

<a id="b-35"></a>
### B-35. 小説OCRの機械単独自動公開 — 保留

**現在地**: 現在の全機械候補は正式policyに未達。Unlimited-OCR BF16は固定5枚すべての
生成反復、Nemotron Parse 2.0 8bitは固定1枚目の4,096 token反復でそれぞれ
fail-fast不採用とした。Qianfan-OCRの固定MLX 4bit変換も固定1枚目で最大CER gateを超え、
2枚目で生成反復したためfail-fast不採用とした。HunyuanOCR 1.5 BF16 GGUFは固定1枚目を通過したが、
2枚目で段落重複・順序入替により最大CER gateを超えたため不採用とした。Codex画像QA込みの
運用品質と、Codexなしの機械性能を分けたまま評価する。Hayai OCR v2固定revisionも固定1枚目で
8文字しか生成せずCER 99.4932%となったためfail-fast不採用とした。honmono-ocrは縦書き行benchmarkが公開されたが、モデル本体と
参照GitHubを認証なしで取得できず、ページ分割・読順復元も別途必要なため直ちに評価しない。実装済みgateと実測値は
下記正本へ置く。

Qwen3.5-OCR-JP-2B固定revisionは固定5枚中4枚で総合CER 0.2416%だったが、`001751`だけが
8,000 token上限まで反復し、単体5枚総合CER 344.1829%となったため単独候補にはしない。既存の
`has_suspicious_repetition`は固定5枚でこの1枚だけを検出し、同ページだけHTML末尾も切断された。参照正解を使わず、
反復または末尾切断時だけ
dots.mocrへ切り替える複合候補は、過去の同revision・固定5枚実測から総合CER 0.3285%以下、
ページ最大0.6907%以下となるため固定5枚gateを通過した。初期規則の固定79枚screeningは15枚時点で
総合CER 0.5166%、`000260`が3.1042%となりfail-fastしたが、レビュー前提版では全79枚を再開・完走した。

ADR-0022で、Qwenを主候補、dots.mocrを全ページの独立副候補とし、反復・HTML切断・非保持markup・
隣接する狭い縦列bboxの読順違反・副候補の有意な文字量増加をレビュー初期候補の切替signalにする。
ADR-0023により、候補切替・解析異常・反復・画像のみ・分類未確定・内容riskとclean標本を人手QAし、
残るclean通常本文を監査付き承認する版へ更新した。機械gate未達なので自動公開には使わない。
修正後本文は運用品質として採用するが、機械CERへ混ぜない。

開封済み79枚ではQwen単体が反復4枚を含み総合CER 104.9354%、dots単体が0.8990%、レビュー用複合版が
0.4091%だった。複合版は79枚中7枚をdotsへ切り替え、最大ページCERは2.8835%で2.0%未満gateだけが残った。
したがってQwen主候補＋dots副候補の構成を維持するが、候補選択だけで公開品質とはみなさない。

**残作業**:

1. レビュー前提laneは、57画面の全承認、4画面の補正、隔離DBでの公開、検証済みbackup、旧run 76への
   rollbackまで完了した。run 184は再activate可能な`completed / approved`として保持し、本番DBへは未適用である。
2. 機械総合合格は将来の自動公開条件として継続する。新しい未調整holdoutでpolicy JSONの全gateを満たすまで、
   自動公開と人手QA省略は実装しない。

レビュー前提laneの完了条件は[小説OCR品質改善 実装計画](小説OCR品質改善_実装計画.md)の
複合engine統合、1冊のリスク対象QA、監査付き残ページ承認、公開・rollback確認。policy JSONの全gate合格は
自動公開の条件として残す。現行契約は
[OCR設計書](../../design/詳細設計/機能別/OCR設計書.md)、実測は
[OCR品質改善 技術知見](../技術知見/OCR品質改善_技術知見.md)を参照する。

<a id="b-36"></a>
### B-36. 既存要約・人物辞典の再生成とQA — 保留（現方式不採用）

可読性優先promptで既存生成物を更新する候補。OCR本文・画像・索引を変更せず、隔離成果物、機械gate、
独立評価、人手承認を通った場合だけ公開する。失敗時は旧公開版を保持する。

**現在地**: 初回v1は3冊全部で意味不一致6件、review引用不一致4件でfail closedになった。
同じ6件を一般化した実験v2で同一source SHAから新規生成しても、11巻は1回限定引用修正後に
完全一致gateを通過できず、10巻と12巻の独立reviewはそれぞれ4件の意味不一致を検出した。
詳細、一覧、人物辞典の文章化・人手確認・公開は未実施で、旧公開版を維持する。
現行の「全巻本文から1回で役割付きfact graphを生成」経路は不採用とする。

**残作業**:

1. 同モデルのprompt微調整や同一候補の追加修正は終了する。
2. 再開する場合は、原子的な行為fact抽出と、作中発言・最終状態・actor roleの別session判定を
   分離するなど、現行と実質的に異なる方式を新しい完了条件とともに起票する。
3. 新方式で3冊の全factがsupportedになるまで文章化と公開DB置換を行わない。

正本は[Sol生成・評価設計](../../design/詳細設計/機能別/小説RAG_Sol生成・評価設計.md)、
[ADR-0018](../../design/基本設計/ADR/0018_sol-primary-post-ocr-generation.md)。モデル別の全実測は
[整理前バックログ](../../archive/検証/バックログ_2026-08-22_整理前.md)と
[小説RAG検証履歴](../../archive/検証/小説RAG_技術検証履歴.md)を参照する。

### C-5. 読書統計ダッシュボード

月別冊数、作者・シリーズ傾向を表示する。集計定義と閲覧履歴の扱いを着手前に確定する。

### C-10. 新規キャプチャ後の自動OCR・DB構築

capture完了からjob queueへ自動投入する。失敗隔離、負荷時間帯、手動overrideを設計する。

### C-11. RAG検索結果エクスポート

回答、引用本文、ページ番号をJSON／Markdownで保存する。個人情報と元本文の出力量を確認する。

### C-14. 読書会 Phase 4 — 3人以上のパネル

2話者marker、prompt、保存schema、UIを一般化する。B-28〜B-30完了後に再判断する。

### C-13. 複数モデル回答比較UI

同一queryを複数backendへ送り比較する。GPU競合、同一条件、保存量、実行時model選択を設計する。

## 対象外の原則

個人LAN・単一利用者・同人誌特化という前提から、認証／マルチテナント、公開API向けrate limit、
microservices、Kubernetes、GraphQL、外部クラウドLLMへの自動送信は対象外とする。
撤去済みタグやシリーズ自動生成、ePub、レーティングも、利用要件が変わらない限り再導入しない。
個別判断の履歴は[整理前バックログ](../../archive/検証/バックログ_2026-08-22_整理前.md)を参照する。

## 運用ルール

- 新しいユーザー体験は本書、内部改善はリファクタリング計画書へ置く。

- 実装完了時は本書から削除し、変更履歴と現行設計へ記録する。
