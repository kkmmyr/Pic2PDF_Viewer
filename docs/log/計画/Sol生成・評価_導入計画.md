## 1. 現在地

| 段階 | 状態 | 判断 |
|---|---|---|
| Phase 1: 10巻固定パイロット | 完了 | 高リスク主張の重大不一致または引用不一致があれば公開しない契約を確認した |
| Phase 2: 固定コーパス拡張 | 不採用 | 全巻直接fact graph生成経路は文章化、完成文評価、人手確認、公開DB変更へ進めない |
| Phase 3: 手動承認付き運用 | blocked | 再開には新しい候補経路と受入判断が必要 |

## 2. Phase 3を開始する条件

次をすべて満たした場合だけ、Full Buildの生成部分をSol候補経路へ切り替える。

- 重大誤り0件
- 固定ケース100%合格
- Schema・ローカルゲート合格率95%以上
- 一覧版・詳細版の人手修正が軽微
- Qwen/Gemma/Luna複合経路より成功1冊あたりの総作業時間が短い

対話QA、embedding、チャンク文脈生成は変更しない。自動公開はPhase 3の対象外とする。

## 3. 再開時の作業

1. 直接fact graph生成とは別の候補経路と、その失敗時の停止条件を設計書へ追加する。
2. 固定OCR本文SHA、主張単位の根拠、独立review、完成文評価、人手確認を分離した評価packageを用意する。
3. 隔離CLIでのみ評価し、公開DB import・Web API・UI・定期実行・全冊バッチ・新規DBテーブルを追加しない。
4. 受入条件を満たす結果とユーザーの別承認が揃うまで、結果import・一括確定を実装しない。
