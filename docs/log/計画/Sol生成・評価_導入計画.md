# Sol生成・評価 導入計画

> status: blocked | last-verified: 2026-09-05 | owner: project owner
>
> 状態詳細: 改訂済みの原子fact経路を新しい評価として再開する受入判断がなく、Phase 3を開始しない

Sol主生成・独立評価の現在の隔離CLI、fail-closedゲート、外部送信・公開境界は
[Sol生成・評価設計](../../design/詳細設計/機能別/小説RAG_Sol生成・評価設計.md)を正本とする。
Phase 1・2の実測は[追加実測履歴（凍結）](../../archive/検証/小説RAG_Sol生成・評価_追加実測履歴_2026-09-05.md)、
整理前の導入条件は[導入計画整理前（凍結）](../../archive/検証/Sol生成・評価_導入計画整理前_2026-09-05.md)を参照する。

## 1. 現在地

全巻本文から直接fact graphを生成する旧候補は不採用で、実測と停止判断は凍結記録へ移した。
現行の[Sol生成・評価設計](../../design/詳細設計/機能別/小説RAG_Sol生成・評価設計.md)には、
原子的な行為fact抽出、全factの独立評価、文章化、完成文評価を分離する改訂案が定義済みである。
この改訂案を新しい評価として開始する受入判断がないため、Phase 3はblockedのままとする。

## 2. Phase 3を開始する条件

プロジェクトオーナーが改訂案の再評価を別途承認し、
[Sol生成・評価設計](../../design/詳細設計/機能別/小説RAG_Sol生成・評価設計.md)の全体フローと
ローカルゲート、独立評価、公開確定の契約をすべて満たした場合だけ、Full Buildの生成部分を
Sol候補経路へ切り替える。判定値を本書へ複写せず、同設計を唯一の受入契約とする。

対話QA、embedding、チャンク文脈生成は変更しない。自動公開はPhase 3の対象外とする。

## 3. 再開時の作業

1. 現行設計の改訂案を評価対象にするか、対象冊数、停止条件、利用量上限を別途承認する。
2. 固定OCR本文SHA、原子fact、独立review、完成文評価、人手確認を分離した新しい評価packageを用意する。
3. 旧候補の出力や同じ失敗ケースを学習済みの調整材料として混ぜず、隔離CLIだけで評価する。
4. 公開DB import・Web API・UI・定期実行・全冊バッチ・新規DBテーブルを追加しない。
5. 現行設計の受入契約を満たす結果とユーザーの別承認が揃うまで、結果import・一括確定を実装しない。
