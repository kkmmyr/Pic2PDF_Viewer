# Kindle 購入カタログ画面 UI/UX 改善 引継ぎ

作成日: 2026-07-25

状態: **要件確定・実装前（2026-07-25）**

対象画面: `/kindle/catalog`

確定要件: [Kindle 購入カタログ画面 UI/UX 改善 要件](../../design/要件定義/Kindle購入カタログ画面_UI改善_要件.md)

## 0. 要件整理の結果

- デスクトップを主対象、iPad を閲覧対象とし、端末による機能制限は行わない。
- Kindle 領域を購入書籍、画像紐付け、キャプチャ、取込・管理の固有 URL 付き 4 タブへ分ける。
- 購入書籍を初期ページとし、検索専用の高密度テーブル + 書籍詳細パネルを採用する。
- 画像紐付けは左右比較 + 候補選択 + 最終確認とする。
- 月次取込は既存 3 API の「すべて差分取込」と個別実行を用意する。
- キャプチャは運用設定完了まで利用準備中とし、新規ジョブ作成を表示しない。
- 誤操作防止と状態の分かりやすさを最優先する。
- API、DB、取込ロジックは変更しない。

## 1. この文書の目的

Kindle 購入カタログのデータ移行と初回リリースは完了した。次のチャットではバックエンド移行をやり直さず、実データが入った画面を基準に UI/UX の改善要件を固める。

この文書は、次の担当チャットが最初に読む設計書、変更してよい範囲、現行データ、未確定事項、受入条件のたたき台をまとめた引継ぎ資料である。

## 3. 現行画面が持つ機能

1. ヘッダー
   - Kindle Info 差分取込
   - シリーズ自動購入取込
   - Amazon CSV 差分取込
   - 旧 DB 移行確認
2. 統計カード
   - 書籍、購入、KU、返品、シリーズ、画像紐付け件数
3. 書籍一覧
   - タイトル検索
   - 種別、所有状態、画像状態フィルター
   - 50 件ページング
   - comic / novel キャプチャジョブ作成
4. 既存画像の ASIN 紐付け
   - Pic2PDFViewer の comic / novel だけを対象に候補表示
   - 人が候補を確認して確定
5. キャプチャジョブ
   - 状態一覧を 5 秒間隔で更新

## 4. 変更してはいけない境界

- `kindle購入履歴` の画像、表紙キャッシュ、画像パス、レビューを取り込まない。
- 既存画像の ASIN は候補スコアだけで自動確定しない。
- Pic2PDFViewer の既存画像を移動・複製・削除しない。
- 購入カタログ DB と `meta2.db` の役割分離を維持する。
- UI 改善だけを理由に API、DB スキーマ、取込ロジックを変更しない。必要性が判明した場合は、実装前に別判断としてユーザーへ提示する。
- Windows キャプチャエージェントは、専用 Samba 共有とトークンの運用設定が完了するまで「利用準備中」として扱う。
- 実データの再移行、全削除、再構築を行わない。

## 5. 次チャットで確認する設計論点

以下は決定事項ではなく、現行画面を見ながら確認する質問である。

### 5.1 画面の主目的

- 最も頻繁な操作は購入書籍の検索・確認か。
- 既存画像の ASIN 紐付けを当面の主作業として前面に出すか。
- 差分取込は常設ボタンか、管理・メンテナンス領域へまとめるか。
- キャプチャ開始は一覧行の主操作か、書籍詳細または選択操作へ分離するか。

### 5.2 情報設計

- 初回移行済みのため、「旧 DB 移行確認」を通常運用の主要操作から外すか。
- 定期取込、既存画像整理、キャプチャをタブまたはセクションで分離するか。
- 11,419 冊を前提に、表・カード・密度のどれを優先するか。
- 所有状態、種別、画像状態のうち、一覧で常時見せる情報を絞るか。
- 30 件の未紐付け作業に、進捗件数や「判断保留」を用意するか。

### 5.3 利用端末

- デスクトップを主対象とするか。
- iPad 幅でも検索・フィルター・主要操作を無理なく使える必要があるか。
- スマートフォンは閲覧のみか、紐付け操作まで対象にするか。

### 5.4 見た目

- Pic2PDFViewer の既存ナビゲーション、色、ダークモードを維持する。
- 情報量の多い管理画面として密度を優先するか、余白を広く取るか。
- 書影は現スコープに存在しないため、旧アプリの表紙画像をデザイン目的で復活させない。

## 6. 受入条件のたたき台

- 初回移行済み利用者にとって、通常使う操作と一度だけの管理操作の優先順位が明確である。
- 書籍検索、種別・所有・画像状態フィルター、ページ移動の既存機能を失わない。
- 差分取込中、成功、変更なし、失敗が画面上で理解できる。
- 既存画像の紐付けは、対象書籍と候補 ASIN のタイトル・著者・種別を比較してから確定できる。
- 自動紐付けは行わない。
- キャプチャが未設定の場合、利用できない理由と必要な準備が分かる。
- loading、empty、error、disabled の各状態を設計する。
- ライト・ダークテーマの両方で視認できる。
- キーボード操作、フォーカス表示、ボタンの accessible name を維持する。
- 最低限、デスクトップ幅と iPad 相当幅でレイアウトを確認する。
- API・DB・取込結果を変更しない UI-only 案を第一候補とする。

## 8. 実装時のプロジェクト規約

- 最初に `architecture-overview`、実装時に `docs-workflow`、`frontend-conventions`、`test-writing` を使用する。
- API 通信は `apiClient` と TanStack Query を維持する。
- OpenAPI 生成型を参照し、`any` を使用しない。
- 通知は `sonner`、確認は共通 `Dialog` / `ConfirmDialog` を使用する。
- import は `@/` エイリアスを使用する。
- ページがさらに肥大化する場合は、Kindle 専用コンポーネントへ責務分割する。
- UI 変更後は `npx tsc -b`、`npm run lint -- --quiet`、関連 Vitest、本番 build を実行する。
