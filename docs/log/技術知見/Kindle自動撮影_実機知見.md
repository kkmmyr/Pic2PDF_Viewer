# Kindle 自動撮影 実機知見

> status: living | last-verified: 2026-10-08 | owner: Kindle capture

Kindle デスクトップアプリを使った連続撮影・取込について、現在再利用する実機上の確認手順と注意点をまとめる。
本書は契約を新設せず、要件と状態遷移は
[Kindle 自動撮影取込 要件](../../design/要件定義/Kindle自動撮影取込_要件.md)、実装契約は
[Kindle 購入カタログ設計](../../design/詳細設計/機能別/Kindle購入カタログ設計.md)を正本とする。
過去の受入結果と障害調査は[実機検証履歴](../../archive/検証/Kindle自動撮影_実機検証履歴.md)へ凍結した。

## 1. 実行前提

- Windows の Kindle デスクトップアプリへ対象 Amazon アカウントでログインしておく。
- Pic2PDFViewer backend と capture agent を起動し、購入カタログに対象 ASIN が存在することを確認する。
- Kindle、capture agent、シリーズ CLI を同一 Windows ユーザーで実行する。UI Automation セッションを跨がない。
- 画像、manifest、state、取込先の空き容量と書込権限を確認する。
- 同時に許可する active capture job は全 source・全 ASIN を通じて最大1件である。
- 既定は dry-run。実撮影は対象 manifest を確認してから `--apply` を明示する。

## 2. シリーズ連続処理

シリーズ CLI は inventory を取得し、指定順に1冊ずつ job を作成・監視する。state schema v2へ
manifest digest、完了 ASIN、撮影画面数、warning、復旧回数、停止理由を原子的に保存する。

- resume は `--resume-session` を明示し、同一 manifest・`running` state の場合だけ許可する。
- 完了 ASIN、画面数、warning の対応が崩れた state は resume しない。
- Kindle process の自動復旧は `--recover-kindle-crash` 指定時だけ有効で、撮影前または0画面、
  process 消失、許可 error code、同一 ASIN の一意照合、他 active job なしをすべて満たす場合に最大1回行う。
- `download_failed`を含む任意の1冊目の失敗でシリーズ全体を停止し、後続 job を作らない。
  失敗巻を隔離して継続する方式は将来候補であり、現行運用では使わない。
- 一時停止は新しい job を作成する前に行う。実行中 job を OS レベルで強制終了せず、状態とログを保全する。

## 3. Kindle UI 操作

- UI Automation の対象ウィンドウを一意に特定し、前面化とサイズ固定後に撮影する。
- 未ダウンロード書籍はダウンロード完了を待ち、タイムアウト時は `download_failed` として停止する。
- 先頭移動は直接移動を優先し、成立しない場合だけページ送りへフォールバックする。
- ページ送り後は描画安定を待ち、同一画面の連続取得、ページ不変、UI overlay を品質判定へ渡す。
- Kindle アプリ更新後はウィンドウタイトル、Automation 要素、本文矩形、移動操作を再検証する。

## 4. source 別の撮影範囲

| source | 基本単位 | 重要な確認 |
|---|---|---|
| `comic` | 見開き表示を含む画面 | 左右ページ順、中央綴じ、余白、ナビゲーションUI混入 |
| `novel` | 1画面 | 縦書き列の欠落、上下UI、通知overlay、小さい本文、ページ重複 |

本文矩形は固定値だけに依存せず、実機プロファイルと品質検査を組み合わせる。source を跨いで
画面数基準を共有しない。シリーズ画面数外れ値は同 source の成功済み3冊以上を母集団にした
warningであり、登録取消や後続停止には使わない。

## 5. 品質ゲート

登録前に package validator が manifest、画像列、hash、撮影枚数、warning policy を検査する。
不正型、欠落、重複、順序不整合、blocking overlay は fail closed とし、既存公開物を保持する。

目視確認では次を確認する。

1. 先頭・中間・末尾に欠落、重複、白紙化がない。
2. 漫画は見開き順と端切れ、小説は縦列・ルビ・上下端が成立する。
3. Kindle ナビゲーション、OS通知、カーソル等が本文へ重なっていない。
4. warning は候補ページと code を確認し、誤検知だけを承認する。

2026-08-22 の未調整524画面は人手確認で欠陥0件だった。これは陰性品質の受入であり、
実陽性検出率の証明には使わない。今後見つかった実障害は、修正前画像と確定 label を回帰コーパスへ追加する。

## 6. 公開・置換・キャッシュ

- 撮影成功だけでは公開完了としない。package 検証、転送、登録 transaction、公開先確認までを1単位とする。
- 置換時は既存画像を回復可能な形で退避し、途中失敗時は旧公開物と DB 参照を維持する。
- 公開後は API のページ数、先頭・末尾画像、reader の実表示を確認する。
- 同名画像を置換した場合、ブラウザーキャッシュで旧画像が見えることがある。再読込だけで判定せず、
  配信ファイルの hash と URL 応答を確認する。
- `novel` は画像公開後に OCR を別 job として実行し、OCR 品質ゲート合格前に本文・索引を置換しない。

## 7. 障害時の確認順

1. capture job の status、error code、heartbeat、撮影画面数を確認する。
2. Kindle process と対象 ASIN の表示状態を確認する。
3. session state と manifest digest を保全し、resume 条件を満たすか判定する。
4. download・UI不調・転送・登録失敗は自動復旧せず、原因解消後に新しい job として再実行する。
5. 既存公開物、索引、バックアップを確認してから再撮影・置換する。

## 8. 再検証トリガー

次の変更後は、漫画1冊・小説1冊以上で先頭から登録までを再確認する。

- Kindle アプリまたは Windows の更新
- UI Automation selector、本文矩形、ページ送り待機時間の変更
- capture agent、package validator、warning policy の変更
- 転送先、公開先、Samba、バックアップ経路の変更
- source 名または reader URL 契約の変更

## 9. 新版非対応書籍を旧版で補完する手順

通常は新版を優先し、内容非対応が確認できた書籍だけ旧版で補完する。
2026-10-07の実機では旧版2.9.1.71006のタイトルに`Kindle for PC3`が含まれ、
実行ファイルは`%LOCALAPPDATA%/Amazon/Kindle/application/Kindle.exe`だった。
アカウント名の接頭辞があるため先頭一致にはせず、実行ファイルと対象windowも照合する。

旧版ライブラリの検索欄は`search-bar`、書籍カードは`library-item-option-{ASIN}`。
ASIN検索をReturnで確定し、題名・巻と照合する。ダウンロード済みは
`badge-Local-{ASIN}`と画像の「ダウンロード済み」で確認する。
親カードの名前に古い未ダウンロード表示が残ることがあり、名前だけで完了判定しない。
ダウンロード開始のダブルクリックは完了後の自動openを保証しない。

既存の自動agentのライブラリcontrollerは新版向けであり、この旧版経路は
全自動フォールバックの実装済みを意味しない。補助取得では書籍と表紙移動を個別に確認し、
既存`NovelKindleCapturer`のF11・画像保存処理を利用する。
旧版でも閲覧領域へフォーカスを合わせ、操作カーソルを除去してからカナリアを行う。
カナリア後は同一先頭画像への復帰を確認し、既知の左送りを終端で逆転させない。

旧版フッターは`位置No. n/total`。先頭1、同一total、末尾100%、
視覚無変化の再試行を併せて確認し、ローカル画像の目視確認後だけ既存manifest・QA・
package検証を通して登録する。先頭位置が文字表紙の版では、カラー表紙取得済みと記録しない。
失敗した過去jobは保持し、登録には新規jobを使用する。

位置番号は表示ページの先頭であり、総位置との差が数位置以内になるとは限らない。
銀盤1巻は連続撮影102画面・100%・3119/3137で終端無変化となった。
総位置3137への直接移動で表示された最後の注意書きは102枚目の最終列に含まれていた。
総位置への直接移動はページ内の再配置を起こすため、その画面だけを未取得ページと数えない。
終端判断では100%と無変化だけでなく、直接移動した末尾の文章を最終保存画像と照合する。

2026-10-07の補完取得では、次の12冊・1,267画面を旧版で取得して登録した。

| 対象 | 巻 | 保存画面数 |
|---|---|---:|
| 銀盤カレイドスコープ | 1〜9 | 953 |
| 下ネタという概念が存在しない退屈な世界（本編） | 3・5 | 181 |
| 魔法少女禁止法 | 2 | 133 |

全保存画像の目視確認、全転送画像のSHA-256照合、各冊の先頭・中間・末尾画像の
HTTP配信照合を通過した。各冊で総位置への直接移動と保存末尾を照合し、
カーソル・操作UIの写り込みがないことを確認した。警告候補は扉・章間余白・
黒地の口絵等の実画像を確認して承認した。銀盤9冊の先頭は文字表紙である。
対象3シリーズの巻順を登録し、従来のメタデータはシリーズ項目以外の保持を照合した。
今回指定された8シリーズの購入済み対象58冊はすべて画像登録済みとなった。
画像取得の受入であり、この補完作業ではOCRを実行していない。

## 10. 新旧Kindleの同時起動と補助ウィンドウ

2026-10-07の不足巻取得で、新版の表示ウィンドウとは別に、旧版側の
タイトルが`Kindle`の小さな補助ウィンドウが存在した。従来の`find_window()`は
タイトルの先頭一致で最初のwindowを採用するため、この補助windowを選択した。
本文領域のUI Automationは新版を参照したまま、撮影側だけ別windowを最大化し、
`Novel body bounds do not fit the capture frame.`で0画面のまま停止した。

表示中の新版windowを直接指定すると撮影できたが、先の操作で残った黒い小窓が
保存画像の左上に写り込んだため、100画面の撮影分を登録前の目視ゲートで却下した。
新版を閉じても補助windowは残り、旧版を閉じると従来の検索でもwindowなしとなった。
両版の終了を確認してから新版だけを起動し直し、先頭3画面の保存画像で写り込みが
消えたことを確認した。この順序と結果は実機の観測であり、常用agentの修正済みを意味しない。

補助取得では新旧を同時に起動せず、切替時は利用しない版を終了する。
撮影対象は実際に表示されたwindowの識別情報・題名・ASINを照合して指定する。
ウィンドウ内の画面取得だけでは他windowの重なりを検出できないため、実際の保存画像も
撮影直後の数画面で確認する。問題があれば登録前に停止し、原因解消後の新規jobで撮り直す。

## 11. 不足巻の補完取得と新版の終端表示

2026-10-07に、途中取得だった7シリーズの購入済み不足34冊と、追加指定の
『化物語』上・中・下3冊を取得した。合計37冊・4,738保存画面を登録し、
小説DBの画像登録済み冊数は222冊から259冊になった。

| 対象 | 今回取得した巻 | 保存画面数 |
|---|---|---:|
| この素晴らしい世界に祝福を！（本編） | 10〜17 | 757 |
| おこぼれ姫と円卓の騎士 | 3・13〜17 | 570 |
| 蜘蛛ですが、なにか？（本編） | 1〜10・12〜16 | 2,462 |
| 後宮一番の悪女 | 二・三 | 175 |
| 「君を愛することはない」と言った氷の魔術師様の片思い相手が、変装した私だった | 2 | 107 |
| 悪役令嬢の中の人 | 2 | 95 |
| グリムコネクト | 4 | 147 |
| 化物語 | 上・中・下 | 425 |

新版で36冊、旧版で『化物語』上巻116画面を取得した。『化物語』中・下巻は
新版で取得できており、同一シリーズでも巻ごとに利用可能な版を確認する。
全保存画像の一覧と各冊の先頭・中間・末尾の拡大画像を目視し、転送画像の
全SHA-256と各冊3点のHTTP配信を照合した。8シリーズの巻順を反映し、
作業前の既存メタデータは対象のシリーズ項目以外が一致することを最終照合した。
この作業ではOCRを実行していない。

新版の終端表示には`Location n of total • 100%`と`ページn/total • 100%`の
両形式があった。補助取得の終端確認は両方を読み取り、保存末尾の内容と
終端無変化も併せて確認する。英語形式だけを受け付けて停止した撮影は登録せず、
日本語表示を照合したうえで新規jobにより取得し直した。常用agentの変更は行っていない。

おこぼれ姫14巻と蜘蛛12巻では新版のダウンロードが一度失敗したが、
ライブラリで同じASINの失敗表示を確認し、再ダウンロード後の完了表示と
表紙を個別確認すると新版で取得できた。単発の`download_failed`だけで
旧版必須と断定しない。失敗jobを保存し、原因解消を確認後に新規jobを作成する。

## 12. 操作カーソルと撮影開始・終了時の確認

操作用の青いカーソルは、利用者のマウスを動かさなくても保存画像へ写ることがある。
撮影前に操作セッションを終了し、先頭数枚の実保存画像で消えたことを確認する。
ウィンドウの確認画像だけを根拠に採用しない。写り込みがあれば登録前に停止し、
失敗jobを保持して原因解消後の新規jobで取得する。

補助プロセスの終了やフォーカスの変更を撮影中に行わない。
PyAutoGUIのfail-safeが発火したら無効化せず、撮影停止を確認してから
対象window・フォーカス・カーソル位置を再確認する。
撮影終了後はライブラリへ戻し、通常操作へ戻ることを確認する。
過去に操作終了後もマウスを動かしても矢印が見えないとの報告があり、
別の操作で復帰したが原因と恒久対策は未確定である。

2026-10-08のエンデ3冊は新版で395枚を取得し、全保存画像の一覧、拡大標本、
全転送hash、各冊3点のHTTP配信を照合した。撮影後もOCR未実施・未索引を確認した。
過去の撮影時にOCRを実行していなくても、その後の別処理でOCR済みになる場合があるため、
撮影当時の操作と現在のOCR状態を区別して報告する。
シリーズ整理・累積取得・現在状態の照合結果は
[追加取得記録](../../archive/検証/小説シリーズ整理と追加取得_2026-10-08.md)を参照する。
