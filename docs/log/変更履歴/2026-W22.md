## 2026-05-31: feat — doujin PDF 生成を Linux サーバー完結化・Samba 共有導入・nginx .mjs MIME type 修正

### 概要
`POST /api/generate` の `source_dir` パラメータを廃止し、サーバー側の固定入力ディレクトリ（`DOUJIN_INPUT_DIR`）を使用するよう変更。Linux サーバー上の入力フォルダを Samba 共有（`\\medaroserver\pic2pdf-input`）として公開することで、Windows からネットワークドライブ経由でファイルを置けるようにした。これにより Windows バックエンドは doujin 生成に不要になった。また nginx の `/assets/` 配信で `.mjs` が `application/octet-stream` になっていた MIME type バグも修正。

### 変更ファイル

**Backend**
- `backend/config/__init__.py` — `DOUJIN_INPUT_DIR`（env: `DOUJIN_INPUT_DIR`、既定 `data/doujin/input/`）を追加
- `backend/routers/generate.py` — `GenerateRequest` モデル（`source_dir`）を廃止、`DOUJIN_INPUT_DIR` を固定入力元に変更。ディレクトリ未存在時は 503 を返す。`linux_sync.sync_after_generate()` 呼び出しを撤去。`GET /api/status` も `source_dir` クエリパラメータを廃止
- `backend/tests/conftest.py` — `DOUJIN_INPUT_DIR` をテスト用 tmp パスへの monkeypatch に追加
- `backend/tests/test_router_generate.py` — テストケースを新 API に合わせて全更新

**Frontend**
- `frontend/src/config/generate_api_client.ts` — `VITE_GENERATE_API_URL` を撤去し常に同一オリジンへ送信
- `frontend/src/hooks/useGenerateJob.ts` — `StoredJob.sourceDir` / `restoredSourceDir` を除去、`startJob(jobId)` に簡略化
- `frontend/src/hooks/usePdfStatus.ts` — `source_dir` クエリパラメータを除去
- `frontend/src/pages/GeneratorPage.tsx` — `sourceDir` 入力欄を撤去、Samba 共有案内テキストを表示
- `frontend/src/test/useGenerateJob.test.ts` / `usePdfStatus.test.ts` — 新 API に合わせてテスト更新

**nginx / 設定**
- `deploy/nginx-pic2pdf-viewer.conf` — `/assets/` に `.mjs → text/javascript` MIME type を追記

**ドキュメント**
- `docs/04_環境構築/Linux_Sambaセットアップ.md` — 新規作成（Samba インストール・smb.conf・Windows 接続手順・運用フロー）
- `docs/04_環境構築/サーバー連携よく利用するコマンド.md` — doujin 新刊追加フローを Samba 経由に更新
