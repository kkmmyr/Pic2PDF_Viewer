## 2026-04-26: Python パッケージ管理を uv に移行

### 概要

`backend/` と `kindle-pdf/` の Python 環境を `venv + pip + requirements.txt` から `uv + pyproject.toml + uv.lock` に移行。依存解決の高速化と再現性の向上が目的。

### 主な変更ファイル

**新規作成:**
- `backend/pyproject.toml` — FastAPI バックエンド依存定義（`[dependency-groups] dev` で pytest 系を分離）
- `backend/uv.lock` — 依存ロックファイル
- `kindle-pdf/pyproject.toml` — Kindle キャプチャ依存定義（`[dependency-groups] gpu` で yomitoku + CUDA版 PyTorch を分離、`[[tool.uv.index]]` で pytorch-cu121 インデックスを定義）
- `kindle-pdf/uv.lock`
- `docs/04_環境構築/uv環境セットアップ.md` — uv のインストール・セットアップ手順

**更新:**
- `backend/start_server.bat` — `python -m venv` / `pip install` / `activate` を `uv sync` + `uv run uvicorn` に置換
- `起動方法.md` — 起動コマンドを `uv run` に統一
- `.claude/CLAUDE.md` — 起動方法セクションを uv ベースに更新

**削除:**
- `backend/requirements.txt` / `backend/requirements-dev.txt`
- `kindle-pdf/requirements.txt` / `kindle-pdf/requirements-gpu.txt`
- `backend/venv/` / `kindle-pdf/venv/`（旧仮想環境）

### 移行範囲外

- `D:\61.tool\common\ocr\` の共有 OCR 環境（yomitoku + PyTorch CUDA）は他プロジェクトとも共有しているため、本移行のスコープ外。`kindle-pdf/start_batch_ocr.bat` は引き続き共有 venv を参照。

### 効果

- 依存解決速度: pip 比で約 10〜100 倍（初回環境構築 31 秒で完了）
- 再現性: `uv.lock` で完全固定
- 起動: `activate` 不要（`uv run` が `.venv/` を自動検出）
