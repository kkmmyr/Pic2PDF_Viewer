## Kindle小説撮影で表紙の上下端が欠ける

- **確認日・対象**: 2026-09-19、ASIN `B09P18GHW4`、再撮影job
  `12b3053b-55f5-4c0a-8f2f-00ca4bca95e2`の`001.png`。
- **影響**: Kindleの元表示にある表紙上側の絵柄と下側の装飾英字の一部が保存画像では欠ける。
  上下端候補46件のうち他45件は元表示と一致。ほかの書籍への影響範囲は未調査。
- **原因候補**: 小説用cropは本文のヘッダー・フッターを除外するが、表紙は異なる表示領域を使う。
  座標取得とcrop適用時点の再現測定が必要であり、原因の確定と修正は未実施。
- **次の一手 / owner**: project owner。表紙・本文・挿絵で撮影範囲を測定し、
  表紙の全体保持と本文のUI除外を両立する修正を行う。
- **解消条件**: 境界テストと実機再撮影で表紙の上下端が元表示と一致し、通常登録後も
  画像連番・転送整合性・旧画像とメタの保全が成立すること。それまでは全品質受入を保留する。
- **証跡**: [全46件の照合記録](../archive/検証/Kindle品質候補照合_B09P18GHW4_2026-09-19.md)。

## 停止中の旧 Windows サービス登録は管理者再登録待ち

`scripts/setup_service.bat` と設計書は uv workspace のルート `.venv` へ統一済み。
一方、現在の `Pic2PDFViewer` Windows サービスは停止・無効化された旧登録で、
`backend/.venv/Scripts/python.exe` を参照している。

- **影響**: Linux 本番と通常開発には影響しない。無効化されたサービスを
  そのまま再有効化した場合だけ旧環境へ依存する。
- **解消条件**: Windows サービスを再利用するとき、管理者として
  `scripts/setup_service.bat` を実行し、登録先がルート `.venv` であることを確認する。
