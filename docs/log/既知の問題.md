## Windows OCR agentは実行環境manifestを省略した結果を受理する

- **確認範囲**: 2026-09-05、コミット`4598d76`のソースと既存テストの静的照合。
- **設計との差**: [OCR設計書](../design/詳細設計/機能別/OCR設計書.md)は新規runの
  `runtime_manifest_json`保存を求める。一方、`OcrAgentPageResultIn.runtime_manifest`は省略可能で、
  `ocr_run_store._save_run_provenance()`は値がある場合だけ検証・保存する。
  agentのcompleteから呼ばれる`validate_complete_run()`もmanifest必須検証を行わず、
  空のmanifestのままQA待ちまで進める。`test_router_ocr.py`にも省略したpage POSTを受理するテストがある。
- **影響**: agent経由の新規runについて、実行環境の監査情報が必ず保存されるとは保証できない。
  この確認だけから本番runの欠損や公開状態を推測しない。QA待ちへの到達は公開承認を意味しない。
- **未決事項**: 新規agent入力を必須化する範囲と互換性、または設計契約を変更するかの判断。
  今回の文書整理では入力・承認条件を変更しない。
- **解消条件**: 採用方針を決め、省略時・既存run・通常worker経路を含む実装とテストを揃え、
  OCR設計書へ反映する。

## 停止中の旧 Windows サービス登録は管理者再登録待ち

`scripts/setup_service.bat` と設計書は uv workspace のルート `.venv` へ統一済み。
一方、現在の `Pic2PDFViewer` Windows サービスは停止・無効化された旧登録で、
`backend/.venv/Scripts/python.exe` を参照している。

- **影響**: Linux 本番と通常開発には影響しない。無効化されたサービスを
  そのまま再有効化した場合だけ旧環境へ依存する。
- **解消条件**: Windows サービスを再利用するとき、管理者として
  `scripts/setup_service.bat` を実行し、登録先がルート `.venv` であることを確認する。
