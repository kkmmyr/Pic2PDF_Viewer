## 2026-07-27 設計書横断照合で確認した実装差分

### Kindle シリーズ取込の期待冊数が省略可能

`docs/design/要件定義/Kindle自動撮影取込_要件.md` は、シリーズ対象冊数の一致を
最初の job 作成条件としている。一方、`scripts/capture_kindle_series.py` の
`--expected-total` は任意で、未指定の `--apply` では冊数照合なしに開始できる。

- **影響**: 候補解決漏れがあっても、少ない冊数のままシリーズ処理を開始できる。
- **暫定運用**: `--apply` では必ず `--expected-total` を指定し、dry-run の
  対象一覧・冊数を確認する。
- **解消条件**: apply 時に期待冊数を必須化するか、対象範囲から期待冊数を
  自動決定して不一致なら job を作らない。

### novel_db 書籍名から画像パスを作る境界の検証不足

`GET /api/novel_db/books/{book_name:path}` は `book_name` を service へ渡し、
画像ディレクトリを組み立てる経路で、共通の `validate_safe_name` /
`resolve_under_base` を通していない。

- **影響**: LAN 内シングルユーザー前提でも、ファイル境界の防御が他ルートより弱い。
- **暫定運用**: 外部公開せず、信頼できないクライアントから API を受けない。
- **解消条件**: 正規化後のパスが `KINDLE_NOVEL_IMAGES_DIR` 配下にあることを
  service 境界で検証し、不正名を 4xx で拒否する。

### OpenAPI 型規約に旧形式が残る

`GET /api/meta` と一部の build / discussion schema は、ネスト内に
`dict` / `list[dict]` を公開している。また frontend の手書き
`RebuildJobMode` は API の `generate_contexts` を含まず、旧値を含む。

- **影響**: OpenAPI 生成型と手書き型の差により、変更時の型検査が契約ずれを
  見逃す可能性がある。
- **暫定運用**: `/openapi.json` を実契約の正本とし、変更時は
  `frontend/src/types/api.d.ts` を再生成する。
- **解消条件**: ネスト schema の具象型化と、手書き job mode の生成型置換。

### Windows NSSM セットアップが旧 member-local venv を参照

uv workspace の正本はルート `.venv` だが、`scripts/setup_service.bat` は
`backend/.venv/Scripts/python.exe` を登録する。

- **影響**: 新規クローンでルート `uv sync` だけを実行した環境では、
  Windows サービス登録に失敗する。
- **暫定運用**: 稼働中の既存 `backend/.venv` を削除しない。新規適用は
  スクリプト修正後に行う。
- **解消条件**: setup script とサービス設計をルート `.venv` へ統一し、
  新規 workspace で登録・起動を実機確認する。

## SearXNG 上流エンジンのレート制限によるサークル名自動登録失敗

> **2026-04-29 更新**: 根本解決策として DLsite / FANZA への直接 HTTP クエリを実装。
> `generated` ソースでは SearXNG より先にこれらを試みるようになった。SearXNG はフォールバックとして残存。

### 概要

サークル名自動登録機能を大量（目安: 20件以上）実行すると、SearXNG の上流検索エンジンが
レート制限・CAPTCHA ブロックを受け、全件「作者不明」が返るようになる。

### 現在の動作（2026-04-29 以降）

`generated` ソースは以下の 4 ステップで解決を試みる:
1. **DLsite 直接検索** — `dlsite.com/maniax` 検索ページを HTTP フェッチ → Gemma で抽出
2. **FANZA 直接検索** — `dmm.co.jp/dc/doujin` 検索ページを HTTP フェッチ → Gemma で抽出
3. **SearXNG site: フィルタ** — `site:dmm.co.jp OR site:dlsite.com` 絞り込み検索
4. **SearXNG 汎用** — `{title} サークル 同人誌` 汎用クエリ

直接検索が成功した場合 SearXNG は呼ばれないため、レート制限の影響を受けにくくなった。

### 症状（SearXNG フォールバックに降りた場合）

- `GET /api/meta/auto-fill/test` の `searxng_hit` が `false` を返す
- `unresponsive_engines` に以下のようなメッセージが並ぶ:

```json
"unresponsive_engines": [
  ["brave",      "一時停止: リクエストが多すぎます"],
  ["duckduckgo", "CAPTCHA"],
  ["karmasearch","一時停止: アクセスが拒否されました"],
  ["startpage",  "解析エラー"]
]
```

SearXNG の確認 URL: `http://localhost:8080/search?q=test&format=json`

### 根本原因

SearXNG は複数の外部検索エンジンに並列リクエストを送る。短時間に大量リクエストを行うと
各エンジン側でボットとみなされ、一時停止・CAPTCHA・アクセス拒否が発生する。

### 対処方法（SearXNG フォールバック使用時）

#### 1. 制限解除を待つ（数時間〜1日）

ブロックは時間経過で解除される。解除後に「作者不明」のエントリは自動的に再試行対象となる
（`overwrite=false` でも「作者不明」エントリは再処理される設計）。

#### 2. 待機時間の設定

`backend/services/auto_fill_service.py` の `AUTOFILL_REQUEST_DELAY_SEC`（現在 5 秒）を調整する。

#### 3. 分割実行

一度に全件処理せず、数十件ずつ日を分けて実行する。
