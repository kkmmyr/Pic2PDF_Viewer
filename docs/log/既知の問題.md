## Mac MLX runtimeのsampling乱数固定（2026-09-18確認）

Mac既存venvは`mlx==0.32.0` / `mlx-lm==0.31.3`を使用している。同じ版の隔離評価で、
実サーバーの推論スレッドでは異なるseedが同じ出力になり、乱数が固定される不具合を再現した。
単独のsampling関数テストだけでは検出できなかった。

- **影響**: seed違いの品質評価が独立試行にならず、反復・上限終了をモデル固有の問題と誤判定する。
  Linuxのllama-server/Ollama経路には今回のMLX不具合を適用しない。既存Macサーバー自体での再現試験は未実施。
- **現在の対処**: 今回の評価プロセスだけでcategorical samplerのimport時compileを外し、
  異なる3 seedの出力差と同一seedの再現をHTTP経由で確認した。既存venv・起動設定は未変更。
- **解消条件**: Macの通常runtimeで修正版または同等の回避策を検証し、実サーバーのseed試験、
  thinking分離、固定小説品質・長文自然停止を再確認してから切り替える。過去のMLX結果も、
  同じ版・同じ推論経路でseedに依存した結論は再検証対象とする。
- **上流**: [MLX #4234](https://github.com/ml-explore/mlx/issues/4234)、
  [mlx-lm #1439](https://github.com/ml-explore/mlx-lm/issues/1439)、
  [import時compileを外す修正案](https://github.com/ml-explore/mlx-lm/pull/1593)。
