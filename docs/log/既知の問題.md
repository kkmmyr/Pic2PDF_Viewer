## OCR実行環境manifest必須化の本番反映待ち

- **ソース上の解消**: 新規agent入力を必須化し、共有保存処理とQA移行でschema・engine・model revisionを検証する。Qwen/dots複合workerは実際の各推論プロセスのmanifestを保持する。契約は[OCR設計書](../design/詳細設計/機能別/OCR設計書.md)を参照する。
- **互換性の決定**: manifestのない旧途中runのページを再利用・後付けせず、新規runで全ページを処理する。既にQA待ち・公開済みのデータへ必須化を遡及しない。
- **稼働環境**: 2026-09-05の読み取り確認時、本番は `backend-20260829203709-366` で今回の修正を未反映。SuryaのQA待ち10run中8runはmanifestが空だった。
- **残作業**: 次回リリースでLinux受信側と稼働させるOCR agent/workerを同じ契約へ更新し、新規runのmanifest保存とQA移行を確認する。公開承認は別工程とする。

## 停止中の旧 Windows サービス登録は管理者再登録待ち

`scripts/setup_service.bat` と設計書は uv workspace のルート `.venv` へ統一済み。
一方、現在の `Pic2PDFViewer` Windows サービスは停止・無効化された旧登録で、
`backend/.venv/Scripts/python.exe` を参照している。

- **影響**: Linux 本番と通常開発には影響しない。無効化されたサービスを
  そのまま再有効化した場合だけ旧環境へ依存する。
- **解消条件**: Windows サービスを再利用するとき、管理者として
  `scripts/setup_service.bat` を実行し、登録先がルート `.venv` であることを確認する。
