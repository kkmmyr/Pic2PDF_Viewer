## 追加ガイド

新規エントリは本ファイル下部「直近の追記」セクションの**先頭**（最新が上）に `## YYYY-MM-DD: type — タイトル` 形式で追記する。`type` は `feat` / `fix` / `refactor` / `chore` / `docs` / `test` / `perf` / `style` / `revert` / `change` のいずれか。詳細フォーマットは `/changelog` スラッシュコマンドが直近コミットから草稿を生成する。

週境界（毎週月曜日）を跨いだら、本ファイル下部の前週分を切り出して `変更履歴/YYYY-Www.md` を新規作成し、上記「アーカイブ索引」テーブルに 1 行追加する。

## 2026-07-03: docs — 設計書 0 ベース再設計（3 バケット構造 + 機械強制ガバナンス）

`docs/` が 71 ファイル・27,000 行まで肥大化し実害が出ていた（変更履歴.md が週次ローテ規約を無視して 3,420 行まで累積・index.md と mkdocs.yml nav の手動二重管理によるリンク切れ・過去の folder move で doc→doc リンクが 6 本破損）。根本原因は「ルールが prose だけで強制力ゼロ」だったこと（`.claude/hooks` は全て advisory、pre-commit は markdown を全 hook から除外）。0 ベースで再設計し、ルールをコード化した。

- **3 バケット構造へ全面再編**（`git mv` で履歴保持）: `docs/design/`（静的設計書・要件定義/基本設計/ADR/詳細設計/環境構築）/ `docs/log/`（生きた文書・変更履歴/既知の問題/技術知見/計画）/ `docs/archive/`（凍結）。旧 `01_要件定義`〜`06_リファクタリング`+`99_アーカイブ` は廃止。
- **`scripts/maintenance/check_docs.py` 新規（pre-commit でコミットをブロック）**: docs 間リンク切れ・`log/変更履歴.md` の行数超過（800行）・mkdocs nav 孤児/dead entry の 3 種を機械検知。故意に違反を仕込んでコミットが実際にブロックされることを実地確認済み。
- **`scripts/maintenance/check_claude_drift.py` 拡張**: 走査対象に `memory/` と `mkdocs.yml` を追加（従来は `.claude/` のみで両者を見ていなかった）。
- **CI に `docs` ジョブ追加**: `check_docs.py` + `mkdocs build --strict`（`validation.links.not_found/anchors` は info 化 — 設計書は意図的に backend/frontend のソースコードへリンクするため。nav 同期は strict のまま維持し独立した二重チェックとして機能）。
- **API 仕様書を Swagger UI/OpenAPI に一本化**: 手書き 1,922 行の `API仕様書.md` を `design/詳細設計/API.md`（102行）に縮小。エンドポイント一覧・スキーマは `/docs`・`/openapi.json`（既に `generate:types` の型ソース）を正とし、OpenAPI が表現できない設計意図（JST 規約・novel_db 共通仕様・SSE イベント契約 4 種・PATCH セマンティクス等）のみ残した。`backend/main.py` の `FastAPI()` に title/description/version を追加。

- **参照の一括更新**: `mkdocs.yml` nav・`docs/index.md`（手動リンク一覧を廃止しバケット説明+ガバナンス要約に置換）・`.claude/CLAUDE.md`・`.claude/commands`・`.claude/agents`・`.claude/skills`・`memory/` の全 `docs/` パス参照を新構造へ更新。ついでに移行前から存在した孤児ファイル・stale 参照（存在しない「アーキテクチャ詳細_バックエンド編/フロントエンド編」参照 6 箇所等）も是正。
