## 4. Viewer内テキスト検索

### 対象
Searchable PDF（OCRでテキスト埋め込み済みの novel ソース）でテキスト検索を実現。  
画像ベース閲覧（isImageMode）では非対応（テキストレイヤーが存在しないため）。

### 操作方法
- ヘッダーの **Search** ボタン、または **Ctrl+F** でサーチバーを表示
- テキスト入力後300msデバウンスして全ページを走査
- **Enter** で次のマッチへ、**Shift+Enter** で前のマッチへ、**Esc** で閉じる
- 最初にマッチしたページへ自動ジャンプ

### 実装ファイル

| ファイル | 変更内容 |
|---|---|
| `frontend/src/components/reader/PdfSearchBar.tsx` | 新規: 検索バーUI（入力・件数表示・前後ナビ・閉じるボタン） |
| `frontend/src/components/reader/PageRenderer.tsx` | `searchText` / `customTextRenderer` props 追加。テキストレイヤーを条件付き有効化 |
| `frontend/src/components/reader/ReaderHeader.tsx` | Search ボタン追加・`isSearchOpen` prop 追加 |
| `frontend/src/components/viewer/ReaderPanel.tsx` | 検索状態管理・Ctrl+F ハンドラ・全ページ走査・ハイライトレンダラー統合 |
| `frontend/src/components/reader/index.ts` | `PdfSearchBar` export 追加 |

### テキストハイライトの仕組み
`react-pdf` の `customTextRenderer` に `<mark>` タグを返す関数を渡し、検索語をオレンジ背景でハイライトする。  
テキストレイヤーは検索時のみ `renderTextLayer={true}` にすることで、通常閲覧時のパフォーマンスを維持する。

## 既知の制約・今後の検討事項

- **検索は PDF モードのみ対応**。画像ベース閲覧 (isImageMode) ではテキストレイヤーが存在しないため検索不可。
- **検索バーはヘッダー表示中のみ表示**。マウスをヘッダーゾーンに移動して表示してから使う設計。没入型閲覧への影響を最小化するため。
- **ダークモードは MUI コンポーネント（OCRPage）に未適用**。MUI は別途 ThemeProvider を設定する必要がある。

## 1. Generator 非同期化

### 変更前の問題

`POST /api/generate` は同期処理だったため、大量PDF生成時にブラウザが完了まで応答待ちになっていた。

### 実装内容

#### Backend ([backend/routers/pdfs.py](../backend/routers/pdfs.py))

- `GenerateJob` クラスを追加: 1ジョブの状態を表すデータクラス（`job_id`, `status`, `current_item`, `files`, `error`）
- `JobStore` クラスを追加: スレッドセーフなジョブ保持ストア（最大20件で自動削除）
- `JobStatus` enum 追加: `pending` / `running` / `completed` / `failed`
- `POST /api/generate` を変更:
  - `scan_and_generate` をバックグラウンドスレッドで実行
  - レスポンスとして即座に `{ job_id, status: "pending" }` を返す
- `GET /api/generate/job/{job_id}` を追加: ジョブの進捗・結果を取得

#### Frontend

- [frontend/src/types/index.ts](../frontend/src/types/index.ts): `GenerateJob` 型・`GenerateJobStatus` 型を追加
- [frontend/src/config/api.ts](../frontend/src/config/api.ts): `GENERATE_JOB` エンドポイントを追加
- [frontend/src/pages/GeneratorPage.tsx](../frontend/src/pages/GeneratorPage.tsx): 全面書き換え
  - ジョブ投入後、`useEffect` + `setInterval` で `/api/generate/job/{job_id}` をポーリング（1.5秒間隔）
  - ジョブ状態に応じてプログレスバー・アイコンを表示
  - `completed` / `failed` 時にポーリングを自動停止

### データフロー

```
Client POST /api/generate
  → Backend: ジョブ生成・バックグラウンドスレッド開始
  → 即時レスポンス: { job_id }

Client GET /api/generate/job/{job_id} (1.5s間隔)
  → status: pending → running (current_item が変化)
  → status: completed → files: [...生成済みファイル]
```

## 既知の制約・今後の検討事項

- Generator ジョブは **サーバー再起動で消える**（メモリ上のみ）。長時間サーバー運用する場合はSQLiteなどへの永続化を検討。
- ジョブは最大20件まで保持。古いジョブは自動削除される。
- お気に入りは **localStorage** に保存のため、ブラウザのデータをクリアすると消える。
- 並び替えの選択は **ページリロードで初期値（名前昇順）に戻る**。永続化が必要な場合は `localStorage` へ保存する拡張が可能。
