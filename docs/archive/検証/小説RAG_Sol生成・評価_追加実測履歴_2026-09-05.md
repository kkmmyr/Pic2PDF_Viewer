# 小説 RAG Sol 生成・評価 — 追加実測履歴

> status: frozen | source: `docs/design/詳細設計/機能別/小説RAG_Sol生成・評価設計.md` | moved: 2026-09-05

設計書から分離したPhase 1・2の実測。現在の未実装境界とPhase 3条件は元設計書を正本とする。

## Phase 1 r3-r6

固定正解を除去した同一契約のmedium再試行（r3）は、事実表では「最長10年間」と黎天河を保持したが、
途中状態と最終状態を別factへ分離できず、一覧版から限定期間と黎天河が欠落したためローカルゲートで不合格となった。
独立評価と公開反映は実行していない。次は同じ中立プロンプト・Schema・fixtureのままhighを比較し、
mediumだけを追加調整して固定ケースへ過適合させない。

同一条件でreasoning effortだけをhighへ変更した再試行（r4）は、一覧版の「最長十年間」と黎天河を回復し、
詳細版の網羅性も改善した。一方、途中意向と最終決定を同じfactへ統合し、拘束factへ仁耀の侵入行為と
黎天河の拘束行為を混在させた。また原文の「茉莉花たち」を「皓茉莉花と珀陽」へ分解し、珀陽を戦術立案者・
指揮承認者として断定したため不合格とした。highも独立評価・公開反映へ進めない。

この比較から、Phase 1の次段階はreasoning effortや固定ケース固有のプロンプトを追加することではなく、
高リスク場面を行為単位へ分割した検証済み事実グラフを決定的処理で構築し、Solにはその事実グラフからの
文章化だけを担当させる方式を検討する。

r4の4エラーと71〜79ページだけを新規Sol highへ渡した限定修正（r5）は87.244秒で、拘束fact、途中意向、
最終決定、解放・離脱を分離し、役割過剰特定を除去した。適用後は49 factとなりローカルゲートへ完全合格した。
続く別Sol high独立評価は14件中12件を支持し、R06とR10を重大不一致として停止した。R06は公開用詳細版ではなく
監査用の言い換えが翔景を発見主体へ追加した不一致、R10は監査用言い換えと一覧版が将来の最長10年逃亡依頼を
完了形へ変えた不一致だった。公開文と監査主張の完全一致対応がないことを新しい根本原因とし、公開しない。

修正後候補から高リスク語へ一致する詳細21文、一覧7文、人物説明13文を開始・終了位置と文ハッシュ付きで
完全一致抽出したr6では、確定OCR全文を渡した別Sol highが41文中40文を支持した。r5のR06/R10に対応する
実際の公開文は支持され、言い換え由来の偽陽性を除去できた。一方、詳細版の「茉莉花へ白楼国の未来を託して」は、
原文が託した対象を複数候補のまま未確定にしているためE18で重大unsupportedとなった。2回目修正と公開は行わない。

## Phase 2 初回とv2

2026-08-23の初回Phase 2実測では、10巻60 fact、11巻53 fact、12巻54 factを生成した。主生成の
完全一致引用は10巻5件、11巻1件を1回のquote-only限定修正で直し、12巻は修正0件でローカルgateを
通過した。別の新規Sol highによる全fact評価は、10巻58 supported / 1 contradicted / 1 unsupported、
11巻51 supported / 2 contradicted、12巻52 supported / 1 contradicted / 1 unsupportedだった。
途中説明を最終事実へした断定、意図の追加、`witness`と`tactical_planner`の過剰付与を検出した。
review自身にも完全一致しない引用が10巻1件、11巻1件、12巻2件あり、3冊ともfail closedで停止した。
文章化、完成文評価、人手確認、公開DB変更は行っていない。

次runは`sol-fact-graph-v2` / `sol-fact-review-v2` promptを使い、旧候補の限定修正ではなく
同じsource SHAから新規候補を生成する。review v2は候補のactorごとに立案・承認・実行・知覚を
別々判定し、作中発言と最終真相、意図と結果、当該時点の身分を再確認する。review引用が
原文へ一致しない場合は別sessionの新規reviewとし、同一reviewの自動修正で合格させない。

v2実測は本番DBをread-onlyで再照合し、3冊とも初回と同じpage数・文字数・
source SHAで実施した。主生成は10巻47 fact、11巻44 fact、12巻57 fact。完全一致しない
候補引用は10巻5件、11巻39件、12巻0件で、10巻は1回限定quote-only修正後に通過したが、
11巻は同修正後も不一致が残り停止した。12巻は修正なしで通過した。

別の新規Sol high reviewで、10巻は43 supported / 4 unsupportedに加えreview引用不一致1件、
12巻は53 supported / 4 contradictedだった。11巻はlocal gate不合格のためreviewしていない。
対象を修正した具体例があっても、`tactical_planner`・`witness`の過剰付与、
人物の当時の身分、複合claimの一部だけが支持される誤りが再発した。評価済み104 factの
生verdictはsupported 96件（92.31%）で、review引用gateを含めると2冊とも不合格である。

3冊生成、2冊引用修正、2冊reviewの合計はinput 656,802 token、output 92,422 token
（内reasoning 40,795 token）。並列実行時の最長値は生成437.68秒、引用修正154.74秒、
review 322.19秒だった。意味精度は初回v1より改善せず、v2を既定promptへ昇格しない。
現行の全巻直接fact graph生成経路は不採用とし、文章化、完成文評価、人手確認、公開DB変更は
行わない。v2 promptは不採用経路の固定SHAと実行成果を再現する検証資産に限定する。

当初のファイル反復読込方式は主生成1冊あたり約76万〜107万input tokenを消費した。runnerで
manifest・本文・候補を初期stdinへ名前・文字数・SHA付きdata sectionとして一度だけ封入し、sandboxから
再読できなくしたところ、全fact評価は1冊約12.4万input tokenへ縮小した。以後はこのinline方式だけを使う。
