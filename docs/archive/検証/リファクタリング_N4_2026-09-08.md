## 1. 完了範囲と所有者

| 所有者 | 分離後の責務 |
|---|---|
| `search.py` | 公開入口、query/scope解決、lexical backend選択、embedding・tableの組立、検索→統合→人物取得→整形の実行順 |

既存の公開関数の引数、`search.SearchHit`・packageからの公開importとfield、`sanitize_snippet`を維持した。
`lexical_search`とquery変換、`SearchHit`の定義・escape・URL生成の本体はAST比較でも同一である。
検索接続を差し替えて順位統合・表示データを検査でき、抽出した3 moduleの逆依存は静的検査で拒否する。

N3の生成・公開処理、page全文索引のstate/builder/query、書籍サマリ検索、retrieval、検索router、
schema/migration、model・promptは変更していない。索引の自動修復・既定検索backend変更も含まない。
既存table取得helperがmissing時に空tableを初期化する挙動は維持し、検索全体が常に副作用なしとは扱わない。

## 2. 固定した契約

| 観点 | 確認した結果 |
|---|---|
| 順位・重複 | lexical/vectorの生scoreではなく順位で加算。同一ページの複数チャンクも各順位分を加算 |
| 同点・上限 | RRF同点はlexical→vectorの初出順。書籍別上限・top制限後に人物を取得 |
| snippet | 最初のlexical候補を採用。空なら最初のvector本文へ移り、200字切出し後にescape。mark以外のHTMLはescape |
| 出典・人物 | 書名・page番号・全URL encode・最低3桁page名、主要人物のtrim・空要素除外・順序と重複を維持 |
| scope・filter | all/book/series、空scopeでの早期return、FTSの公開可否・文字数・ページ余白、vectorのprefilter・多めの取得・後置余白を維持 |
| vector同点 | `_distance`昇順でstable sortし、同点はadapterの返却順を維持 |
| fallback | ICU正常0-hitはfallbackせず、例外時はFTSへ縮退。shadow失敗もFTSを返し、質問本文・例外本文をログへ出さない |
| その他の失敗 | FTSのSQLite OperationalErrorは空結果。hybridのlexical/vector例外は握り潰さず伝播 |
| 全文読込み | 適格ページ・文字数で絞ってから余白を適用。本文はrawのまま、200字制限や検索用escapeを行わない |

これらを既存68件と、分離前に追加した14ケースで固定した。分離後は公開importと依存境界15ケースを追加した。
最初の追加FTS fixtureはtrigram検索へ2文字queryを渡して0件となったため、filterの検査に適した
4文字queryへ直し、変更前実装で14件が通ることを確認してから分離した。

別途、seed `20260908`で候補列・重複・空snippet・HTML・長文・件数上限を組み合わせた1,000ケースを
旧`hybrid_search`と新しいrank/presentationへ渡し、`asdict(SearchHit)`が完全一致した。
これは固定入力の制御・整形比較であり、実モデル品質や稼働環境の検索性能測定ではない。
