## 2. 失敗時の受入条件

| 失敗点 | 期待する停止・例外 |
|---|---|
| meta / novel migration / Kindle migration | 後続初期化・開始・停止を呼ばず元の例外を伝播 |
| queue開始 | 正常終了した資源がないため停止なし |
| watcher開始 | queueのみを停止。稼働区間へ入らない |
| 稼働区間 | watcher→queue停止後に元の例外を伝播 |
| watcher停止 | 失敗を保持してqueue停止を継続 |
| 複数失敗 | 元の失敗→停止順で全例外のidentityを保持したgroup |
| 呼出し元キャンセル | 回収を保護し、終了後にCancelledErrorを再送出。停止失敗はcauseへ保持 |
| 回収中の繰返しキャンセル | 各停止を1回ずつ試み、最初のキャンセルを保持 |
| 停止期限 | 協調的な30秒期限。TimeoutErrorへ資源名noteを付け、後続停止を試みる |
| 呼出し元の期限 | 外側のasyncio.timeoutがTimeoutErrorへ変換でき、回収失敗をcauseから追跡可能 |

開始済みとは`start()`の正常終了を指す。未完了のstart内の部分資源はserviceが回収責任を持つ。
完了済みmigrationの巻戻し、stopの再試行、実行threadの強制終了は追加しない。

## 3. 検証

- 修正前に登録済みlifespanへ失敗を注入し、watcher開始・停止の2ケースでqueue停止の欠落を再現した（2 failed / 8 passed）。
- 修正後の起動・runtime・依存境界は48 passed。追加した22ケースに、失敗の集約、元の例外identity、無効な期限、各開始点・稼働・停止でのキャンセル、繰返しキャンセル、deadlineを含む。
- キャンセル・期限テストはEventで同期し、停止順、task.cancelled()、回収taskの残存なしを確認。実モデル・本番DBを起動しない。
- 最終版で`uv run pytest -q --cov --cov-fail-under=65`を実行し、1,859 passed / 4 skipped / 既存warning 1件（413.24秒）。coverageは73.34%で65%基準を充足。warningはStarlette TestClient/httpxの既存非推奨通知。
- basedpyrightは0 errors / 0 warnings。変更PythonのRuff lint・formatに合格。
- 品質監査で追加テストの複雑度超過を検出し、失敗点ごとの期待停止をparameter表へ整理。C901は35 current / 35 baselineを維持。
- OpenAPIは109 paths・hash `ed33f214ffed`、依存境界・保守資産台帳・file map・code size・Knipに合格。基準値の緩和は行わない。
- 文書検査に違反なし。MkDocs strict buildに合格し、今回追加した参照先は固定anchorを付けてHTMLへの到達を確認した。凍結記録内の既存リンク切れ30件は情報扱いで維持。
