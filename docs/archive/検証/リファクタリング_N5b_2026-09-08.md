# リファクタリング N5b 実施・検証記録

> status: archived | last-verified: 2026-09-08 | owner: project owner

N5aの未コミット変更を保持して実施した、撮影完了時のLibraryメタ更新・復元の責務分離。
現在の未完了事項は[リファクタリング計画書](../../log/計画/リファクタリング計画書.md)を正本とする。
比較対象の撮影コードは`1b5e893`と同一だった。受入はローカル実装・隔離保存先での検証までとする。

## 1. 完了範囲と所有者

| 所有者 | 分離後の責務 |
|---|---|
| `capture_registration.py` | 検証・配置・メタ更新・package archive・job確定の順序制御。変更なし |
| `CapturePublication` | 画像/退避/package操作、補償順、`meta_updated`等の完了flag、Library操作の呼出し |
| `library/capture_metadata.py` | 既存メタのASIN照合、ASIN更新、更新前entryのdeepcopy、復元/削除 |
| `meta_store.py` | 既存source lock、同一transactionの読取りと差分保存。変更なし |

Libraryの`validate_capture_replacement`と`CaptureMetadataChange.apply/restore`へ委譲した。
publication内部の`previous_meta_entry`は`CaptureMetadataChange.previous_entry`へ移し、
変更オブジェクトはpublicationごとに作成する。対象source/book ID/ASINは呼出し時に渡す。
既存`CapturePublication`の構築引数、撮影job/API、manifest、schema、エラー文言、
正常時の公開順、既存画像の退避世代は維持した。

## 2. 固定した契約

| 境界 | 確認内容 |
|---|---|
| 置換可否 | 画像がある場合のみ同一book ID/ASINを確認。メタ欠落・ASIN欠落・別ASINでは画像を保持して拒否 |
| 新規登録 | 新規entryは`authors: []`とASIN。別書籍/別sourceを更新しない |
| 既存更新 | ASINだけを更新し、著者・既読・閲覧回数・非表示等の既存値を保持 |
| snapshot時点 | 構築時ではなく、保存callback内の更新直前にdeepcopy。保存失敗時もsnapshot取得は先に済む |
| 復元 | 更新前entryがなければ対象を削除、あればentry全体を戻す。同一entryの後続編集とmergeしない既存範囲を維持 |
| 保存失敗 | SQLite triggerで実保存失敗を注入。旧行を保持し`meta_updated=False`のまま。復元を重ねない |
| 復元失敗 | メタ復元の例外が伝播し、後続のpackage/画像補償へ進まない既存動作を保持。改善はTM-11 |
| 全体補償 | 既存のready検証・staging・退避・publish・meta・archive・job更新前の失敗注入、新規/置換の両方を維持 |
| 最終確定失敗 | 条件付きjob更新0行、quality warning保存失敗でも既存の補償・job状態を保持 |

分離前に13ケースを追加し、既存の撮影job/rollbackと合わせて36 passed / 1 skipped。
分離後はsnapshotの非共有・保存失敗前の取得2ケース、依存境界17ケースを追加した。
撮影・メタ・既存Library依存境界を合わせた検査は88 passed / 1 skipped、
追加snapshot検査は2 passedだった。

`capture_registration.py`は比較元と全文一致。
`CapturePublication`の`__post_init__`、stage、backup_existing、publish_target、
archive_package、rollbackの6メソッドはAST比較で同一だった。
この確認は実ファイル・隔離DBでの制御/保存検証であり、実Kindle画面の撮影受入ではない。

## 3. 構造と依存検査

| 指標 | 分離前 | 分離後 |
|---|---:|---:|
| `capture_publication.py`行数 | 120 | 106 |
| Libraryメタadapter行数 | — | 35 |
| publicationの`meta_store`直接import | 1 | 0 |
| publication内のメタ書換えcallback | 2 | 0 |

`services/library/capture_metadata.py`だけに`services.meta_store`（型を含む）を許可した。
その他はcopy/dataclass/型用標準moduleだけを許可し、SQLite/SQLAlchemyやmeta DBへの直接接続、
config・HTTP・Kindleへの逆依存を拒否する。他のLibrary moduleの禁止規則は維持した。
撮影publicationからの`meta_store`/`meta_db`直接参照も検査へ追加した。
検査は絶対/相対/from-packageの静的importに限定し、動的import全般の排除を保証しない。

汎用repositoryや新しいqueueは導入せず、既存storeの書込み経路を一つに保った。
書類・ファイル総数の削減や処理速度・工数の改善率は受入条件にしていない。

## 5. 後続と復旧

N5a/N5bのローカル受入を終え、次はN6のLibrary/Reader状態契約と機能入口の整理とする。
まずViewerのURL・store同期、Readerの書籍切替、一覧を保持する表示方式を固定し、
一画面・一状態単位で進める。物理配置の一括移動から始めない。

補償失敗時に後続資産の回収が停止する境界は、別変更TM-11へ移した。
本番障害の発生を確認したという意味ではなく、隔離DBで再現した既存の制御順である。
TM-8（Mac実モデル）・TM-9（起動停止cleanup）も未完了として残す。

N5bのコード変更をrevertしてもschema変更やデータ再作成は不要である。
ただしコードrevertは既に公開した画像・メタを戻す操作ではない。
N5a、既存の`@AutomationLog.txt`・`tmp/`を保持し、今回commit/pushは実施していない。
