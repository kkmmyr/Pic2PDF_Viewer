# GPT-6.0 / GPT-6.1 画像OCR・1冊比較

> status: frozen | verified: 2026-10-04

今回の1冊ではGPT-6.1 Solの初回OCR候補はGPT-6.0 Solより本文の欠落・読順の崩れが少なかった。
ただし6.1にも一文の欠落と誤字が残り、画像QAなしの全冊採用・自動公開を支持する結果ではない。
これはCodexでの運用比較であり、モデル単体の正式ベンチマークやCER測定ではない。

## 対象と選定

- 『りゅうおうのおしごと！１５．５ ～髪を切った理由～【電子限定配信版】』、全24キャプチャ画面。
- サーバーの撮影済み小説から、品質を見ずに画像枚数が最少の冊子を選択した。
- 各画像は3516×1940 PNG。表紙・扉2、権利表記・イラストレーター紹介2、物語本文17、あとがき1、広告・奥付2。
- 読み取り専用DB照会では対象巻のcanonical OCRは見つからなかったため、同じ画像から6.0対照を新規生成した。
- 過去の保存済みSol画像OCR campaignはGPT-5.6 Solの記録だった。今回の6.0候補は過去runの再利用ではない。
  過去の品質不足の経緯は[停止記録](Sol画像OCR_campaign_停止記録.md)を参照する。

## 条件と証跡

| 項目 | 条件 |
|---|---|
| モデル指定 | `gpt-6-sol` / `gpt-6.1-sol`、reasoning effort `high` |
| 試行数 | 各モデル1回、全24画面 |
| 入力 | 同じ原画像。サーバーSHA・取得manifest・ローカルSHAが24/24一致 |
| 転記規則 | 縦書き右→左、本文と非本文を分離、ルビ除外、推測補完禁止 |
| 独立性 | 生成担当は相手候補・既存OCR・外部の作品情報を参照しない |
| 画像確認 | 両モデルとも全原画像を確認、必要時crop可。各8画面で追加cropを使用 |
| 固定 | 初回候補JSONを保存後、比較・QAで書き換えない |
| QA | 全24画面×2候補を別担当または統合担当が原画像と照合。生成担当による対照監査も含む |

共通転記指示のSHA-256は
`c97316a81daac382561a63021af32e94ad887a7bc583b59c1568260baabe9258`。
モデルごとの担当指示全体は保存しておりSHAは異なる。cropの位置・利用画面・agentの作業手順も異なる。
同一画像・共通規則でのCodex運用比較として解釈し、差をモデル更新だけの因果効果とは断定しない。
`view_image(detail=original)`でもツール表示時に縮小される場合があり、必要箇所をcropで拡大確認した。
モデル名はagent起動時の指定であり、APIの固定snapshot ID・課金token・純粋推論時間は測定していない。

画像・初回候補・プロンプト・ハッシュ・監査・集計はGit管理外の
`../pic2pdf-sol-runs/ocr-gpt61-20261004/`（リポジトリの兄弟ディレクトリ）へ保存した。
主な証跡は`manifest.json`、`evaluation-plan.json`、`raw/`、`control-gpt60/`、
`audit/`、`audit-control/`、`comparison/candidate-comparison.json`、`comparison/audit-summary.json`。
閲覧用初回全文は`transcription-gpt61-initial.txt` / `transcription-gpt60-initial.txt`。

## 結果

重大誤りは、文・段落の欠落、意味に影響する読順入替・置換、原文にない独立した文の追加を対象とした。
以下は今回の画像QAで**発見した誤りのある画面数**であり、正解率・全文完全一致率ではない。

| 指標 | GPT-6.0 Sol | GPT-6.1 Sol |
|---|---:|---:|
| 保存完了 / 失敗 | 24 / 0 | 24 / 0 |
| 本文＋あとがきの重大誤りあり画面 | 15 / 18 | 1 / 18 |
| 非本文の重大誤りあり画面 | 1 / 6 | 0 / 6 |
| 正規化した本文文字数 | 20,787 | 22,178 |

本文重大誤りの画面番号は6.0が6・7・8・9・10・12・14・15・16・17・18・19・20・21・22、6.1が7。
キャプチャ番号を用い、紙面ページ番号とは区別する。6.1の正規化前本文は22,971文字、非本文663文字。
候補同士の正規化本文編集距離は2,228だったが、どちらも正解本文ではないためCERへ換算しない。

### 代表例

- 画面6：6.0は連続する6段落と別の一文を落とし、説明と問いの順序も入れ替えた。6.1はこれらを保持した。
- 画面16・19：6.0は母娘の問答・説明を複数段落欠落した。6.1では同じ大きな欠落は見つからなかった。
- 画面3：6.0は権利表記を部分欠落し、原文にない禁止文を追加した。6.1は原画像の記述を保持した。
- 画面7：両モデルとも、誤解を早く解かなければ遅刻するという内心の一文を丸ごと落とした。
  候補間一致だけでは検出できず、6.1を無条件採用できない根拠になった。
- 画面13：6.1は「警察署」を「警察」と転記した一方、6.0は「署」を保持した。
- 画面17：6.1は「期間限定」を「期限限定」と誤読し、台詞末尾へダッシュを追加した。
  初期監査には6.0側の誤りとする誤判定があったが、統合担当が原画像cropを再確認して取り消した。

ほかに引用符、小書き仮名、三点リーダーなどの誤りが6.1にも残った。
軽微誤りは監査項目のまとめ方・句読点の確認粒度が統一されていないため、span総数の優劣を指標にしない。
6.1の自己申告`uncertain_spans`は全画面0だったが、画像QAでは重大・軽微誤りが見つかった。
自己申告の不確かさ0を品質合格条件にできない。

## 採否と限界

- 今回の1冊では6.1を**画像QA・補正付きの候補生成**に使う有望性を確認した。
  初回候補のまま全冊採用する判定は不合格とした。
- 独立した人手正解全文を作成していないため、正式CER、文字精度、品質policyへの適合は未判定。
  原画像照合もモデルを使った監査であり、人手による独立ground truth評価ではない。
- 短い縦書き小説1冊・1試行に限る。目次、本文中の挿絵、漫画の吹き出し、複雑な段組み、長編全冊への一般化はできない。
- 未開封holdoutや[品質改善計画](../../log/計画/小説OCR品質改善_実装計画.md)のH3を満たす評価ではなく、既存の公開契約は変更しない。
- 既存OCRの書換え、canonical DBへの登録、索引更新、公開は実施していない。

入力・候補24件ずつのschema/画像SHAと、48組の監査coverage/候補SHAを機械検証した。
候補差分の大小だけで正誤を判定せず、共通誤りを含めて原画像で照合した。
