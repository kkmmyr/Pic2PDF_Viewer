# 画像生成カタログ設計

> status: living | last-verified: 2026-08-18

## 1. 目的

`imagegen-catalog/` は、生成画像と「どの条件で作成したか」を同じ画面で見返すための独立ローカル Web アプリである。既存の Pic2PDF Viewer の画像閲覧・書籍管理とは分離し、画像生成の試行錯誤とプロンプトの再利用を対象にする。

初期版は Codex の生成結果を対象とし、将来は他の生成サービスも同じカタログスキーマへ取り込めるよう、`source` と汎用的な `prompt` / `parameters` フィールドを持たせる。

## 2. 構成

```text
imagegen-catalog/
├── backend/                 # FastAPI + uv
├── frontend/                # React + Vite + TypeScript
├── data/
│   ├── catalog.json         # 初期データ兼開発用メタデータ
│   └── assets/.gitkeep      # 画像本体はGit管理しない
├── deploy/                  # ローカルサーバー用のsystemd定義
├── scripts/                 # ビルド・デプロイ補助
└── README.md
```

- Backend 開発ポート: `8788`
- Frontend 開発ポート: `5178`
- リリース時は FastAPI が `frontend/dist/` を SPA として配信する。
- `IMAGEGEN_CATALOG_DATA_DIR` を指定すると、画像と JSON の保存場所をアプリのGit checkout外へ切り替えられる。
- 本番のFastAPIは `127.0.0.1:8788` で待ち受け、Tailscale ServeのHTTPSポートからのみTailnetへ公開する。

## 3. ポータビリティ方針

画像とカタログJSONは、アプリ本体とは分離したデータディレクトリをポータブル単位とする。画像URLは絶対パスではなく `assets/` 配下からの相対パスだけを保存する。

```text
本番サーバー: /home/amashio/apps/imagegen-catalog-data/
├── catalog.json
└── assets/
    └── ...画像ファイル...
```

`data/catalog.json` は初期データ・開発用のサンプルとしてリポジトリに残すが、`data/assets/*.png` は `.gitignore` で除外する。本番サーバーの `IMAGEGEN_CATALOG_DATA_DIR` が画像とJSONの正本であり、通常のコードデプロイではデータディレクトリを上書きしない。

初回だけローカルの `data/` をサーバーのデータディレクトリへseedし、以後はサーバー上の画像を追加・バックアップする。別PCへ移す場合はサーバーのデータディレクトリを丸ごとコピーする。生成元の一時ディレクトリや `.codex` のパスはカタログの画像パスとして保存しない。

## 4. データモデル

`catalog.json` のトップレベルは次の構造を持つ。

```json
{
  "schema_version": 1,
  "updated_at": "2026-08-18T00:00:00+09:00",
  "entries": []
}
```

エントリの主要フィールド:

| フィールド | 役割 |
|---|---|
| `id` | カタログ内で不変な識別子 |
| `title` | 一覧表示用タイトル |
| `asset_path` | `data/assets/` からの相対パス |
| `source` | `codex` などの生成元 |
| `character` | キャラクター名・作品名（未設定を許容） |
| `style` | スタイル名、媒体、頭身、雰囲気、変更軸 |
| `prompt` | 指示文、禁止事項、参照画像、生成方式、パラメータ |
| `tags` | 検索・絞り込み用タグ |
| `created_at` | 生成日時または記録日時 |

`style` と `prompt` は生成サービスに依存しない自由度を残し、将来の他サービス対応で同じ UI に表示できるようにする。

### 4.1 媒体・年代比較用の生成バッチ

作風の差分を背景や配色だけに留めないため、媒体・年代を1グループ単位で固定した生成バッチを扱う。各バッチは `data/generation_specs/` に仕様JSONとして保存し、次の情報を1バリエーションへ持たせる。

- `style`: 媒体・年代の説明（例: 1980年代白黒少女漫画、16-bitドット絵、粘土ストップモーション）
- `prompt_constraints`: 指定媒体で必須となる質感・描画制約
- `negative_extra`: その媒体で避ける描画方式（例: 現代的なデジタル彩色、3D、アンチエイリアス）
- `group_id` / `group_label`: UIで媒体別に比較・絞り込みするための分類

同じキャラクターの識別要素（短い赤茶色のウェーブボブ、紫系の瞳、控えめな表情）は共通条件として維持する。一方、媒体ごとの禁止条件は共通のnegative条件へ追加し、生成条件と実画像の比較可能性を保つ。画像本体は引き続きGit管理せず、生成後にサーバーのデータディレクトリへ配置する。

媒体変換を大量に行う前には、公式公開立ち絵を外部参照として使う「原作寄り・キャラクター再現確認」バッチを先に作成する。この確認バッチでは媒体差を抑え、顔立ち・髪型・瞳の色味・制服・年齢感・表情を固定する。公式参照画像は同定用にのみ使用し、アプリのデータディレクトリやGitHubへ同梱しない。確認後に、同じidentity anchorsを保ったまま媒体ごとの描画制約を適用する。

## 5. API

- `GET /api/health`: 起動確認
- `GET /api/catalog`: 検索・作品・キャラクター・スタイル・生成元で絞り込んだ一覧
- `GET /api/entries/{entry_id}`: 1件の詳細
- `GET /media/{asset_path}`: `IMAGEGEN_CATALOG_DATA_DIR/assets/` 内の画像配信
- `GET /api/export`: 現在のカタログ JSON の取得

API は JSON を読み取り、書き込みは初期版では `data/catalog.json` を直接更新する運用とする。画像の登録 UI や生成サービス別インポーターは後続スコープであり、初期版では JSON と画像を所定の相対パスへ配置して再読み込みする。

## 6. フロントエンド

- カード型ギャラリーで画像・タイトル・スタイル・タグを表示する。
- 検索欄、作品、キャラクター、生成元、スタイルのフィルターを提供する。未設定の作品・キャラクターも選択できる。
- 詳細ドロワーで大きな画像、プロンプト、ネガティブ条件、参照画像、スタイル条件、パラメータを表示する。
- 詳細画面で作品名とキャラクター名を表示し、未設定の場合は「未設定」と表示する。
- 詳細 JSON をクリップボードへコピーできる。
- データは毎回 API から読み込むため、サーバーのデータディレクトリを差し替えて再読み込みすれば別PCのカタログを表示できる。

## 7. セキュリティ・制約

- ローカル LAN・シングルユーザーを前提とし、認証は初期版では持たない。
- `asset_path` はデータディレクトリの `assets/` 内に解決される相対パスだけを許可し、パストラバーサルを拒否する。
- 初期版はユーザー指定の任意ファイルパスをサーバーから直接配信しない。
- 本番サービスはlocalhost bindとし、Tailscale Serveのtailnet-only HTTPSを経由して公開する。Funnelは使用しない。
- systemd user serviceで常駐させ、コードデプロイとサーバー管理データの同期を分離する。通常のデプロイで画像を削除しない。
- 初期カタログでは、最初の銀髪キャラクター10枚を作品・キャラクター未設定のオリジナルとして記録し、Kanon / 天野美汐の分類と混在させない。
- LAN 外へ公開する場合は認証、CORS、リバースプロキシ、アップロード制限を別途設計する。

## 8. 将来拡張

- Codex 以外の生成元向け JSON インポーター
- 画像と JSON を一つにまとめた zip パッケージのインポート・エクスポート
- プロンプト差分比較、スタイル別の比較表示、再生成用プロンプトのコピー
- 生成元・モデル・seed・サイズ・品質などのサービス固有パラメータ表示
