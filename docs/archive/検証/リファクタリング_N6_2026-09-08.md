# リファクタリング N6 実施・検証記録

> status: archived | last-verified: 2026-09-08 | owner: project owner

Library/Readerの状態契約と機能公開入口を整理したローカル受入記録。
比較元は`3b433f5`（N5b + OCRテスト待機修正）。現在の後続作業は
[リファクタリング計画書](../../log/計画/リファクタリング計画書.md)を正本とする。

## 1. 完了範囲と所有者

| 所有者 | 分離後の責務 |
|---|---|
| `pages/ViewerPage.tsx` | `features/library`の公開入口を配置するroute境界 |
| `features/library/LibraryWorkspace.tsx` | 一覧のmount維持とreader表示。Readerは公開入口経由で参照 |
| `features/library/useLibrarySession.ts` | URL解釈、source/pathのstore投影、選択・閉じる・上階層遷移、PDF一覧invalidate |
| `features/reader/index.ts` | 既存ReaderPanelの公開入口。表示componentの一括移動はしない |
| `features/reader/useReaderLifecycle.ts` | 書籍reset、画像ページ数同期、URL初期page適用、page pair resetを既存順に登録 |
| `hooks/reader/useReaderState.ts` | 既存専門hookの組立、close/direction/document handler、既存返却値を維持 |

URLは遷移の正本、TanStack Queryは書籍・metaの正本、Zustandは一覧の選択UIと
URL由来contextの投影、Reader専門hook/Contextは読書session、一時hookはdialog等を所有する。
API、query key、schema、書込み先、Context selector、画像/PDF描画ロジックは変更していない。
新設lifecycleからReact以外への依存と、route/workspaceからの境界外importを機械検査する。

## 2. 固定した契約

- 移動前にViewerの統合テスト2件とReader初期化順のテスト3件を追加した。
- URL戻る/進む、source/path投影、初期page、作者/series query保持、次巻選択時のpage消去、
  編集後の正しい`pdfQueryKey`無効化を確認した。
- 一覧DOM・入力・scroll保持、reset callbackの順序、画像ページ数同期、ページ数確定待ち、
  初期pageの一度だけの適用、書籍切替、close handlerの順序を固定した。
- 既存のReader専門hookテスト（読了、編集、見開き、関連書籍等）は全体検査で継続した。
- 初期page適用keyは書籍名と初期pageの組合せのまま。path/sourceを追加する挙動変更は行わない。

   RTL見開き送り・読了、削除取消、一覧復帰、履歴戻る/進む、キャッシュ済み再開、
   再度編集して削除確定、画像ページ数と一覧queryの更新。
2. 390px: 同じ操作と、絞り込みDialogの左右16px・focus内包・Escape閉じるを確認。
3. doujin画像reader: `?file=Book01.pdf&page=3`からの初期表示と戻る操作。
4. doujin PDF reader: 実PDF worker/canvasの描画、初期pageと戻る操作。

再実行例（独立Vite起動後、frontendから実行）:

```powershell
$env:PLAYWRIGHT_BASE_URL = 'http://127.0.0.1:5196'
npx playwright test e2e/library-reader-session.spec.ts --workers=1 --retries=0 --reporter=list --output "$env:TEMP/pic2pdf-n6-browser"
```

Windowsで既存Playwright出力ディレクトリの走査・削除にEPERMが発生したため、検証出力を
一時ディレクトリへ分離した。ESLintも生成された`playwright-output` / `playwright-report`を除外する。
ソースのlint検査対象は維持した。

## 4. 受入の限界と後続

- N6の構造変更と既存動作の一致を受入した。390pxではReaderヘッダー右側の検索・編集等が
  画面外へ出る既存問題がある。分離前コードでも同じ表示を確認し、
  [B-38](../../log/計画/バックログ.md#b-38)へ記録した。全ヘッダー操作のモバイル到達性を
  解消済みとはしない。本文・keyboard操作・一覧復帰は上記の範囲で通過している。
- APIは隔離fixtureであり、本番サービスとの接続、実データ更新、実端末タッチは追加受入していない。
  backendのproduction変更はなく、N5b時点のbackend全体検査をN6の再実行として計上しない。
- N7は参照調査と移動効果の判断から始める。Library/Reader全ファイルの集約や、
  未確認の外部利用を持つ互換入口の撤去を一括して行わない。
- 復旧はN6の変更単位をrevertする。データmigrationや再生成は不要。
