# Kindle 購入カタログ画面 UI/UX 改善 要件

> status: frozen | archived: 2026-08-22 | 実装済み。現行契約は [Kindle 購入カタログ設計](../../design/詳細設計/機能別/Kindle購入カタログ設計.md) を参照

要件状態: **実装・受入確認完了（2026-07-25）**

## 1. 目的

初回移行済みの Kindle 購入カタログを、通常運用で使う検索・確認・月次取込・画像整理の優先順位に合わせて再構成する。

最優先の利用目的は次の 2 点とする。

1. 11,419 冊規模の購入カタログから本を素早く検索・確認できること
2. Amazon データの差分取込と Kindle キャプチャによる画像取込を、安全に開始・監視できること

本改善は UI-only とし、既存 API、DB スキーマ、取込ロジック、データの役割分離を変更しない。

## 2. 前提と対象ユーザー

- 個人 LAN 内の単一利用者による通常運用を対象とする。
- デスクトップを主要な作業環境とする。
- iPad は閲覧中心でよいが、端末種別を理由に機能を無効化・非表示化しない。
- iPad 相当幅では、ページ全体に横スクロールを発生させず、検索・一覧・詳細を閲覧できることを目標とする。
- スマートフォン専用の操作最適化は今回の必須範囲に含めない。

## 3. 優先原則

1. 誤操作防止と状態の分かりやすさを、クリック数の少なさより優先する。
2. 通常使う検索と、一度だけ・月次で使う管理操作を分離する。
3. 一覧は書影のない高密度テーブルを基本とし、詳細操作を行内へ大量に並べない。
4. ASIN は候補スコアだけで確定せず、対象と候補を人が比較して最終確認する。
5. 将来の複数選択を考慮した構造にするが、使い道のないチェック欄だけを先行表示しない。

## 4. 情報設計

Kindle 領域内に 4 つのタブを置き、各タブに固有 URL を割り当てる。

| タブ | URL | 役割 |
|---|---|---|
| 購入書籍 | `/kindle/catalog` | 検索、絞り込み、一覧、書籍詳細 |
| 画像紐付け | `/kindle/links` | Pic2PDFViewer の既存画像と Kindle カタログ候補の比較・確定 |
| キャプチャ | `/kindle/capture` | 利用準備状況、既存ジョブ、将来のジョブ作成 |
| 取込・管理 | `/kindle/imports` | 月次差分取込、個別取込、旧 DB 移行などの低頻度管理操作 |

- Kindle 領域へ入った際の初期ページは「購入書籍」とする。
- タブはグローバルナビを 4 項目へ増やすものではなく、Kindle 領域内のサブナビゲーションとする。
- ブラウザーの戻る・進む、再読込、ブックマークで現在のタブと検索状態を復元できること。

## 5. 購入書籍ページ

### 5.1 検索とフィルター

- タイトル、ASIN、著者を 1 つの検索欄で検索する。
- 入力後 300ms 程度のデバウンスで自動検索し、Enter では待たずに実行する。
- 種別、所有状態、画像状態の既存フィルターを維持する。
- 検索語、各フィルター、ページ番号、ページ件数を URL クエリへ保存する。
- フィルター変更時は 1 ページ目へ戻る。
- 有効な検索条件を認識でき、個別または一括で解除できること。

### 5.2 一覧

- 初期表示は 25 件とし、25 / 50 / 100 件から選択できる。
- タイトル、著者、種別、所有状態、画像状態を常時表示する。
- ASIN、シリーズ、巻情報などは、画面幅に応じて副情報または詳細パネルへ移す。
- 行内には漫画撮影・小説撮影を常時並べない。
- 行を開くと書籍詳細パネルを表示する。
- ページ件数、現在ページ、総ページ数、前後移動を明示する。
- loading 中は既存行を突然消さず、更新中であることを表示する。

### 5.3 書籍詳細パネル

- タイトル、ASIN、著者、種別、所有状態、シリーズ、巻、画像状態を確認できる。
- キャプチャ環境が利用可能になった後は、詳細パネル内で comic / novel を確認してジョブ作成へ進む。
- キャプチャ確定前に、対象タイトル、ASIN、出力先種別を確認する。
- 音楽、アプリ、未分類項目などを一覧上の 1 クリックで誤って撮影対象にしない。

### 5.4 将来の複数選択

- 将来は一覧左端にチェック欄を常時表示し、選択件数と一括操作を一覧上部のツールバーへ表示する想定とする。
- 今回は一括操作の要件がないため、機能しないチェック欄は表示しない。
- 一覧行、列定義、ツールバーを責務分割し、将来チェック列を追加しても検索・詳細パネルを作り直さずに済む構造とする。

## 6. 画像紐付けページ

### 6.1 対象

- 左側は `meta2.db` で管理する Pic2PDFViewer の既存 `comic` / `novel` 画像とする。
- 右側は `kindle_catalog.db` の Kindle 購入カタログ候補とする。
- 確定時に更新するのは、既存フィールドを保持した `meta2.db.books_meta.asin` だけとする。
- DB 同士の統合、画像の移動・複製・削除、既存メタデータの上書きは行わない。

### 6.2 比較 UI

- 2 カラムを基本とし、左に紐付け対象、右に候補一覧を表示する。
- 対象側は source、タイトル、著者、シリーズを表示する。
- 候補側はタイトル、ASIN、著者、種別、候補スコア、候補理由を表示する。
- 巻違いを判別できるよう、シリーズ名・巻表現をタイトル内または副情報として読めること。
- 候補を選択した後、対象と選択候補を並べた最終確認を経て確定する。
- 候補行を表示しただけ、または候補を選択しただけでは DB を変更しない。
- 未紐付け残件数と、現在何件目を処理しているかを把握できること。

### 6.3 iPad 表示

- 2 カラムを縦積みに切り替えて閲覧できる。
- 端末判定によって確定操作を無効化しない。

## 7. キャプチャページ

### 7.1 通常運用

- 専用 Samba 受信箱と共有トークンはデプロイ時の運用前提とし、画面から設定しない。
- 購入書籍詳細に「撮影して取り込む」を表示し、対象、source、ページ送り方向、Kindle起動済み・ログイン済み・画面ロックなし・処理中の端末操作禁止を確認して新規 job を作成する。
- 全source・全ASINのいずれかにactive jobがある間は新規job開始を無効化し、
  同一ASINまたは他ASINの処理中jobを確認できる導線を表示する。
- 初回 job 作成は購入書籍詳細で行い、キャプチャページは既存 job の監視と failed job の再実行を担当する。
- 書籍の自動選択、未ダウンロード待機、先頭移動を含む通常運用仕様は、[Kindle 自動撮影取込 要件](../../design/要件定義/Kindle自動撮影取込_要件.md)で管理する。

### 7.2 ジョブ表示

- queued などの内部値をそのまま主表示せず、日本語ラベルと説明を表示する。
- 待機、実行中、完了、失敗を視覚的に区別する。
- タイトル、ASIN、出力先種別、ページ送り方向、状態、失敗理由を確認できる。
- capture job だけを 5 秒間隔で更新する既存挙動を維持する。

## 8. 取込・管理ページ

### 8.1 月次差分取込

- 月 1 回程度の低頻度操作として、購入書籍ページから分離する。
- 「すべて差分取込」で既存の Kindle Info、Amazon CSV、シリーズ自動購入の 3 API を順に呼び出す。
- 新しい一括 API は追加しない。
- 3 処理は個別にも実行できる。
- 各処理について待機中、実行中、成功、変更なし、失敗を個別表示する。
- 一部が失敗しても、成功済み処理と失敗処理を区別し、失敗した処理だけ再実行できる。
- 最終実行日時と直近結果を、トースト消失後もページ上で確認できる。

### 8.2 旧 DB 移行

- 初回移行済みのため、通常操作と同格に表示しない。
- 「初回移行・メンテナンス」などの低頻度管理領域へ配置する。
- preview と commit の分離、および旧アプリの画像・表紙・レビューを移行しない確認を維持する。

## 9. 共通状態とアクセシビリティ

- 4 ページそれぞれで loading、empty、error、disabled、success を設計する。
- エラーは対象操作と再試行方法が分かること。
- 重要操作は処理中に二重実行できないこと。
- ライト・ダークテーマの両方で文字、境界、状態色を識別できること。
- キーボードでタブ、検索、フィルター、ページ移動、詳細パネル、確認ダイアログを操作できること。
- フォーカス表示を消さない。
- アイコンだけのボタンには accessible name を付ける。
- iPad 相当幅でグローバルナビとページ本体がページ全体の横スクロールを発生させない。

## 10. スコープ外

- 旧アプリの画像、表紙キャッシュ、画像パス、レビュー、評価、感想の取り込み
- 既存画像の ASIN 自動確定
- Pic2PDFViewer の既存画像の移動・複製・削除
- 購入カタログ DB と `meta2.db` の統合
- API、DB スキーマ、取込ロジックの変更
- キャプチャエージェントの Samba・トークン運用設定そのもの
- 今回の一括操作機能実装
- スマートフォン専用 UI

## 11. UI 案比較

### 案 A — 高密度ワークベンチ + 詳細パネル（採用）

- 固有 URL を持つ 4 タブ
- 購入書籍は高密度テーブル
- 行選択で右側またはオーバーレイの詳細パネルを開く
- 画像紐付けだけは常設 2 カラム比較
- 低頻度操作は取込・管理へ隔離

**採用理由**: 検索が最優先、書影がない、11,419 冊規模、将来のチェック列追加という条件に最も合う。行内操作を減らしつつ、確認が必要な操作だけ詳細パネルへ集約できる。

### 案 B — 常設マスター・ディテール

- デスクトップでは一覧と書籍詳細を常に左右表示
- iPad では縦積み

**不採用理由**: 詳細を見ていない時間も一覧幅を消費し、著者・種別・状態の一覧比較が弱くなる。将来のチェック列追加とも競合しやすい。

### 案 C — カード型タスクダッシュボード

- 書籍、取込、未紐付け、ジョブをカードで表示
- 書籍もカード一覧を中心にする

**不採用理由**: 書影を使わない要件ではカードの利点が小さく、25〜100 件の比較と複数選択に不向き。検索開始までの情報量も増える。

- [x] `/kindle/catalog` を開くと購入書籍ページが表示され、検索をすぐ開始できる。
- [x] 初回移行と月次取込が購入書籍ページの主要操作として表示されない。

## 13. 実装・検証結果

- 4 ページと Kindle 内サブナビゲーションを React Router の固有 URL として実装した。
- 購入書籍は URL 同期検索、25 / 50 / 100 件ページング、レスポンシブ表、詳細ダイアログへ再構成した。
- 画像紐付けは対象・候補比較と最終確認を分離し、確認ダイアログの確定前には mutation を呼ばない。
- キャプチャは運用設定完了後に通常運用へ移行し、購入書籍詳細からのjob作成、自動工程の監視、失敗理由と確認付き再実行を提供する。取込・管理は既存 3 API の順次・個別実行と履歴表示を持つ。
- デスクトップ、iPad 縦 768px・横 1024px、ライト・ダーク、検索、詳細、確認キャンセルを実データ接続で確認した。紐付け確定、差分取込、旧 DB 移行は既存データを変更するため実機では実行せず、Vitest の API モックで呼出順と確認境界を検証した。
