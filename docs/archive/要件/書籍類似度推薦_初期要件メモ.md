## 1. 目的・ユーザー価値

読書会で「この本に似ている」という表現を自然に使えるようにする。
書籍詳細ページ（閲覧画面）に類似書籍を最大 5 件表示し、「次に読む本を探す」体験を補助する。

---

## 2. 対象 source

- **novel のみ**
- comic / doujin は対象外（スコープ外）

---

## 3. 類似度の計算軸

### 3.1 ハイブリッド 3 軸スコア

| 軸 | 内容 | 初期重み |
|---|---|---|
| 全文 embedding | bge-m3 で生成済みの全文ベクトル（既存） | 1/3 |
| サマリ embedding | 書籍サマリ文から生成した別ベクトル | 1/3 |
| メタ情報一致 | タグ/ジャンル + 著者/サークル名の Jaccard 係数 | 1/3 |

合成スコア = (cos_全文 + cos_サマリ + meta_jaccard) / 3

> 均等重みで実装し、実機テスト後に調整可能な設計にする。重みは定数として管理し、UI 調整機能は作らない。

### 3.2 欠損値の扱い

- **全文 embedding・サマリ embedding のいずれかが欠けている書籍はペア計算対象外**
- メタ情報（タグ・著者）が空の場合、その軸のスコアは 0 として扱う
- 結果が 0 件の書籍には「推薦なし」と表示する

---

## 4. 表示仕様

### 4.1 表示場所

- **書籍詳細ページ（閲覧画面）の下部パネル**のみ
- 一覧ページ・サイドバーへの表示は不要

### 4.2 表示件数・閾値

- 合成スコア ≥ 0.7 のペアのみ表示
- 最大 5 件（降順ソート）
- 0 件の場合は「類似する書籍が見つかりません」を表示

### 4.3 表示内容

各推薦カードには最低限以下を表示する（既存の書籍カードコンポーネントを流用可）:
- サムネイル
- タイトル
- スコア値（小数点 2 桁）
- 詳細ページへのリンク

---

## 5. データモデル

### 5.1 新規テーブル: `book_similarities`

```sql
CREATE TABLE book_similarities (
    source_book_id TEXT NOT NULL,
    target_book_id TEXT NOT NULL,
    score REAL NOT NULL,
    computed_at TEXT NOT NULL,
    PRIMARY KEY (source_book_id, target_book_id)
);
CREATE INDEX idx_book_similarities_source ON book_similarities (source_book_id);
```

- `source_book_id` / `target_book_id` は novel の書籍 ID
- ペアは有向（A→B と B→A を両方保存）または無向どちらでも可（実装時に決定）

### 5.2 既存テーブルへの変更

- なし（meta.json のタグ・著者フィールドは読み取り専用で参照）

### 5.3 サマリ embedding の保存先

- 既存の embedding DB（novel_db の SQLite）に `summary_embedding` カラムを追加する
  - サマリ未生成の場合は NULL（ペア計算対象外になる）

---

## 6. API 仕様

### 6.1 類似書籍取得

```
GET /api/novel/{book_id}/similar
```

レスポンス（成功時 200）:
```json
{
  "book_id": "xxx",
  "similar_books": [
    { "book_id": "yyy", "title": "...", "score": 0.82, "thumbnail_url": "..." },
    ...
  ]
}
```

- 結果が 0 件でも 200 を返す（`similar_books: []`）
- book_id が存在しない場合は 404

### 6.2 類似度バッチ再計算（管理画面用）

```
POST /api/admin/novel/recompute-similarities
```

- 管理画面の「類似度を再計算」ボタンから呼び出す
- レスポンスは即時返却（202 Accepted）でジョブ ID を返す
- 進捗は既存のジョブ管理画面（`/novel/manage`）で確認
- 失敗したペアはログに記録して継続（全体ロールバックなし）

---

## 7. 処理フロー（バッチ）

```
管理画面ボタン → POST /api/admin/novel/recompute-similarities
  → job_worker キューに投入
  → 全 embedding 完備の novel 書籍をリストアップ
  → 全ペアに対してスコア計算
  → score ≥ 0.7 のペアのみ book_similarities に UPSERT
  → 失敗ペアはログに記録して次のペアへ継続
  → ジョブ完了をステータス更新
```

---

## 8. スコープ外（やらないこと）

| 項目 | 理由 |
|---|---|
| comic / doujin の類似度 | embedding 品質・OCR 依存が高い。novel で先行実証する |
| 書籍追加時のリアルタイム自動再計算 | 書籍数が増えたとき O(N²) になる。手動バッチで十分 |
| スコア軸の UI 調整機能 | 定数管理で十分。UI 化のコストに見合わない |
| ユーザーフィードバック機能 | 単一ユーザーツールのため不要 |
| 一覧ページへの類似度表示 | 詳細ページのみで目的は達成できる |
