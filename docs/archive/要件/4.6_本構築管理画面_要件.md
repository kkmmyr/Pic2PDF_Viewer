# 4.6 本構築専用管理画面 要件定義

作成: 2026-05-13  
ステータス: 要件確定（/grill-me 完了）

---

## 目的・ユーザー価値

小説本の Full Build（OCR → Embedding → サマリ → 登場人物 → コンテキスト）は数分〜数十分かかるが、現在は DB タブで実行しており進捗が見えづらい。  
専用の `/novel/build` ページを設けて **ジョブキューの可視化・エンキュー操作・リアルタイムログ確認** を一元化する。

---

## 対象ユーザー

アプリ管理者（ローカル LAN 内の 1 ユーザー）

---

## 機能スコープ

### 含むもの

- `/novel/build` 新規ページ（小説ソース専用）
- **Full Build ジョブ**のエンキュー（対象: 全冊 / 特定 1 冊）
- ジョブキューのリアルタイム可視化（SSE）
- 待機中ジョブのキャンセル

### 含まないもの（明示的スコープ外）

- OCR 単体・Rebuild 単体ジョブ（既存 `/novel/ocr` 画面で継続）
- 同人誌・漫画ソースのビルド（将来拡張候補）
- E2E テスト（C-8 として別タスク化）

- フロントエンドは `EventSource` で購読、ページ離脱で切断

## バックエンド仕様

### ジョブキュー管理

- グローバルシングルトン `JobQueue` をメモリ内に保持（プロセス再起動でリセット）
- 構造:
  ```python
  @dataclass
  class Job:
      id: str          # uuid4
      book_name: str
      status: Literal["waiting", "running", "done", "error"]
      progress: int    # 0-100
      log: list[str]
      started_at: datetime | None
      finished_at: datetime | None
      retry_count: int  # 最大 1 回
  ```
- `running`: 最大 1 件（シリアル実行、既存ワーカーと同一）
- `done` リストは最新 50 件を保持

### ジョブ実行ルール

| 条件 | 挙動 |
|---|---|
| 同一書籍が waiting/running に存在する状態でエンキュー | 422 返却 + トースト「すでにキューに存在します」 |
| ステップ失敗（1 回目） | 同ステップから自動リトライ（retry_count = 1） |
| ステップ失敗（2 回目） | status = error で停止、次ジョブへ移行、ユーザーが手動再エンキュー |
| 待機中ジョブのキャンセル | `DELETE /api/novel/build/jobs/{id}` でキューから除去 |
| 実行中ジョブのキャンセル | 不可（ボタン非表示） |

### API エンドポイント（概要）

| メソッド | パス | 用途 |
|---|---|---|
| GET | `/api/novel/build/jobs` | キュー全体のスナップショット |
| POST | `/api/novel/build/enqueue` | ジョブ登録（body: `{book_name, all_books}`) |
| DELETE | `/api/novel/build/jobs/{id}` | 待機中ジョブキャンセル |
| GET | `/api/novel/build/stream` | SSE ストリーム（差分更新） |

## 完了条件

1. **手動ゴールデンパス**: 小説 1 冊を選択 → エンキュー → ログ・進捗表示確認 → 完了ステータス確認
2. **二重エンキューのエラー確認**: 実行中書籍を再度エンキューしてトースト表示を確認
3. **待機中キャンセル確認**: 待機エントリの × ボタンでキューから消えることを確認
4. **vitest**: キュー状態管理ロジック（`useNovelBuildQueue`）のユニットテスト
5. **pytest**: enqueue / cancel / stream エンドポイントのユニットテスト
6. **設計書更新**: 詳細設計書（バックエンド・フロントエンド編）+ API 仕様書
