`docs/01_要件定義/バックログ.md` を Read で読み込み、以下を報告してください。

バックログは A（高優先）/ B（中優先）/ C（低優先）の3階層と「対象外」セクションで構成されている。
実装済み機能は冒頭の「実装済み機能の履歴」テーブルに移動されている。

## 報告内容

1. **未着手・検討中の機能一覧** — A/B/C 各セクションに残っている項目を表で
   - 列: ID / タイトル / 優先度 / 工数 / 特記（保留中など）
   - **保留判断済みのものは「保留」と明記**（B-17 漫画キャプション検索など）
2. **実装済みサマリ** — 「実装済み機能の履歴」テーブルの件数と直近 3 件
3. **対象外の件数** — 件数のみ（詳細は不要）
4. **次に着手すべきおすすめ** — 未着手のうち工数が小〜中でスコープが明確なものを 1〜3 件提示。
   「工数: 小」のものは特に優先。全て工数大なら「設計検討フェーズが先」と報告

## 注意

- バックログは行数が多いので全文 Read（1 回で取得可能）
- 報告は簡潔に。表は Markdown で。バックログ本文の貼り付けは不要
- 内部リファクタ / 依存更新は本バックログに含まれない（それらは `/refactor-status` を案内）
