# /grill-me — 着手前に要件を固める対話インタビュー

新機能・リファクタ・移行など「とりあえず実装に入ると後でやり直しになる」種類の作業で、ユーザーが `/grill-me <機能名>` で呼び出した時に発動する。Claude が能動的に質問し、ユーザーの回答で次の質問を分岐させながら、要件の決定木を埋めていく。

## 進め方

`AskUserQuestion` を使って 1 メッセージあたり 1〜3 問ずつ提示する。

- 各質問は推奨選択肢を 2〜4 個用意する
- コンテキスト（設計書 / 既存実装）から推測できるものは 1 位に置いて「(Recommended)」を付ける
- ユーザー回答を踏まえて次の質問を組み立てる（分岐）
- 「Other」自由記述で答えられた場合は、その内容を踏まえて深掘り

## 必ず潰す質問カテゴリ

すべてのカテゴリで最低 1 問は出す。コンテキストから自明な項目はスキップしてよいが、その判断を一言ユーザーに伝える。

1. **目的とユーザー価値** — 何を解決するのか、誰のための機能か
2. **データモデル / スキーマ影響** — 新規フィールド、既存 meta.json の互換性、永続化先
3. **影響範囲** — どの router / service / component / 設計書が変わるか
4. **UI / API の変更有無** — 新 API、既存 API のシグネチャ変更、UI コンポーネント
5. **エッジケース** — 空入力、大容量、並行アクセス、Kindle 連携の特殊条件
6. **失敗時の挙動** — ロールバック、部分失敗、リトライ、エラー表示
7. **スコープ外（やらないこと）** — 明示的に除外する範囲
8. **完了条件** — テスト観点、設計書更新範囲、リリース判定
9. **既存機能との競合** — 機能追加候補.md の他項目・進行中リファクタとの衝突

## 終了条件

- 全カテゴリで 1 問以上潰し、かつユーザーが「もう十分」と表明する
- または、ユーザーが先に切り上げを宣言する

## 出力

質問が尽きたら、回答内容を **要件サマリ Markdown** にまとめて配置先を提案する。

- **軽量機能**（数十行レベル、設計書影響なし） → [docs/01_要件定義/機能追加候補.md](docs/01_要件定義/機能追加候補.md) の該当ティアに追記
- **中〜重量機能**（複数ファイル、設計書更新あり） → `docs/01_要件定義/<機能名>_要件.md` として新規作成し、機能追加候補.md からリンク
- **リファクタ系** → [docs/06_リファクタリング/リファクタリング計画書.md](docs/06_リファクタリング/リファクタリング計画書.md) の追加候補に追記

要件サマリ作成後は `docs-workflow` skill の手順（設計書 → 変更履歴 → ソース）に移行する。

## 不要なケース

- typo / コメント整理 / 色やメッセージ変更などの軽微編集
- 要件が既に固まっている作業（設計書記載済み、ユーザーが詳細指示済み）
- 緊急バグ修正（先に直す、要件は事後に整理）
- 1 問で確定できる単純機能追加（その場で確認すれば足りる）

迷ったら「これは grill-me に値するか？」を最初にユーザーに 1 問だけ聞いて判断する。
