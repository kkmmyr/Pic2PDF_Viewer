# ドキュメント連動の変更手順

設計の意図を変える編集（仕様・挙動・I/O・データ構造の変更）は、以下の順序で進める：

1. **関連する設計書（`docs/` 配下）を更新する**
   - どの設計書が該当するかは `architecture-overview` skill の一覧を参照
   - 仕様変更 → 要件定義 / 基本設計、実装方針 → 詳細設計、API → API.md（+ /openapi.json）、データ保存 → 詳細設計+セキュリティ
2. **`docs/log/変更履歴.md` に追記する**
   - 日付 + 概要 + 影響範囲を 1 エントリ
3. **設計書の更新を確認してからソースを修正する**

## この手順が不要なケース

- typo 修正・コメント整理・ログメッセージ変更
- 既存ロジックを変えないリネーム / フォーマット
- テストコードの追加・修正
- 設計書側に未反映の "実装の都合" な微修正

迷ったら手順を実行する側に倒す（後から復元するより簡単）。

## hook との関係

`remind_docs_update.sh` (PreToolUse) が同様の意図を **advisory** として通知する。hook は機械的に出るリマインダー、本 skill はユーザー意図を踏まえた手順そのものの定義。
