# アーキテクチャ概要

このプロジェクトの設計書は `docs/` 配下にすべて格納されている。コードを大きく変える前に **アーキテクチャ詳細**（バックエンド編／フロントエンド編）を確認し、必要に応じて他の設計書を読む。

## まず読むべきファイル

- **[docs/02_基本設計/アーキテクチャ詳細_バックエンド編.md](docs/02_基本設計/アーキテクチャ詳細_バックエンド編.md)** — backend / Kindle / データディレクトリのファイルマップ
- **[docs/02_基本設計/アーキテクチャ詳細_フロントエンド編.md](docs/02_基本設計/アーキテクチャ詳細_フロントエンド編.md)** — frontend のファイルマップ

新機能追加・複数ファイル横断の修正時は、変更領域に応じて該当側を最初に読む。

## 設計書の所在

```
docs/
├── 01_要件定義/
│   ├── 要件定義書.md
│   └── 機能追加候補.md       ← バックログ（A/B/C ティア）
├── 02_基本設計/
│   ├── 基本設計書.md
│   ├── アーキテクチャ詳細_バックエンド編.md   ← まず読む
│   ├── アーキテクチャ詳細_フロントエンド編.md  ← まず読む
│   └── ADR/                  ← 設計判断の記録（README.md から一覧）
├── 03_詳細設計/              ← API仕様書・OCR・セキュリティ・詳細設計（BE/FE/共通）
├── 04_環境構築/              ← uv・GPU・運用ガイド・mkdocs
├── 05_記録/
│   └── 変更履歴.md           ← 直近の変更（過去分は 変更履歴/YYYY-Www.md）
└── 06_リファクタリング/
    ├── リファクタリング計画書.md  ← 未着手 Phase・追加候補
    └── リファクタリング履歴.md   ← 完了 Phase 詳細
```

## レイヤ構成

- **バックエンド** (`backend/`): FastAPI + Python（uv 管理）。ルーター/サービス分離。詳細規約は `backend-conventions` skill が発動
- **フロントエンド** (`frontend/`): React + TypeScript + Vite。`viewer/`（状態管理）と `reader/`（プレゼンテーション）の階層分離。詳細規約は `frontend-conventions` skill が発動

## 関連 skill

- 設計書 → 変更履歴 → ソース修正 の手順は `docs-workflow` skill を参照
