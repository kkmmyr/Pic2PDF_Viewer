# アーキテクチャ概要

全体の入口は[設計書トップ](../../../docs/index.md)、文書の責務・移管・検査は
[設計書運用ルール](../../../docs/design/環境構築/設計書運用ルール.md)を参照する。
横断契約の正本はトップの正本マップで確認し、機能固有の説明を共通設計へ複製しない。

## 変更前に読む文書

| 確認したいこと | 文書 |
|---|---|
| 利用者要件・システム境界 | [要件定義](../../../docs/design/要件定義/要件定義書.md) / [基本設計](../../../docs/design/基本設計/基本設計書.md) |
| backendの責務・保存境界 | [バックエンド設計](../../../docs/design/詳細設計/詳細設計書_バックエンド編.md) |
| backend / Kindleの実ファイル | [バックエンド ファイルマップ](../../../docs/design/詳細設計/詳細設計書_バックエンド_ファイルマップ.md) |
| frontendの共通規約 | [フロントエンド設計](../../../docs/design/詳細設計/詳細設計書_フロントエンド編.md) |
| frontendの実ファイル | [フロントエンド ファイルマップ](../../../docs/design/詳細設計/詳細設計書_フロントエンド_ファイルマップ.md) |
| KindleのWindows / Linux横断契約 | [自動撮影ジョブ契約](../../../docs/design/詳細設計/機能別/Kindle自動撮影ジョブ契約.md) |
| OCR候補・QA・公開 | [OCR設計書](../../../docs/design/詳細設計/機能別/OCR設計書.md) |

ファイルマップは自動生成であり、手書きの各層設計とは別文書で管理する。
Kindle内部実装は`kindle-pdf/docs/`、共通LLMのモジュール利用は`common/llm/docs/`にも文書がある。
これらは横断契約を再定義せず、`docs/design/`の所有文書を参照する。

## 文書の配置と案内

- `docs/design/`: 現行要件・基本設計・ADR・詳細設計・開発運用契約。
- `docs/log/計画/`: 未完了のバックログ・OCR改善・Sol導入・内部改善。
- `docs/log/技術知見/`: 再利用する実測・注意点・評価資料。
- `docs/log/変更履歴.md`: 直近履歴と週別索引。週次本文は`docs/log/変更履歴/`に保存する。
- `docs/archive/`: 完了・中止・置換時点の凍結記録。[索引](../../../docs/archive/index.md)から全件を参照する。
  初期の週次履歴は既存の`archive/変更履歴/`に残し、変更履歴の週別索引からも辿れる。

サイドバーは「設計」「開発・運用」「計画」「記録・履歴」の目的別構成とし、物理配置と区別する。
