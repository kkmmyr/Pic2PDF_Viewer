# アーキテクチャ概要

このプロジェクトの設計書は `docs/` 配下にすべて格納されている。コードを大きく変える前に **詳細設計書**（バックエンド編／フロントエンド_ファイルマップ）を確認し、必要に応じて他の設計書を読む。

## まず読むべきファイル

- **[docs/design/詳細設計/詳細設計書_バックエンド編.md](../../../docs/design/詳細設計/詳細設計書_バックエンド編.md)** — backend / Kindle / データディレクトリのファイルマップ（クラス設計込み）
- **[docs/design/詳細設計/詳細設計書_フロントエンド_ファイルマップ.md](../../../docs/design/詳細設計/詳細設計書_フロントエンド_ファイルマップ.md)** — frontend のファイルマップ

新機能追加・複数ファイル横断の修正時は、変更領域に応じて該当側を最初に読む。

## 設計書の所在

```
docs/
├── design/                        ← 静的設計書（編集イン・プレース）
│   ├── 要件定義/
│   │   └── 要件定義書.md
│   ├── 基本設計/
│   │   ├── 基本設計書.md
│   │   └── ADR/                   ← 設計判断の記録（README.md から一覧）
│   ├── 詳細設計/
│   │   ├── 詳細設計書_バックエンド編.md         ← まず読む
│   │   ├── 詳細設計書_フロントエンド編.md
│   │   ├── 詳細設計書_フロントエンド_ファイルマップ.md  ← まず読む
│   │   ├── 詳細設計書_共通.md
│   │   ├── API.md
│   │   ├── セキュリティ設計書.md
│   │   └── 機能別/                ← OCR設計書 等、機能単位の詳細設計
│   └── 環境構築/                   ← uv・GPU・運用ガイド・mkdocs
├── log/                            ← 生きた文書（頻繁に更新）
│   ├── 変更履歴.md                 ← 直近の変更（800行超で 変更履歴/YYYY-Www.md へ切り出し。check-docs pre-commit hook が行数を機械チェック）
│   ├── 技術知見/                   ← 小説RAG技術知見・テスト知見
│   └── 計画/
│       ├── バックログ.md               ← 機能追加候補（A/B/C ティア）
│       └── リファクタリング計画書.md    ← 未着手 Phase・追加候補
└── archive/                        ← 凍結（完了済み計画・過去要件・週次変更履歴アーカイブ）
    ├── リファクタリング履歴.md      ← 完了 Phase 詳細
    ├── 要件/                       ← アーカイブ済み機能要件
    └── 変更履歴/                   ← 週次アーカイブ（YYYY-Www.md）
```

## レイヤ構成

- **バックエンド** (`backend/`): FastAPI + Python（uv 管理）。ルーター/サービス分離。詳細規約は `backend-conventions` skill が発動
- **フロントエンド** (`frontend/`): React + TypeScript + Vite。`library/`（状態管理、旧 `viewer/` からリネーム済）と `reader/`（プレゼンテーション）の階層分離（`components/` / `hooks/` 配下）。詳細規約は `frontend-conventions` skill が発動

## 関連 skill

- 設計書 → 変更履歴 → ソース修正 の手順は `docs-workflow` skill を参照
