# source-command-refactor-status

Use this skill when the user asks to run the migrated source command `refactor-status`.

## Command Template

`docs/log/計画/リファクタリング計画書.md` を Read で読み込み、以下を報告してください。

リファクタリング計画書は本体（追加候補・対象外・新規 Phase テンプレ）と履歴（完了 Phase 1〜N の詳細）に分割されている。本コマンドは**本体のみ**を読み、履歴.md は必要なときだけ参照する。

## 報告内容

1. **完了状況サマリ** — 本体「概要」テーブルから「完了 Phase 数」「直近完了」「次の動き」を抜粋
2. **未着手・追加候補** — 「未着手・追加候補」セクション配下のすべての有効な候補を抽出して表で。対象セクション: § 未着手候補 — リファクタリング / § 未着手候補 — 技術メンテナンス / Phase 51 完了後 / 52 完了後 / 54 後 等の既存グループすべて。**ストライクスルー (`~~...~~`) されていない有効な候補のみ**
   - 列: 優先度 (P1/P2/P3/スキップ) / 種別（リファクタリング / 技術メンテナンス） / 内容 / 由来（どのセクションか）
3. **スキップ判断（参考保持）** — 件数のみ言及（詳細は履歴.md にあるため省略）
4. **対象外（現状維持）** — 件数のみ言及。要すれば最初の 3 件のみ抜粋
5. **次に着手すべきおすすめ** — 有効な候補のうち P1 があれば優先、なければ P2 から独立性の高い順に 1〜3 件提示。すべて P3 / スキップ寄りなら「新規発掘待ち」と報告

## 注意

- 計画書本体は短い（70 行程度）ので全文 Read で OK
- 履歴.md（リファクタリング履歴.md）は本コマンドでは読まない（行数大、必要時のみ別途読む）
- 報告は簡潔に。表は Markdown で。計画書本文の貼り付けは不要
